# 地牢场景重画 v1

2026-10-30。沿用用户已确认的地痞据点 v6 画风、棋格规格和生活痕迹，按 [77号规范](../../../docs/design/77-grid-scene-art-standard.md) 制作。新图已接入当前游戏渲染，供用户复核；v6 的认可不自动等于这批新图全部获批。

墙地：水泥地、木地板、工业地面、道路、灰墙、露砖灰墙、潮石墙、半漆车间墙、铁漆面，共9类。其中水泥地、灰墙直接使用v6已有材质，其余7张重画。

共新增103张当前有效生成图（96张物件状态图、7张材质图）；另复用4项已认可v6素材。制作过程使用内置图像生成与编辑工具。未修改人形、尸体、树木、采集植物、矿石等自然资源。

## 来源与显示规格

- `prompts/`：生成／编辑提示词、参考图和保留的原始生成路径。修正前来源保留。第一张遗留箱子的逐字提示词未完整留存，单独标明，不用重构文案冒充原记录。
- `provenance.json`：当前每张PNG与原始来源的SHA256对应；两张复制图列出v6来源。
- `registration.json`：人工核对的底部接地点、实体底宽、逻辑占格、状态映射；这是当前显示数据源。
- `asset-checks.json`：原图尺寸、透明范围、显示边界和SHA256。PNG原像素保留，透明裁切只在显示层执行。
- `manifest.json`、`js/dungeon/grid-scene-catalog.js`：由当前登记生成，包含裁切、锚点、原生朝向与人物比例检查基准。

格宽144px、格高约101.82px，地面轴斜率±1/√2，竖直边保持竖直。小物件仅占格内合理面积，多格家具按脚点落地；不使用开盖后的裁切宽度缩小整件容器。圆形轮廓不以底弧拟合地面轴。桌面、座面、床面和机组机身已单独复核，不能根据包含地面纵深的PNG总高度判断人物比例。

## 接入

`DungeonGridArt`统一提供新素材，既有容器ID、搜索、设施消耗、食材余量及撤离规则不变。覆盖容器、恢复点、领悟点、据点家具、食材筐、撤离路牌、地牢墙地。旧存档携带的旧设施图路径也通过设施类型映射至新图。旧素材继续保留以便回查。

用户的房间布局原样保存在 `../street-thug-boss-room-v6/default-layout.json`，已作为固定房间正式生成、预览与编辑器恢复默认的共同来源；个人浏览器草稿保留。整间小屋已于2026-10-30确认并接入第四层，只平移位置，不改内部布局。

同日进行全地牢显示修正：保留本目录原图与98状态，普通建筑统一薄墙与门高、室外地表连续衔接、单格物件朝向可使用空地。头目小屋外围预留区继承周围地面，不再铺整圈水泥地。见77号规范及 `tools/street-thug-boss-room-generation.html` 的实际地图分类检查。

## 检查与维护

浏览 `tools/dungeon-grid-art-review.html`，可以切换类别、已用状态、格线及朝向；显示尺寸与正式棋盘一致。每张图旁保留主角和头目作参照。

修改原图或登记后，先运行 `tools/inspect-boss-room-assets.py` 更新本目录 `asset-checks.json`，再运行 `tools/build-grid-scene-catalog.mjs`。最后运行 `tools/test-dungeon-grid-scene-art.mjs` 检查56种物件的真实绘制分支、状态映射、占格、缩略图、食材四态与自然资源保留。`tools/register-grid-*.mjs`是首次批量登记脚本，不要用它覆盖后来人工调整后的`registration.json`。

来源核对工具：`tools/build-grid-scene-provenance.mjs`。检视截图存于 `reference/dungeon-grid-scene-v1/qa/`。
