## 最小交易流程（Market 单次小额交易）

> 只描述 `scene_type = Market` 的**一次会话**内的小额单次交易，从打开交易界面到成交或关闭为止。

### 前提与会话边界

- **会话定义**：玩家与**单个**市场摊贩/商人进入交易界面后，形成一次交易会话；会话到点击「成交」或关闭界面结束。
- **只在成交落地**：会话内的「给/要」操作只改变会话临时状态；**只有点击「成交」**才会修改双方真实库存与资金池。
- **关闭不落地**：任何关闭交易界面的方式（含关闭按钮/Esc/切场景等）都视为取消本会话；本会话内已选的数量与待处理行全部丢弃，不写回真实库存/资金池/商誉。
- **单次小额边界**：Market 必须受单笔上限约束（例如商人字段 `max_single_trade_amount` 或场景规则给出的单笔金额/件数上限）；超过上限则本次「成交」不可通过。

### 玩家视角流程（5–7 步）

1. 与市场商人对话，选择「交易」打开界面；标题栏显示其“能用哪些货币交易”（按 `accepted_currencies` 展示）。
2. 左侧看到自己可交易物品列表，右侧看到对方可交易物品列表；两侧独立滚动，行数不足一侧用空行补齐。
3. 通过步进按钮调整本次数量 \(N\)；步进只改显示，不会立刻改变背包/对方库存。
4. 点击「给 N 个/全都给」或「要 N 个/全都要」，将对应物品加入对侧的“待处理行”；同一物品在本会话内只占一行，数量变化只改数字；数量为 0 时行隐藏。
5. 在双列表下方看到一行净利润/净亏损展示：`n[货币名]`（整数，可正/负/0），用于直观看本笔交易的得失。
6. 若本笔包含“向商人出售”且商人现钱不足，系统会弹出确认提示；玩家可选择取消或继续。
7. 点击「成交」完成结算并落地；或直接关闭界面放弃本会话（不发生任何实际变化）。

### 系统视角实现流程

#### 1) 会话初始化（打开交易界面时）

- **建立交易上下文**：创建会话对象，至少包含 `scene_type = Market`、`merchant_id`、`accepted_currencies`（有序列表）。
- **载入双方库存快照**：把玩家与商人的可交易物品拉成两侧列表的行数据（每行至少含 `item_id`、`name`、`count`，以及用于估值的 `base_value`/`tags`）。
- **初始化会话内字段**（对每个物品行）：
  - `session_available_count = count`（本会话内还可用于给/要的数量）
  - `session_delta_give = 0`、`session_delta_take = 0`（玩家视角：计划给出/拿取数量）
- **初始化净利润展示口径**：
  - 本会话用于展示的货币取商人最优先货币：`accepted_currencies[0]`（同 `accept_currencies[0]` 概念）。
  - 将会话当前的 `net_profit_value` 换算为整数 `net_profit_in_primary_currency`，用于 UI 显示 `n[货币名]`（利润行为本会话实时估算值，不等同最终到账“钱”的精确变化）。

#### 2) 会话内更新（不落地）

- **步进按钮**：仅更新 UI 的当前 \(N\)，不改任何会话库存字段。
- **给/要动作**（点击「给 N 个/全都给」「要 N 个/全都要」时）：
  - 更新对应物品行的 `session_delta_give/session_delta_take`（实现可选择“累加”或“设为最新计划值”，但需保证会话内同物品只形成一条最终计划）。
  - 同步扣减对应持有侧的 `session_available_count`，避免会话内超用。
  - 触发重算会话聚合值：`V_player_give`、`V_player_get`、`net_profit_value`，并刷新利润行 `n[货币名]`。
- **待处理行策略**：
  - 同一物品的待处理行只更新数量，不新增重复行。
  - 待处理数量归零时隐藏该行（不立即删除），便于会话内再次增加时复用。

#### 3) 点击「成交」校验（允许失败，失败则仍停留在会话内）

- **单笔上限校验（Market）**：按本场景口径对“本笔交易规模”做封顶校验（例如金额口径或件数口径），超过则拒绝成交。
- **会话内数量一致性校验**：任一物品的 `session_delta_*` 不得为负；且不得超过本会话初始 `count`（也即不应出现 `session_available_count < 0`）。
- **资金池不足校验（玩家出售给商人）**：
  - 计算本笔中需要由商人支付给玩家的金额，与 `fund_pool_current` 比较。
  - 若超出：弹出确认；玩家取消则成交失败返回；玩家确认则进入结算，且超出部分按“转商誉”规则处理（见下）。

#### 4) 结算落地（只在成交时执行）

- **库存落地**：遍历所有物品行：
  - 若 `session_delta_give > 0`：从玩家真实库存扣减对应数量，并加入商人真实库存。
  - 若 `session_delta_take > 0`：从商人真实库存扣减对应数量，并加入玩家真实库存。
- **资金池与商誉落地（玩家出售给商人时）**：
  - 在 `fund_pool_current` 覆盖范围内的部分：正常支付给玩家（以货币物品/等价结算口径实现），并扣减商人 `fund_pool_current`。
  - **超出资金池部分**：不再支付金钱收益，按超出部分的价值折算为**地区商誉增量**（“按单笔结算”的超出部分，仅指这一笔成交里超出的那段）。
  - 若结算后 `fund_pool_current = 0`：本会话后续（若仍允许不关闭窗口）应禁止玩家继续向该商人出售；购买不受此条影响。
- **会话结束**：成交成功后，视 UI 设计可直接关闭交易界面或回到初始列表；但无论哪种，都必须视为本会话已终结。

#### 5) 关闭与清理（成交或取消都要做）

- **删除会话临时数据**：清空/丢弃所有 `session_available_count`、`session_delta_give/session_delta_take`、`V_player_give/get`、`net_profit_*` 等会话字段。
- **清除待处理行**：所有隐藏行/待处理行在成交后或关闭时都应从 UI 与会话数据中移除，避免下次打开界面继承旧状态。
