## 最小交易流程（Market 单次小额交易）

> 只描述 `scene_type = Market` 的**一次会话**内的小额单次交易，从打开交易界面到成交或关闭为止。

### 前提与会话边界

- **会话定义**：玩家与**单个**市场摊贩/商人进入交易界面后，形成一次交易会话；会话到点击「成交」或关闭界面结束。
- **只在成交落地**：会话内的「给/要」操作只改变会话临时状态；**只有点击「成交」**才会修改双方真实库存与资金池。
- **关闭不落地**：任何关闭交易界面的方式（含关闭按钮/Esc/切场景等）都视为取消本会话；本会话内已选的数量与待处理行全部丢弃，不写回真实库存/资金池/商誉。
- **单次小额边界**：Market 必须受单笔上限约束（例如商人字段 `max_single_trade_amount` 或场景规则给出的单笔金额/件数上限）；超过上限则本次「成交」不可通过。

### 玩家视角流程（5–7 步）

1. 与市场商人对话，选择「交易」打开界面；标题栏显示其“能用哪些货币交易”（按 `accepted_currencies` 展示）。
2. 左侧看到自己可交易物品列表，右侧看到对方可交易物品列表；表头可含 **单价** 以对应价值列，**不写货币缩写**（见下文「字体层级」表头条与 `trade_ui_layout.md` **7.1-A**）。两侧独立滚动，行数不足一侧用空行补齐。
3. 通过步进按钮调整本次数量 \(N\)；步进只改显示，不会立刻改变背包/对方库存。
4. 点击「给 N 个/全都给」或「要 N 个/全都要」，将对应物品加入对侧的“待处理行”；同一物品在本会话内只占一行，数量变化只改数字；数量为 0 时行隐藏。
5. 在双列表下方为底栏**利润行**（自左至右：**「询价」**、净利润展示区、**「成交」**；整体留白与对齐见 `trade_ui_layout.md` **第二节、6.5、第七节**）：
   - **未完成有效询价（默认）**：净利润区固定为 **`？？ [货币名]`**（两个全角问号、**1 个半角空格**、商人最优先货币的显示名），**不**展示千分位盈亏整数；两侧列表的**价值列**亦为 **`？？`**（**7.1-A**），与 layout 一致。
   - **完成有效询价后**：净利润区改为 **`n [货币名]`**（`n` 为按本会话估算的整数，可正/负/0），随待处理行变化实时刷新；千分位与空格规则见下文「利润行」小节及 layout **6.5**。
   - **手动询价**：底栏 **「询价」**按钮**始终保留、不隐藏**；玩家点击后触发有效询价（若技能/场景/商人规则不允许，则保持占位并可辅以简短提示，文案由实现定）。
   - **贸易技能自动询价**：若角色 **贸易**（生活系，见 `docs/design/11-skills.md`）达到数据表配置的**自动询价阈值**（具体数值不在本文写死，见 `trade_ui_layout.md` **7.3**），则**打开交易界面即视为已完成有效询价**：价值列与利润区**初始**即按已询价规则显示数字，无需点击「询价」；**「询价」**仍以**已询价**视觉状态显示在底栏最左侧（layout **7.2**），避免布局跳动。
6. 若本笔包含“向商人出售”且商人现钱不足，系统会弹出确认提示；玩家可选择取消或继续。
7. 点击「成交」完成结算并落地；或直接关闭界面放弃本会话（不发生任何实际变化）。

### 系统视角实现流程

#### 1) 会话初始化（打开交易界面时）

- **建立交易上下文**：创建会话对象，至少包含 `scene_type = Market`、`merchant_id`、`accepted_currencies`（有序列表）。
- **载入双方库存快照**：把玩家与商人的可交易物品拉成两侧列表的行数据（每行至少含 `item_id`、`name`、`count`，以及用于估值的 `base_value`/`tags`）。
- **初始化会话内字段**（对每个物品行）：
  - `session_available_count = count`（本会话内还可用于给/要的数量）
  - `session_delta_give = 0`、`session_delta_take = 0`（玩家视角：计划给出/拿取数量）
- **初始化净利润展示口径**：
  - 本会话用于展示的货币取商人最优先货币：`accepted_currencies[0]`（同 `accept_currencies[0]` 概念）。
  - 会话层可将当前 `net_profit_value` 换算为整数 `net_profit_in_primary_currency`（本会话实时估算，不等同最终到账「钱」的精确变化）。**未有效询价时** UI 不展示该整数与各列单价，利润行与价值列仅为 **`？？ …`** 占位（与玩家流程第 5 步、`trade_ui_layout.md` **6.5、7.1** 一致）。**完成有效询价**（含 **贸易** 技能触发的自动询价）后，再显示 **`n [货币名]`** 与单价数字。

#### 2) 会话内更新（不落地）

- **步进按钮**：仅更新 UI 的当前 \(N\)，不改任何会话库存字段。
- **给/要动作**（点击「给 N 个/全都给」「要 N 个/全都要」时）：
  - 更新对应物品行的 `session_delta_give/session_delta_take`（实现可选择“累加”或“设为最新计划值”，但需保证会话内同物品只形成一条最终计划）。
  - 同步扣减对应持有侧的 `session_available_count`，避免会话内超用。
  - 触发重算会话聚合值：`V_player_give`、`V_player_get`、`net_profit_value`，并刷新利润行（已询价时为 **`n [货币名]`**，未询价仍为 **`？？ [货币名]`**）。
- **待处理行策略**：
  - 同一物品的待处理行只更新数量，不新增重复行。
  - 待处理数量归零时隐藏该行（不立即删除），便于会话内再次增加时复用。

#### 3) 点击「成交」校验（允许失败，失败则仍停留在会话内）

- **单笔上限校验（Market）**：按本场景口径对“本笔交易规模”做封顶校验（例如金额口径或件数口径），超过则拒绝成交。
- **会话内数量一致性校验**：任一物品的 `session_delta_*` 不得为负；且不得超过本会话初始 `count`（也即不应出现 `session_available_count < 0`）。
- **资金池不足校验（玩家出售给商人）**：
  - 计算本笔中需要由商人支付给玩家的金额，与 `fund_pool_current` 比较。
  - 若超出：弹出确认；玩家取消则成交失败返回；玩家确认则进入结算，且超出部分按“转商誉”规则处理（见下）。

#### 4) 结算落地（只在成交时执行）

- **库存落地**：遍历所有物品行：
  - 若 `session_delta_give > 0`：从玩家真实库存扣减对应数量，并加入商人真实库存。
  - 若 `session_delta_take > 0`：从商人真实库存扣减对应数量，并加入玩家真实库存。
- **资金池与商誉落地（玩家出售给商人时）**：
  - 在 `fund_pool_current` 覆盖范围内的部分：正常支付给玩家（以货币物品/等价结算口径实现），并扣减商人 `fund_pool_current`。
  - **超出资金池部分**：不再支付金钱收益，按超出部分的价值折算为**地区商誉增量**（“按单笔结算”的超出部分，仅指这一笔成交里超出的那段）。
  - 若结算后 `fund_pool_current = 0`：本会话后续（若仍允许不关闭窗口）应禁止玩家继续向该商人出售；购买不受此条影响。
- **会话结束**：成交成功后，视 UI 设计可直接关闭交易界面或回到初始列表；但无论哪种，都必须视为本会话已终结。

#### 5) 关闭与清理（成交或取消都要做）

- **删除会话临时数据**：清空/丢弃所有 `session_available_count`、`session_delta_give/session_delta_take`、`V_player_give/get`、`net_profit_*` 等会话字段。
- **清除待处理行**：所有隐藏行/待处理行在成交后或关闭时都应从 UI 与会话数据中移除，避免下次打开界面继承旧状态。

## 交易界面最小视觉规范（与 `trade_ui_layout.md` 对齐）

> 本节补充「最小可用」的视觉与交互细节，确保实现时不会出现错位、字体层级混乱、或关键文案/数字格式不一致。
> `trade_ui_layout.md` 负责结构与交互要素，本节负责最小外观口径与上文 Market 最小流程。若 **`basic.md`、本文件与 `trade_ui_layout.md`** 就交易界面相关约定冲突，解释顺序为 **`basic.md` → `trade_ui_layout.md`（第二至七节等）→ `minium_capitalism.md`（本节）**，与 `trade_ui_layout.md` **7.5** 一致；发现冲突时应回并文档同步修订。

### 画布与缩放

- **基准分辨率**：1280×720。
- **适配**：等比缩放 \(scale = min(viewW/1280, viewH/720)\) 并居中；鼠标命中检测需将 CSS 像素映射到 Canvas 实际像素坐标（避免 DPR 下 hover/click 偏移）。
- **像素风约束**：`imageSmoothingEnabled = false`；边框/按钮尽量像素对齐。

### 主题色（棕金体系，参考 `test-scene.html`）

- **背景**：深棕/炭黑系（如 `#1c1815` / `#1c1612` / `#26211d`）。
- **描边/分隔**：棕色与灰褐（如 `#4d3f35` / `#57534e`）。
- **强调色**：暖金（如 `#fbbf24`）用于 hover、重点提示。

### 字体层级（必须产生差异）

- **标题栏**：26px；其中**货币名** 26px 加粗。
- **表头**（“玩家可交易物品 / 对方可交易物品”）：24px；仅**“玩家/对方”**加粗，且表头字号略小于标题栏。表头区域可附 **单价** 字样以对应价值列（**7.1-A**），**不写货币缩写**；币种由标题栏「说能用 [货币名]…」与玩家所持货币理解，与 `trade_ui_layout.md` 一致。
- **物品行**：
  - **物品名**：20px。
  - **“× 数量”**：18px 加粗（比按钮字大，但略弱于物品名）。
- **列表内按钮文字**（步进、给/要、全都、关闭 X）：16px。
- **底行文字**（成交按钮文字、利润行文本）：20px。

### 行对齐与留白（防止错位的硬约束）

- **行高唯一真源**：列表中“物品名/数量、**价值列**（`？？` 或单价数字）、步进/动作按钮”必须使用同一行高与同一 rowY 计算；禁止出现“文本用一套 ROW_H、按钮用另一套 ROW_H”的错位实现。
- **垂直对齐**：物品名与数量在行内**左对齐**且**上下居中**（`textBaseline=middle` + 行中线）。
- **列表上下留白**：列表内容区域上下 inset = **一行文字字号的 2/3**（以当前 18px 计算为 12px），且滚动上限需按扣除 inset 后的可视高度计算。

### 按钮交互外观（最小三态）

- **hover**：边框变金、背景变亮一档。
- **pressed**：背景变暗并“内缩 1px”；文字需随 pressed 内缩同步偏移（否则视觉不居中）。
- **disabled（视觉）**：当数量为 0/无可用库存等情况下，按钮降 opacity（不强制禁用逻辑时也要有视觉提示）。

### 步进区的 N：必须可输入且与按钮有差异

- **差异化**：N 框是“输入槽/显示槽”风格，高度、宽度与配色需区别于 **`--` / `-` / `+` / `++`** 步进按钮（`++`/`+` 为 +10/+1，`--`/`-` 为 −10/−1）。
- **输入方式**：点击 N 框弹出可编辑输入（可用覆盖在 Canvas 上的 HTML `<input>` 实现）。
- **输入过滤**：实时只允许 `0-9`（允许为空）；提交时仍需 `parseInt + clamp` 保底。
- **非法/空输入策略**：非法或空输入按 **0** 处理；最终 clamp 到 \([0, availableCount]\)。

### 利润行 `n[货币名]` 的格式与对齐

- **格式**：数字三位一组半角逗号分隔，负数同样分组；数字与货币名之间保留 1 个半角空格。
  - 示例：`12,345,678 创世结晶`、`-1,234 创世结晶`。
- **与价值列、询价的衔接**：若界面已实现 `trade_ui_layout.md` 中的**询价**与**价值列**，则未询价时利润行可为 **`？？ [货币名]`**，询价后为 **`n [货币名]`**；**列表内价值列**仅为 `？？` 或数字，**不在表头写货币缩写**，细则以 `trade_ui_layout.md` **6.5、7.1** 为准。
- **对齐**：利润文本右对齐到“成交按钮左侧”的锚点；文本变长时只向左扩展，不得向右挤压成交按钮。
- **过长处理**：必要时从左侧省略为 `…<尾部>`，保证右侧数字/货币名可见且不覆盖成交按钮。
