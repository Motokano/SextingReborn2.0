# 交易界面布局说明 (trade_ui_layout.md)

本文档约定交易弹窗的布局与交互要素，供实现时参照。规则与设计意图以 `basic.md` 为准。

---

## 一、基本约定

- **货币概念**：本作中物品本身即一般等价物，交易以物易物为核心。具体使用的货币存在八种，分为高级货币与低级货币。默认在交易界面使用的价格单位应为商人最优先使用的低级货币。
- **主内容区**：两个列表左右并排，等宽各占一侧。
- **标题栏与接受货币说明**：窗口标题栏内展示一句接受货币说明，格式为：**「[交易对象名] 说能用 [货币名]、[货币名] 交易」**（[交易对象名] 为当前交易对象称呼，[货币名] 按该商人实际接受的货币列表填入，多个货币名用顿号分隔）。实现时该文案与标题栏内其他元素（如关闭按钮）**融入同一标题栏**，不另起间隔。

---

## 二、主内容区：双列表结构

- **左侧**：玩家持有且可供交易的物品列表。
- **右侧**：交易对象可供交易的物品列表。

两列等高、可独立滚动；空态显示「空」。

### 两侧行数不一致时

- 以**行数较多的一侧**为基准确定主体结构的行数。
- **行数较少的一侧**在不足部分**留空**（即多出的行不显示物品与操作列，仅保留空行或占位，使两侧行数对齐）。
- 这样表格总行数 = max(左侧物品数, 右侧物品数)，避免因两侧长度不同导致错位或布局异常。

### 双列表下方的利润行（询价、利润/亏损与成交）

- 在双列表表格**下方**隔开一行（留空或分隔线），单独显示一行，自左至右包含：**「询价」按钮**、**利润/亏损展示区**、**「成交」按钮**（详见**第七节**）。与面板左、下边缘的留白须与利润行整体内边距一致，避免贴边。
  - **利润/亏损展示**在未完成有效询价前的占位格式、询价后的数字格式及对齐，见 **6.5**（与「询价」联动）。
  - **商人最优先使用的货币**：商人可接受的货币来自**商人模板**（`trader_template.md`）中的 **accept_currencies** 数组；**最优先使用的货币**即为该数组中**第一位的货币**（`accept_currencies[0]`），用于净利润/净亏损与价值列价格的换算与展示。**不在界面提供按货币下拉切换**；价值列与利润行默认均使用该货币。
  - **结算按钮（成交）**：
    - **位置**：处于该行的**最右侧**（询价与利润展示在左，按钮在右；同一行内）。
    - **显示文案**：按钮文字为 **「成交」**。
    - **点击效果**：仅当用户点击该「成交」按钮时，才执行结算逻辑（合并到列表、对双方库存做加减、删除隐藏行等）；未点击「成交」前，给/要操作只影响会话内展示与待处理行，不修改实际库存。具体规则见下文「结算时的合并与库存变更」。

## 三、列表单行结构

每一行包含三大部分（从左到右）：

1. **物品与数量**：`[物品名] × 数量`
2. **价值列**（在数量右侧、操作列左侧；规则见**第七节 7.1**）：未询价时为 **`？？`**；有效询价后为**该物品单价**的**数字**（千分位、右对齐）；**数据行不写货币全名**；表头仅标 **单价**（不写货币缩写），币种由**标题栏**与**玩家持有货币**理解（**7.1-A 紧凑口径**，全文与 ASCII 均按此统一）。
3. **操作列**（在价值列右侧，单独一列）：
   - **步进区**（在价值列与动作区之间）：`[ -- ]`、`[ - ]`、当前数量 `[ N ]`、`[ + ]`、`[ ++ ]`。其中 **`--` / `++` 表示一次增减 10，`+` / `-` 表示一次增减 1**（仅文案缩短，逻辑与原先 ±10、±1 一致）。
   - **动作区**：`[给 N 个]` / `[要 N 个]`、`[全都给]` / `[全都要]`；「给 N 个」与「全都给」（或「要 N 个」与「全都要」）之间留 **1 个半角空格** 的间距。
   - **紧凑占位**：步进按钮为**窄矩形**，宽度按「单字按钮 < 双字按钮」分级（`+`/`-` 最窄，`++`/`--` 略宽），整体显著窄于旧版 `-1`/`+10` 等宽按钮方案，为价值列与物品名腾出横向空间。

### 左侧（玩家可交易物品）

- 步进：`[ -- ]`、`[ - ]`、`[ N ]`、`[ + ]`、`[ ++ ]` 用于修改「本次要给出的数量」（`++`/`+` 增，`--`/`-` 减）。
- 按钮：`[给 N 个]` 按当前 N 执行给出；`[全都给]` 给出该物品全部持有量。

### 右侧（对方可交易物品）

- 步进：`[ -- ]`、`[ - ]`、`[ N ]`、`[ + ]`、`[ ++ ]` 用于修改「本次要拿取的数量」。
- 按钮：`[要 N 个]` 按当前 N 执行拿取；`[全都要]` 拿取对方该物品全部数量。

### 步进与范围

- 步进单位：±1、±10（共四个按钮）。
- 当前数量 N 不得超过该行物品的可用数量（左侧不超过玩家持有，右侧不超过对方持有）。
- 实现时可将 N 夹在 0 与可用数量之间，或在边界处禁用对应的步进按钮。

### 步进按钮的交互效果

- 交互者点击**任意步进按钮**（`[ -- ]`、`[ - ]`、`[ + ]`、`[ ++ ]`）时，**仅使页面上显示的该行「操作数量」N 发生变化**（`++`/`+` 对应 +10/+1，`--`/`-` 对应 −10/−1）。
- **不**对库存进行任何实际增减或交换操作，**不**执行任何其他指令。步进只影响界面上的数值展示，真正改变库存的动作由「给 N 个」「要 N 个」「全都给」「全都要」或后续的结算流程触发。

### 点击给/要后的待处理行

- **触发时机**：每次点击「给 N 个」「全都给」（左侧）或「要 N 个」「全都要」（右侧）时，除按当前 N 或全部数量执行一笔给/要并扣减己方当前交易库存外，在**对方列表**中需有对应的待处理行用于展示本笔数量。
- **对方列表**的含义：
  - 点击**给 N 个 / 全都给**时：在**右侧（对方可交易物品）**列表中体现该笔（新增一行或更新已有行，见下）。
  - 点击**要 N 个 / 全都要**时：在**左侧（玩家可交易物品）**列表中体现该笔（表示己方从对方处拿取、在己方列表中显示的待取项）。
- **同次交易内、同一物品只占一行；数量只改数字**：在同一次交易会话中（即点击「成交」按钮之前），通过步进或再次点击给/要修改某物品的待给/待要数量时，**同一物品在对应列表中只存在一行**。第一次对该物品执行给/要时新增该行；之后对该物品的数量修改**只更新该行上显示的数字**，不新增行、不重新拼接列表。实现时不应每次操作都重新生成或拼接整表行，而应复用已有行并更新其数量展示。
- **数量为 0 时隐藏行**：若某侧某物品的待处理数量变为 0，该列表中该物品的待处理行**先隐藏**（不显示），需要时再显示；行不删除，以便数量从 0 再次增加时直接更新该行数字并显示，避免重复新建行。
- **待处理行展示与扣减**：
  - **物品名样式**：该行物品名以**下划线**显示，并在名称旁**标注当前待给/待要的数目**（如「红铁块 × 3」），该数目随步进或给/要操作更新。
  - **库存扣减**：点击「给 N 个」或「全都给」后，从**玩家当前交易库存**（会话内可用于给出的数量）中扣减对应数量；点击「要 N 个」或「全都要」后，从**对方当前交易库存**（会话内可用于被拿取的数量）中扣减对应数量。
  - **按钮保留**：待处理行上仍显示该侧应有的步进区与动作按钮（「给 N 个」「全都给」或「要 N 个」「全都要」），具体交互（如是否可撤销、是否可再改数量）由实现决定，此处仅约定界面需保留按钮展示。

### 结算时的合并与库存变更

- **触发**：用户点击该行最右侧的**「成交」按钮**后，本次交易会话结束并执行结算；只有此时才进行库存修改操作。
- **合并到列表**：结算时，所有在本会话中「给予」或「要取」的物品，按**实际交易时给予/要取的数量**，分别并入**双方已有的物品列表**（即：玩家给出的数量并入对方列表对应物品，玩家要取的数量并入己方列表对应物品）；若某物品在目标列表中尚不存在，则新增该物品及其数量。
- **库存加减**：在合并的同时，对**交易双方的库存**做对应加减：玩家给出的数量从玩家库存中扣减、加入对方库存；玩家要取的数量从对方库存中扣减、加入玩家库存。结算完成后，双方库存与列表展示应与上述规则一致。
- **隐藏行的处理**：会话内因待处理数量变为 0 而隐藏的待处理行，在以下两种情况下应**删除**（从界面与数据中移除），不再保留：**点击「成交」后**；**交易窗口被关闭时**（含未点成交即关闭、按 Esc 关闭等）。

### 价格估算与货币的处理
- **物品实际价格**：目前我们已经有“基线价值” `base_value` 字段用于进行物品实际价格的计算。但实际交易时，物品的实际价格不应直接读取 `base_value`，而是在交易窗口触发后，结合物价涨跌，计算地区通胀系数 `` 和商人货品偏好计算得出的临时变量。

- **货币**：货币作为一般等价物，在游戏交易过程中应该以最高优先级进行考虑。商人与玩家进行交易时。

## 六、最小视觉与细节交互口径（实现需遵守）

> 本节补充对话中新增的实现约束，用于保证 UI 不错位、数字格式一致、并与最小流程文档对齐。
> 若与 `basic.md` 规则冲突，以 `basic.md` 为准；否则本节与 `minium_capitalism.md` 保持一致。

### 6.1 字体层级（必须产生差异）

- **标题栏**：26px；标题中的**货币名**为 26px 加粗。
- **表头**（“玩家可交易物品 / 对方可交易物品”）：24px；仅**“玩家/对方”**加粗，且表头字号略小于标题栏。须在表头区域为**价值列**附 **单价** 字样即可，**不**写货币缩写；玩家结合标题栏「说能用 [货币名]…」及自身背包中的货币，理解价值列数字所指币种，与 **7.1-A** 一致。
- **物品行**：
  - **物品名**：20px。
  - **“× 数量”**：18px 加粗。
  - **价值列**（`？？` 或单价数字）：与「× 数量」**同级或略弱**（如 18px；若与数量同列对齐，优先保证行高与操作列一致）。
- **列表内按钮文字**（步进、给/要、全都、关闭 X）：16px。
- **底行文字**（成交按钮文字、利润行文本、询价按钮文字）：20px；若「询价」按钮尺寸较成交略小，字号可与成交同为 20px，或略降 1～2px 由实现微调，须保持清晰可读。

### 6.2 行对齐与留白（防止错位）

- **同一行的定义**：每列的“物品名/数量、**价值列**、N 框、步进按钮、动作按钮”必须归为同一行；行高与按钮布局挂钩。
- **文本对齐**：物品名与数量**左对齐**且在行内**上下居中**。
- **列表上下留白**：列表内容区域的顶部与底部需与边框留空；留白高度取“一行文字字号的 \(2/3\)”（以 18px 计约 12px）。滚动上限需按扣除留白后的可视高度计算。

### 6.3 步进区的 N：必须可输入并与按钮差异化

- **差异化**：N 是“输入槽/显示槽”，外观必须与 **`--` / `-` / `+` / `++`** 步进按钮区分（例如更宽、更像输入框）。
- **可输入**：点击 N 槽可直接键入数字修改 N（建议用覆盖在 Canvas 上的 HTML `<input>` 实现）。
- **输入过滤**：实时仅允许 `0-9`（允许为空）；提交时仍需 `parseInt + clamp` 保底。
- **非法/空输入策略**：非法或空输入按 **0** 处理；最终 clamp 到 \([0, 可用数量]\)。

### 6.4 按钮三态与文本居中（视觉居中优先）

- **hover**：边框变金、背景变亮一档。
- **pressed**：背景变暗并“内缩 1px”；按钮文字需随 pressed 内缩同步偏移。
- **disabled（视觉）**：当数量为 0/无可用库存等情况下，按钮降 opacity（即使逻辑未强制禁用也要提示）。
- **按钮文本居中**：采用“视觉居中”口径；默认 16px 按钮文字允许向下微调约 1px，20px 可不下沉，以保证观感居中。

### 6.5 利润行的询价联动、格式与对齐

本节约定利润行**文本区域**（询价按钮右侧、成交按钮左侧）的展示规则；询价按钮的位置与样式见**第七节**。

- **未完成有效询价前（默认）**：不展示具体预估盈亏整数。利润区固定为 **`？？ [货币名]`**：两个全角问号、**1 个半角空格**、再接**商人最优先使用货币的显示名**（与 `accept_currencies[0]` 对应展示名一致）。此状态下**不出现**千分位数字 `n`。
- **完成有效询价后**：切换为与下文一致的 **`n [货币名]`** 展示（`n` 为当前会话下、按内部价值估算的**净利润折合该货币后的整数**，可正、可负、可为 0）。**格式**：`n` 每三位一个半角逗号分组，负数同样分组；`n` 与货币名之间保留 **1 个半角空格**。
  - 示例：`12,345,678 创世结晶`、`-1,234 创世结晶`。
- **对齐**：利润文本（无论是 `？？ [货币名]` 还是 `n [货币名]`）均需**右对齐**到「成交按钮左侧」的锚点；文本变长时只向左展开，不得向右挤压成交按钮。
- **过长处理**：必要时从左侧省略为 `…<尾部>`，保证右侧问号或数字及货币名可见且不覆盖成交按钮。
- **与「贸易」技能**：若角色 **贸易** 技能达到配置的自动询价阈值（见 `docs/design/11-skills.md` 生活系「贸易」及数据表），则打开交易界面时**视为已完成有效询价**，利润区**初始即**按上述 `n [货币名]` 规则显示；无需玩家点击「询价」。此时「询价」按钮**仍保留在利润行最左侧**，并处于**已询价**视觉状态（见 **7.2**），**不隐藏**，避免布局跳动。

### 6.6 与 `minium_capitalism.md` 的对齐

- `minium_capitalism.md` 描述最小交易流程与会话边界；本节补充最小视觉口径。
- 实现时应保证两者一致：例如“只在成交落地”“待处理行隐藏不删除”“利润行格式与对齐”等规则，在流程与 UI 两侧都要匹配。
- **补充**：`minium_capitalism.md` 中利润行若未写「未询价占位」，以本节 **6.5** 为准——未询价为 `？？ [货币名]`，询价后为 `n [货币名]`。

## 七、价值列与询价

本节约定**价值列**、**询价按钮**及与 **贸易** 技能的联动。数值计算仍遵循 `basic.md` 第 9 章与 `trade_ui_data_structures.md`；本文件只约束布局、默认/询价后展示形态与按钮视觉。

### 7.1 价值列（每行一物，单价；7.1-A 紧凑口径）

本文件**仅约定**紧凑口径：**数据行只显示 `？？` 或单价数字**，**不在每行写货币全名**；表头**仅标「单价」、不写货币缩写**，币种含义由**标题栏**与**玩家持有货币**自然对应。若产品日后需要「每行带全名」或「表头带缩写」布局，另文约定，**不**以本节 ASCII 为准。

- **位置**：在每一行的**操作列左侧**增加一列「价值列」。从左到右为：`[物品与数量]` → **`[价值列]`** → `[步进区]` → `[动作区]`。左右两列表结构对称，价值列仅描述本侧该行物品。
- **语义（重要）**：价值列展示的是**该行对应物品的单价**（每 1 个堆叠单位、在商人报价口径下折合**商人最优先货币**的整数价格），**不是**「该行 × 数量」的总价。总价若需辅助理解，可由玩家在心智上用单价 × 数量推算，界面不在此列显示总价。
- **默认展示**：未询价时，价值列统一为 **`？？`**（两个全角问号），不展示数字。
- **询价后的展示**：**仅显示单价整数**（千分位、**右对齐**、固定较窄列宽；过长时左侧 `…` 省略，尾部数字仍尽量可见）。**不在数据行重复货币显示名**。表头**只保留「单价」文案，不附货币缩写**；与标题栏「说能用 [货币名]…」及玩家对当前交易货币的认知一致即可。可选：悬停价值格 tooltip「单价（完整货币名）」以辅助新手。
- **不提供**货币下拉切换；多接受货币时仍以 **`accept_currencies[0]`** 为展示口径。
- **与 `basic.md` / 以物易物**：未询价时的 **`？？`** 满足「未向玩家暴露精确数值」的交互节奏；询价后展示的是**商人给出的、用于本会话参考的明码单价（仅数字）**，与底栏净利润同属「询价后可读」层级（底栏仍用 **`n [货币名]`**，见 **6.5**）。

### 7.2 询价按钮（手动与已询价态）

- **位置**：交易窗口**底部利润行的最左侧**（`profitBar` 区域内），与面板左缘、下缘保留**与利润行其它元素相当的**内边距（可与 `profitText` 左缘或 `profitBar` 的 padding 对齐），避免贴边、拥挤。
- **尺寸**：宽、高均**略小于**同行最右侧「成交」按钮（建议面积约 **85%～92%**，或高度低 **2～4 逻辑像素**，在 1280×720 逻辑坐标下微调至观感协调）。
- **文案**：**「询价」**（全文统一此称呼，与 UI 其它文案一致）。
- **点击后逻辑**：触发一次**有效询价**（若规则允许）：全表各行价值列由 **`？？`** 更新为 **7.1** 规定的单价；利润行由 **6.5** 的 **`？？ [货币名]`** 更新为 **`n [货币名]`**。若因技能不足、场景限制、商人拒绝等无法询价，价值列与利润行保持占位，并可辅以简短提示（文案由实现或文案表补充）。
- **已询价视觉状态**（手动点击成功后，或 **贸易** 技能触发**自动询价**时，均进入此态）：
  - 按钮填充色**饱和度降低**（同一色相下降低饱和度或略提高灰度），与默认未询价态形成对比；
  - 在按钮面上叠加**灰色斜线纹理**（建议 **45°** 细斜线，间距与线宽符合像素风小尺寸），呈现**浅阴影 / 已压印**质感；斜线透明度与线宽须保证「询价」二字仍可清晰辨认。
- **自动询价时**：**不隐藏**询价按钮；按钮**直接显示为已询价视觉状态**（见上条），避免利润行布局跳动。

### 7.3 贸易技能与自动询价

- **技能对齐**：**贸易**为生活系技能，定义见 `docs/design/11-skills.md` §8.2 生活系技能表（「通过与商人交易提升；等级影响打折力度」等）。实现侧引用技能时，ID 须与该文档「实现约定（技能 ID）」及实际技能配置表一致；若表中尚未登记 **贸易** 的 ID，定稿时应遵循生活系 **`life_` 前缀**约定。
- **规则**：当角色 **贸易** 达到**配置阈值**（等级或熟练度区间由数据表给出，**不在本布局文档写死**）时，**打开交易界面即视为已完成有效询价**：价值列与利润行**初始**即按已询价规则展示；玩家无需点击「询价」。询价按钮仍以**已询价**样式显示在利润行最左侧（见 **7.2**）。

### 7.4 布局示意（ASCII）

利润行（与第二节、第四节总览一致；底栏保留 **`[货币名]`** 全名，见 **6.5**）：

```
│  [ 询价 ]          ……          ？？ [货币名]  或  n [货币名]              [ 成交 ]   │
```

列表单行（**7.1-A**：价值列与物品、步进之间用竖线分隔；表头仅含「单价」、不写缩写，此处从略）：

```
│ 物品A × 3 │ ?? │ [--][-][ N ][+][++]  [给N个] [全都给] │
│ 物品A × 3 │240 │ [--][-][ N ][+][++]  [给N个] [全都给] │   ← 已询价，仅数字
```
