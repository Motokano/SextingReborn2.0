# 棋子标准：主角定外观，骨骼参考定姿势

用户于2026-09-14再次明确：已认可的主角形象应当成为主角与普通NPC的共同外观结构标准。骨骼校准页中的示意人物只用于解释姿势，不能作为角色设计模板。

## 当前优先规则

1. 外观标准是已认可的主角：参见 `hero/appearance-reference.png` 及项目 `assets/map/isometric/pose-atlas-v1/` 完整图册。保留其头身比例、身体轮廓、手脚造型、衣着体积、底座和手绘风格。
2. 模块化的验收标准是：把主角拆开，再以正常站姿装回去，仍然看起来是原来的主角。不能为了匹配参考示意人的骨长、锚点或宽度而拉长、压窄、改变主角比例。
3. `rig/` 保存共用姿势的角度、支撑关系、左右ID和128种状态。参考示意人的几何外形不具有美术约束力。原始参数保留，不从图片覆盖它们。
4. 后续应以主角外观部件建立独立绑定和姿势适配层，借用保存的动作关系。若参考骨长与主角比例冲突，处理动作适配，不让主角外观迁就参考人。适配参数另存并复用于普通NPC，不能宣称原矩阵已经适配完成。
5. 新NPC仅修改发型、脸部特征、肤色、服饰和配饰，使用同一主角结构和适配后的共用姿势；特殊Boss按用户约定另做。

## 文件状态

- `rig/skeleton.json`、`rig/poses.json`：骨骼与姿势参考副本，独立保留，不是外观模板。
- `hero/appearance-reference.png`：已认可主角外观参考。
- `hero/parts.png`、`hero/parts/`：第一轮生成的部件草稿，尚未确认与原主角一致，不能作为新NPC生产标准。
- `hero/skin.json`、`assembler.mjs`、`viewer.mjs`：此前直接按参考骨长装配的实验。因其将主角外观迁就参考骨架，已撤回标准地位。保留供排查，不部署、不用于批量生成正式NPC。

游戏继续使用已认可的主角图册外观。模块化尚未完成验收，不把“能够输出128种状态”视为“保持主角形象的模块化已经完成”。
