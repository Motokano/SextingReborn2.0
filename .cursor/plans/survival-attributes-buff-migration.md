# 生存属性效果 Buff 管线化（计划补遗与已定口径）

> 与「生存属性 Buff 化」总方向一致；本条记录策划已定规则，供实现时对照。  
> 总技术方案见仓库内原规划（阶段：Buff 能力扩展 → 模板化 → `Survival` 硬切换 → 入口门禁）。

---

## 一、生存监听 Buff 通用机制（全局）

- **来源**：由生存属性区间判定，不依赖传统固定 `duration`。
- **互斥**：同一维度的分段 Buff 组内**至多一枚**，不叠加；切换区间即换 Buff。
- **不可驱散**：统一打不可主动驱散标签；仅因**监听条件不再满足**而移除。
- **计时器（体重/死亡等）**：
  - **各自进入时起算、离开即清**：每个与区间绑定的 Buff 有独立 tick 计数；进入该 Buff 的区间时从 0 开始；离开该区间（或不满足条件）立即**清零**该 Buff 对应计数，不跨状态继承。

## 二、饱食度（Satiety）— 已定口径

### 2.1 边界

- **上限 `150`（闭区间到 150）**。

### 2.2 分段与 Buff（`0~100` 及超上限、零点）

| 区间（含端点依表） | Buff 名 / 作用 |
|----|----|
| `120.1 ~ 150` | **吃撑了**：最终战斗出招速度总降 **-30%**；连续 **144 tick** 维持该状态则 **体重 +1 kg**（可重复：每满 144 tick 结算一次，计数在结算后从 0 重计，仍受「离开即清」约束） |
| `100.1 ~ 120` | **吃太多**：最终战斗出招速度总降 **-10%** |
| `60 ~ 100` | **充分进食**（**含 100**）：体力自然恢复速度 **+10%** |
| `30 ~ 59.9` | **轻度饥饿**：体力自然恢复速度 **-10%** |
| `10 ~ 29.9` | **重度饥饿**：体力自然恢复速度 **-10%**；底气自然恢复速度 **-10%**；**连续 144 tick 维持**则 **体重 -1 kg**（同通用计数器语义） |
| `0.1 ~ 9.9` | **极度饥饿**：体力自然恢复速度 **-40%**；底气自然恢复速度 **-40%**；**连续 144 tick 维持**则 **体重 -1 kg** |
| `= 0` | **饥肠辘辘**：**连续 432 tick** 维持 `satiety=0` 则**死亡**；`satiety>0` 时立刻移除本 Buff 并**同时清零**死亡与减重两条计数；再次掉到 0 两计数从 0 重计；**每连续 144 tick 维持** **体重 -1 kg**（与死亡推进并行，见 2.3） |

- **已废弃**：原「>=90 才能 overcap」「消化 Buff 才能>100」等旧过量规则；**不再**单独维护旧式过量增重/重度饥饿减重的独立 tick 表，改由上表 Buff 驱动（按策划表）。

### 2.3 与「饥肠辘辘」的计数说明

- 在 **`satiety=0` 且为「饥肠辘辘」** 时，使用**两个独立 tick 计数器**（**`satiety>0` 时两者一并清零**）：
  1. **死亡线**：满 **432 tick** → 死亡
  2. **体重线**：每满 **144 tick** → 体重 **-1 kg**，该线计数在结算后从 0 重计（仍在 0 则继续下一轮）
- **重度/极度/饥肠辘辘** 的 **144 减重** 均符合「**进入该区间/状态起算、离开即清**」；因互斥，同一时刻只跑其中一条 144 计数器。

### 2.4 与旧版差异

- 旧版 `0~100` 分段（60/40/15）、体力/底气 0.5 倍、重度禁止体力精力动作、饱食=0 旧 100 tick 饿死、旧 500 tick 增重/减重**均已不作为最终口径**，以本文件第二节为准。

## 三、饮水度（Thirst）— 已定口径

### 3.1 边界

- **上限 `100.0`（闭区间到 100.0）**；保留一位小数，**无**「过量饮水」上界 Buff。

### 3.2 分段与 Buff

| 区间（含端点依表，闭开写死免歧义） | Buff 名 / 作用 |
|----|----|
| `= 0.0` | **口干舌燥**：底气自然恢复 **×0.4**；**不可**与可交互 NPC 对话/交易/交任务；**连续 432 tick** 维持 `thirst=0` 则**死亡**（计数语义见 3.3） |
| `0.1 ~ 40.0` | **口渴**：底气自然恢复 **×0.5** |
| `40.1 ~ 100.0` | **饮水充足**：底气自然恢复 **+10%**（等价为最终乘子 **×1.1**） |

- **与旧 `survival-config` 差异**：`thirst_normal_min` 原 **60** 仅对旧版「60～正常」分段有效；**Buff 化后以本表 40.1 为「充足」下界**，实现/配置迁移时需改监听阈值，勿再混用 60 作为本维充足档。

### 3.3 与「口干舌燥」的死亡计数

- 在 **`thirst=0.0` 且为「口干舌燥」** 时，死亡线：**满 432 tick** → 死亡（与第二节饥肠辘辘**同一 tick 长度**）。
- **`thirst>0.0` 时** 立刻移除本 Buff 并**清零**该死亡计数，不跨区继承、不累计到 `0.1~40` 等其它档。

## 四、营养值（Nutrition）— 监听 Buff 与收口约束

### 4.1 分段与 Buff（闭开区间）

| buff_id | 名称 | 监听区间（闭开） | 具体效果 / 读入口 |
|----|----|----|----|
| `survival_nutrition_malnutrition` | 营养不良 | `[0, 11)` | 底气自然恢复惩罚（`Survival.getDiqiRegenMultiplier()` 乘入 `nutrition_malnutrition_diqi_regen_mult`） |
| `survival_nutrition_normal` | 营养正常 | `[11, 31)` | 中性占位，无数值 effect，**不得删除**（保证监听组单一可观测态） |
| `survival_nutrition_abundant` | 营养充沛 | `[31, 71)` | 精力→潜能效率（`Survival.getNutritionPotPerEnergyMultiplier()` 返回 `nutrition_abundant_pot_per_energy_mult`；自修/学习链路**仅此入口**接乘区） |
| `survival_nutrition_peak` | 营养极境 | `[71, 101)` | 底气上限容器加成（`computeDiqiCapLimitFromBreath` / `Survival` 中按 `nutrition_peak_diqi_cap_pct`） |

- **互斥组**：`group_id: survival_nutrition`；同一时刻至多一枚 `survival_nutrition_*`。
- **阈值来源唯一**：分段边界**只**读 `data/survival-config.json`（`nutrition_malnutrition_max` / `nutrition_normal_min|max` / `nutrition_abundant_min|max` / `nutrition_peak_min` 等推得的闭开区间），**禁止**在 `js/*` 或工具里再写死一套 10/30/70 等第二真相。

### 4.2 六条硬约束（给后续实现 / Agent）

1. **abundant 落地唯一入口**：`精力 → 潜能` 效率**只能**通过 `Survival.getNutritionPotPerEnergyMultiplier()` 读取；自修/学习/潜能结算处**禁止**再写 `if (nutrition 数值在某某区间)` 的并行判段。
2. **normal 占位必保留**：`survival_nutrition_normal` 为监听真相占位，**不得**以「无效果」为由从表或运行时代码中删除；无数值仍占组内一格。
3. **阈值唯一真相**：nutrition 分段的上下界**只**来自 `survival-config`；改分段必改配置 + `buffs.json` 中 `survival_listener.range` 与 `Survival` 内闭开实现三者对齐，不留下硬编码第二套边界。
4. **切段后立刻同步**：任何会改 `nutrition` 的写路径（含 `setState`、每 tick 衰减、`addNutrition`、含 `survival_delta` 的食物链等）之后，必须能落到与 `state.nutrition` 一致的监听 Buff；**进入 / 离开 peak 后必须立即**重算 `diqi_cap_limit` 并夹紧 `diqi_current`（不得延迟到「下一 tick 才对账」作为常态）。
5. **可观测性（可选但推荐）**：若需调试/日志定位切段，应约定统一入口（如依赖 `syncNutritionStateBuff` 内日志或已注册的 world 事件），**禁止**在多处各写 `console` 或散落判段，避免与 Buff 状态漂移。
6. **兼容收口里程碑**：`abundant` 的潜能乘区在自修链路**接线完成**后，**禁止**任何运行时仍用「直接读 `state.nutrition` 算档位」来驱动营养系效果；允许保留的**仅**为 `BuffSystem` 未就绪时的**防御性回退**（`getNutritionRangeByValue`），并应在加载完成后被监听 Buff 盖回。

## 六、实现注意事项（给开发）

- `+/-10%` 等恢复类效果需接在**与现有 `Survival` 自然恢复同一条算式**上，避免与 Buff `survival_delta` 混淆（监听 Buff 更可能是 **乘子** 而非常量加扣）。
- 最终出招速度 `±%` 须在**与现有取整/合成顺序**文档一致的那一步后应用（见 `combat-initiative` / 出招速度管线）。
