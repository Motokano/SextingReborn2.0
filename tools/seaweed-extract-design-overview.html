海藻精（渠内输送与作物吸收）设定说明

0. 每 tick 与重算顺序

每 tick（农业地图）

① 清水 → ② 海藻精 → ③ 水藻爆发判定 → ④ 吸水 → ⑤ 吸微量元素 → ⑥ 爆发扣健康 → ⑦ 其它

⑤ 先照单吸收微量元素 → ⑥ 再扣健康（默认 −2，Buff 可减，≥0，健康 clamp）。③ 用①②后的 W/C 实时判定。

水道结构重算（§5）后

  1. 完成水道、主干/支流、清水可达与每格水量；
  2. 立刻清空全场水渠上的海藻精浓度；
  3. 再同步作物海藻精请求登记 / 撤销。

1. 总流程

罐内海藻精效果
5000 tick → 施肥器判水流归属 → 扫已登记请求
无请求 / 不可达 / 无邻接有水注入口 → 不维持浓度
有请求且可达 → 择唯一方向 → 入口后均分至终点 → 每 tick 刷新状态

注入 = 对路径上有水渠施加持续浓度状态（效果存续且本 tick 满足条件时刷新），不是一次性脉冲。
默认 B 面：有水 + 海藻精即维持（§15.6）。超融合在场时全场文丘里切 A 面（按需，§15.1～§15.3）。

2. 文丘里施肥器

水流归属（只看水流）

  • 自施肥器格四邻接有水水渠回溯到水池，得到主流 / 支流 #N。
  • 不看邻接耕地。
  • 四邻接无有水渠 → 无归属，不输送。

A 面：扫描与响应

施肥器归属扫描范围本 tick 注入次数
支流 #N仅支流 #N至多 1 次（该流 1 株作物）
主流主流 → #1 → #2 …可对每条水流各维持 1 次
  • 每条水流本 tick 最多响应 1 株「已登记且可达」的请求作物（多株取扫描顺序第一株）。
  • 只要检测到至少 1 株可达请求，即对该水流维持浓度（不必覆盖该流上所有请求株）。
  • 多个施肥器 → 不同来源，同格浓度相加。
  • 择向：水流优先级（主流先于 #1…）+ 同流内 下→右→左→上。
  • 可达：与清水相同，不能向更高的水渠爬升。

其它液态肥（如存量氮肥）不走渠内浓度系统，仅各自模板效果。

超融合（全局切换）

  • 建造 200 金，工程 10 tick / 5 体力每 tick（与其它设施一致）。
  • 场上 ≥1 座 → 全场文丘里海藻精改为 A 面；全部拆除后恢复 B 面 默认。

B 面：常注（默认，无请求检测）

  • 与 A 面共用：水流归属、扫描哪几条流、注入方向、§15.4 均分、多施肥器异来源相加。
  • 去掉 §15.3 作物请求扫描；不读 seaweedRequests。
  • 条件：罐内海藻精效果存续 + 四邻有水渠 + 能沿该水流抵达水流终点 → 即维持浓度。
  • 可润空渠（无作物也可有浓度）；作物吸收仍只看邻渠浓度，与是否登记请求无关。

3. 作物「请求海藻精」（仅 A 面输送门禁）

  • 模板字段 requests_seaweed_extract（默认 false）。
  • 为 true 时才可能登记请求；为 false 从不登记。

登记条件与时机

  • 必须四邻接至少一格有水水渠，且能按 §12 得到受水归属。
  • 播种时无水 → 不登记；首次满足前提的 tick或水道重算后再登记。
  • 登记目标：主流一条；若归属支流 #N，再向支流 #N一条。
  • 仅属主干时：只登主流。

撤销与成熟

  • 收获、枯萎、清作物 → 撤销请求。
  • 受水归属变更 → 撤销旧支流请求，按新归属重登。
  • 已成熟待收获：请求保留，施肥器仍可维持渠浓度（流经）；该作物不再吸收微量元素。

false 不登记请求，但生长中若邻渠有浓度，仍可按 §6 吸收（与是否请求无关）。

5. 浓度：均分、持续状态、叠加

单格浓度 = 设定浓度 ÷ 入口后至该水流终点的有水渠格数

无水渠、注入口本身不参与均分与承载。

互动试算（按施肥器等级）

持续状态

  • 效果 tick 内存活且本 tick 该水流满足输送条件 → 按上式每 tick 刷新各格份额（同来源覆盖，不在同 tick 内累加同来源）。
  • 本 tick 不满足 → 该施肥器在该水流不写入。
  • 效果 tick 归零 → 该施肥器不再维持。

清水水量与海藻精浓度分开存储；清水仍走 §8～§11。

6. 作物吸收微量元素

  • 与吸水同一 tick、同一 §12 来源水渠。
  • 本 tick 吸收量 = 该格当前 海藻精浓度（0 则 0）。
  • 不扣减渠内浓度（只读）。
  • 累加 累计微量元素；展示 1 位小数。
  • 仅生长周期内；成熟后冻结不累计。
  • 成熟/完美：各作物单独配微量元素区间；与水分组合为 AND（都满足才算，例如完美种植）。
唯一来源水渠 → 读水量 → 累计水分 + 读浓度 → 累计微量元素

7. 水藻爆发（浓度 × 水量）

仅有水水渠（W > 0）。记 W = 当前实际水量，C = 格上海藻精浓度。

爆发：C : W 高于 2.5 : 1　⇔　C > 2.5 × W
恢复：C ≤ 2.5 × W（恰为 2.5:1 时不爆发）

互动：是否爆发

对作物

  • §12 唯一来源渠爆发 → 生长中作物：⑤ 先照单全收浓度，⑥ 再扣健康（默认 −2/tick）。
  • 无 §12 来源、已成熟、C≤0 的渠：不扣 / 不爆发。
  • 不要求作物发送请求；邻格爆发但非来源渠 → 不扣。
  • 健康 ≤0 → §4b.1b 枯萎。爆发不阻止施肥器继续送肥。

常量与表现

策划常量默认
algae_bloom_concentration_ratio_threshold2.5
algae_bloom_health_loss_per_tick2
  • 扣血走开放接口（Buff 可减），最终扣减 ≥0，健康 clamp。
  • 地图 / demo 须显示爆发渠格样式；不要玩家提示条/飘字/日志。
  • 多来源 C 相加后再比；高等级施肥器易配高浓度 → 易爆发（预期风险）。

8. 施肥器：海藻精罐与浓度 UI

  • 物品 liquid_seaweed_extract：消耗 1 个注入，持续 5000 tick；可再次注入重置倒计时。
  • 仅效果存续期间才可能维持渠内浓度。
  • 施肥器 3 级；每次升级 5 金钱。
等级设定浓度可调范围
1 级5～10
2 级3～15
3 级1～20
  • 升级后若当前设定超出新等级范围，应夹紧到新范围内；默认建议 1 级取 5 或 7。
  • 无单格渠内浓度硬顶。

8b. 埋地陶瓮（与渠内海藻精分轨）

  • 两条累计条（禁止混写）：海藻精 → traceAbsorbed（累计微量元素）；液态肥 → fertilizerAbsorbed（累计施肥值）。
  • 海藻精：仅文丘里 → 渠内浓度 → 邻接耕地吸收微量元素（§4b.1c / §15）；请求见 §3（仅 A 面输送门禁）。
  • 液态肥：仅埋地陶瓮 → 八邻 → 累加施肥值（§4b.1d，示范 +0.5/tick/瓮）；不是微量元素。
  • 液态肥请求（§4b.1f）：作物模板 requests_liquid_fertilizer；八邻有陶瓮时可登记；仅登记且模板为 true 的作物才接收瓮的施肥值（无渠网被动吸收）。
  • 多瓮：同格作物在多个瓮八邻内时，按瓮数叠加；各瓮独立扣单位。
  • 完美判定可选 perfectMinFertilizer，与水分/微量 AND；门槛宜低（约 12～22，示范肥 0.5/tick）。
  • 微量排斥作物（§4b.1g）：豆芽/莲子/芡实为致死；杏樱桃扁桃梨柠檬与三类豆为严重排斥。完美要求 trace ≤ trace_safe_max；排斥作物不登记海藻精请求，但邻渠仍会吸收浓度。
  • 农业 tick 顺序见 28-agriculture-irrigation.md §15.0 步骤 5b。

9. 实现速查（禁止项）

  • tick：清水 → 海藻精 → 爆发判定 → 吸水 → 微量元素(trace) → 陶瓮→施肥值(fert) → 爆发扣健康
  • 爆发：C:W>2.5:1；C≤0 不爆发；维持肥液不阻止
  • 地图须显示爆发格；不要玩家向提示
  • 重算后先清空渠浓度，再同步请求
  • 注入 = 持续状态 + 每 tick 刷新，非一次性脉冲
  • 注入口不计入均分；吸收不扣渠浓度
  • 同水流每 tick 最多 1 株请求响应；主流施肥器可对多水流各维持 1 次
  • 异来源相加；同来源同格不叠
  • 默认 B 面：有水+海藻精即输送
  • 超融合在场 → A 面（无请求不输送）
  • 施肥器无邻接有水渠时不输送
  • 其它液态肥不走渠内浓度
  • 不要求农业 UI 调试层展示逐格浓度/注入箭头
