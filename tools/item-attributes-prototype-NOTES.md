# 物品属性大类试作

问题：主表只加载大类，大类内缺失的小属性是否确实不生成状态、不显示？零值是否仍然保留属性？配置、实例状态和角色认识能否分离？

页面上半部分仍是独立交互试作，便于同时查看配置与信息卡；纯逻辑位于 `item-attributes-prototype.mjs`。页面下半部分新增“正式接入自动验收”，直接读取游戏使用的三张 v2 目录、模块定义和运行时适配器。无第三方依赖。

运行：`npm run prototype:item-attributes`，打开 http://127.0.0.1:8013/tools/item-attributes-prototype.html?no_reload 。

三张逻辑表：主表 `items` 只引用大类；配置表 `configs` 按大类和引用ID保存组；字段定义 `definitions` 描述字段类型、标签与演示认知条件。当前定义只实现三份样例所需子集，未知大类/字段明确拒绝，不冒称8类都已实现。

木材和电池取自当前目录快照。干木材虽然文案说耐烧，但正式数据燃料值是0，不能直接当作正数迁移；本例初始保留堆肥属性，由按钮试配燃料。普通苹果当前不存在，重量、恢复量、保鲜时长全为示意值。没有调整正式平衡数据。重取快照：`node tools/build-item-attributes-prototype.mjs`。

试用顺序：

1. 木材：增加燃料属性，值为0 → 玩家已检查时显示0；移除 → 无燃料行、无空标题。其他生产属性不受影响。
2. 苹果：同时加载食物与生产，饮水0仍显示；未配置燃料/供水就不出现。腐败只验证实例计时，不模拟正式转化。
3. 电池：先保存75电量快照，再扣到0并读回，恢复75；然后把0电量保存再读回，仍为0，不回填成初始满电。读取不初始化或改写模板。
4. 切换只见外观/已认识名称/已检查性能，观察名称与属性过滤。演示条件不是正式技能等级或观察证据实现。
5. 展开配置编辑，删除可选组、设零值、填错字段/引用或超容量，确认合法配置创建新实例，非法配置保持原状。此按钮明确重置实例，区别于普通读档。

试作快照保存在页面内存，刷新清除。正式第一阶段已经接入背包/仓库复制、堆叠比较、旧状态兼容和两条信息显示读取；页面的自动验收会核对539个普通物品、27件装备、16个实物改造件、8个大类、29个正式配置组、缺失属性、零值和未知实例状态保留。稳定实例身份、真实装配与组合重量仍属 k278 后续。

正式定义和读取契约已经迁入运行时；此页面保留为交互解释与验收入口。

本次浏览器核对：木材配置燃料0后出现0值行，移除后行消失；电池归零后保存/读回仍为0；切换只见外观后，玩家卡只显示轻巧小圆筒，不出现能源标题或容量电量。完整配置仍可在独立编辑检查区查看。
