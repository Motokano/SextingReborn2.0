# 烹饪台修复界面试作

用户选择 C 分步修复。A/B 已移除，旧 variant 参数兼容但不再改变布局。
启动：npm run dev -- 8016；访问 /tools/cooking-unlock-prototype.html?variant=C。

## 本轮规则

- 点数只在内存中结算，不向页面、提示、进度条或无障碍标签输出所需/贡献/剩余数值。
- 页面只显示实物持有、备料、消耗和退回件数；工程状态用文字描述。
- 少量投入允许部分修复，实际消耗后保留进度，后续只补剩余需求。
- 超额备料按整件退回；已消费单件内部的余量不生成碎片或公共余额。
- 名称调用正式 InventoryEquipment.getDisplayName，使用样例角色的语言认识；不用 editor_name 显示物品。
- 对用途的认识是独立样例标记，不通过物品隐藏分类推定玩家已知。未知用途物品只在不分类的随身物品区域展示外观名，不能投入。
- “备齐这类材料”仅选择本步已知用途的全部库存，不按隐藏需求自动凑出精确数量。

示例库存、后台需求/贡献与用途认识标记均未定案；未接真实角色认知、背包、对话事件或存档。试作不读取或写入正式存档，刷新清除。

手动浏览器验证：取消不提交；少量黄泥修补后可继续；后续备齐材料完成并退回整件余料；结果、确认和物品选择均无点数且使用外观名称。正式接入时再设计真实库存转移与项目保存。

用户修订：核对材料步骤已经是最终检查，点击「核对并修复」直接结算并显示结果，移除重复确认弹窗。返回选材仍不扣除材料。
