# 畜牧系统完整链路复核

日期：2026-09-12。对象为当前工作区，不是 Git 基线。此次只新增审计脚本和证据，不修改游戏结算或替用户确定新的数值。

## 优先修复：可绕过规则或破坏状态

| 编号 | 问题及证据 | 建议 |

## 需要明确设计，不能直接当作新 bug 修掉

- **草的消耗量与饱腹恢复脱钩**：充分草地上，能啃、白板、挑食的饱腹恢复相同，但耗草不同。若 Perk 目的就是管理草高，可以成立；若表示摄食能力/效率则需要对应营养收益。不能只凭名字选一个方向。
- **吃不到草但仍长肉**：10 kg 牛在无可食草、无饲料、初始饱腹 100 时，100 tick 后长至 11.455 kg，饱腹约 97.78。可以解释为消耗储备，但当前饱腹既是门槛又不是质量预算，尚不能做整体物料守恒承诺。
- **同窝共享一次遗传抽样**：四只猪崽得到完全相同 Perk 组合，代码只在整窝之前抽一次。应明确想要整窝一致还是逐只独立；父本消失导致遗传改变则属于前面的确定缺陷。
- **诊疗同健康值顺序**：三头同 HP 动物、Lv1 诊疗只治前两头；倒序会改变本 tick 受益者。但后续按最低 HP 优先可能自行轮换，单 tick 差异不足以证明长期治疗不公平。
- **信息素强度**：每 1000 tick 只有一次 50% 纳入机会，随后再过单 tick 受孕概率；地鸣用整轮等效概率。两者时间口径差距很大，需按定位比较长期繁殖收益。
- **鸡性别**：当前产蛋没有性别门槛，但鸡繁殖体系也未完整展开，应先明确鸡是否统一抽象为产蛋鸡，不能贸然新增公鸡管理负担。

## 组合与高级模块结论

旧长期组合的结论仍成立：两牛第一次交接草高约 0.9765 m，羊不能吃；三牛可把第一次交接压到约 0.4008 m，但不能保证长期供草。预处理草地、低密度和理想供料的组合也会长期掉膘。鸡 15,000 tick 老死本身符合当前物种配置，不把所有死亡都称为算法漏洞。

跨臂传动、实体废料账本、气候草高曲线与基础物流分离仍未实现。当前回收虽不重复计算同一清污事件，但污染还不是完整的实体原料账本；它不能证明从作物到全部畜牧产物守恒。遗传、覆盖范围和升级问题应在高级模块重写前修正，否则复杂模块会进一步放大异常。

建议顺序：F01–F05 → 共享服务与覆盖 F08/F09/F11 → 产出预算 F06/F07/F12/F13 → 参数、升级与状态边界 → 高级模块独有机制和长期经济调参。所有补给和生产预算应自动结算，不增加逐头重复操作。
