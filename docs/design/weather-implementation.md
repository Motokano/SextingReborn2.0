# 天气与温度首版实施记录

2026-09-24。用户已授权采用可配置试玩初值并接入本地游戏。以下是首版运行范围，不代表最终平衡。机制正本见 [季节、天气与温度](weather-seasons-and-temperature.md)。

## 已接入

- `js/weather.js` + `data/weather-config.json`：13种天气、四季、地区气候、持续热浪/寒潮、受约束的天气转换、独立随机状态、温度渐变、地图覆盖和有界历史。
- `GameTime.advanceTicks` 同步推进所有已配置地区；普通地图默认金木地区。北部山区、沿海是可选配置，尚未擅自把既有地图分配给这些地区。
- 普通相邻地图读取同一地区气温，不因首次进入产生额外温差。特殊地图可独立天气/温度；地图环境事件支持渐变或明确骤变。
- 正式存档包括地区随机状态、天气阶段、有效温度、已读取地图状态与环境效果。旧档按其恢复tick确定性初始化一次，不伪造迁移前天气历史。无效天气快照在修改游戏状态前拒绝。
- 玩家体温按暴露程度分档变化，内部保留小数；体温偏离决定身体惩罚。旧环境Buff不再充当身体状态，状态切换沿用生存广播。
- 当前体温、按来源登记的范围/速率/恢复效果随生存存档保存；范围完全覆盖或环境速率为零不练耐候，恢复抵消仍计入实际暴露成长。
- 冷热惩罚接玩家战斗速度和实际行动体力扣费。移动、采集、制作、钓鱼、狩猎、建造等费用预检查已适配；直接扣体力的Buff效果不再被当作动作重复放大。
- 疲劳继续按实际行动消耗累计；普通恢复、移动不扣饮食储备保持原规则。休息没有温度免疫。
- 页面顶部只显示当前可见天气，日志记录天气与身体变化；同状态不反复提示，不暂停持续行动、不新增自动惊醒。没有精确气温/体温HUD或自动天气预报。

## 试玩初值

环境、概率、温度修正、暴露与身体惩罚集中在 `data/weather-config.json`，标记 `playtest-unbalanced`；体温上下限和死亡差值继续位于既有 `data/survival-config.json`。

| 项目 | 试玩初值 |

| 基础可承受环境温度 | 12～30℃，再叠加耐候及其他来源 |
| 超出范围的暴露档 | 超出0／5／12℃后分别采用0.01／0.03／0.06℃每tick |
| 适温自然恢复 | 每tick向标准体温恢复0.03℃ |
| 身体轻／中／重度 | 偏离标准体温0.5／1.5／3℃ |
| 失温中度 | 战斗速度×0.9 |
| 失温重度 | 战斗速度×0.75、动作体力消耗×1.25 |
| 过热中度 | 动作体力消耗×1.25 |
| 过热重度 | 战斗速度×0.85、动作体力消耗×1.5 |
| 死亡阈值 | 低于或等于标准−6℃、高于或等于标准+5℃ |
| 内部体温夹紧 | 20～55℃；死亡阈值现已可达 |
| 环境渐变上限 | 每tick 0.15℃ |
| 热浪／寒潮修正 | +6℃／−8℃，持续288～720 tick |
| 历史保留 | 每地区最近64段已结束天气及当前段 |

这些数字是游戏试值，不是医学模型。旧24℃/50℃死亡门槛与30～42℃夹紧的冲突已解决，旧0.03℃恢复被一位小数舍弃的问题已修复。

## 对外接口

- 内部事实：`Weather.getEnvironment(map)`；条件读取：`Weather.matches(condition, map)`，可按season/weather/tag/event及温度上下界组合判断。
- 玩家天气描述：`Weather.observe(map)`，只返回当地可见天气与观察地点/tick，不返回温度、地区历史或冷暖事件后台标识。
- 地区内部历史：`Weather.getHistory(region)`。仅有界窗口，不保证覆盖任意离线区间；迁移前历史不存在，调用者不可补造。
- 地图规则：`map.environment`，或配置的 `maps[map_id]`。字段包括 `region`、`weather`（含`none`）、`observable`、`temperature`、`temperature_offset`、`temperature_by_season`；原地图 `ambient_temperature` 和季节表继续兼容。
- 地图临时温度来源：`Weather.setMapEffect(source, map, {offset, ticks, immediate})`，传null清除此来源。不会自动驱动敌人。
- 个人防护：`Survival.setTemperatureSource(source, effect)`，字段为 `cold_range`、`hot_range`（相加）、`cold_rate`、`hot_rate`（相乘）、`recover`（向标准恢复）、`delta`（直接升降）、`ticks`（可选持续时间）。同源调用替换，传null清除；不自动叠加同源实例。
- 直接干预体温：`changeBodyTemperature(delta)`、`recoverBodyTemperature(amount)`。前者可越过标准并触发死亡，后者停在标准体温。
- 动作费用：`getActionStaminaCost(base)` 和 `consumeStamina(base)`；已预先计算后的扣费必须传 `{raw:true}`，防止倍率应用两次。移动同时保留 `{source:'movement'}`。`getActionStaminaBudget()` 仅为仍使用“基础费用预算”的活动适配器提供可支付额度，不能作为真实体力显示。
- 战斗速度：既有 `CharacterAttributes.getCombatSpeed()` 返回含体温倍率的值，保留既有最低速度1。

## 明确保留的后续工作

- 敌人仅读取环境；本轮不新增敌人自动体温、寻路、避雨、冻死或热死。
- 未配置任何新功法、御寒衣物、防具模块、温度计或药品；具体内容按后续设计接上述入口。基础耐候仍存在，但不代表夏冬应对装备与获取路径已经完整。
- 钓鱼可调用统一环境入口，但首塘当前鱼种生态仍沿固定温感与原时段规则；不把气温当水温，也未自动开启雨天增益。
- 农业固定供水、畜牧生产不变；普通NPC没有新增天气行为。
- 没有新增逐格环境、雨雪粒子、天气地图视野惩罚或仪器测量交互。认知基础现为不泄露数值的观察接口；未来测量物品需实现带时间地点、误差与知识依据的读数。
- 地区曲线、现有地图归属、天气持续性以及防护获取仍需实玩校准。
