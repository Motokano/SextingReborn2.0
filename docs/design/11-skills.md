#### 8.2.1 生活技能熟练度规则

- 所有生活技能采用**“用什么升什么”**的熟练度系统，使用 5000000 次（五百万次）视为满熟练度（100%）。
- 熟练度带来的效果一律按**乘法系数**作用在各自的基础几率上：
  - 实际几率 = 基础几率 × (1 + 熟练度对应的额外比例)
  - 例如基础高品质几率为 10%，额外 +30% 时，最终几率 = 10% × (1 + 0.3) = 13%。
- **熟练度上升速度**：某些手段可提升或降低熟练度上涨速度；该接口需为后续扩展预留（实现时预留可插拔的倍率/修正入口，不在此文档枚举具体手段）。

- **钓鱼熟练度**：每 +1% 熟练度，
  - 钓鱼成功率：基础成功率 × (1 + 0.3%)；
  - 提升品质几率：基础提升品质几率 × (1 + 1%)；
  - 稀有鱼出现几率：基础稀有几率 × (1 + 0.15%)。

- **挖矿熟练度**：每 +1% 熟练度，
  - 挖矿成功率：基础成功率 × (1 + 0.3%)；
  - 挖到高品质矿石几率：基础高品质几率 × (1 + 1%)；
  - 稀有矿/副产品几率：基础稀有几率 × (1 + 0.15%)。

- **伐木熟练度**：每 +1% 熟练度，
  - 砍伐成功率：基础成功率 × (1 + 0.3%)；
  - 高品质木材几率：基础高品质几率 × (1 + 1%)；
  - 稀有木材/副产品几率：基础稀有几率 × (1 + 0.15%)。

- **狩猎熟练度**：每 +1% 熟练度，
  - 狩猎成功率：基础成功率 × (1 + 0.3%)；
  - 高品质猎物/素材几率：基础高品质几率 × (1 + 1%)；
  - 稀有猎物/稀有掉落几率：基础稀有几率 × (1 + 0.15%)。

- **采集熟练度**：每 +1% 熟练度，
  - 采集成功率：基础成功率 × (1 + 0.3%)；
  - 高品质草药/果实几率：基础高品质几率 × (1 + 1%)；
  - 稀有植物/稀有杂物几率：基础稀有几率 × (1 + 0.15%)。

- **畜牧熟练度**：每 +1% 熟练度，
  - 畜产品产出成功率：基础成功率 × (1 + 0.3%)；
  - 畜产品高品质几率：基础高品质几率 × (1 + 1%)；
  - 不额外提高稀有动物/稀有产物几率（畜牧偏稳定量产）。

- **种植熟练度**：
  - 仅在**收获作物时**提升熟练度（种下不涨，仅收获涨）。
  - 每 +1% 熟练度：
    - 高品质作物几率：基础高品质几率 × (1 + 1%)；
    - 双倍产物几率：基础双倍几率 × (1 + 1%)。

#### 8.2.2 采集技能与采集点机制

采集在**灌木丛**与**草丛**两类采集点上进行；产出由各采集点对应的**产出表**决定，产出表可区分药草、野果、杂物等，具体物品种类在表中配置（见下「产出表」）。地图上通过格子元素 id 引用采集点类型，逻辑根据 id 选择对应产出表与规则。

**采集技能（仅看熟练度）**：

- **采集成功率**：仅与**采集熟练度**相关。**实际成功率 = base + base × (熟练度% × 0.003)**，其中 base 为采集点基础采集成功率（如 0.6），熟练度% 为当前采集熟练度百分比（0～100）；不设上限，若结果大于 1 由实现夹紧。
- **熟练度与五百万次满**：与 8.2.1 生活技能熟练度为**同一套**；每成功采集 1 次计 1 次，满 **5000000 次（五百万次）** = 熟练度 100%。
- **每次采完**：每次采集完成（成功率判定通过并完成产出结算后）熟练度计数 +1（与五百万次满一致）。

**采集技能统一流程**（灌木丛、草丛共用）：

1. **前置条件**：当前格为采集点（元素 id 为 `gathering_bush` 或 `gathering_grass`）；角色**背包未满**且**体力 > 0**（背包已满或体力为空时不可采集，不扣体力、不推进 tick）。
2. **成功率判定**：每个采集点类型有各自的**基础采集成功率** base（在采集点表中配置）；**实际成功率 = base + base × (熟练度% × 0.003)**（熟练度% 为当前采集熟练度百分比）。先进行本次采集成功率判定；**只有判定成功后才进入步骤 3 的产出判定**。**判定失败**：本次无产出，**仍消耗 2 体力并推进 1 tick**。
3. **产出**：成功率判定通过后，**先**按产出表行**权重**随机抽取 **1 行**得到物品 id 与基础品质档位，**再**根据**采集熟练度**做一次**品质上修**：**熟练度每高 5%，有 5% 概率将本次品质上修一档**（品质 1～6 = 粗糙～传说，上修后最高到传说/6 档）。即熟练度 5% 时 5% 概率上修一档、熟练度 10% 时 10% 概率上修一档，依此类推；上修仅一次，不连续 roll。
4. **体力**：每次采集（无论成功失败）消耗 **2** 点体力（与 06 生存一致，可从配置读取）。
5. **工具**：不强制工具，徒手可采；工具为可选。有工具时同时加成**成功率**与**高品质/稀有概率**，在**工具表**中增加对应字段（如 `gathering_success_bonus`、`gathering_quality_bonus` 等），具体数值在工具表配置。
6. **熟练度**：采集成功即熟练度计数 +1（与 8.2.1 同一套，五百万次满），熟练度参与成功率、品质上修及 8.2.1 中高品质/稀有几率的计算。

**可采次数与刷新**：灌木丛与草丛均**不设采空**，可一直采；唯一限制为**背包已满**或**体力为空**时不可采集。

**挂机**：采集为可挂机动作（见六、生存）。挂机时**每 1 tick 执行一次**「成功率判定 → 成功则产出表抽取」；仅当**背包已满**、**体力为空**或**玩家手动停止**时结束挂机。

**采集点类型与地图调用**：

| 采集点 | 元素 id（地图格子引用） | 展示名 | 产出表 |
|--------|-------------------------|--------|--------|
| 灌木丛 | `gathering_bush`        | 灌木丛 | 灌木丛产出表（单独配置） |
| 草丛   | `gathering_grass`       | 草丛   | 草丛产出表（单独配置）   |

- **触发方式**：玩家**站在该格执行「采集」**时，系统根据当前格元素 id 判定为灌木丛或草丛，并走对应产出表与上述流程。
- **实现约定**：地图数据中，若某格为采集点，则该格元素类型/实体 id 为 `gathering_bush` 或 `gathering_grass`；配置表（如采集点表、地图格子表）中通过该 id 关联到对应产出表 id，便于扩展更多采集点类型。

**配置字段建议**（采集点表，供地图与逻辑读取）：

- `gathering_point_id`：与地图元素 id 一致（如 `gathering_bush`、`gathering_grass`）。
- `display_name`：展示名。
- `base_gathering_success_rate`：该采集点类型的**基础采集成功率** base（如 0.6 表示 60%）；灌木丛与草丛**建议均为 0.6**。实际成功率 = **base + base × (熟练度% × 0.003)**（熟练度% 为 0～100）。
- `loot_table_id`：产出表 id，指向该类型采集点使用的产出表。
- `stamina_cost`：每次采集体力消耗（当前约定 2）。
- `tool_required`：是否强制工具（当前均为 false）。工具对采集的加成在**工具表**中配置：`gathering_success_bonus`（成功率加成）、`gathering_quality_bonus`（高品质/稀有概率加成）等。

**产出表**：

- **表结构**：每条（每行）为 **物品 id + 权重 + 品质档位**，在同一行上直接写权重即可。**品质 1～6 分别对应粗糙、普通、精良、稀有、史诗、传说**（品质即稀有度，不单独再 roll「稀有」）。**抽取与品质上修**：先按表内权重随机到一行得到物品 id 与基础品质档位，再按**采集熟练度**做一次品质上修：熟练度每高 5%，有 5% 概率上修一档（最高到传说），见上流程步骤 3。
- **灌木丛与草丛表完全独立**：两张产出表互不共用条目，各自配置。
- **内容倾向（暂定）**：
  - **灌木丛产出表**：以**野果**类物品为主；具体物品 id、权重、品质档位在表中配置。
  - **草丛产出表**：以**药草**类物品为主；具体物品 id、权重、品质档位在表中配置。
- **物品 id**：由设计/配置自行生成或命名，在物品表与产出表中一致引用即可。
- **单件重量**：野果、药草在物品表中均约定单件 **0.1 kg**（如物品表字段 `weight_kg` 等）；负重与背包判定按此计算。
- **品质范围**：采集产出的野果、药草均可出现**品质六档**（1～6 = 粗糙～传说）；产出表每行配置品质档位与权重。

**配置字段建议**（产出表每行）：`item_id`、`weight`、`quality_tier`（1～6 对应粗糙～传说）；产出表 id 与采集点表之 `loot_table_id` 对应。物品表中野果/药草类物品的 `weight_kg` 建议为 0.1。

**工具表**（与采集相关）：增加 `gathering_success_bonus`（对采集成功率的加成）、`gathering_quality_bonus`（对高品质/稀有概率的加成）等字段，具体字段名与数值在工具表配置。

#### 8.2.2a 采集点实例、地图引用、分物品品质硬上限

- **数据主文件**：`data/gathering_point_instances.json`（`defaults`：`map_entity_id` → 默认 `instance_id`；`instances`：各实例完整配置）。
- **地图格**：`entity_id` 为**视觉/样式键**（如 `gathering_bush`）；可选 **`gathering_instance_id`** 引用上述实例。未写时由 `defaults[entity_id]` 解析默认实例。
- **实例字段**：含 `wild_interaction_category`（`fishing` / `mining` / `logging` / `hunting` / `gathering`）、成功率与体力、`loot_rows`（行内 `item_id`、`weight`、`quality_tier`、`quality_tier_max`）。**不枯竭**规则见野外采集点通用约定。
- **分物品品质硬上限**：每行可选 **`quality_tier_max`（1～6）**；在熟练度**品质上修之后**将结果**夹紧**到不超过该上限（仍用 1～6 档语义）。未配置时视为 **6（传说）**。
- **工具**：`tools/gathering-point-editor.html` 编辑实例并导出 JSON（与 `data/items.json` 联动选择 `item_id`）；`tools/map-editor.html` 可选绑定 `gathering_instance_id`。随机生成地牢时在房间实体列表中写入相同结构即可引用同一实例 id。

### 8.3 战斗系

战斗技能分为五类；**设计或配置每条战斗技能时，须首先且仅能归入其一**：**徒手**、**兵器**、**呼吸法**、**步法**、**招架**（实现可与分类 id 合一，如 `category: unarmed | weapon | breath | footwork | parry`）。

| 类别 | 说明（待细化） |
|------|----------------|
| **徒手** | 徒手战斗技能（拳脚、指法等）；走肢上主动与招式循环。 |
| **兵器** | 兵器战斗技能（刀、剑、棍等）；走肢上主动与招式循环。 |
| **呼吸法** | 底气运用、护体、催发等；**挂载全局 hub**（`hubs.breath`），不占肢上主动招式循环。 |
| **步法** | 战斗身法根基；**挂载全局 hub** `hubs.footwork`（不占肢上主动招式循环）。**不设招式熟练度**；战斗 **\(V_{\text{base}}\)** 来自当前挂载步法技能的 **`combat_speed_base`**（未挂载时用常数 `base_speed_no_footwork`）；对敌方命中**仅通过速度**间接影响。可在 **`hub_actions[]`** 配动作，经 **`19` 动作菜单**或战斗流程对自身 **上 buff**（与 Buff 系统对接）。同时**仅可挂一条**步法技能，**可切换**，**切换后立即生效**。学习/使用门槛**仅看先天**（见 `05`）。 |
| **招架** | 仅作招架槽技能；**无招式**、无肢上普攻链；招架数值随等级成长；**随等级或条件解锁的内容走「动作」**（见 [19-action-system.md](19-action-system.md)），具体解锁列表在**该招架技能单条设计**中声明。 |

#### 8.3.1 战斗技能通用规则

- **战斗资源（气力与底气；无「气劲」）**  
  角色战斗相关消耗仅使用 **气力值**（`qi_li`，**仅战斗中**启用，快耗快消，规则见 `07`）与 **底气**（`diqi`，生存向积累与恢复、与**呼吸法**关系见 `06`「底气与行气」等）。**不存在名为「气劲」的独立资源**；旧稿或实现若出现「气劲」字样，应迁移为气力或底气之一并与此处对齐。

- **技能等级与潜能消耗（四档）**
  - 战斗技能**模板**等级上限为 **1000 级**（全局常量 `default_combat_skill_max_level`；单条技能可用 `max_level` 覆盖），**不是写死常量**：运行时**可练上限**（展示用等级天花板）可由**唯一或少量事件**通过**开放接口**与存档字段 `skill_max_level_bonus` 略作抬升（见下节）。**当前企划**：仅**一个**事件会把「基本拳脚」`combat_basic_unarmed` 的可练上限 **+1**（至 **1001**）；**第 1001 级在数值上与第 1000 级相同**，仅为等级数字/UI/纪念意义，**不外推**威力与潜能曲线。
  - 使用**潜能**进行升级。
  - 战斗技能按**难度系数**分为**四档**，**共用同一条潜能消耗曲线**，仅**基数**不同：同一等级所需潜能 = **基础曲线该等级消耗 × 难度系数**（难度 1/2/3/4 对应系数 1×/2×/3×/4×）。故一档在**模板满级 1000** 下练满约 2000 万，二档 4000 万，三档 6000 万，四档 8000 万。若仅把可练上限抬到 1001 而不改 `max_level`，曲线仍按**模板满级**封顶查表；**1000→1001** 的潜能消耗与 **999→1000** 同档（最后一档每级消耗相同）。
  - **基础曲线（难度 1 时的每级潜能消耗）**——三段设计，200 级前平缓、400 级后明显变陡（第三段到**模板满级** \(L_{\text{tpl}}\)，默认 1000；公式内取 \(L_{\text{curve}}=\min(\text{当前等级}, L_{\text{tpl}})\)）：
    - **1～200 级**：每级消耗 **5000** 潜能（常数），合计 100 万，便于快速到 200 级。
    - **201～400 级**：每级消耗**线性**从 5000 增至 **20000**，即 \(Cost(L) = 5000 + 75 \times (L - 200)\)（\(L \in [201,400]\)），合计约 250 万。
    - **401～1000 级**（即至 \(L_{\text{tpl}}\)）：每级消耗**线性**从 20000 增至 **35000**，即 \(Cost(L) = 20000 + 25 \times (L - 400)\)（\(L \in [401, L_{\text{tpl}}]\)），默认 \(L_{\text{tpl}}=1000\) 时合计约 1650 万。
    - 以上三段合计约 **2000 万**（难度 1）；难度 2/3/4 时每级消耗分别 ×2/×3/×4，总消耗约 4000 万/6000 万/8000 万。
  - **实现约定**：上述常数（5000、20000、35000、75、25）及难度系数从配置表读取，便于调参。**难度在配置技能时声明**：在战斗技能配置中用字段**难度 1 / 2 / 3 / 4** 表示所属档位；**未配置或未填写时默认难度 1**。策划在设计每条战斗技能时须明确声明该技能的难度档位。

- **技能等级上限的额外约束（可选）**
  - 设计战斗技能时，可声明该技能的**当前等级不得超过**某一指定战斗技能的当前等级；约束**一律不得超过**，即升级、师傅传授、载入存档等所有会改变等级的场合都须校验，依赖技能等级下降（如死亡扣级）时，本技能等级若高于依赖则夹紧至依赖技能当前等级。
  - **依赖关系不能成环**：若技能 A 声明等级不得超过技能 B，则 B 不得再声明等级不得超过 A（或经 A 传递形成的任何环）；设计时与配置校验时均须保证无环。
  - 示例：后续设计「散打」时，可声明散打的当前等级不能超过「基本拳脚」的当前等级；未声明则仅受**该技能有效等级上限**与师傅可传授上限约束。
  - **实现约定**：技能配置中可选字段（如 `level_cap_skill_id`）引用另一战斗技能 ID；所有会改变等级的逻辑（升级、传授、载入、死亡扣级等）均须校验并夹紧；配置加载或编辑时校验依赖关系无环。

- **技能有效等级上限（开放接口）**
  - **模板上限**：每条战斗技能配置可选 `max_level`（整数）；缺省时取 `data/combat-skills.json` 中 `constants.default_combat_skill_max_level`（默认 1000）。**威力、招架、潜能等曲线一律以模板上限为数学上界**，不因 `skill_max_level_bonus` 外推。
  - **角色修正**：存档中与 `skills` 并列持久化 `skill_max_level_bonus`：`{ [skill_id]: number }`，为**可正可负的整数**，与模板上限**相加**得到**可练/展示上限** \(L_{\text{eff}} = \max(1,\; \texttt{max\_level} + \texttt{bonus})\)。剧情、NPC 触发器等**只应通过**修改该表或调用运行时 API 改变该上限；**禁止**在业务逻辑中写死「唯一上界」而绕过接口。
  - **参与数值的等级**：\(L_{\text{curve}} = \min(\text{存档中的实际等级},\; \texttt{getTemplateMaxLevel}(\ldots))\)，实现为 **`getSkillLevelForStatCurves(skillId, level)`**。实际等级为 1001 且模板为 1000 时，\(L_{\text{curve}}=1000\)，与满模板级**完全相同**。
  - **API（与实现对齐）**：
    - `getTemplateMaxLevel(skillId)` → 模板值（曲线封顶）；
    - `getSkillLevelForStatCurves(skillId, level)` → \(L_{\text{curve}}\)；
    - `getEffectiveSkillMaxLevel(character, skillId)` → 模板 + `skill_max_level_bonus`（**仅**升级夹紧与 UI 展示「可练至几级」；`character` 可省略则无修正）；
    - `getProgressionSkillMaxLevel(character, skillId)` → `min(Effective,\; 依赖技能等级)`（若配置了 `level_cap_skill_id`）；
    - `addSkillMaxLevelBonus` / `setSkillMaxLevelBonus` → 修改 `character` 上修正（实现中通常经 `InventoryEquipment` 状态读写）。
  - **NPC 触发器**：效果类型 `modifySkillMaxLevelBonus`，参数 `skillId`、`delta`（整数）；若当前等级超过新的 `getProgressionSkillMaxLevel`，须将等级夹紧。

- **战斗技能升级途径**
  - 战斗技能等级提升（消耗潜能）可通过以下两类途径获得进度：
    - **师傅 NPC 直接传授**：与具备传授该技能条件的师傅 NPC 进行「学习」交互，**学习一次消耗 10 点精力**，推进 **1 tick**；潜能消耗与升级进度按该技能难度与当前等级依上文曲线结算。**师傅只能传授到其自身该技能的等级为止**：师傅 NPC 对该技能有一个**可传授上限等级**，玩家通过该师傅学习时，最多只能被教到该等级；在学习界面中需展示「师傅该技能等级」或「可教至多少级」，供玩家判断。**设计 NPC 时声明**：每位师傅在各技能上的可传授等级（或上限）在配置该 NPC 时单独声明。
    - **自修**：角色可挂机进行自修；**每 1 tick 固定消耗 1 点精力**，潜能消耗与升级进度按同一曲线结算。**部分技能自修前需满足特定条件**（如已习得某技能、达到某属性、完成某剧情等）；若该技能有自修门槛，须在**设计该技能时在配置中声明**（如条件类型、判定字段或任务 ID），未满足条件时不可选择该技能进行自修。
  - **实现约定**：传授的“学习一次 = 10 精力 + 1 tick”与自修“每 tick 1 精力”的常数可从配置表读取；技能配置中为每条技能标注是否可被传授、自修条件（可选，无则默认可自修）。**NPC 配置**：设计师傅 NPC 时须为每个可传授技能声明该师傅的**可传授上限等级**（即师傅「会这个技能多少级、最多能教到多少级」）；学习界面读取并展示该上限，供玩家查看。

- **技能等级与基础威力**
  - 每个战斗技能都有一条独立的“**技能等级 L → 基础威力系数 Base(L)**”曲线，用于定义该技能在不同等级下的**基础威力**（**徒手 / 兵器**等参与普攻伤害的技能适用；**招架**类无招式，一般不定义伤害向 `Base(L)`，除非单条设计声明例外）。
  - 单次招式在计算伤害时，先取所属战斗技能当前等级 \(L\) 对应的基础威力系数 `Base(L)`，再乘以该招式的熟练度乘区与其他乘区（呼吸法威力、出力大小、环境、实战经验等）。

- **武器基础伤害（接入命中伤害公式）**
  - 与 [08-hit-parry-damage.md](08-hit-parry-damage.md) 原始伤害中的「武器基础伤害」对应：
    - **徒手**（拳脚、指法等）：**武器基础伤害 = 攻击方筋骨**（先天 + 后天之**实际值**，属性定义见 `05-character-attributes.md`）。
    - **兵器**：武器基础伤害 = 所持武器在物品/武器表中配置的基础伤害字段（具体字段名以实现为准）。
  - 原始伤害链仍为：**武器基础伤害 ×（招式+呼吸法威力系数）× …**（余同 `08`）；徒手仅将首项定为筋骨。

- **招式与招式熟练度（参与伤害）**
  - **适用于拥有招式的类型**：**徒手**、**兵器**的主动战斗技能。**招架**、**纯 hub 挂载的呼吸法**若不参与肢上普攻链，则**不设招式**；**步法**（`category: footwork`）**不设招式熟练度**，也不使用下文「招式使用次数 → \(R_{\text{move}}\)」模型。**呼吸法**熟练度统计见 **`hub_actions[]`** 与 `19`。其它若需「技能总熟练度 / 后遗症」等，由**该技能单条设计**另定口径（不得默用下文多招式算术平均，除非为该技能显式定义等价实体）。
  - 每个**拥有招式**的战斗技能包含若干个**招式**；**每个招式都是独立实体，只隶属于某一条战斗技能，不跨技能共享**。
  - 每个招式有自己的**使用次数计数** \(P\)，仅在**该招式成功命中目标时**计数 +1：
    - 打空、被闪避或被招架不增加使用次数；
    - 若为多段攻击，只要本次释放中**至少一段命中**，本次也只视为使用 1 次。
  - 统一约定：**单个招式满熟练度 = 使用 50000 次 = 100% 熟练度**。
  - 记某招式当前使用次数为 \(P\)，则其**熟练度比例**为：
    \[
    R_{\text{move}} = \min\left(\frac{P}{50000},\,1\right)
    \]
  - 该招式在技能等级为 \(L\)、使用次数为 \(P\) 时的**最终威力系数**为：
    \[
    Final_{\text{move}}(L, P)
    = Base(L) \times (1 + R_{\text{move}})
    \]
    - 即：**这一次出手是哪一招，就只看这招自己的熟练度**；
    - 熟练度满时，该招式在当前技能等级基础上获得 **+100%（×2）** 的线性加成。
  - **熟练度上升速度**：与生活技能一致，某些手段可提升或降低招式熟练度上涨速度；该接口需为后续扩展预留（实现时预留可插拔的倍率/修正入口，不在此文档枚举具体手段）。
  - **实现约定**：伤害公式中的“技能/招式熟练度乘区”，一律使用**“当前出手招式的熟练度 \(R_{\text{move}}\)”**，**不再使用“整条战斗技能的总熟练度”作为伤害乘区**。

- **技能总熟练度（不参与单次伤害，只用于奖励）**
  - 为了体现“整条功夫练得有多熟”，每条战斗技能在内部维护一个**技能总熟练度**，用于解锁该技能专属的被动奖励。
  - 设某条战斗技能下共有 \(N\) 个招式，第 \(i\) 个招式的熟练度比例为 \(R_i\)（按上文 \(R_{\text{move}}\) 规则计算）。
  - 该战斗技能的**技能总熟练度**定义为所有招式熟练度的**算术平均值**：
    \[
    SkillProficiency
    = \frac{1}{N}\sum_{i=1}^{N} R_i
    \]
  - 直观理解（以 4 招为例）：
    - 单招式满熟练度时 \(R_i = 1\)，对总熟练度贡献 \(1/4 = 25\%\)；
    - 四招全满时，总熟练度 = 100%；
    - 若只练满两招，其余两招为 0，则总熟练度为 50%。
  - **用途限定**：
    - **技能总熟练度不参与任何单次伤害计算**，只作为“该技能整体掌握程度”的指标；
    - 仅用于本技能对应的**熟练度奖励设计**（见下“后遗症/构式”）。
  - **实现约定（配置表）**：
    - 具体“在多少 % 技能总熟练度时解锁哪些奖励”，完全由**战斗技能配置表定义**；
    - 本文档不写死统一档位，设计战斗技能时必须**同时设计该技能的熟练度奖励触发点与效果**。
  - **无招式技能**（如招架类）：不适用默认的「\(N\) 个招式熟练度算术平均」；须在单条技能设计中声明**技能总熟练度**如何累计（例如按招架成功次数、按已解锁动作的使用次数等），否则不启用总熟练度后遗症链。

- **透支：战斗技能的被动槽位解锁**
  - 特殊技能「透支」通过剧情解锁后，**为战斗技能开启被动槽位**：
    - 每条战斗技能可以拥有若干个被动槽位，用于装备该技能对应的“后遗症”（构式）；
    - 槽位数量与上限由技能配置表定义（如字段 `max_post_effect_slots`），本节不写死具体数值。
  - 槽位为**挂在战斗技能上的局部被动槽**，而非全局统一被动栏；后遗症的作用范围见下「后遗症」小节。

- **后遗症（由技能熟练度解锁的构式，被动技能）**
  - **定义与性质**：
    - **后遗症**主要由战斗技能的**技能总熟练度**解锁；**亦可**由**单招式熟练度**达到阈值解锁（见下「单招式熟练度解锁」）。
    - 在实现与数据结构上，后遗症是一种**可装备的构式**：装备在**技能被动槽**或（本条扩展）**肢体装配位**上，在满足 `scope` / `valid_*` 时于对应出手或结算中生效。
  - **效果形态**：
    - 后遗症不局限于“+x% 伤害”类数值增益，可以改变规则或标签，例如：
      - 示例：「以掌为刀」——当装备者使用**钝击类伤害的招式**时，将本次攻击的**伤害类型从“钝击”改为“劈砍”**，后续伤害类型微调与部位系数均按“劈砍”结算。
  - **绑定关系与作用范围**：
    - 默认情况下，后遗症只对**挂载它的那条战斗技能**生效：
      - 例如某后遗症装备在「基本拳脚」上，则只影响「基本拳脚」下的招式；
      - 不影响其他战斗技能，除非该后遗症在配置中明确声明为“全局作用”。
  - **作用范围接口预留（实现约定）**：
    - 在后遗症/构式配置中预留作用范围字段（示意）：
      - `scope = "self_skill"`：默认，只影响挂载它的这条战斗技能；
      - `scope = "global"`：影响所有满足条件的招式/行为（全局被动）；
      - 未来可扩展 `scope = "tag:xxx"`：仅影响带特定标签的技能或招式。
    - 实现时，后遗症的逻辑统一从该字段判断作用范围，便于后续扩展“影响全局”的特殊后遗症，而不修改底层结构。
  - **单招式熟练度解锁（与总熟练度并列）**：
    - 某招式配置中可增加 **`post_effect_unlocks`**：数组项为 `{ min_proficiency_ratio, post_effect_id }`，当该招式的 **\(R_{\text{move}} \ge \texttt{min\_proficiency\_ratio}\)**（与上文「50000 次满」同一套 \(R_{\text{move}}\)）时，解锁对应 **`post_effect_id`**（定义在 **`/data/post-effects.json`**）。
    - 解锁仅表示「获得装配资格」；当前实现为**肢体级装配**：后遗症挂在 `lhand` / `rhand` / `lfoot` / `rfoot` 之一，对该肢体已装备并出手的招式生效。
    - 后遗症条目中用 **`valid_skill_ids` / `valid_move_ids`** 做运行时生效校验：即使后遗症已装在肢体上，仍仅在命中 `valid_*` 的技能/招式上生效。
    - **同肢同后遗症唯一**：同一 `post_effect_id` 在同一角色上、**同一条出招肢**（`lhand` / `rhand` / `lfoot` / `rfoot`）范围内**无论有多少招式槽，至多装配 1 份**。可在**四条肢各装配 1 份**同一 id（例如「不假思索」在左右手、左右脚各一，共 4 份同时生效），但**禁止**在同一肢体上对同一 id 重复装配（含多槽均装刺拳且各挂一次等情形）。
  - **单招式熟练度 → 后天五维（与后遗症并列）**：
    - 某招式可配置 **`proficiency_attr_unlocks`**：数组项为 `{ min_proficiency_ratio, acquired }`，其中 **`acquired`** 为对象，键为后天五维 id（`jingu` / `flexibility` / `breath` / `dexterity` / `focus`），值为**达到阈值时一次性计入**的整点数（可与 `14` 中 `skill_attr_gain` 的 id 命名一致）。
    - **呼吸法**的 **`hub_actions[]`** 条目可同样配置 **`proficiency_attr_unlocks`**（及可选 **`proficiency_max_uses`**，缺省同全局 `move_proficiency_max_uses`）；熟练度计数一般写入存档 **`skills[skill_id].move_usage[hub_action_id]`**（与肢上招式共用字段名，仅 id 空间不重叠）。**例外（已定）**：**`combat_basic_breath`** 下 **`19` 动作菜单** 的 **血气化劲 / 吐气纳精 / 调息 / 吐纳** 成功结算**统一**累加 **`move_usage.tu_na`**（与 **`tu_na`** hub 条目的 **`proficiency_attr_unlocks`** 共用一条成长线），见 **`19` §6**。
    - 当该招式 **\(R_{\text{move}} \ge \texttt{min\_proficiency\_ratio}\)**（与 `post_effect_unlocks`、50000 次满同一套 \(R_{\text{move}}\)）时，将 `acquired` 中各键**累加**进角色后天属性；在 **`recalcCharacterStats`** 中与装备、`skill_attr_gain` 同级汇总。
    - **与装备无关**：只要存档中该技能条目的 **`move_usage`** 使该招式达到阈值即生效；**不**因未装备该技能而收回（与「基本拳脚」按技能等级给后天筋骨的口径一致：等级在就有贡献）。
    - 多条目、多属性：同一招式可配置多项阈值（按序各自判定）；同一 `acquired` 内多键分别累加。
  - **解锁方式（实现约定）**：
    - 每条战斗技能的**技能总熟练度档位**与对应可解锁的后遗症列表，在该技能的配置表中定义；**单招式解锁**见上，写在对应 **`moves[]`** 条目内；**呼吸法 hub 动作**的后遗症/后天奖励写在 **`hub_actions[]`** 条目内（若有）。
    - 设计战斗技能时，须同时给出：
      - 技能本身的等级曲线 `Base(L)`（**徒手/兵器**等需要时；招架等可省略或单条声明）；
      - 该技能下所有招式列表与招式熟练度规则（**仅适用于有招式槽的徒手/兵器**）；**呼吸法**写 **`hub_actions[]`** 与解锁等级、**不**写肢上招式槽；
      - 技能总熟练度的奖励设计（在哪些熟练度百分比解锁哪些后遗症），**和/或**各招式的 `post_effect_unlocks`、**`proficiency_attr_unlocks`**（**和/或**各 **`hub_actions[]`** 条目的 `proficiency_attr_unlocks`）；
      - （若适用）**等级上限依赖**：本技能等级不得超过哪条战斗技能的等级；若无则不必声明。

- **变式（装备在招式槽的被动技能）**
  - **定义与定位**：
    - **变式**是可装入肢上招式槽的**被动技能实体**，在数据与显示上与主动招式并列，但在战斗结算上**不作为出手招式**。
    - **与主动招式共用同一套招式槽**：同一槽位只能装其一（主动招式或变式），不可同槽同时存在。
    - 变式属于“槽位内被动”，其效果作用域由声明决定：可作用于该肢体上的主动招式，或作用于该肢体上的招架结算（见下“作用对象声明”）。
  - **目标过滤（可对被辅助招式提出要求）**：
    - 变式可以配置 `valid_move_ids` / `invalid_move_ids`（可选），用于限制只作用于特定 `move_id` 或其集合。
    - 变式可以配置动作标签过滤（例如 `required_move_tags`）：要求该肢体在本次释放时具备招式所需的对应标签，才允许变式效果赋予该招式。
    - 变式可以配置伤害/段数过滤（多段时基于 `subhit_index` 与 `is_last_subhit` 等事件上下文判定），例如：仅作用于“第一段”“最后一段”“指定段序号”等；也可进一步限制目标招式的伤害类型（与实现的伤害类型枚举对齐）。
    - 若未声明任何 `target_filters`（或等价限制字段），默认视为“对该肢所有可辅助主动招式均可作用”。
  - **与后遗症关系（强制）**：
    - 变式**不能被后遗症辅助**：后遗症判定目标仅为实际出手的主动招式；变式自身**不**作为后遗症可挂载对象。
    - 因此，变式条目不配置 `post_effect_slot_max`，默认视为 **0**；`valid_move_ids` 等后遗症装配校验不应把变式 id 作为合法 move 目标。
  - **与招式循环关系（强制）**：
    - 变式虽占用招式槽位，但**不参与招式指针轮转**；轮转时应跳过变式槽，仅在可用主动招式槽之间前进。
    - 若某肢体当前仅装备变式且无任何可释放主动招式，则该肢体视为“当前无可用招式”，按肢体优先顺序切到下一肢；若四肢均无可用主动招式，本次攻击无效。
  - **触发条件（与 Buff 对齐）**：
    - 变式的触发/强度依赖判定采用与 Buff **同一套**条件计算口径：变式触发使用的事件上下文字段应与 Buff 的 `BuffEventContext` 保持一致（例如 `hit_roll_success`、`damage_final`、`move_id`、`subhit_index`/`is_last_subhit`、`tags` 等）。
    - 变式可调用与 Buff 同级的“开放接口”（例如资源/底气、Buff/DeBuff 是否存在、招架阶段结果、目标部位状态等），但只有当触发条件满足时，才把效果赋予“本次需要被辅助的主动招式/该次 sub-hit”的结算上下文。
    - 触发判定按“每段独立”执行：多段招式的每个 sub-hit 都必须独立检查触发条件。
    - 只有当触发条件满足时，变式才把效果赋予“本次需要被辅助的主动招式/该次 sub-hit（或该次招架结算）”的上下文；若条件不满足，则该段/该次结算不生效。
    - 若未声明 `trigger`（或等价触发条件字段），默认触发条件恒为 true：即在通过目标过滤后，总是为被辅助招式赋予该变式效果。
  - **作用对象声明（强制）**：
    - 每个变式必须显式声明其辅助对象范围：`assist_scope = active_moves | parry | both`（字段名可等价）。
    - 当声明包含 `parry` 时，该变式才允许装入招架槽位体系；未声明 `parry` 的变式不得装入招架槽。
  - **叠加与唯一性（强制）**：
    - **同一肢体内同一 `variant_id` 唯一**：禁止重复装配同 id 变式。
    - 同肢多个不同变式**互不覆盖、互不排斥**，按“效果叠加”处理（数值类累加/连乘与冲突字段并存规则在 `14-implementation` 的执行器中定义）。
  - **来源技能等级缩放（强制）**：
    - 变式本身不提供熟练度与熟练度奖励；其效果强度/参数的缩放，依赖变式的**来源技能**等级（`source_skill_level`），而不是变式自身的等级或使用次数。
    - 变式获取来源可来自任意技能（含呼吸法、步法、招架等），即变式是通用机制，不绑死在某一技能类型上。
    - 缩放规则为**线性增长**，自变量取来源技能的**实际等级**（非曲线封顶等级）。
    - 若某技能没有可参与普攻链的主动招式实体（例如呼吸法/步法/招架，或其它仅提供变式来源的技能），其“招式熟练度/技能总熟练度”按该技能既有规则处理；变式不会额外产生熟练度贡献。
    - 若来源技能等级不再满足变式生效条件（例如低于 `min_source_level`），须**强制清空该肢体上由该来源约束失效的变式槽位**。
  - **结算时机（实现约定）**：
    - 当某肢体的某个主动招式进入具体 sub-hit 的命中/伤害结算时，先汇总该肢已装备且满足“目标过滤 + 触发条件”的变式效果，再应用到该 sub-hit 的上下文（如系数、标签改写、附加效果派发等）。
    - 当某肢体进行招架结算且存在声明 `assist_scope` 包含 `parry` 的变式时，同样在对应招架上下文执行“目标过滤 + 触发条件”后赋予效果。
    - 变式不产生“出手一次”的概念：不计 `move_usage`，不触发“命中即计次”的招式熟练度规则。
    - 变式 effect 允许改变所有已开放战斗结算维度（含命中/招架/伤害链、标签与事件派发、以及熟练度增减相关结算字段）。
  - **变式 effect 体系（强制独立）**：
    - 变式使用独立的 effect 类型体系（如 `variant_effect_type` / `variant_effect_params`），**不复用** Buff 的 `effect_type` 目录；以确保“变式 effect 与被辅助主动招式结算上下文强绑定”。
    - Buff 与变式仅共享“触发条件/上下文判定口径”，不共享 effect 目录与执行器实现。

- **装备到肢体与出招循环**
  - **徒手**与**兵器**类主动战斗技能必须**装备在肢体上**才能在战斗中参与普攻出招循环；当前可装备的肢体包括：左手、右手、左脚、右脚。
  - **呼吸法**、**步法**不占上述肢上主动槽，挂载 **`hubs.breath` / `hubs.footwork`**，规则见 [19-action-system.md](19-action-system.md) 与 [07-combat-core.md](07-combat-core.md)（**\(V_{\text{base}}\)** 来自步法，见 `05` 5.7）。
  - **呼吸法**（`category: breath`）**不设肢上招式槽**，不参与普攻链；其 **「吐纳」等**在 **`hub_actions[]`** 配表，由 **`19` 动作菜单**执行（见 **8.3.3「基本呼吸法」**）。
  - 每条肢体同时可装备 **1 个主动战斗技能（徒手或兵器） + 1 个招架技能**。
  - 每个**带招式槽**的主动战斗技能（**徒手 / 兵器**）拥有若干个**招式槽**；玩家从已解锁的主动招式与可用变式中选择装入槽位并设定顺序。
  - **每肢最低主动招式数量（强制）**：每条已装备主动战斗技能并参与普攻链的肢体，共用槽布局中**至少必须有 1 个主动招式**。禁止把该肢体所有槽位都配置为变式。
  - **招架变式槽（已定）**：每条肢体的招架技能侧新增独立“招架变式槽”体系，**最多 5 槽**，按招架技能等级每 **200 级**解锁 1 槽（200/400/600/800/1000）。仅允许装配声明可辅助招架（`assist_scope` 含 `parry`）的变式。
  - **每槽类型与出力成数（已定）**：招式槽为共用槽，槽内可放主动招式或变式。
    - 主动招式：存 `move_id` + `power_level`（1～12，夹紧在模板 `power_level_min`～`power_level_max`）；本击成数 \(k\) 取当前主动招式槽的 `power_level`。
    - 变式：存 `variant_id`；不使用 `power_level`；不参与招式指针轮转，仅在对应肢体主动招式结算时赋予效果。
  - 每条装备了此类主动技能的肢体，都会维护一条**独立的招式循环序列**；循环仅在该肢已装备的**主动招式槽**中进行，变式槽位不参与轮转。
  - 玩家可以为四个肢体设定**出招优先顺序**（如：左手 → 右手 → 左脚 → 右脚）；在一次攻击中：
    - 系统在“未损毁且当前有可用招式”的肢体中，按优先顺序选择一条肢体作为本次出招肢体。
    - 若该肢体已损毁，直接跳到下一条肢体；若所有相关肢体均不能出招，则本次攻击视为无效。
  - 当某肢体被选中出招时：
    - 按该肢体的招式循环，取出**当前轮到的招式**尝试释放。
    - 如果因为动作标签不符、肢体状态异常等原因导致招式**无法释放**，本回合动作白费，但该肢体的招式指针仍视为“已轮到过一次”，在下次轮到该肢体时会进入下一招。

- **动作标签与肢体状态**
  - 每个招式都要求装备肢体具备某些**动作标签**（例如“拳击”“勾击”“踢击”等）。
  - 若肢体不具备招式所需的动作标签，则该招式既不能装入该肢的槽位，也无法在战斗中释放。
  - 肢体的动作标签可以被一些系统实时增减（例如通过特殊装备、buff、或永久改造等方式）；标签变化**即时生效**。
  - 若玩家在某肢上预先装备了需要特定标签的招式，而战斗中该肢失去了对应标签，则那些招式视为暂时不可用。
  - 肢体一旦被判定为“损毁”，则视为该肢无法再使用任何主动或招架招式，直到通过特殊手段恢复。

- **招式特殊效果与条件判定（开放接口）**
  - **招式**在释放与结算时，若配置有**特殊效果**且该效果的触发或强度依赖**条件判定**，则判定侧**只允许**通过引擎已实现、并对技能/战斗逻辑**开放（登记可查）的只读接口**取数；凡属此类开放接口暴露的游戏状态，均可作为条件输入（例如资源是否足够、Buff 是否存在、目标部位是否满足等），**不在此文档穷尽枚举**。
  - **招架流程中的特殊效果**（如招架成功时回复、反击等）：若需条件判定或强度与上下文相关，**与招式相同**，必须且仅能使用上述**同一套**开放接口（含槽位布局、后遗症装备、出招肢/非出招肢等已约定维度）；须在**该招架技能或关联效果**的设计中显式声明所引用的查询。
  - **设计约定**：单条招式、动作或招架效果配置中引用何种查询，须在对应设计中**显式声明**（便于审表与实现对照）；实现上新增可供配置引用的查询维度时，应走**统一登记**（如查询 id / 上下文字段清单），避免「仅单条可用的私有硬编码通道」。
  - **常见可作为条件输入的开放上下文示例**（实现以登记接口为准，下列为典型维度）：
    - **招式槽布局**：该战斗技能当前**已解锁的招式槽数量**；各槽位**当前装备的招式 id**（含空槽）；**各槽位为该招式配置的 `power_level`（1～12）**；若需区分肢体，则为**该肢上挂载的该技能**的槽布局与同序。
    - **指定肢体的槽位是否装有指定招式**：招式设计中可声明：在**使用本招式并结算效果时**，通过只读查询判断**某肢体**上、**某主动战斗技能**的**第 N 个招式槽**（槽索引以实现约定为准，如 0 基或 1 基）当前装备的招式 id **是否为**（或是否属于）配置给定的 id / id 集合。
      - **肢体如何指定**：既可写死为**固定肢体 id**（如左手、左脚、右脚等，枚举以实现为准），也可使用**肢体选取器**先解析出一条目标肢再查询，例如「随机一条腿部肢体」「在左/右腿中随机」「首条未损毁且已装备技能 S 的腿」等。选取器的种类、参数、随机是否可复现（种子）以实现登记为准；**单条招式设计须在效果中显式写明**选取器或固定肢、**战斗技能 id**、**槽位索引**、**要比对的招式 id**（或集合），避免歧义。
      - **技能 id**：通常为本效果关心的那条**肢上主动战斗技能**（可与当前出手技能相同或不同，以实现开放查询为准）；若该肢未装备该技能或槽位尚未解锁，按实现约定返回「无槽 / 空槽 / 不可查询」等语义，供条件表达式使用。
    - **循环与指针**：该肢当前**招式循环序列**、**下一轮将出的槽位索引**或等价指针（以实现字段为准）。
    - **后遗症（构式）**：该战斗技能被动槽上**是否装备指定后遗症**、已装备后遗症 id 列表、槽位占用情况等（与上文「透支」开启的被动槽一致）。
    - **出招肢体与非出招肢体**：条件判定须能区分**本次实际用于出招的肢体**（出招肢体）与**同一角色上其余未担任本次出招者的肢体**（非出招肢体）。可对出招肢做只读查询（如该肢上挂载的主动/招架技能、招式槽与循环指针、动作标签、损毁、装备等），亦可对**任意指定的一条或多条非出招肢**做相同维度的查询，或做聚合（例如「是否存在一条未损毁的非出招肢满足某条件」）。连击或多段中若每击肢位不同，以**该击结算时刻**的出招肢为准，非出招肢为相对该击的其余肢；具体字段以实现登记为准。
    - 其他已开放接口：如 Buff/Debuff、**气力值**、**底气**、肢体损毁与标签、装备与属性、场地与回合等——**凡对技能系统开放的只读查询均可接入同一套条件判定**，具体名称与路径以实现登记为准。

- **招架相关声明与接口**  
  - **招架类战斗技能没有招式**：不提供肢上普攻招式槽与招式循环；招架判定使用的等级与数值来自**该招架技能本体等级**（招架等级不单独设）。  
  - 上述“无招式”不影响“招架变式槽”机制：招架侧可有独立的变式装配槽，但这些槽不属于普攻招式槽，也不参与招式循环。  
  - 招架类技能随等级或剧情等**解锁「动作」**的，须在单条设计中声明（解锁条件、效果、资源、`tick_cost` 等），并归入 [19-action-system.md](19-action-system.md) 的动作表/登记体系；**不是**战斗招式。  
  - **徒手/兵器**技能若某招式**参与招架**，仍须在技能/招式配置中声明：基础招架成功率、基础卸力比例（可为等级函数或表）。  
  - 若招架成功时有**特殊效果**（如回复底气、反击等），须声明效果内容、触发条件（条件判定遵循上文「开放接口」）、该效果**是否受柔韧的招架效果加成**；实现上保留招架特殊效果的调用接口（按技能 ID 或标签触发），供扩展使用。  
  - 部分技能**仅能作为招架技能**装备（不提供主动攻击招式、不可装备为肢体的主动战斗技能），须在技能配置中标注（`only_parry` 或等价字段）。

    \[
    W_{\text{coef}} = W_{\text{skill}} \times M_{\text{move}} \times G \times K_{\text{试探}}
    \]
    其中仅当本击为 **摆拳**（`move_id` **`swing_punch`**）且攻击方持有 **试探** 时 \(K_{\text{试探}} = 1 + 0.05s\)，否则 \(K_{\text{试探}}=1\)。**顺序**：**先技能 \(W_{\text{skill}}\)，再招式乘子 \(M_{\text{move}}\)，再手套 \(G\)，再试探**。

  - **刺拳：试探 Buff（`buff_probe`，已定）**  
    - **获得**：**刺拳**在 **命中判定成功** 时叠层（口语「命中即叠」；口径同 `18-buff-system.md`：**命中 roll 成功**即算，其后招架致 0 伤仍可叠层），对 **攻击方** 施加或叠加 **试探**。  
    - **层数**：**最多 3 层**；再叠时按 Buff 通用规则 **重置持续时间**（`expires_at_tick` 按持续重算）、**夹紧 max_stacks**（见 `18`）。  
    - **效果（并入威力系数，已定）**：层数 \(s\in\{0,1,2,3\}\) 时，仅当本击为 **摆拳**（**`move_id` = `swing_punch`**，显示名「摆拳」）时  
      \[
      K_{\text{试探}} = 1 + 0.05\,s,\quad W_{\text{coef}} = W_{\text{skill}} \times M_{\text{move}} \times G \times K_{\text{试探}}
      \]
      **当 \(W_{\text{skill}}\times M_{\text{move}}\times G=1\) 时**：\(W_{\text{coef}} = 1 + (1 \times 5\% \times s)\)。**不**在暴击、环境、底气催发之后再乘同一因子。  
      - **连击 / 多事件**：每一次独立的 `swing_punch` 攻击结算（唯一 `event_id`，见 `18.6`）在合成 \(W_{\text{coef}}\) 时 **各乘一次** \(K_{\text{试探}}\)（\(s\) 取**该次算伤前**攻击方层数）。  
      - **同一招式 cast 内多 sub-hit**：每一 sub-hit 在合成该段 \(W_{\text{coef}}\) 时 **各乘一次** \(K_{\text{试探}}\)，\(s\) 取**该 sub-hit 算伤前**层数；**不在 sub-hit 之间单独清空**，避免第一段结算后层数被削光、后续段吃不到加成。  
    - **消耗（清空）**：**不是**「每次扣 1 层」，而是满足条件时 **一次性移除整个 `buff_probe` 实例（全部层数清空）**。  
      - **命中与伤害**：**命中判定失败**的摆拳段：**不**清空试探。**命中判定成功**且该段（或该招式实例，见下）**伤害结算已完成**的，**即使最终伤害为 0**（如被招架）：**要**清空（与叠层口径对齐：roll 成功即进入「可结算」路径）。  
      - **连击**：每一记 **独立的** `swing_punch` 出手，在该记 **命中成功且该记伤害结算完成后**，**整实例清空**（全部层数）。  
      - **同一 cast 多 sub-hit**：**仅在该招式实例的全部 sub-hit 均结算完毕后**，若**至少有一段**为命中成功且已走伤害结算（含 0 伤），则 **一次性整实例清空**；若**全程无任何段命中成功**，则**不清空**。  
    - **数据驱动**：`/data/buffs.json` 中 `buff_probe` 的 `effects` 声明 **`multiply_w_coef_factor`**（见 `18.3.1`），战斗结算除解析该 effect 外，仍须按本条实现叠层、清空与多段顺序；`triggerEventKind` / `triggerEventName` / `triggerTags` 与 **`probe_pipeline_manual`** 用于注册表与编辑器对齐，**不**表示仅靠通用扫描流水线即可自动跑完试探逻辑。  
    - **唯一性**：全游戏 **仅此一种** 试探 Buff（`buff_id` **`buff_probe`**）；**仅**刺拳按上表叠层，**不**另做同名分叉。

    - **出力**：与刺拳相同（模板默认 **10 成**，每槽 **1～12**）。  
    - **命中部位权重**：**头 10%、胸 15%、腹 35%、左/右手各 10%、左/右脚各 10%**（合计 100%）。  
    - **招式威力乘子**：配置 **`move_power_multiplier` = 1.0**，与技能等级曲线、招式熟练度等合成的 **\(W_{\text{skill}}\)** 一起在 \(W_{\text{coef}}\) 中体现（见上式）。  
    - **失衡（`buff_off_balance`）**  
      - **施加对象**：**被击中者（目标）**；配置字段 **`on_hit_roll_success_apply_buff_target`**（与刺拳对己的 `on_hit_roll_success_apply_buff_actor` 对仗）。  
      - **时机**：**命中判定成功**即叠加或刷新（口语与 `buff_probe` 叠层口径一致）；**即使随后被招架、最终伤害为 0**，**仍叠加**（与 `08` 先命中后招架顺序一致）。**未命中**不叠。  
      - **层数与持续**：**最多 3 层**；**持续 8 tick**；再叠加时按 `18` **重置持续时间**并夹紧 `max_stacks`。  
      - **效果**：每层使 **最终招架几率** 减少 **5 个百分点**（在 `08` 柔韧倍率与默认硬上限之后做**加法**修正，再对招架几率 **clamp** 到合法区间，下限 0）。实现可汇总为 **`BuffSystem.getParryChanceDeltaPercent(防方 ownerId)`**。  
      - **与试探**：**无**（不叠、不清 `buff_probe`）。  
    - **熟练度奖励（后天属性）**：单招式熟练度 **\(R_{\text{move}} \ge 20\%\)** 时，**后天柔韧 +15**（配置 `proficiency_attr_unlocks`，与 `data/combat-skills.json` 中 `whip_kick` 一致）。
    - **数据**：`/data/buffs.json`；`/data/editor/buff_event_registry.json` 标签含 **`move_whip_kick`**、**`off_balance`**、**`off_balance_pipeline_manual`**；effect 类型 **`parry_chance_delta_percent`** 见 `18.3.1`。

  - **动作标签**：须在 `05` / 装备与改造体系中可赋予肢体的标签集合内命名，并与实现枚举一致；若某肢缺标签，该招不能装入该肢槽位也不能释放。
  - **多段**：若段数 &gt; 1，须声明每段是否单独命中/招架/扣资源，并满足 Buff 等系统对「每段唯一事件 id」的约定（见 `18-buff-system.md` 与实现）。
  - **参与招架**：本技能为**主攻技能**；若个别招式要提供「以招代架」等，须在表中另列并在技能配置中写招架成功率/卸力（见 `08`）。默认可填「本招不单独作为招架源，招架用招架槽技能」。

- **后遗症与肢体装配（已定：刺拳 / 摆拳）**
  - **全局表**：后遗症定义在 **`/data/post-effects.json`**（id、`name_key`/`desc_key`、作用域、`valid_skill_ids` / `valid_move_ids`、`effect_type` 等）。
  - **刺拳**（`jab`）：
    - **解锁**：单招式熟练度 \(R_{\text{move}} \ge 20\%\)（`min_proficiency_ratio`: **0.2**）时，解锁后遗症 **`post_no_second_thought`**（显示名 **「不假思索」**）。**曾否获得**由后台 **`CharacterAttributes.post_effects_obtained`**（及 **`getPostEffectsObtainedCount` / `getPostEffectsObtainedIds`**）供条件判定，**不对玩家默认 UI 展示**（见 `14-implementation`）。
    - **装配**：当前实现为肢体级装配；玩家将「不假思索」装配在某条出招肢体上后，该肢体出手招式可触发其效果。`valid_move_ids: jab` 继续用于“仅刺拳生效”的校验。**同一肢体上该 id 仅能装配一份**（四肢可各一份），见上「同肢同后遗症唯一」。
    - **效果**：`effect_type` **`initiative_always_first`**——当该肢体本击实际出手招式命中 `valid_*`（当前为刺拳）时，先手判定见 **`07-combat-core.md`**「先手例外」：本击攻击方固定先于防守方出手；**不**改变连击次数规则。
    - **文案**（`data/ui_text_zhCN.json`）：**「无心，无我。——仅剩拳锋。」**（`posteffect.no_second_thought.desc`）；名称 **「不假思索」**。
  - **摆拳**（`swing_punch`）：
    - **解锁**：\(R_{\text{move}} \ge 20\%\) → **`post_po_xiang`**（**「破相」**）。
    - **装配**：当前实现为肢体级装配；`valid_move_ids: swing_punch` 用于“仅摆拳生效”的校验；**同肢同 id 唯一**仍适用（见上）。
    - **效果**：`effect_type` **`dispel_one_beneficial_buff_on_target`**；**命中 roll 成功**即对目标尝试驱散 1 个增益实例；**被招架至 0 伤照样驱散**（与 `08` 先判定命中再招架顺序一致）。**文案**：**「凡所有相，皆是虚妄。」**（`posteffect.po_xiang.desc`）。
  - 其它招式 / 技能总熟练度档位的后遗症：**待续**，仍可用 `max_post_effect_slots`（技能级）与总熟练度表扩展，与本条**招式槽**模型并存。

- **招式槽与初始配置**
  - 角色在学会「基本拳脚」时，默认已掌握刺拳与正蹬，对应**立即解锁 2 个招式槽**。
  - 当技能等级达到 50 级并学会摆拳与鞭腿时，每学会一个新招式**额外解锁 1 个招式槽**，最终该技能共计 **4 个槽位**。
  - UI 中仅显示当前已解锁的槽位，未解锁的槽位不显示，避免在早期暴露未来结构。
  - 玩家可以在每个槽内自由选择已解锁的招式，并为装备了「基本拳脚」的每条肢体分别设定槽内招式顺序；不同肢体可以有完全不同的出招顺序。

- **等级与基础威力曲线**
  - 「基本拳脚」的 **`base_power_curve`: `unarmed_simple`** 下，`CombatSkills.getBasePower` 返回的是**随技能等级变化的威力倍数** \(Base(L)\)（浮点运算，实现中**保留两位小数**），参与伤害链中的 \(W_{\text{技}}\) 等（见 `08` / `combat-melee-resolve`）：**非**旧版「常数 10 × 分段 \(M(L)\)」模型。
  - **曲线等级**：\(L_{\text{curve}}=\min(\text{实际等级}, L_{\text{tpl}})\)，\(L_{\text{tpl}}=\texttt{getTemplateMaxLevel}(\ldots)\)。**实际等级超过模板满级时仍按 \(L_{\text{curve}}=L_{\text{tpl}}\) 取 \(Base\)**。
  - **配置**（`data/combat-skills.json` → `constants`）：**`base_power_unarmed_mult_at_1`**（默认 **1**，对应 \(L=1\)）、**`base_power_unarmed_mult_at_max`**（默认 **3.5**，对应 \(L=L_{\text{tpl}}\)，即相对 1 级 **+250%** 总威力倍数；如 1000 级模板满级 \(Base=3.50\)）。
  - **归一化进度**：设 \(L=L_{\text{curve}}\)，当 \(L_{\text{tpl}}>1\) 时
    \[
    t = \frac{L - 1}{L_{\text{tpl}} - 1}\quad (t \text{ 夹紧到 } [0,1])
    \]
  - **线性插值**（每级在倍数上均匀递进；\(L_{\text{tpl}}=1000\) 时每级约 **+0.25%** 相对基数 1 的递增速率 toward 满级总 +250%）：
    \[
    Base(L) = m_1 + (m_{\max} - m_1)\, t
    \]
    其中 \(m_1=\texttt{base\_power\_unarmed\_mult\_at\_1}\)，\(m_{\max}=\texttt{base\_power\_unarmed\_mult\_at\_max}\)。例：\(m_1=1,m_{\max}=3.5,L_{\text{tpl}}=1000\) 时 \(Base(1)=1.00\)，\(Base(1000)=3.50\)；\(L=500\) 时 \(t\approx0.4995\)，\(Base\approx2.25\)。
  - 在原始伤害公式（`combat-melee-resolve`）中：\(Base(L)\) 与呼吸、招式倍率、\(G\)、试探、惯用肢等以 \((x-1)\) 形式并入加性「增伤」；**本招熟练度比例** \(R_{\text{move}}\) 也**加在增伤 ΣΔ 内**（不再单独乘 \((1+R_{\text{move}})\)）。**技能总熟练度**比例 \(R_{\text{skill\_total}}\) 以 **\((1+R_{\text{skill\_total}})\)** 作为**技艺总熟**独立乘区（见 `combat-skills.js` 的 `getSkillTotalProficiency`）。**实战经验**乘区 \(F_{\text{实战经验}}\) 由 **`docs/design/04-combat-exp.md`** 的全局实战经验值给出（`InventoryEquipment.getCombatExperienceDamageMultiplier`，与 \(R_{\text{skill\_total}}\) 分列）。

- **熟练度与最终威力**
  - 「基本拳脚」下各招式的熟练度计数、熟练度比例 \(R_{\text{move}}\) 等，仍按 8.3.1「招式与招式熟练度（参与伤害）」计数与 \(R_{\text{move}}\) 定义。**地图近战 resolve** 中 \(R_{\text{move}}\) 已并入加性增伤；文档记号 \(Final_{\text{move}}(L,P)=Base(L)(1+R_{\text{move}})\) 与**当前实现**在形式上不完全等同（实现另乘技艺总熟 \((1+R_{\text{skill\_total}})\) 与实战经验 \(F_{\text{实战经验}}\)）。
  - 该技能的**技能总熟练度**按 8.3.1 的算术平均折算；四招全满时技能总熟练度为 100%，用于解锁该技能对应的后遗症（构式）。

- **永久属性加成（后天筋骨）**
  - 「基本拳脚」作为长期修行的基础功法，按**技能当前等级**给予后天筋骨（配置驱动，见 `data/survival-config.json` 中 `skill_attr_gain`）：
    - **每满 20 级**：**后天筋骨 +1**（即贡献为 \(\lfloor L/20\rfloor\) 点筋骨，\(L\) 为存档中的实际等级；20 级起第一档）。
  - **1001 级特例**：\(\lfloor 1001/20\rfloor = \lfloor 1000/20\rfloor = 50\)，与满模板 1000 级相同，不额外多 1 点筋骨。
  - **按招式熟练度的后天奖励**（与上并列、配置在 `data/combat-skills.json` 的 **`proficiency_attr_unlocks`**，见上「正蹬」「鞭腿」及 8.3.1「单招式熟练度 → 后天五维」）：
    - **正蹬**（`front_kick`）：**\(R_{\text{move}} \ge 20\%\)** → **后天筋骨 +15**。
    - **鞭腿**（`whip_kick`）：**\(R_{\text{move}} \ge 20\%\)** → **后天柔韧 +15**。
  - 该加成为全局永久加成：
    - 与当前是否装备「基本拳脚」无关，只要该技能等级达到阈值即生效。
    - 招式熟练度奖励同样**仅依赖存档计数与阈值**，达到即计入后天；**`move_usage` 变化后须触发 `recalcCharacterStats`**（与升级、换装同级）。
    - 加成计入后天部分，不会突破先天属性的 40 点上限设定，但会与先天值相加用于实际数值计算。

#### 8.3.3 「基本呼吸法」

- **配置 id**：`combat_basic_breath`（与 `data/combat-skills.json` 一致；显示名 **「基本呼吸法」**；挂载 **`hubs.breath`**）。**类型**：呼吸法（`category: breath`）；**难度**、**模板等级上限**等同其它战斗技能默认值（`max_level` 1000 等），除非单条覆盖。
- **无肢上招式槽**：**`moves` 为空数组**；**不配** `slots_unlock_by_level`（或等价字段为 0 / 不声明）。不参与 8.3.1 所述**普攻链**与**出力成数槽**。
- **Hub 配表 `hub_actions[]`**：每条为 **呼吸法特殊动作**的数据源（**非**肢上招式槽），至少 **`id`**、**`name`**、**`unlock_level`**、**`tick_cost`**、效果字段（如 **`qi_li_restore`**、底气护体的 **`diqi_consume_ratio_of_max`** / **`diqi_consume_min`**（底气消耗下限夹紧） / **`shield_tri_type_damage_reduce_pct`**）、可选 **`cooldown_ticks`**、**`battle_only`**、**`proficiency_attr_unlocks`** / **`proficiency_max_uses`**、可选 **`exclude_from_skill_total_proficiency`**（见下 **底气护体**）。**玩家执行入口**为 **`19`「动作」菜单**（血气化劲 / 吐气纳精 / 调息 / 吐纳 / **底气护体** 同列）；**不在**武学枢纽强制要求独立战斗条按钮。
- **冷却存档**：**`skills[combat_basic_breath].hub_action_cooldown_ticks[hub_action_id]`**（剩余 tick），规则见 **`19` §6** 总述。
- **吐纳**（`tu_na`，**1 级**解锁）：
  - **消耗**：成功执行后推进 **`tick_cost` = 1** tick（失败不推 tick，见 `19` §4）。
  - **效果**：**`qi_li_current +=`** 配置 **`qi_li_restore`**（当前 **50**），夹紧 **`qi_li_max`**（见 `07`）；**`battle_only`** 时非战斗整次失败。
  - **冷却**：**`cooldown_ticks` = 5**；与 **`hub_action_cooldown_ticks.tu_na`** 同步递减（见上、`19`）。
  - **熟练度与奖励**：**`move_usage.tu_na`** 与 **血气化劲 / 吐气纳精 / 调息** 成功结算**共用累计**（见 `19` §6）；**\(R \ge 50\%\)** → **后天呼吸 +20**（`proficiency_attr_unlocks`）；**`recalcCharacterStats`** 在 `move_usage` 变化后调用。
- **底气护体**（`diqi_huti`，**50 级**解锁，见 `19` §6.6、`06` 底气护体示例）：
  - **消耗**：**`tick_cost`**（当前 **1**）、**`battle_only`**；先算 **\(B=\lfloor diqi_{\max}\times\texttt{diqi\_consume\_ratio\_of\_max}\rfloor\)**，再 **下限夹紧**：**\(C=\max(\texttt{diqi\_consume\_min},\,B)\)**（配置 **`diqi_consume_min`** 当前 **1**，与 `14` 底气/气力扣费 **`d_min`** 口径一致）。**`diqi_max=0`** → **整次失败**（不进入扣费）；**`diqi_current < C`** → 整次失败；成功则 **`diqi_current -= C`**，**护体容量 `shield_value = C`**。
  - **持续与叠加**：**无 tick 时长**；**`shield_value > 0` 时不可再次施展**（避免叠盾/刷新，直至护体被击破）。
  - **减伤**：**劈砍 / 戳刺 / 钝击** 均为 **`shield_tri_type_damage_reduce_pct`**（当前 **0.25**）；结算顺序与扣减 **`shield_value`** 见 `06`/`08`。
  - **熟练度与总熟练**：**不**计入 **`move_usage.tu_na`**；配 **`exclude_from_skill_total_proficiency: true`**，**不参与** **`getSkillTotalProficiency`** 平均，以免稀释吐纳对 **`breath_power_multiplier`** 的影响（运行时见 **`CombatSkills.getSkillTotalProficiency`**）。
- **与 `19-action-system` §6**：**基本呼吸法 ≥1** 解锁 **血气化劲、吐气纳精、调息、吐纳**；**≥50** 额外解锁 **底气护体**。吐纳线的 **熟练度、威力、后天奖励** 依赖 **`move_usage.tu_na`** 与 **`getSkillTotalProficiency(combat_basic_breath, …)`**（**`exclude_from_skill_total_proficiency`** 的 hub 条目不参与该平均）。
- **呼吸法威力系数** \(F_{\text{呼吸法威力}}\)（乘入 `05`/`08` **技能侧** \(W_{\text{skill}}\)）：  
  - **`breath_power_multiplier`**：**`base` = 1.0** + **`proficiency_bonus_unlocks`**（`min_proficiency_ratio`、`multiplier_delta` **加法**）。  
  - **熟练度口径**：**`getSkillTotalProficiency(skillId, move_usage)`**（`moves` + **`hub_actions`** 平均，**跳过** **`exclude_from_skill_total_proficiency: true`** 的条目；当前 **吐纳** 与 **多源共用 `move_usage.tu_na`** 时，**总熟练度 = 吐纳条目的 \(R_{\text{move}}\)**——**底气护体** `diqi_huti` **被排除**）。  
  - **总熟练 \(\ge 50\%\)** → **+0.3** → **\(F_{\text{呼吸法威力}} = 1.3\)**。  
  - **未挂载 `hubs.breath`** 或非 breath：**\(F = 1\)**（除非单条另声明）。
- **新呼吸法（策划已定：沿用）**：新增 **`category: breath`** 技能**沿用**本条的 **`hub_actions[]` + `breath_power_multiplier`** 配置形状（未配置 `breath_power_multiplier` 时 **`getBreathPowerMultiplier` 视为 1**）。
- **新步法**：新增 **`category: footwork`** 技能**沿用** **`hubs.footwork` 单槽挂载**、**`combat_speed_base`**、可选 **`combat_speed_per_10_levels`**（等级平直加速）、**无熟练度**、**`hub_actions[]` 仅服务动作/Buff** 的模型；不在单条中引入「步法熟练度乘区」参与命中（命中侧仅速度）。

#### 8.3.4 「基本步法」

- **配置 id**：`combat_basic_footwork`（显示名 **「基本步法」**；挂载 **`hubs.footwork`**）。**类型**：`category: footwork`。
- **全局 hub**：与呼吸法同级；**不占肢体槽**；**同时仅可挂载一条**步法技能；**可随时切换**，**立即**影响 **`CharacterAttributes` 缓存的战斗速度**（`recalcCharacterStats` 在 hub 变更时触发）。
- **无肢上招式槽**：**`moves` 为空**；不配 `slots_unlock_by_level`；**`getSkillTotalProficiency` 对步法恒为 0**；**不参与** `sumFromMoveProficiencyAttrUnlocks`。
- **战斗速度（实现口径）**：先算浮点 **`speedFloat = V_{\text{base}} \times (1 + 0.005 \times S_{\text{身手}} + \sum P)`**（与 `05` 5.7 一致），再 **`floor(speedFloat)`**，最后 **加上步法等级平直奖励**。其中 **\(V_{\text{base}}\)** 来自技能 **`combat_speed_base`**（正数）；未挂载 `hubs.footwork` 或模板缺失时 **`base_speed_no_footwork`**（默认 1）。**`combat_speed_per_10_levels`**（可选，整数）：挂载该步法且存档有等级 \(L\) 时，额外 **`floor(L/10) × combat_speed_per_10_levels`** 点战斗速度（**基本步法** 为 **每 10 级 +1**）。**不再**用鞋子 `base_speed` 覆盖 \(V_{\text{base}}\)（鞋子等仍可通过词条 **`speed_bonus`** 进入 \(\sum P\)）。
- **命中**：步法**不**提供独立「闪避率」乘区；对敌命中关系**仅通过**已算好的**战斗速度**参与 `08` 公式。
- **`hub_actions[]`**：可选；用于声明步法专有动作（冷却、tick 等按条目标）；执行时可 **`triggerBuffPipeline`** 等对**自身**上 buff。与**熟练度统计无关**。
- **门槛**：若配置学习/使用条件，**仅与先天属性比较**（后天不计），同 `05` / 本节通用规则。

#### 8.3.5 「基本招架」

- **配置 id**：`combat_basic_parry`（显示名 **「基本招架」**）。**类型**：`category: parry`；**`only_parry: true`**。

- **类型**  
  - **招架**类；**无招式**；不配招式槽与招式循环。

- **定位（分肢装备）**  
  - **仅能作为招架技能**装备在肢体 **招架槽**（`limbs.*.parry`）；**不可**装入 **进攻槽**（`active`）。可与任意主动战斗技能同肢搭配；**每条肢各装一份**时，各肢独立一条技能等级存档（同一 `skill_id` 多条肢可同时存在，等级以存档中该技能条目为准——当前实现为**角色级单一** `skills[combat_basic_parry].level`，与各肢共等级）。招架结算取**实际承担招架的那条肢**上所挂招架技能 id 与等级（实现以战斗引擎为准）。  
  - 招架等级 = 该战斗技能 **`skills[skill_id].level`**（与 8.3.1「招架等级不单独计算」一致）。

- **等级上限**  
  - 模板 **`max_level`** 默认 1000（与其它战斗技能一致）；升级方式一致（潜能等）。

- **招架数值（线性随等级，三系共用）**  
  - **基础招架成功率**与**基础卸力比例**对 **劈砍 / 戳刺 / 钝击** **同一组数值**（命中后仍是一次招架判定；非三种独立格挡率）。  
  - **1 级**：基础招架成功率 **15%**，基础卸力比例 **20%**。  
  - **模板满级**（默认 1000 级）：基础招架成功率 **45%**，基础卸力比例 **50%**。  
  - 对 \(L_{\text{curve}}=\min(\text{实际等级}, L_{\text{tpl}})\)，当 \(L_{\text{curve}}<1\) 时两值视为 0；当 \(L_{\text{curve}}\ge 1\) 时在 **L=1** 与 **L=L_{\text{tpl}}** 间**线性插值**。配置字段：`parry_success_at_level_1`、`parry_success_at_max`、`parry_reduce_at_level_1`、`parry_reduce_at_max`（`getParryValues`）。  
  - 再经柔韧乘算与默认硬上限：见 `08-hit-parry-damage.md`（`parry_flexibility_mult_per_point` 等）。

- **熟练度**  
  - **每次招架成功**（本次判定为招架成功、伤害未结算）计 **1 次使用**，写入 **`skills[combat_basic_parry].move_usage.parry_success`**（键名可由 `parry_proficiency_usage_key` 覆盖）。满熟练比例分母 **`parry_proficiency_max_uses`**，缺省同全局 `move_proficiency_max_uses`（如 50000）。  
  - **技能总熟练度**：`getSkillTotalProficiency(combat_basic_parry, move_usage)` 对招架类取 **该键单一 \(R\)**（非多招式平均）。  
  - 结算侧在招架成功后调用 **`InventoryEquipment.incrementSkillMoveUsage(skillId, usageKey, 1)`**（内部 **`recalcCharacterStats`**，便于后续 `proficiency_attr_unlocks` 等扩展）。  
  - **后天奖励（已定）**：**总熟练 \(R \ge 50\%\)** → **后天柔韧 +40**（配置 **`parry_proficiency_attr_unlocks`**，由 **`recalcCharacterStats`** 与招式熟练度奖励同链汇总）。

- **学习与门槛**  
  - **初始默认未习得**（`level < 1` 或未入档）。**基本招架无额外学习门槛**；若将来某招架技能有筋骨/呼吸等要求，**仅在单条中显式声明**。  
  - **招架槽空**或**未习得**：**跳过招架结算阶段**（不掷骰、不卸力），见 `08`「招架结算阶段」。

- **承担招架的肢体（与 `08` 一致）**  
  - **四肢受击**：用**对应肢**的招架槽；**该肢已损毁**则**无法**用该肢格挡，本击**跳过招架段**。  
  - **头 / 胸 / 腹受击**：按 **`lhand` → `rhand` → `lfoot` → `rfoot`** 选**第一条未损毁肢**的招架槽；**四肢全毁**则**无法格挡**，跳过招架段。

- **资源**  
  - **基本招架**：**无**气力/底气等消耗（有消耗的技能单条声明）。

- **日志与事件**  
  - 战斗日志文案见 **`data/ui_text_zhCN.json`** `log.combat.parry.*`；Buff 管线事件名见 **`data/editor/buff_event_registry.json`**（`parry_guard_limb_resolved`、`parry_phase_skipped`、`parry_roll_succeeded` 等）。实现辅助 **`CombatParry`**（`js/combat-parry.js`）。

- **动作与特殊效果**  
  - **随等级解锁的动作**：默认**无**；若扩展，在单条设计中声明。  
  - **招架特殊效果**：默认**无**。若配置，须符合 8.3.1「开放接口」约定。

- **其它招架模板**  
  - 未配置 `parry_*_at_level_1` / `parry_*_at_max` 的招架技能，可仍用旧式 **`parry_success_at_1000` × (Lcurve/Ltpl)**（与全局 constants 兜底）。

### 8.4 特殊系

特殊系技能**不在常规升级/点数树中**，仅通过**剧情推进或特殊任务**解锁，每个都有独特作用，通常用于：

- 改变部分底层规则（例如某些惩罚或限制的例外情况）；
- 开启全新玩法或交互（例如特殊视角、特殊结算方式）；
- 提供无法通过数值堆叠获得的能力。

具体特殊技能列表在剧情与任务设计阶段一并细化。

#### 8.4.1 特殊技能栏

- **地位与结构**
  - 特殊技能栏与**战斗技能栏、生活技能栏、生存技能栏**并列，为同一层级的**独立技能栏**；角色拥有四个技能栏：生存、生活、战斗、特殊。
  - 特殊技能栏内展示与管理的，均为**特殊系技能**（通过剧情或特殊任务解锁，不进入常规升级/点数树）。

- **技能用途（判定与认知）**
  - 栏内技能**绝大多数**用于被**其他技能、事件、系统**引用做判定，例如：
    - 作为门槛（如「拥有某特殊技能才可学习/使用某战斗技能」）；
    - 作为事件分支条件（如剧情/任务根据是否拥有某特殊技能走不同分支）；
    - 作为是否开放某功能、某交互的判定条件。
  - **认知引擎**以「角色是否拥有/解锁栏内某特殊技能」为条件，判定是否**开启或展示对应的 UI**（例如某界面、某入口、某选项是否对玩家可见或可用）。即：特殊技能栏既是数据来源，也是 UI 开放与否的判定依据。

- **实现约定**
  - 在角色/存档数据结构中，特殊技能与生存/生活/战斗技能一样，占**独立栏位**（如 `skills.special` 或等价结构），便于与其它三栏统一处理。
  - 认知引擎在决定是否展示某 UI 时，应查询**特殊技能栏**内是否包含配置所要求的特殊技能（或等级等），再决定是否开启该 UI。
