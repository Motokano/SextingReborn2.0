# 二十四、属性经验系统（五维成长扩展）

> 目标：在不改动“先天/后天五维”基础框架的前提下，新增一条可持续、可配置、可平衡的成长线，让角色在战斗、生存、生产中的实际行为持续沉淀为五维成长。

---

## 24.1 已确认口径（当前定稿）

- **定位**：属性经验（以下简称 `AttrEXP`）是“行为 -> 后天五维”的奖励系统，用于鼓励玩家进行各种生活行为。
- **作用对象**：仅作用于五维后天值：`jingu`（筋骨）、`flexibility`（柔韧）、`breath`（呼吸）、`dexterity`（身手）、`focus`（专注）。
- **不触及项**：
  - 不直接改先天属性；
  - 不直接改技能等级曲线；
  - 不新增并行属性真相（最终仍由 `CharacterAttributes.recalcCharacterStats()` 汇总后天值）。
- **与熟练度关系（已定）**：完全独立。熟练度系统不再提供任何后天五维加成；后天五维由属性经验系统单独提供该通道。
- **统一时间口径**：所有自动增减与结算节奏沿用全局 `tick` 语义，不建立独立时间轴。

---

## 24.2 核心概念

### 24.2.1 属性经验池

每个维度拥有独立经验池与属性值成长轨道（互不共享）：

- `attr_exp.jingu`
- `attr_exp.flexibility`
- `attr_exp.breath`
- `attr_exp.dexterity`
- `attr_exp.focus`

每个池至少包含：

- `exp`：当前经验值（非负整数）
- `attribute_level`：通过属性经验系统累计提升的后天属性点数（从 0 开始）
- `total_gained`：累计获得经验（用于统计/成就/调试）

### 24.2.2 属性经验 -> 概率结算 -> 后天属性

属性经验不采用“攒够阈值直接加点”的传统模式，而是采用“经验影响加点概率”的结算模式：

- 每条属性维护独立经验值（`exp`）；
- 每条属性维护独立成长等级（`attribute_level`），专门记录“该系统已提供了多少后天属性点”；
- 当触发专门的“属性经验结算事件”时，读取该属性当前 `exp`，计算本次“属性 +1”的概率；
- 若判定成功：该属性后天值 `+1`，`attribute_level +1`，并清空该属性经验（`exp = 0`）；
- 若判定失败：该属性经验不清空（保留到下次结算）；
- 五条属性互相独立判定，互不影响。

结算成功后必须触发统一重算入口（与技能升级、装备变化同级）。

## 24.3 成长来源（已确认入口）

属性经验通过以下入口发放（你已确认）：

- **事件触发**：在事件上可配置“给予哪个属性、给多少属性经验”。
- **生活技能互动**：在生活技能相关互动上可配置属性经验发放。
- **使用物品**：在使用物品时可配置属性经验发放。

发放规则说明：

- 发放单位为“属性经验值”，目标是五维中的某一项或多项；
- 每种行为发多少经验，由配置决定，不写死在文档公式中。

## 24.4 升级公式（概率型）

### 24.4.1 结算触发

- 存在一个专用事件用于触发属性经验结算（由你配置触发时机）；
- 每次触发时，对五条属性分别执行一次“概率判定”。
- 为事件系统提供专用结算接口，供事件直接调用（避免各系统私自实现第二套结算逻辑）。
- **单次结算事件内，同一属性不允许多次成功**（每属性最多 +1）。

### 24.4.2 概率函数结构

每条属性在结算时使用：

- `P(attr_up) = f(exp_current)`

其中：

- `exp_current` 为该属性当前经验值；
- `P(attr_up)` 为本次结算该属性增长 1 点的概率；
- `f` 受当前属性值区间影响（同样经验值在更高属性区间应得到更低概率）。
- 概率分段使用该属性的 `attribute_level` 判定阶梯区间。

已确认约束：

- **概率永远不会等于 100%**（只能逼近上限，不能到达 1.0）。
- **每一级属性对应的经验效率不同**：属性越高，同经验值带来的成功概率越低。
- **每 10 点 `attribute_level` 为一个阶梯区间**（如 0-9、10-19、20-29、30-39...），按区间切换函数参数。
- **单阶梯内函数形状**：前期增长慢，随后增长率逐步提升（前缓后快）。
- **阶梯快照口径**：同一结算事件内，所有判定均使用“结算前”的 `attribute_level` 取阶梯，不因本次其它属性先判定成功而改变阶梯。

### 24.4.3 判定结果

- **成功**：`attr += 1`，`exp = 0`；
- **失败**：`attr` 不变，`exp` 保留。

### 24.4.4 设计含义

- 属性经验数值越高，结算时成功概率越高；
- 玩家不需要追踪“固定经验阈值”，而是围绕“下一次结算成功率”做行为规划。

### 24.4.5 案例口径（你已确认）

在相同经验值下，不同属性段的成功概率不同：

- 当属性处于 `20 -> 21` 区间时，累计 `5000` 经验可对应约 `50%` 成功率；
- 当属性处于 `30 -> 31` 区间时，累计 `5000` 经验可对应约 `35%` 成功率。
- 当属性处于 `40 -> 41` 区间时，累计 `5000` 经验可对应约 `28%` 成功率。
- 当属性处于 `50 -> 51` 区间时，累计 `5000` 经验可对应约 `20%` 成功率。

该案例用于确认“同经验值在更高属性段概率下降”的设计方向；当前四个锚点可用于拟合首版分段概率曲线，后续再补充各阶梯完整参数。

### 24.4.6 首版分段函数草案（按四锚点校准）

> 本节为“先做出来看看”的实现草案，便于你审阅；不代表最终定稿。

#### A) 分段与符号

- 设当前属性值为 `S`，其阶梯索引为 `k = floor(S / 10)`。
- 设当前属性经验成长等级为 `L_attr`（即 `attribute_level`），其阶梯索引为 `k = floor(L_attr / 10)`。
- 每个阶梯（每 10 点）有一组参数：`P_cap(k)`、`E_scale(k)`。
- 结算时该属性当前经验为 `E`（即 `exp_current`）。

#### B) 概率函数（前缓后快 + 永不100%）

采用指数饱和函数（幂次 > 1）：

- `P_up(E, k) = P_cap(k) * (1 - exp(- (E / E_scale(k))^gamma ))`
- 建议 `gamma = 1.6`（满足“前期增长慢，后续增长率逐步提升”）。

性质：

- `E = 0` 时，`P_up = 0`；
- `E` 增加时，`P_up` 单调上升；
- 上限为 `P_cap(k)`，只要 `P_cap(k) < 1`，则概率永远不可能达到 100%。

#### C) 先给一版阶梯上限（可调）

- `20-29`：`P_cap = 0.80`
- `30-39`：`P_cap = 0.72`
- `40-49`：`P_cap = 0.64`
- `50-59`：`P_cap = 0.56`

说明：上限随阶梯下降，体现高属性段更难增长。

#### D) 用四个锚点反算 `E_scale`

锚点（你已确认）：

- `20 -> 21`：`E=5000` 时 `P=0.50`
- `30 -> 31`：`E=5000` 时 `P=0.35`
- `40 -> 41`：`E=5000` 时 `P=0.28`
- `50 -> 51`：`E=5000` 时 `P=0.20`

反算公式：

- `E_scale(k) = 5000 / ( -ln(1 - P_anchor(k) / P_cap(k)) )^(1/gamma)`

按 `gamma=1.6` 与上面 `P_cap` 反算得到一版参数：

- `20-29`：`E_scale ≈ 5060.86`
- `30-39`：`E_scale ≈ 6447.65`
- `40-49`：`E_scale ≈ 7063.27`
- `50-59`：`E_scale ≈ 8330.74`

这组参数在 `E=5000` 时可精确对齐四个锚点概率。

#### E) 结算与落地口径

- 每次“属性经验结算事件”触发时，对每个属性独立计算 `P_up(E, k)`。
- `rand < P_up`：该属性后天值 `+1`、`attribute_level +1`，并将该属性 `exp` 清零。
- 否则：属性不变，经验保留。
- 概率判定后若有任一属性增长，触发统一重算入口。
- 单次结算事件内每个属性只进行一次判定，禁止同一属性多次成功。

#### F) 后续可继续调的仅三项

- `gamma`：控制“前缓后快”的弯曲程度；
- `P_cap(k)`：控制每阶梯理论上限；
- 锚点表：继续补更多 `E=5000` 或其它经验点的目标概率。

#### F.1 阶梯扩展规则（已定：延伸到 1991-2000）

在已确认四个锚点基础上，后续阶梯按固定“难度放大倍数”扩展：

- 已确认锚点（`E=5000`）：
  - `20-29` -> `50%`
  - `30-39` -> `35%`
  - `40-49` -> `28%`
  - `50-59` -> `20%`
- 从 `60-69` 开始到 `1991-2000`，每升一个 10 点阶梯，统一使用同一放大倍数：
  - `difficulty_mult(next) = difficulty_mult(current) * 1.03`
- 其中 `50-59` 作为扩展起点，定义 `difficulty_mult(50-59)=1.0`。
- 终阶梯为 `1991-2000`；`2001+` 统一按 `1991-2000` 阶梯参数计算（不再继续放大）。

实现建议（与现有概率函数兼容）：

- 将放大倍数折算到经验尺度：
  - `E_scale(k) = E_scale(50-59) * (1.03 ^ step_from_50_to_k)`（仅对 `k >= 60-69`）
- 概率函数仍使用：
  - `P_up(E, k) = P_cap(k) * (1 - exp(- (E / E_scale(k))^gamma ))`
- 当 `k >= 1991-2000` 时，固定使用 `k=1991-2000` 的参数。
- 结算触发时机：由事件系统调用专用接口的频率决定。

#### G) 概率对照表（当前草案参数）

以下数值基于当前草案参数（`gamma=1.6` + 上述 `P_cap` 与 `E_scale`）：

| 属性阶梯 | 1000 exp | 3000 exp | 5000 exp | 8000 exp |
|---|---:|---:|---:|---:|
| `20-29` | 5.76% | 28.12% | 50.00% | 70.01% |
| `30-39` | 3.56% | 18.34% | 35.00% | 54.46% |
| `40-49` | 2.74% | 14.36% | 28.00% | 45.11% |

## 24.5 经验发放规则（待你逐条定）

- 事件是否发放、发放给哪条属性、发放多少，全部由配置项定义。
- **单次行为允许同时给多个属性经验**（同一行为可配置多个 `attr_id -> fixed_exp`）。
- **发放值为固定值**（不使用浮动区间、不使用随机值、不使用条件倍率修正）。
- **行为失败时不给属性经验**（仅成功行为发放）。
- 单次上限、重复衰减、tick 限速等规则后续按你的方案再补充。
- 当前不设 `exp` 硬上限。

## 24.6 与现有系统的关系

### 24.6.1 与五维后天汇总

- 属性经验不是替代项，而是“后天来源新通道”；
- 结算顺序上与装备、Buff、技能成长并列，统一进入后天汇总；
- 最终仍通过现有重算机制更新缓存衍生值。

### 24.6.2 与技能熟练度/等级

- 技能系统与属性经验系统相互独立；
- 熟练度不再提供后天五维；
- 属性经验是后天五维成长的独立奖励通道。

### 24.6.3 与平衡侧的硬约束

- 属性经验带来的后天增量应小于“同阶段技能成长主收益”，定位为长期底盘增益；
- 禁止出现“只刷 AttrEXP 不练技能也能碾压同阶段内容”的路径。

## 24.9a 运行时接口契约（供实现）

以下接口为首版建议契约，命名可按项目风格微调，但语义保持一致。

### 1) 发放属性经验（事件/互动/用物品调用）

- `grantAttributeExp(ownerId, grants, context)`

参数：

- `ownerId: string`（首版通常为 `player`）
- `grants: Array<{ attr_id, exp }>`（允许同次发放多属性，`exp` 为固定正整数）
- `context`（可选，记录来源：`event_kind/event_name/source_id` 供日志与调试）

行为：

- 仅执行“经验入账”，不做概率判定；
- 将各 `attr_id` 的 `exp` 累加到 `attribute_experience[attr_id].exp`；
- 同步累加 `total_gained`；
- 不触发属性重算。

返回：

- `{ ok: true, applied: Array<{ attr_id, exp_applied }> }`

### 2) 结算一次属性经验（专用事件调用）

- `settleAttributeExpOnce(ownerId, context)`

参数：

- `ownerId: string`
- `context`（可选，记录本次结算事件信息）

调用口径（已定）：

- 由一个**特殊事件**负责调用该接口；
- 每次调用该特殊事件时，等价于执行**一次**属性经验结算判定。
- **触发边界**：仅有显式调用 `settleAttributeExpOnce` 的事件才会触发属性经验结算；未调用该接口的其它事件一律不触发结算。

行为（强约束）：

- 读取“结算前快照”`attribute_level_snapshot`，据此为每个属性确定阶梯；
- 对五属性分别进行一次概率判定（同属性最多一次成功）；
- 成功：`attribute_level +1`、对应后天属性 `+1`、该属性 `exp=0`；
- 失败：属性不变，`exp` 保留；
- 若任一属性成功，调用统一重算入口（如 `recalcCharacterStats()`）。

返回：

- `{ ok: true, settled: [...] }`，每项建议包含：
  - `attr_id`
  - `exp_before`
  - `attribute_level_before`
  - `probability`
  - `success`
  - `exp_after`
  - `attribute_level_after`

### 3) 只读查询（UI/调试）

- `getAttributeExpState(ownerId)`：返回 `attribute_experience` 全量快照。
- `previewAttributeExpProbability(ownerId, attr_id)`：返回“按当前状态计算的下一次结算成功概率”（不修改状态）。

### 4) 错误处理约定

- 非法 `attr_id`：拒绝并记录 warning，不中断其它属性处理；
- 非法 `exp`（<=0 或非整数）：该条忽略并记录 warning；
- 任一条目失败不应导致整批崩溃（条目级容错）。

## 24.9b 实现加固约束（已定）

以下条目作为实现硬约束，用于保证“每次事件调用=一次结算判定”口径下的稳定性：

1. **同 tick 去重**
 - 同一 `ownerId` 在同一 tick 内，属性经验结算最多成功执行 1 次；
 - 若同 tick 收到重复调用，后续调用直接返回 `dedup_skipped=true`。

2. **重入保护**
 - `settleAttributeExpOnce` 执行中设置结算锁；
 - 锁未释放前再次进入同一 `ownerId` 结算，必须立即拒绝并记录调试日志（不抛致命错误）。

3. **时序固定**
 - 固定顺序为：`读取快照 -> 五属性判定 -> 批量落盘 -> 统一重算一次`；
 - 禁止边判定边重算，禁止同次结算中多次重算。

4. **快照阶梯口径**
 - 本次结算所有属性的阶梯索引，统一基于“结算前快照”中的 `attribute_level`；
 - 即使本次某属性成功 +1，也不影响本次其他属性的阶梯判定。

5. **发放来源白名单**
 - 仅允许已登记的事件调用 `grantAttributeExp`；
 - 未登记来源调用时，默认拒绝并写 warning（可配置为调试期报错）。

6. **调试日志开关**
 - 默认关闭详细日志；
 - 开启后记录：`tick`、`ownerId`、`attr_id`、`exp_before`、`attribute_level_before`、`probability`、`success`、`exp_after`、`attribute_level_after`。

7. **接口返回语义稳定**
 - 结算接口返回中应包含：`dedup_skipped`、`lock_skipped`、`any_success`；
 - 供事件系统与调试面板直接消费，避免外围再做二次推断。

- 任一属性经验升级后，后天五维变化可立即反映到衍生属性与战斗表现。
- 读入旧存档不报错，且默认值补全正确。
- 属性经验关闭（`enabled=false`）时，系统不产生副作用。
- 长时间挂机场景下，经验增长速率符合预期，不出现指数爆炸。
