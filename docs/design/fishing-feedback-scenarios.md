选取规则：每组避开最近2条，在其余候选中按事件标识稳定选择；不影响游戏随机序列。暂存最近48条事件选句，存读档复用已选文本。旧日志保存最终文本，超出选句缓存的历史只能读日志，不能重新提交旧事件生成文案。调用者使用“本次作业ID＋动作节点ID”作为事件标识，重画不生成新ID。同一事件同时选择多组时需按前述优先级合并，避免重复堆句。

## 共同规则

### 跨钓点、跨水域复用（用户确认）

整套“实际事件 → 可感知事实 → 文案 → 暂停/记录”的规则适用于所有后续水域，不是首塘专用脚本。分为共用规则、共用事实文案池、水域数据三层：

- 共用规则负责感知筛选、暂停去重、记录合并、近期避重与存读档稳定性，不以首塘ID或点位编号分支。
- 共用文案池描述轻点、受力、放线、固定受阻、失饵及残件等现象。同类可感知事实跨水域复用，不按隐藏鱼种或失败原因指定唯一句子。表达应丰富，但证据含义保持稳定，让玩家学习迹象而非背句子。
- 水域数据配置环境、障碍与鱼行为，引用共用预设产生事实；岸边植物、水色、环境声音等地方特色另配。特色文案同样需要事实和感知条件，不能覆盖共用动作语义或偷带诊断。
- 新水域先映射已有事实。只有出现现有事实无法表达、且有观察/判断价值的新现象时，才扩展事实类型、条件、文案池及校验，不复制整套逻辑或句库。
- 作业/事件ID必须跨水域唯一（例如水域ID＋作业序号＋节点ID）。换水域不重置同类文案避重记忆；过去已记录文本不因新水域或配置更新重写。
- 新增水域验收包括：引用存在、无首塘专属依赖、地方名词不串场、相同事实含义一致、不同原因不凭单句泄露、未知事实不因缺文案而用全知兜底。

当前已有候选文案配置及独立选取器；实际跨水域事件接入、统一存档宿主和界面反馈尚待实施验证。本节是复用契约，不把候选模块说成已经完成游戏集成。

### 事实与感知约束

1. 先有实际事件，再筛选可感知事实，最后选择描述。描述不反过来生成鱼口、伤痕或知识。
2. 相同措辞指同类现象，可有多个原因；禁止为了避免重复而把“固定阻力”换写成“主动拉扯”。
3. 单条迹象不保证唯一解释；玩家改变一个条件、进行一次实际动作后，结果应能支持或削弱猜想。无变化也可以是有效结果。
4. 影响玩家决策的显著差异必须有观察或试验途径；观察不到、长期也无法验证的隐藏差异应暂不启用，而不是另加诊断提示。
5. 水面视觉、手上触觉、声音、收回检查分别判断。黑暗不自动给触觉替代，触觉必须有实际受力且角色正在持竿；水下饵消失不能通过菜单、记录或快捷信息提前泄露。
6. 动作及消耗沿用动作表。反馈不额外扣tick，不赠送免费反复探查；抛出前预览、重开面板不重抽事件。
7. 下文“浮漂”“鱼钩”等为设计阅读用语；实际文案通过角色认识选择已知名称或可感知外形称呼。日常动作名称仍使用抛竿、提竿、收竿，不刻意绕口。

## 1. 一直没口：让玩家区分“没有看见”与“已检查到的状态”

| 后台事实/动作节点 | 当时能感知的事实 | 示例描述 | 后续可以验证什么 |
|---|---|---|---|
| 无接触；正常露漂；光线足够 | 浮漂稳定，没有可见新变化 | 浮漂稳定露在水面，等了一阵，没有明显变化。 | 收回检查饵是否还在；不证明水下无鱼 |
| 无接触；实际呈现为持续没入 | 看见浮漂没入且没有横移 | 浮漂缓缓没入，此后没有再露出来。 | 收回检查，再改变配重或位置对比；不直接说明原因 |
| 有未能被感知的接触；光线不足 | 看不清漂相 | 光线太暗，细小的漂动看不清。 | 不能告诉玩家刚才有鱼碰饵；也不说浮漂完全没动 |
| 收回后饵仍存在 | 能看到钩饵仍在 | 收回后，钩上的饵还在。 | 排除“饵已消失”；不能排除曾经试探 |
| 收回后饵不存在 | 钩上已空 | 收回检查，钩上的饵已经不见了。 | 尚不能分辨吃掉、脱落或腐败 |

对比经历：两次在不同可达点位都见到持续没漂，并且收回后钩饵仍在，玩家可以转而检查配装。第三次换配重，只有呈现规则确实变更且可见，才显示新的露漂状态。系统不补一句“配重现在合适了”，也不保证接下来上鱼。

首批不描述“咬痕”“饵被啄小”，因为目前固定份量实例没有对应残留痕迹状态。以后若增加，必须由事件产生并保存，不能靠文案猜测。

## 2. 提竿未中：区分没有挂住、曾短暂受力和固定阻挡

| 后台事实/动作节点 | 当时可反馈 | 收回后可反馈 | 不可推断 |
|---|---|---|---|
| 未入口，提竿后无持续负载 | 提起时没有感到持续拉扯。 | 饵、钩、线实际是否还在 | 不断言提早、饵不合适或水下没鱼 |
| 已入口但挂牢为0，且事件没有传递受力 | 同上，不强行与未入口写出区别 | 检查实际状态 | 隐藏原因可不同，证据不足时允许同描述 |
| 事件确有短暂受力后解除 | 竿梢压了一下，手上一紧，随后松开。 | 钩仍在、饵仍在/已消失，按实际状态 | 不直接断言鱼已脱钩 |
| 提竿时进入固定障碍受阻 | 线在同一方向绷住，提动时拉不回来。 | 尚未收回，不能报告草叶或钩尖状态 | 不直接判定是草、石头或大鱼 |

对比经历：小嘴目标的入口困难可以增加“可见试探但未产生持续拉扯”的经历；换小钩后可能出现入口和持续受力，但只有真实发生才描述。单次前后变化不授予“这鱼适合小钩”的确定知识；鱼种未知时不能把证据绑定为已认识鱼种的偏好。

“短暂受力”需要明确的事件事实，不能从“入口=true、挂牢=0”机械推断。没有这种事件支持时保留无持续拉扯的描述。

## 3. 中途失去拉扯：先描述失去联系，再检查损失

| 后台事实/动作节点 | 当时可反馈 | 收回/查看实物后 |
|---|---|---|
| 本步有明确持续拉力且进度增加 | 拉扯还在，但已经比刚才拉近了一些。 | 不公开进度值 |
| 渔轮实际发生放线，本步未拉近 | 绕线处仍在放线，没有把它拉近。 | 不诊断卸力档位错误 |
| 固定的两次已观察步骤均未拉近 | 连续两次收线，都没能拉近。 | 只有两次均有可感知依据才可这样总结 |
| 脱钩或水下线断，负载突然解除 | 竿梢弹回，手上的拉扯突然消失了。 | 水下原因先保持未知 |
| 收回检查确认钩、线完整 | 同上 | 钩和线都还在。 |
| 收回检查确认子线下游缺失 | 同上 | 末端短线和钩都不见了。称呼按认识替换 |
| 断点就在手边且当时看得清 | 实际看见断裂，可立即描述 | 不必为了神秘而隐藏眼前事实 |

对比经历：若实际保留下来的部件有可见磨损，检查可报告起毛；没有留下相应部件，就不能声称检查到那段已丢线的裂痕。玩家结合猛拉、放线和最终损失推测原因，系统不总结“承重不足”。

现有FS ended后面板可能直接回准备：接入时必须区分“后台已结束对抗”和“玩家是否已经回收、确认残件”。剩余钓组尚在水中时提供真实收回检查步骤；不能靠打开装配树立即揭晓下游损失。这是需修复的认知与流程边界，不是只改字符串。

## 4. 挂草受阻：用动作后的变化区分阻挡与活物拉扯

| 后台事实/动作节点 | 当时可反馈 | 限制 |
|---|---|---|
| 首次固定受阻 | 收到这里便拉不动了，阻力来自同一方向。 | 不公布障碍类别或缠绕档 |
| 放松后再拉，仍处同一障碍阶段 | 放松后再提，仍在相近的位置绷住。 | “相近”依据同一受阻事件，不模拟空间坐标 |
| 有鱼接触且方向/负载确实变化 | 拉扯一阵强、一阵弱，方向也变了。 | 只有负载变化则删去方向句；不因有鱼就虚构变化 |
| 活鱼已钻草，持续受阻同时仍有活动 | 线仍被牵住，其间又传来几下拉扯。 | 同时保留两个事实，不强制二选一 |
| 障碍解除 | 阻力松开，线又能收回了。 | 不直接说鱼跑了或草脱了 |
| 回收后确有保留草叶 | 钩上缠着几根细草。 | 由“带草”事件留下草叶事实，脱开不必然有草 |
| 回收后无可见附着物 | 钩上没有看见附着物。 | 不证明之前没有挂草 |

草叶只是本次工具上的检查事实，不自动生成背包材料物品。可存一个有界的附着物预设ID，回收确认后记录；清除、再次抛投如何处理需由规则明确，不永久累积无限碎片。

## 5. 最小配置与状态契约（拟定）

每条反馈配置：`id`、所需事实`requires`、感知通道`channel`、描述模板`text_id`、暂停策略`pause`、合并键`merge_key`、记录范围`record_scope`。每个可用事实/模板ID在加载时验证；有限条件匹配，不引入自由脚本。

示例：

```json
{
  "id": "retrieve_bait_absent",
  "requires": ["retrieve_completed", "hook_inspected", "bait_absent"],
  "channel": "inspection",
  "text_id": "fishing.feedback.bait_absent",
  "pause": "action_end",
  "merge_key": "cast_id:retrieve_bait",
  "record_scope": "cast"
}
```

三层数据必须分开：

- 后台事件事实：鱼/障碍/部件发生了什么。已确定事实随作业存档，阅读不重算。
- 本次可感知事实：根据当时光线、持竿、回收和认识筛选。存下当时观察，未来光线变好不回补过去未看见的细节。
- 玩家记录：只含已感知事实及当时可知的设置。不能把完整后台事件序列化后交给界面再隐藏部分文字。

优先级：当前必须处理的持续受阻/显著变化 → 动作结果 → 普通观察；同一事件阶段最多暂停一次。真实新变化可以再次暂停；重复无变化按合并键累积“仍然如此”，不重复堆屏。触觉和视觉同时存在可组合，冲突则检查事件来源，不随机选择一个结论。

新增状态保持少量枚举/ID：本次实际感知的负载变化、进度变化、受阻事件、可检查附着物、是否已回收确认。不保存运动轨迹；某现象暂无状态依据时先禁用对应模板。

## 6. 对比记录与界面

准备成本、真实损失保持。每次结束生成一条简短经历摘要，当前反馈仍占右栏，不新增常驻大面板。

例（仅在事实全部成立时）：

> 水草外侧；浮物比上次更靠近钩端。看见两次轻点；提竿未感到持续拉扯；收回后饵还在。

摘要记录点位、时间、当时已知钓组/设置变化和实际现象；“比上次”必须有可比的上一条记录。未知名称用当时外观，未测量不显示米数/磅数；没有比较基准则不写变化。

保留当前次与上一次摘要方便对照，历史记录数量由配置限制并翻页查看，不破坏单屏布局。配置变更不静默改写旧观察。摘要不生成“推荐小钩”“最佳配重”等结论。整理记录不支付新观察成本。

## 7. 验收标准与实施顺序

先补事件事实与感知筛选，再接文案、经历摘要，最后做同种子对比；不先扩写随机句库。

| 检查 | 通过条件 |
|---|---|
| 无活动/看不清 | 不把未见等同无鱼，不虚构漂静止 |
| 未入口/挂牢失败 | 无受力证据时允许同描述；有短暂受力才有相应句子 |
| 脱钩/断线 | 看不见断点时先同类松脱描述，实际检查后区分残件 |
| 草/鱼/鱼钻草 | 信号能组合；无草叶事件不报告草叶 |
| 改装对比 | 变化来自配置效果，不因更换动作本身生成肯定反馈 |
| 重画/暂停/读档 | 不抽新迹象、不多扣成本、不重弹已处理暂停 |
| 各信息入口 | 装配、背包、日志、摘要均不泄露水下隐藏状态 |
| 人工试玩 | 玩家能指出观察依据及下一次想验证的猜想；不要求猜中唯一后台原因 |

四条经历的具体文案为本次提案；机制效果需运行验证。反馈不能保证每次失败都有新发现，也不能把稀少样本总结成必然规律。
