# 装置材料解锁接入记录

2026-09-26，依据用户批准的 [材料点数清单](facility-unlock-point-list.md) 实施。

## 接入范围

- 烹饪台、制药台、制肥桶初修共用选材及结算；灶台供水替换旧对话献祭。旧对话不再扣材料。
- 仓库 16 个升级节点改用分类点数备料。基础仓库免费；路线发现、前置、剧情条件、施工 tick 与体力消耗保持原规则。备料完成后另行开始施工，不重复扣料。
- 原黄历标注格（居住点 7,11）改为工具台设施 NPC，日历、温度计分别解锁，没有本体费用或顺序依赖。地图暂用简易装置绘制，并非正式美术定稿。
- 日历解锁后恢复 HUD 年/日显示，原时钟保留。温度计解锁后在天气栏自动显示所在地图环境温度，取整至摄氏度；切图和 tick 更新，不需逐次测量。内部真实温度仍供系统读取，未改变计算精度。
- 湿度无运行时数据与玩法，按钮明确未开放，不收取材料。

## 认知与交互

使用原物品显示接口，未鉴定材料保持外观名称。按 2026-10-27 最新决定，每个修复部件默认显示配置顺序中的第一种适用基础材料，即使零库存也展开显示；带来高级替代材料后再显示其选项，成功投入过的材料继续保留。既未持有也未实际投入的其他材料整行隐藏，不泄露名称或替代材料数量。基础材料按类别分别为陶土、轻木板、废铁、椰棕纤维和机件，取该类别第一条可用配置，不按贡献点数排序；不适用的羊毛不参与选择。没有“检查用料”按钮；旧说明接口也遵守同一可见性规则。打开界面、查看说明、单纯持有或拖动滑条均不记录投入。旧 `repair_use_known` 用途标记不能证明实际投入，不作为显示或修复门槛。仓库与工具台保留各自的库存交付流程。

内部需求点数、贡献点数及进度百分比继续隐藏。普通设施按部件顺序修复，每次只向第一个未完成部件投入；修好后才开放下一部件。顶部是不可点击的顺序与状态列表，不再有“核对材料”页或任意切换部件的按钮。仓库和工具台继续使用各自的同页材料交付流程。

当前部件的材料数量精简为“持有/所需”，例如 `0/5`；分母为只使用该材料时完成剩余修复所需的件数，分子为实际可用库存，不是滑条选择量。材料可以替代、混用；各行不是必须同时满足的配方。投入件数用整数滑动条选择，旁边显示件数。基础材料和曾实际投入的零库存材料保留显示且滑条禁用；持有替代材料时，零库存基础材料也不会折叠到“其他可替代材料”中。不额外提示“随身无可用材料”。界面删去重复用途介绍、步骤计数、损坏描述和操作教程，也不显示“本次消耗”或“修补后还需”预览。

材料完全由玩家拖动滑条选择，移除“自动选料”和“清空选择”按钮；打开或进入下一部件均不自动选料。材料列表下面直接放“修复当前部件”或“先修补一部分”按钮，随滑条更新可用状态；反馈和下一部件留在同一页面，无额外核对或确认。重新打开时定位第一个未完成部件，滑条从零开始；已有修复进度不清除。需要另行施工的缝纫装配仍保留原施工步骤。

修复进度按项目独立保存。结算优先选择满足本类缺口且超额最少的整件组合，平手选件数更少者。不够时保留本次有效投入；多余整件留在原容器；已消耗整件的多余贡献不找零、不进入公共余额。

仓库可使用随身与仓内库存，遵守优先扣仓设置；封签仓内物品不纳入，携带附属部件的物品不拆作普通材料。羊毛不适合当前绑扎项目，暂不接受。普通设施使用随身材料。

## 存档与实现

共用 `FacilityUnlock`，项目配置见 `js/facility-unlock-config.js`，仓库需求沿用 `data/warehouse-upgrades.json` 的节点配置。原 `CookingRepair` / `CookingRepairPanel` 保留适配入口。

普通设施进度保存在 NPC 状态中，仓库备料进度保存在仓库自身的 `material_progress` 中，和既有存档共同持久化。仓库备料随仓库保留，不受角色用途知识重置影响。保留旧修复标记、厨房供水状态、仓库已完成升级及在建任务。新建角色清除新项目进度及观察工具解锁；读档不会重新收取费用。失败时恢复库存、仓库、标记以及厨房供水状态。

成功投入的材料用 `repair_material_used:<item_id>` 记录在 NPC 状态中，随角色存档保存，跨设施共用；新建角色时清除。只记录结算实际扣除的材料，不记录退回的整件；保存失败或中途扣料失败时一起回滚。旧档只有类别进度，不能反推具体材料，故不从旧进度或说明标记补写投入历史。

### 设施入口菜单（2026-10-27）

设施入口参照副本检查站的小窗口：340px 宽、标题栏右侧关闭、图标与文字的纵向操作列表，不再用横排按钮或“离开”占据操作位。灶台、卫生间、缝纫台、工具台、铸造台、制药台、制肥桶、农田、牧场、仓库和床铺共 11 个设施统一使用此布局；普通 NPC 与检查站保留原入口。识别 `npc.station.*` 或带有 `base_facility` 标签的设施，各自的修复条件、操作和反馈沿用现有逻辑。

后续视觉修订沿用此布局，外观与现有游戏面板统一：复用 `--ui-grain`、`--ui-weave`、`--ui-paper`、`--ui-metal` 及主题文字、边框和强调色，使用相同的衬线标题、按钮渐变、圆角与阴影，不保留检查站单独的纯绿色配色。

设施操作按完成状态互斥显示：制药台、铸造台、制肥桶未修好时仅提供修复操作，部分投入仍属于未完成；全部修好后替换为使用，已完成的修复入口不再显示。关闭修复窗口后返回入口并重新读取进度，读档后也按保存状态显示。主要操作放在“查看”前面，与灶台一致；查看入口保留。卫生间继续按修复前后切换为修复或饮水、洗澡；缝纫台只显示下一项装配或必要的测量，最终完成后显示使用。工具台在日历、温度计全部装好前显示“装配工具台”，之后显示“使用工具台”，尚未开放的湿度计不参与完成判定。农田与牧场继续按“恢复 → 管理”切换，单纯清理完成不能进入管理。床铺和仓库没有首次修复要求，继续直接提供睡觉、仓库操作。

灶台未修好时只显示“修复灶台”和“查看灶台”；修好后显示“使用灶台”，供水尚未接通时再显示“修复灶台供水”，完成的修复入口隐藏。查看在同窗显示简短设施状态，左上角返回；不走旧说明对话，不揭露隐藏替代材料或写入用途记录。关闭材料修复窗口后回到入口，按当前完成状态更新选项。菜单和查看不推进时间，使用烹饪面板沿用原来的时间结算。

原生与 Svelte 共用 `NPCSystem.menu` 状态，样式位于 `css/npc-menu.css`，图标复用检查站的 `RuinsUIIcons`。`tools/test-stove-menu.mjs` 覆盖初修、返回、供水修复、完成隐藏、真实烹饪入口、只读查看、关闭、移动阻断及远程调用限制，并在两种界面中逐一检查全部设施的标题、图标列表、关闭按钮和打开关闭无消耗；普通 NPC、缝纫和卫生间入口继续回归。

### 工具台统一页面（2026-09-26）

NPC 菜单统一使用“使用工具台”入口。左侧列出日历、温度计、湿度计及装配状态，右侧直接呈现所选工具的材料滑条与交付汇总。日历与温度计仍独立解锁、独立保存投入，沿用原 observation 解锁标记，兼容已有存档；只使用随身材料。装好后显示持续生效的用途，日期与温度继续自动显示在 HUD。湿度计仅显示尚未开放，不收取材料。

隔离验收页验证统一 NPC 入口、日历与温度计在同页依次装配、状态更新和温度 HUD 生效；验收使用模拟保存，不代表正式存档往返测试。实现为 `js/toolbench-panel.js` 与 `css/toolbench-panel.css`。

### 农场与牧场长期清理（2026-09-26）

正式入口对未恢复设施显示“恢复农场 / 恢复牧场”。各自累计清理 1000 tick，每 tick 基础消耗 3 体力，使用真实生存动作结算；天气修正、疲劳、饥渴与被动消耗照常生效，因此总实际体力消耗不只基础 3000。每次劳动推进真实世界时间，调度间隔沿用游戏挂机速度。暂停、关闭、页面隐藏或体力不足时停工，读档后必须主动继续。进度只用描述呈现，不显示累计 tick 或百分比。

农场清理入口、水源口与操作位置，保留完整灌溉拼图和未开垦田地；牧场清理轴心与机械臂活动范围，保留四区牧草。清理完成后转入共用材料修复：农场土石 6、木作 4；牧场金属 8、木作 8、机件 4。未修复前关闭生产和动物安置入口，完成后开放既有管理系统，不追加初次电力费。

实现为 `js/facility-labor.js` 与 `js/facility-labor-panel.js`。NPC 存档字段 `facility_labor:<id>`、`facility_cleaned:<id>`、`facility_restored:<id>` 分别记录劳动、清理完成与材料修复完成；`facility_labor_version` 标记迁移。旧存档已开垦、种植、安装模块或安置动物的设施保留开放，尚未使用的设施进入清理流程。保存失败则停工，保留本次内存中的已付劳动与世界变化，提示重试保存，不单独退款或倒退时间。
