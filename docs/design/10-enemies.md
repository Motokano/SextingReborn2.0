## 八（附）、敌人属性与构成（精简自主角）

敌人不沿用主角的完整属性面板，仅保留参与战斗结算所需的数据；**与主角共用同一套技能池**（招式体系，见下「攻击动作」）、命中、招架、减伤链与部位规则，但在数值来源上做精简与直接配置。

### 敌人保留与主角一致的部分

- **肢体方案**：与玩家相同，采用**头、胸、腹、左手、右手、左脚、右脚**七部位；命中部位权重、伤害类型微调系数 \(M_{\text{部位,类型}}\)、部位效果（眩晕、损毁失能等；09 中标「已废」的骨折/暂时失能旧条目不参与）与「八、身体部位与状态效果」一致，便于同一套伤害与损毁逻辑复用。**损毁值上限默认与主角共用**，但**敌人可单独配置** `body_part_destroy_max`（脆皮化，见下「敌人『损毁即血』」节）。**设计时需声明**：敌人的**攻击技能也装备在肢体上**（如左手、右手、左脚、右脚）；**肢体被毁则该肢体上的技能无法使用**，与主角“损毁肢体无法出招”的规则一致。**已损毁部位再受击**时损毁增加值均分到其余未损毁部位，与 **09-body-parts.md** 规则相同。

### 敌人专用配置（与主角的差异）

- **速度**：**直接配置整数**。不按身手/玩家步法 hub/装备计算，每个敌人类型在配置表中给定一个**速度值** \(V\)，直接参与先手、连击与命中率公式（与玩家速度比 \(r = V_{\text{攻}}/\max(V_{\text{防}},\varepsilon)\) 等，见「七、命中、招架与伤害流程」）。

- **内功与身体减伤**：不采用主角的「柔韧 → 基础防御」动态公式。为敌人**直接设计**两类减伤系数，在配置表中为每种敌人设定：
  - **内功减伤**（可选）：可理解为“内气护体”的百分比减伤，在减伤链中为**独立一层**：**卸力 → 护体 → 内功减伤 → 身体减伤 → 伤害类型微调**（内功减伤**不**等价于主角的防具减伤或护体层，三者位置不同）。
  - **身体减伤系数**：直接配置一个**身体减伤百分比**（或等价系数），在减伤链中替代主角的「基础防御（柔韧）」一步；即玩家命中敌人后，在卸力、护体（若有）、内功减伤之后，再乘以该身体减伤系数，再乘伤害类型微调 \(M_{\text{部位,类型}}\)。

- **招架**：规则与主角一致（命中后先判定招架，成功则本次不造成伤害；失败则先按卸力比例硬减伤，再进入护体→内功/防具→身体减伤→伤害类型微调）。**敌人招架不享受柔韧加成**：仅使用**基础招架几率**与**基础卸力比例**，不再乘以 \((1 + \text{系数} \times \text{柔韧})\)。两值在敌人配置表中直接给出，可设 0 表示不招架。  
- **与主角共用机制（已定）**：**招架相关 Buff**、**tick 末位移**、**后遗症 `effect_type`**（如驱散）等，**可与主角共用同一模板**（`data/buffs.json` / `post-effects.json` 中 **`mechanic_shared_with_enemy: true`** 语义）；敌人侧在攻击/受击上下文中挂载等价 **`post_effect_ids`** 或调用 **`melee_hit_enemy_defender`** 管线即可，无需复制一套独立 id（除非单条声明例外）。

- **攻击动作（2026-09 修订：敌我共用技能池）**：敌人**不单独设计一套技能树**——敌我共用**同一套技能池**（主角的技能/招式体系即该池子），每种敌人从池中**选招配 build**（哪些招、爱用哪些、连招倾向、用多狠），并可为极少数敌人（如精英/BOSS/剧情门槛敌人）保留**少量专属绝活**（池外招式）。每条动作/招式**装备在指定肢体上**（见上「肢体方案」），肢体损毁则无法使用该肢上的动作。设计立场：**敌人 = 给玩家出题**，解法不唯一（数值硬扛/机制巧解/绕开都算玩家的努力，均认可）；可存在当前阶段几乎无解、解法靠世界后续机制自然涌现的敌人（打不赢绕开即玩家选择）。敌人用池内招式时**威力口径是否随玩家公式（吃技能侧乘区）或维持敌人直接配置**，见下条原始伤害公式（待裁决）。

- **原始伤害公式（已定）**：敌人**不吃技能侧乘区**。敌人本击的**原始伤害 = 威力随机值 ×（暴击系数，若该动作/敌人配置了暴击）×（环境增伤，若配置）**，随后**直接进入减伤链**（命中 roll → 招架/卸力 → 护体 → 内功减伤 → 身体减伤 → 伤害类型微调）。敌人原始伤害**不乘**成数乘区 \(F_{\text{出力}}\)、不乘实战经验增伤、不乘招式熟练度/呼吸法威力等 \(W_{\text{coef}}\) 技能侧乘区；未配置暴击或环境字段时对应乘区按 1 处理。

- **气力条**：敌人**仅设计一条气力条**（与主角 **气力值** 概念同源、实现上为简化版战斗资源）。气力上限、每回合自然恢复量（或每 N 回合恢复）在敌人配置表中设定；释放需消耗气力的攻击动作时从该条扣除，不足则不可使用该动作。敌人**不沿用**主角的底气上限/行气/完整呼吸法体系；若某敌人需“护体”等，用上条**护体**与**内功减伤**等字段表达，而非照搬 `diqi` 规则。

- **护体**：**是否具备护体、护体减伤比例与护体容量**均可**按敌人具体设定**。若该敌人配置了护体，则与主角的底气护体在同一减伤链位置生效（卸力之后、内功/身体减伤之前——主角侧该层现为「激活盾」，见 **[37-equipment-modular-armor.md](37-equipment-modular-armor.md)**），护体被击破前按配置的减伤比例与容量结算；未配置则无护体层。

### 敌人掉落池

- **设计时提前定义**：每种敌人的**掉落池**在设计该敌人时**提前定义**，明确该敌人死亡后可掉落的**物品有哪些**。
- **每项物品的爆率**：掉落池中**每一项物品的爆率均需详细声明**（如概率、权重或等价规则）；实现时按该爆率在击杀该敌人时进行掉落判定。爆率的具体含义（独立概率、互斥多选一、权重抽样等）在配置表结构或全局规则中统一约定。
- **物品来源**：掉落池中的物品**在物品表中定义**；敌人配置中通过**物品 ID**（或等价引用）指向物品表内的条目，不重复定义物品属性。物品表见项目内物品/配置相关文档。
- **前提（D17 已裁决）**：敌人**默认可被击杀**——未配置 `body_part_destroy_max` 者与主角共用损毁上限，数值上可被磨死，损毁累积至死即进入击杀判定（语义见下「敌人『损毁即血』」节）。因此「击杀敌人后触发掉落」这一前提对默认敌人成立，为每种敌人预置掉落池的设计有效；真正不可杀者仅配置 `limbs_invulnerable` 的木桩/陪练（跳过损毁、不参与死亡判定，亦无掉落）。

### 摸尸与标记（掉落交互 · 2026-09 设计方向）

> 掉落分两层：**数据侧**（loot_table，敌人死亡按爆率结算出「掉了什么」）与**交互侧**（玩家面对尸体怎么拿走东西）。本节约定交互侧，数据侧见上「敌人掉落池」。

**核心前提：背包格子紧张**（下地牢带补给，空间是稀缺资源）。打死敌人面对尸体，玩家二选一：

1. **直接摸**：塔科夫式 loot 界面，**花 tick 逐个辨认物品、逐件拿取**。东西进背包、占格子，玩家当场在「留补给 vs 留战利品」之间取舍——空间自己扛。
2. **打标记（盲标）**：不摸、不占格子，给尸体打标。打完地牢后在入口 NPC 处领战利品，**NPC 抽成**（不是收钱，是直接收走一部分战利品作为手续费）。出地牢领货时**必须向玩家展示「被 NPC 收走了什么」**（结算界面对比：拿到什么 vs 被抽走什么）。

**设计要点**：
- **标记的独一无二好处（为什么值得用，不是摸尸的次优替代）**：
  - **死亡保险**：标记的战利品寄存在 NPC 处，玩家死在地牢里也能领到（只是被抽成）——摸尸摸到的东西在玩家身上，死了就全没；标记的东西死了还在。用抽成换一个「死了也不算白打」的保底，贴合死亡惩罚哲学。
  - **物流回流**：标记运走「有价值但不想背」的东西——典型是**电池**（敌人常见掉落、低价值、占格子，玩家要的是持续供电而不是囤电池）。标记 = 一条不占背包、不怕死的电池/物资回流通道，与电力系统互相喂活（电力需求→想寄存电池→标记被用；标记→稳定电池来源）。
  - **只寄存战利品、只有标记**：标记只作用于尸体掉落，不能主动寄存背包里的物品；不占背包格 = 不是因为它是"背包外挂"，是因为它本来就是「不经过背包」的物流口。
- **盲标是赌博**：标之前看不到内容，玩家对「这类敌人的期望价值 + 这趟的运气」下注，不是对单具尸体下注。
- **价值靠经验判断、但永远有意外**：掉落价值与敌人类型强绑定（杂兵掉杂货、精英/专属怪掉好货），让玩家学得会「高价值自己摸、低价值盲标」；但**偶尔**有违反经验的意外（普通地痞兜里揣着好东西）——这个「将信将疑」正是标记系统的燃料，让玩家永远不敢把话说死。
- **展示被抽走的**是情绪的落点：看到好东西被 NPC 收走 = 痛（早知道自己摸）；看到被收走的是破烂 = 松一口气（还好标了）。每次领货都是一次结果揭晓。
- **补给短缺时摸尸变求生**：长探索下补给不够，玩家开始摸平时不会摸的敌人，因为里面有水有吃的——摸尸的意义从「拿战利品」变成「现场补给」。

**扩展玩法（scav · 吃剩饭）**：分支玩法，玩家用**本体角色**随机被丢进一个地牢搬运尸体，里面可能有残余敌人。定位 = 新手救急 + 发财希望，围绕它可长出一条**殡葬馆**支线剧情（支线主题：末世里死人是常事，但不代表死亡不沉重——与整个世界的「把尸体当资源」形成反差）。细节后议，先保留方向。

### 敌人不包含的内容

- 无生存属性：无饱食、饮水、体力、精力、心情、定力、性能力、性别、营养、体温、体重等。
- 无基础属性与衍生：无筋骨/柔韧/呼吸/身手/专注及由此衍生的负重、学习效率等。
- 无技能栏：无生存/生活/战斗/特殊四条技能栏（技能等级/熟练度体系）；**招式来自共享技能池的选招配置**（build 式，见上「攻击动作」），气力条见上。
- 无装备系统：无多槽位装备与负重；内功/身体减伤、招架、速度等均在敌人配置表中直接给出。

### 实现约定（配置字段建议）

- 敌人类型表（或等价配置）建议字段：`speed`（速度，整数）、`parry_rate`（基础招架几率）、`parry_damage_reduce`（基础卸力比例）、`inner_damage_reduce`（内功减伤，如 0～1）、`body_damage_reduce`（身体减伤系数，如 0～1）、`qi_li_max`（气力上限，可与实现字段名 `enemy_qi_li_max` 等对齐）、`qi_li_regen_per_turn`（每回合气力恢复）；`has_shield`（是否有护体）、`shield_damage_reduce`（护体减伤比例）、`shield_capacity`（护体容量）；`body_part_destroy_max`（**可选**：七部位损毁上限，脆皮化「损毁即血」；未配置时与主角共用上限）；攻击动作列表（每条动作需指定**装备肢体**、**威力范围**（如 `power_min`/`power_max`，攻击时在范围内随机取整或浮点）、伤害类型、**气力消耗**、范围等）；**掉落池**（`loot_table` 或等价）：列表项为（**物品 ID**，**爆率**），物品 ID 引用物品表，爆率按全局约定填写（如 0～1 独立概率、或权重值等），设计时须为每项掉落明确声明爆率。接线/登记见文末「实现记录」。

### 敌人 AI（v1，已实现）

- **追击**：玩家进入 **`aggro_radius`**（默认 5 格，切比雪夫距离）→ 敌人每 **`move_interval_ticks`**（默认 1）向玩家走 1 步（**BFS 最短路径**，8 邻域；避开障碍、玩家格、其它敌人格、NPC 格、传送门格；贴墙/凹角可绕行）。
- **攻击**：贴脸（距离 ≤ 1）→ 每 tick 攻击一次，走与还击同一套**完整玩家受击结算**（命中 roll → CombatParry 肢位招架 → 卸力 → 后遗症 → 底气护体 → 最终伤害）。**去重**：若该敌人**本玩家动作内已经反击过**（你攻击它 → 反击算这一击；你做别的 → AI 主动打），AI 不再补刀——敌人**每玩家动作恰好行动 1 次**，无冷却数字、不叠加。
- **脱战**：距离 > **`leash_radius`**（默认 8）→ 脱战，走回出生点；回到出生点后待机（不巡逻）。
- **不参与**：`can_attack === false` 的敌人（训练木桩）不追击不攻击。
- 驱动/接线细节与 v1 已知边界见文末「实现记录」。

### 敌人「损毁即血」（v1，已实现）

敌人**无独立 HP**：七部位损毁即血量。每次命中 → 命中部位损毁 +Q（Q = 本次最终伤害，走 **09-body-parts「损毁写入」规则**：未损毁部位全加封顶、已损毁部位均分到未损毁部位、全毁则 Q 作废）。

- **死亡判定**：**致命区（头/胸/腹）任一损毁满 = 死亡**；或**七部位全毁 = 死亡**（兜底——打已毁部位时伤害均分，自然流向致命区，"磨死"路径存在）。
- **失能（不致死）**：**手毁**（左/右手任一条损毁满）→ 该肢攻击动作不可用（动作不再可选）；**腿毁**（左/右脚任一条损毁满）→ 敌人不再移动（追击/回巢全停，原地待机只保留攻击）。
- **部位上限与可击杀性（D17 已裁决）**：默认与主角共用上限（头 50/胸 100/腹 80/四肢 100）——数值上极耐打，但**并非机制豁免**：未配置 `body_part_destroy_max` 的敌人**同样参与死亡判定**，损毁持续累积、经均分自然流向致命区，数值上可被磨死——**默认敌人可被击杀**（共用上限只是打得更慢）；配置 **`body_part_destroy_max`** 后脆皮化、击杀更快。真正不可击杀的是配置 `limbs_invulnerable` 的木桩/陪练——**跳过损毁、不参与死亡判定**（打不坏）。
- **策略语义（招式 = 部位策略）**：玩家招式命中部位由 `hit_part_weights` 决定（如「流氓散手」戳眼偏头 60% / 踹膝偏腿 35%+35% / 推搡偏胸腹 40%+30%），因此**选招即选部位**——戳眼爆头速杀、踹膝断腿控场、推搡磨躯干稳定致死。
- 死亡判定时机/落地与实例状态等接线细节见文末「实现记录」。

### 敌人示例：「地痞」（`enemy.street_thug`）

作为**最简单的敌人**（首个敌对单位）示例，与 `11-skills` 8.3.6「流氓散手」同源定位——玩家新学的野路子拳脚，正好用来收拾这些街头混混。

- **定位**：玩家离开基地后的第一个练手对象。无招架、无减伤、无特殊机制，纯粹的「挨打+还手」，用于熟悉命中/招架/减伤链节奏。
- **配置**（`data/combat-enemies.json` → `enemy.street_thug`）：

| 字段 | 值 | 说明 |
|------|-----|------|
| `speed` | 2 | 玩家初始战斗速度约 1.05（身手 10 × 步法基础 1）时，玩家命中约 46%、地痞命中约 86%；地痞伤害低（2～6），前期可打赢 |
| `body_part_destroy_max` | 头 20 / 胸 28 / 腹 24 / 四肢 36 | 「损毁即血」部位上限（见下节）；玩家新角色每招命中损毁约 7～8.4（流氓散手 1 级、筋骨 10）：戳眼爆头约 3 拳命中死、推搡磨躯干约 4 拳、踹膝断腿约 5 拳废 |
| `parry_rate` / `parry_damage_reduce` | 0 / 0 | 不招架 |
| `inner_damage_reduce` / `body_damage_reduce` | 0 / 0 | 无任何减伤 |
| `can_attack` | `true` | 会还手（区别于训练木桩） |
| `qi_li_max` / `qi_li_regen_per_turn` | 0 / 0 | 气力条（本敌全招式零气耗，0 即可；气力系统已接线） |
| `aggro_radius` / `leash_radius` | 5 / 8 | 仇恨 5 格、脱战 8 格（敌人 AI v1） |
| `move_interval_ticks` | 1 | 每 tick 走 1 步；贴脸攻击无冷却（每 tick 一次，反击去重） |
| `actions` | 见下「招式表」 | 攻击动作列表（已实现）；未配置或气力不足时回退 `attack_damage_*` 通用还击 |

- **招式表（攻击动作列表，与「流氓散手」同源的低配版）**：

## 实现记录（敌人系统接线状态 · 截至 2026-05）

> 正文以上为敌人**设计层**（构成/配置/掉落池/语义）；本节为落地登记——接线函数、日志 key、运行时键与已知边界，供实现追溯，不重复正文语义。状态为登记当时（2026-05），此后敌人相关设计/接线见 44-dungeon-enemy-gradient 等较新文档。

- **攻击动作列表与敌人气力条（已接线）**：`actions[]`（`id` / `name_key` / `limb` / `power_min` / `power_max` / `damage_type` / `qi_cost` / 可选 `hit_part_weights`）与敌人气力条（`qi_li_max` / `qi_li_regen_per_turn`，每次还击前按回合恢复、动作扣气、气力不足不可选）接线于 `combat-enemies.js` `pickEnemyAction` / `sampleHitPartForAction` / 气力追踪，由 `combat-melee-resolve.js` `resolveEnemyVsPlayerAttack` 消费；未配 `actions` 或全部动作气力不足时回退 `attack_damage_*` 通用还击。
- **敌人 AI（已接线）**：每个世界 tick 驱动一次（`scene-app.js` `tickEnemiesAfterWorldTick`，挂于 `patchSurvivalTickForWorldSystemsOnce`）；决策在 `combat-enemies.js` `updateEnemyAI`（纯逻辑，可单测），场景落地（改 `map.enemies` 坐标、脏格重绘、走玩家受击管线）在 scene-app；反击去重标记为 `scene-app.js` `enemyCounterAttackFlags`。**已知边界（v1）**：无视线遮挡判定（直线距离即仇恨）；无巡逻游荡；敌人移动真实改写地图坐标（渲染/点击/攻击全链路一致）；同一 tick 先结算移动后结算攻击（贴脸当回合即可出手）；贴脸时原地待机（不绕圈，等下一个未反击的 tick 出手）；AI 攻击不校验玩家是否处于创建/剧情锁阶段（野外遭遇前玩家通常已完成创建）。
- **敌人「损毁即血」（已接线）**：`body_part_destroy_max` + 实例损毁状态 + 死亡队列 + 场景移除 + 肢体失能日志；肢体损毁联动已进 `pickEnemyAction`（手毁→动作禁用）与 `updateEnemyAI`（腿毁→移动停）。**死亡判定时机**：玩家对敌人攻击伤害结算后的损毁写入点（管线 `damage_stub` 与同速 `finalizeSimultaneousStrike`，`combat-pipeline.js` `applyDestroyToDefender`）；玩家先手分支若本击将敌人打死，跳过该敌人本交换的还击段（07「先击杀即避免再挨对方本击」），同速/敌先分支按原结构结算（同速允许同归）。**死亡落地**：`combat-enemies.js` 记死亡队列（实例键 `mapId|i{index}`），场景 `attackEnemy` 结算后 `drainEnemyKillQueue` 移除地图 `enemies[]` 实例 + 坐标脏格重绘 + 日志 `combat.log.enemy_killed`；肢体失能日志（部位被打满瞬间）经 `drainEnemyLimbLossQueue` 输出（手/躯干 `combat.log.enemy_limb_destroyed`、腿 `combat.log.enemy_limb_destroyed_leg`）。
