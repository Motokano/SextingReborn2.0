# 烹饪台初次修复：分类材料投入

已接入现有灶台设施 NPC。C 分步界面为选定方案；旧 repair_unlock 对话自动扣料事件已移除。供水升级不在此次迁移范围。

流程：查看灶台获得有来源的基础修补说明 → 修复灶台 → 灶体/支架选材 → 核对并修复，直接结算，无二次弹窗。材料不足时保存局部修补，关闭后可续修；只选材未提交不扣除。

点数只在后台使用。页面仅显示物品件数，工程状态由未修补、部分修补、部位完成的描述表达。超额投入只退回未使用的整件；已用单件内部余量不折成碎片，不产生公共余额。未使用物品实际留在原容器。

认识名称统一调用 InventoryEquipment.getDisplayName。修补用途由 repair_use_known:<item_id> 独立记录，不能按隐藏类别推定；首次查看说明明确介绍四种基础材料的修补用途，不改变语言、名称或其他属性认识。现有通用用途知识体系尚未完成，此记录限于修补。新说明使用独立事件 ID，旧档听过原修复介绍也能获得说明。

首轮沿用试作平衡值：土石需求10、木作需求8；陶土2、石灰石3、花岗岩5，轻木板4、青竹杆2、松木3。初次说明仅认识陶土、石灰石、轻木板、青竹杆用途，其余无知识来源暂不开放。数值为首轮试用值，不代表全物品体系已经配表。

持久化：cooking_base_repair_progress 与知识标记归 NPC 状态，复用 SaveSystem 对 npcDemo 的保存。完成沿用 cooking_base_station_unlocked；旧档已解锁保持可用。新档任务重置清除进度及知识。修复提交重新核验位置、库存、用途认识，失败撤回扣料与标记；排除带子部件的材料宿主。只使用随身有效容器，不自动取仓库物品。

验证：tools/test-cooking-repair.mjs 使用真实物品目录和 InventoryEquipment 验证扣料、局部进度、NPC 状态恢复、返还、失败回滚与旧解锁；另通过独立8018测试页验证真实 NPC 菜单、说明事件、面板和完成门控。该测试页使用独立库存及保存替身，不等于完整主游戏存档的浏览器验收。
