# 烹饪台初次修复：分类材料投入

已接入现有灶台设施 NPC。2026-10-27 用户修订交互：按顺序实际修复各部件，替代原 C 分步备料后统一核对的界面；旧 repair_unlock 对话自动扣料事件已移除。

流程：打开界面直接显示材料 → 拖动滑条给灶体与台基选材并直接修补 → 当前部件完成后开放支架与外框 → 直接修复后解锁。没有“检查用料”或“核对材料”步骤，部件进度不是可随意跳转的页签。材料不足时保存当前部件的局部修补，关闭后可续修；只选材未提交不扣除。

点数只在后台使用。材料行以“持有/所需”（例如 `0/5`）显示库存和单独使用的剩余需求，列表下面直接放修复按钮，删除“本次消耗”和“修补后还需”预览；不显示内部点数与百分比。工程状态由未修补、部分修补、部位完成的描述表达。超额投入只退回未使用的整件；已用单件内部余量不折成碎片，不产生公共余额。未使用物品实际留在原容器。

认识名称统一调用 InventoryEquipment.getDisplayName，不因显示修复材料而改变语言、名称或其他属性认识。每个部件默认显示配置顺序中的第一种适用基础材料：灶体与台基为陶土，支架与外框为轻木板；零库存时仍展开显示 `0/所需`。其余替代材料仅在当前持有或当前角色曾成功投入后显示，未知替代材料整行隐藏；用完的材料凭投入记录继续显示。不再依赖 repair_use_known:<item_id>；旧说明接口遵守相同显示规则，旧用途标记不等于投入记录。查看、持有、选择或失败提交均不记录使用。

首轮沿用试作平衡值：土石需求10、木作需求8；陶土2、石灰石3、花岗岩5，轻木板4、青竹杆2、松木3。数值为首轮试用值，不代表全物品体系已经配表。

持久化：cooking_base_repair_progress 与 repair_material_used:<item_id> 投入记录归 NPC 状态，复用 SaveSystem 对 npcDemo 的保存。投入记录跨设施共用，仅在成功结算实际消耗时写入，不记录退回材料；旧档不能从类别进度推断具体材料历史。完成沿用 cooking_base_station_unlocked；旧档已解锁保持可用。新档任务重置清除进度及知识。修复提交重新核验位置、库存、材料适用性与部件顺序，失败撤回扣料与投入记录；排除带子部件的材料宿主。只使用随身有效容器，不自动取仓库物品。

验证：tools/test-cooking-repair.mjs 使用真实物品目录和 InventoryEquipment 验证扣料、局部进度、NPC 状态恢复、返还、失败回滚与旧解锁；另通过独立8018测试页验证真实 NPC 菜单、说明事件、面板和完成门控。该测试页使用独立库存及保存替身，不等于完整主游戏存档的浏览器验收。
