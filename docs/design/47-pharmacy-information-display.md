# 制药信息清单、显示优先级与解锁阶段

> 关联：[制药系统](47-pharmacy-system.md)、[物品字段与信息显示](27-item-template-fields-inventory.md)。数值均为虚构游戏量纲。

## 1. 设计原则

**低等级也能做决定；高等级能解释原因、比较原料、优化投入。** 已解锁的信息必须给完整数值、单位、作用对象和条件，不以“强效”“恢复较多”替代实际反馈。

- 玩家自己的动作和已经发生的变化不设制药等级门：投入什么、消耗多少、剩余几次、身体正在怎样变化，始终可查。
- 台面提供的操作读数不设门：浓度预算、成盐需求与缺额、耗材、进度、失败原因。这是操作条件，不是鉴定奖励。
- 专业知识可分阶段解锁：成品作用 → 原料参数 → 配比贡献 → 成分辨识。不要把所有字段重新堆到某一个更高等级。
- 技能解锁不等于发现新配方，不揭示未接触材料，不预测未知相冲。未发现的信息不用真实名称、原始 ID 或风险条目数量旁路泄露。
- 语言技能继续控制物品命名和描述。成分列表、历史和制药台均调用同一命名接口；已可读的数字与操作状态不额外受语言门槛影响。
- “没有毒性”“无法鉴定毒性”“没有此字段”是三种状态，不能都显示为空或零。对有关且已知的零值明确显示，例如“配药净毒性 0”；不据此宣称绝对安全。

## 2. 显示优先级

优先级决定位置，不直接决定解锁等级。当前阻碍操作的原因置顶；没有阻碍时，成品药效先于操作细节。高级解释默认折叠，基础读数不埋进折叠区。

| 优先级 | 玩家当下的问题 | 放置位置 |
|---|---|---|
| P0 操作与异常 | 能不能用/做？差什么？现在发生了什么？ | 禁用按钮旁、进度区、身体状态区；有关的警示置顶 |
| P1 收益与代价 | 到底有什么作用？多久起效？有什么已知代价？ | 成品卡主体、配药结果摘要 |
| P2 选择与比较 | 换一种原料或剂型，哪里更好？ | 原料详情、配药参数区 |
| P3 原理与追溯 | 为什么产生这个结果？哪些投入在起作用？ | 可展开的配比分析、试药记录 |

警示只在适用时出现。外敷药不固定附带针具提示，无成瘾机制的药不固定附带药瘾警告；未知相冲不生成预警。一般卫生风险与当前具体缺少的耗材分开表述。

## 3. 解锁阶段建议

当前默认熟练度公式为 `1 + floor(成功次数 / 5,000,000 × 99)`，上限 100。已有技能条目的 1 级是入门；未掌握按 0 级处理。下表成功次数是按当前公式换算，**不是新增门槛，也不代表现实游玩时长**。

| 制药等级 | 阶段 | 新获得的能力 | 当前公式对应累计成功次数 |
|---|---|---|---:|
| 0 | 会操作、能观察 | 用量、耗时、使用条件、可见现象、台面预算、已发生的身体变化；物品原有功效描述仍按语言门槛显示 | 未掌握 |
| 1 | 看懂成品 | 完整实际药效、起效与计时、作用范围、当前已知的数值代价；可比较成品并预览配药的基础结果 | 技能建档后的入门级 |
| 2 | 看懂原料 | 原料药效族、药效点、毒性贡献、功能/抵消/助溶的区别 | 50,506 |
| 4 | 看懂配比 | 各原料贡献、抵消率与上限、增效和沉淀修正、距下一档差值 | 151,516 |
| 6 | 辨识与复盘 | 化学类别、外来混合药的成分鉴定、已尝试组合的专业解释 | 252,526 |

**0～1 级必须足以完整使用系统。** 2/4/6 级是长期专精奖励的暂定落点；以当前慢成长，不能指望它们解决前期可用性。若试玩表明专精反馈间隔仍太长，应另议知识获得节奏，不在显示代码里擅自改熟练度。6 级以后不继续扣留基本信息，后续成长奖励由工艺、配方和效率系统承担。

成品的“总结果”可以先于原料的“贡献过程”解锁：1 级知道这瓶药会怎样作用于自己，4 级才清楚各份原料如何合成这个结果。允许玩家通过反复对比推断规律，不把知识门槛当作防推理机制。

## 4. 完整信息清单（同优先级内按推荐显示顺序）

“基础结果”仅指现行规则允许显示的药效与常规毒性，不包括隐性相冲后果。所有预览都须明确是基础结果，不使用“全部风险已排除”等文案。

| 信息 | 优先级 | 解锁 | 展示口径与位置 |
|---|---|---|---|
| 当前能否使用/制作及具体原因 | P0 | 0 | 战斗、静止、目标部位、工具、材料、容量、正在加工；直接指出当前阻碍，不只灰按钮 |
| 剩余次数、每次消耗 | P0 | 0 | 实例剩余/最大次数；如“剩余 2/3 次，每次消耗 1 次”，不能只读模板总次数 |
| 使用方式、行动耗时 | P0 | 0 | 口服/外敷/吸入/注射；耗时读配置，外敷列选定部位；不混同起效延迟 |
| 针具与本次卫生条件 | P0 | 0 | 实际使用哪种器具、是否消耗一次性器具/消毒剂；缺失时说明本次卫生风险 |
| 本次投料、可用库存 | P0 | 0 | 物品可读名称 × 数量，已选/持有；自己投入的东西不因技能低而失忆 |
| 浓度占用、容量、剩余空间 | P0 | 0 | 单份占用 × 份数、总占用/上限、剩余或超出；条形图和数字同时展示 |
| 成盐需求、已有供给、缺额 | P0 | 0 | 台面读数；助剂单份供给与总供给。供给不足标明将出现沉淀，保留允许制作的既有规则 |
| 耗材与加工进度 | P0 | 0 | 固定配方材料、燃料、体力、加工 tick、剩余 tick、何时扣除；只显示该操作实际扣除的项目 |
| 沉淀等可见产物状态 | P0 | 0 | 成品与台面均显示；物理现象可见不代表知道其数值原因 |
| 使用后的状态与实际变化 | P0 | 0 | 待起效/生效中/结束、剩余计时；本 tick 各项实际增减、作用部位、当前已有毒性/药瘾/疼痛状态 |
| 制作与用药结果 | P0 | 0 | 成功产出及数量、失败产物、实际扣料；用药消耗、是否添加效果，失败原因可回看 |
| 原有功效描述 | P1 | 无制药门 | 继续受语言控制；不能把未接线的效果写成已有效的承诺 |
| 各项实际药效数值 | P1 | 1 | 体力/精力等每 tick 变化、属性加值、速度/收益倍率、抗性等逐项列出，正负效果一起显示 |
| 起效、持续与作用范围 | P1 | 1 | 即刻或延迟 N tick；按实际计时语义说明何时到期；全身/选定部位，部位药不写全身恢复 |
| 特殊作用与限制 | P1 | 1 | 镇痛是暂时压制疼痛影响，不是修复损毁；抗眩晕等写实际生效条件，不把属性标签当作功能完成 |
| 成品药效族、强度档位 | P1 | 1 | 作为药效摘要的辅助标签，不再占据主收益位置；弱效/常效/强效/纯品四档 |
| 重复使用与当前状态交互 | P1 | 1 | 本次哪些效果能添加、哪些重复效果不会追加；仍有消耗/毒性时明确列出，不能一律描述为刷新时长 |
| 常规数值代价 | P1 | 1 | 适用时列成瘾增量、基础净毒性、已知负向效果；区分该次增加与体内已有累积，不预告未知相冲 |
| 角色修正后的结果 | P1 | 1 | 主显示当前角色适用值，展开看基础值与免疫等修正；不能让玩家拿未修正值误判 |
| 原料用途与药效族 | P2 | 2 | 产药、功能、抵消、助溶分别说明；同一种物质的不同物品形态按各自字段解释 |
| 原料药效点与毒性贡献 | P2 | 2 | 每份与当前份数合计；原料药效点不等于恢复点，抵消成分不直接写成“体内毒性减少 N” |
| 已知固定配方成功率 | P2 | 1 | 显示当前角色、工艺与状态的实际成功率；未知配方不显示匹配与否、结果身份或概率以泄露答案 |
| 各药效族的贡献分解 | P3 | 4 | 每份贡献、份数、增效修正、沉淀修正、最终档位；展示运算结果，不由 UI 另写一套规则 |
| 毒性抵消分解 | P3 | 4 | 原始毒性、抵消贡献、实际抵消比例及上限、沉淀修正、最终净毒性；不要让负值看起来可以无限洗毒 |
| 档位差值与无额外收益的投入 | P3 | 4 | 距下一档的药效点；最高档标明封顶。若加料仍增加毒性/占用，同屏显示，不能称作完全无效 |
| 成分化学类别 | P3 | 6 | 对当前物品作专业分类；不附送相冲组合清单、解法或未见过的原料身份 |
| 非自制混合药成分与份数 | P3 | 6 | 仅当实例确有成分数据时鉴定；低级显示“成分未辨明”，不能猜测、补造或显示原始 ID |
| 自制投料与历史结果 | P3 | 0 记录；分层解释 | 自己投入的材料和已经观察到的现象常驻；族/数值/分解分别按 1/2/4/6 级开放，不倒推出未尝试组合 |

历史记录与成品鉴定是两件事：记得自己投了某包粉，不代表知道粉的专业类别；看到一次相冲，也不能自动获得整张相冲表。已有试药记录应注明当时组合与结果，不能用今天的配方参数改写过去的观测。

## 5. 三个界面的具体组织

### 5.1 成品悬浮卡 / 背包详情

顺序：名称与可见状态 → 当前使用障碍（若有）→ **主要收益与负向药效** → 起效、到期、作用范围 → 用法、耗时、剩余次数 → 适用的常规代价 → 折叠的成分与原理。

- 数值写成“药物效果：精力 +X/tick”“目标部位损毁 −Y/tick”，不用孤立的 `X`、`Y`。数值取实际效果数据，不在文案表手抄。
- 药效卡中的速率是药物贡献；身体面板中的净变化包含自然代谢、其他状态和上限截断，二者明确标注，不能要求数字必然相等。
- 不用“速率 × 模板持续 tick”伪造保证总恢复量。起效、实际有效 tick、属性上限等未核实前不展示总量；可计算的理论值必须注明条件。
- 低于 1 级：保留原有可读功效描述、用法与操作反馈，以一行“药效细节：制药 1 级可辨”合并锁定区，不铺满十几行问号。
- 风险与收益在同一主体区域。基础净毒性为 0 不能导出“无任何风险”，不能越过未知相冲的保密边界。

### 5.2 制药台

固定配方：投料与工艺 → 当前操作障碍 → 成本与进度 → 已知配方产出/成功率 → 已解锁的产物详情。盲配只显示投入、操作条件和过程；成功后再揭示配方与结果。

动态配药：投料清单 → **浓度和成盐双预算** → 1 级基础结果预览（各族实际作用、常规净毒性）→ 4 级贡献分解 → 制作按钮与实际成本。低等级同样能看到容量、缺额、沉淀和制作结果。

成盐沉淀继续按既有设计预告；隐性相冲继续留到使用后结算。即使 6 级，也不能调用相冲结算器生成未尝试组合的预警、致死预测或隐藏冲突数量。两类机制必须明确区分。

动态配药当前没有与固定制作相同的燃料、体力和加工计时链路；信息显示不能凭空补上成本。注射耗时属于使用阶段，不能拿来当配药加工时间。

### 5.3 身体状态与试药记录

身体状态优先显示当前生效/待生效效果、作用部位、剩余时间与本 tick 实际变化。药瘾、毒性、疼痛保留已有可见状态；等级不能把已经呈现的状态重新藏起来。

试药记录区分“制作结果”和“使用结果”，保留组合、份数、时间、当时角色相关状态、实际观察与当时可知的参数。当前 `pharmacy_compound_history` 只是基础数据来源，不能把未记录的信息伪装成旧历史；持久化与记录字段需在实现时补齐、验证。

## 6. 接入现有系统的边界

1. **复用现有字段门槛**：`item-field-display-rules.json` 承担字段等级，补显式排序/分组；不继续按字段名排序。操作类字段改为 0 级，其他按上表迁移。组合摘要采用结构化显示，不强行把每项运行态信息塞回物品模板。
2. **共用一份只读结果**：物品卡、制药台、状态面板共用药效与条件的展示数据；从实际 buff、配置、实例及配药结算结果读取。不得在 renderer 重算独立药理公式。相冲结果在进入预览数据前过滤，不能仅靠 CSS 隐藏。
3. **合并重复内容**：`module.pharmacy_medicine` 的静态用法/风险与字段规则只保留一份展示；通用风险改为适用条件驱动。原料列表不展示内部 item_id。
4. **实例优先**：剩余次数读实例 `charges`，容量、成分、沉淀等按实例与模板的有效值解析；成分名称统一走语言门槛。外来成分鉴定与自制投料记忆要有可靠来源依据，不能因为存在 `components` 就当作玩家已经知道。
5. **锁定状态合并且不泄密**：按知识层级显示一条锁定说明与所需等级；不透露隐藏字段的数量、符号、值或未发现名称。已知的 0 正常显示，缺失数据不当作 0。
6. **实际功能先核实**：`pharmacy_revive`、`pharmacy_bleeding_slow` 等已有数据但缺消费链路的效果，不因补 UI 就成为可用功能。接线或调整对应内容描述后，才能作为有效药效展示；玩家文案不出现开发占位说明。
7. **不顺便裁决历史矛盾**：旧文档存在失败不损主料与当前开工扣料的差异、三档与四档药效的差异、旧毒性参数等。实现说明按当前行为如实展示；涉及玩法改变另行定案，不把文档旧值直接复制进 UI。

## 7. 实施顺序与验收

先补 0～1 级完整反馈和统一排序，再接 2/4/6 级分析。这样早期玩家立即受益，后续知识奖励也有真实内容。

- 在 0/1/2/4/6 级及各门槛前一级检查物品卡、台面、历史的一致性；验证语言 0～4 级的名称/描述门槛，不能通过成分或 ID 旁路泄露。
- 检查一次性、多次使用、已消耗一次、动态混合药、沉淀产物、纯功能药、含负向效果药和没有已实现效果的条目。
- 对照真实结算核验药效速率、倍率、起效/到期、目标部位、免疫修正、重复使用、成瘾与毒性增量；不只测试字符串存在。
- 当前体力不足、器具缺失、浓度超限、成盐不足、战斗与静止限制都有对应反馈；允许继续的操作不能被 UI 擅自禁止。
- 已知配方可见结果与成功率，未知配方不可见；未知相冲在所有等级均无预告，也不通过历史空槽、错误提示、差值比较泄露。
- 制作前后核对真实扣料与产出；身体面板核对实际变化与上限截断；历史存读档后不丢失、不改写旧结果。
- 药效、用法、风险各显示一次；信息缺失、未解锁、已知零值分开；未解锁区不挤占主要收益与操作反馈。

本轮交付为上述设计清单和建议门槛；运行时代码、字段配置和玩家文案尚未修改。
