## 1 体验目标与已定边界

死亡要让玩家看清致命的一刻，经历一小段无法解释的感知，在醒来后知道本次失去了什么，并尽快继续行动。培养皿以相同的灯光轮廓、液体声音和外部人影建立辨识度，每次只呈现已定的一句台词，编号随死亡次数变化；不靠解说交代真相。

已定边界：

- 玩家头、胸、腹任一部位损毁达到实际生效上限即死亡；四肢损毁只影响行动，不单独触发死亡。
- 已到账潜能全部保留，只取消未结算的探索报酬。资料台等兴趣点已经发放的潜能属于已到账余额。
- 死亡失去全部随身装备、衣服口袋物品、背包及内容、拖拽载具及内容；水壶的词条、改造和剩余水随实例消失。死亡不生成可拾回的玩家装备包，也不补发新手装备。
- 家中仓库、生产存货、属性经验、招式熟练度、实战经验和已学制作知识保留。资料台本趟已学的配方也保留。
- 每门已习得战斗技能扣当前等级的10%，扣除量向下取整且至少1级，结果不低于0；生活技能不套用这项扣级。
- 复活时身体功能恢复，各部位仍保留上限50%的损毁；体力、底气、饱食、饮水恢复至各自上限50%，心情回到正常中心值。
- 保留短暂“地狱”过场，实际发生在克隆人培养皿中，再于藏身处醒来；固定皿内主观视角，暂不解释克隆。旧“到地狱与NPC对话”不再要求独立冥界地图或柜台NPC，外部人声可作为候选表现。遵循[01号](01-philosophy.md)的玩家感知视角和零教学原则。
- 培养空间位于藏身处地下，有50个用于主角备用身体的培养皿，使用后可继续培养补充；50是设施数量，不是累计复活次数上限。
- 50个培养皿与未来主线、存档系统有关，具体联系等待用户解释；当前按场景装饰处理，地下不开放，只在死亡后呈现皿内片段。
- 玩家死亡后先选择「回藏身处复活」，才开始培养皿演出；唯一台词为「变...求...0000X号，...准」，编号读取玩家死亡次数，台词结束后在藏身处复活。
- 敌人沿用共用面粉袋尸体棋子，主角保留现有128状态图册、125%显示比例和独立阴影。肢体失能与死亡分别处理，不恢复骨骼拆装。

## 2 死亡判定与结算边界

### 战斗死亡

用户已确认玩家与当前敌人采用相同的要害死亡条件：**头、胸、腹任一部位损毁达到该部位实际生效上限，即判定死亡。**四肢满损毁继续走现有失能规则；断腿、无法移动、眩晕和昏迷本身不触发死亡。玩家要害致死的运行接入仍待完成。

要害满损毁直接死亡，不增加濒死倒计时、救援窗口或额外即死概率，也不另加全身血条。

死亡只读取真实结算结果：

1. 先按现有防御和损毁分摊规则落地本次伤害，再检查致命条件。完全吸收、闪避与零损毁不触发战斗死亡。
2. 普通先后手交战中，致命段之后不再对死者执行后续连段或还击。致命之前已落地的伤害、消耗和永久成长保留。
3. 同速交战沿用双方试算、同时提交，允许同归于尽。必须完整提交同速组，再进入死亡流程，不能先清空玩家装备影响另一侧试算。
4. 一个结算组内多个原因同时成立，只生成一次死亡记录。主因取既有结算顺序中首个有效致命事件，其他原因可以留在内部记录，界面不轮番弹出多次死亡。

### 生存与药物死亡

饥饿、脱水、极端体温、药物毒性和精力击穿沿用各自现有条件，统一进入同一死亡流程。本稿不重配它们的阈值，也不把普通精力耗尽、体力耗尽或昏迷改成即死。

### 地牢中途关闭后的死亡

2026-11-02用户已确认：**玩家在地牢探险途中关闭游戏，再次打开直接按死亡结算。刷新、崩溃或系统关闭后重新加载同样处理；仅切后台且原游戏会话仍在不判死。**此前助手提出的原地续玩方案不采用。这是出征中断的系统性死亡，不要求角色先达到要害、生存或药物致死阈值。

仍沿用正常死亡损失与保留规则，不追加一套退出罚款。次数只增加一次，出征终止，未结算探索报酬作废，已标记尸体按既有回收规则交接。保存完成后显示死亡界面，等待玩家选择「回藏身处复活」，不能直接复活或自动跳过选择播放演出。判定与边界见第8节。

| 穿戴装备、随身备用装备、装备上的真实部件 | 连同实例状态一起消失，不拆成地面零件 |
| 装备背包、随身备用包及其完整内容树 | 按唯一实例归属清除，不遗漏关闭背包的 `backpack_contents` |
| 拖拽载具及其内容 | 删除拖拽实体、内容和绑定引用；不通过普通解绑把它留在地上 |
| 家仓、设施存货、已完成的生产结果 | 保留，死亡不把世界资产当作随身物品清空 |
| 死前已经放到普通地图地面的物品或背包 | 继续服从原地图保存与清理规则，不转成死亡掉落，不重置清理计时 |
| 地牢内未带走的地面物品和未标记尸体 | 随本次出征结束失去访问；不转移到新地牢或家仓 |
| 已标记并锁定分配的敌人尸体袋 | 沿用正式回收规则交接到本趟批次，死亡不重抽内容、抽成或重复建袋 |
| 入场门票及已经完成的消耗 | 保留已发生的消耗，不因死亡退票或退材料 |

当前旧式收纳字段只为兼容清理保留，玩家界面继续只使用衣服口袋、背包和载具名称。打开地面背包不会改变其所有权；死亡发生时未提交的拖拽取消，已成功提交的交换按实际归属处理。

### 技能与知识

战斗技能扣级公式为：`L = 0` 时不扣；`L > 0` 时扣 `max(1, floor(L × 0.10))`，最低降到0。例：120→108，19→18，1→0。

扣级先统一计算，再按[11号](11-skills.md)的技能依赖上限校验，最后重算属性。技能记录和已经知道的名称不因降到0而删除；实际可用招式和装配继续接受等级校验，不通过复活重新授予等级。

属性经验池、永久属性成长、肌肉解锁、实战经验、招式熟练度、已学配方及剧情知识不回退。首版建议已投入技能的自修进度 `study_exp` 保留绝对值，复活结算不自动触发升级；之后继续自修时沿正式规则处理。自修进度的保留是新增细则，待评价。

### 潜能保留与未结算报酬

**2026-11-02用户确认：已到账潜能全部保留，未结算探索报酬全部作废。**此规则与正式[地牢接入说明](dungeon-runtime-integration.md)及 `DungeonRuntime.die()` 的现有处理一致，覆盖此前资料台记录中“潜能沿用死亡损失”的模糊表述。

资料台等兴趣点已经成功发放的潜能保留，包括全配方掌握后以1500为基础并应用倍率的实际到账数。尚未撤离交图的探索报酬不发放，也不先计入余额再扣除；不能将已到账潜能清零或减半。

资料台已用状态不回退；不能通过死亡重复研究或重复领取同一张台的1500基础潜能。

### 投保边界

[03号](03-death-and-insurance.md)的投保、快照、代码与取回另作一阶段。首版死亡过场不展示未接入的保险按钮，不虚构赔付、领取凭证或赠送物品。后续保险只能读取同一死亡记录中关联的有效保单，避免另起一套死亡结算。

## 4 玩家经历的完整流程

**已确认的玩家流程：死亡 → 选择「回藏身处复活」 → 播放培养皿演出及台词 → 台词结束 → 在藏身处复活。**

结算与保存按这个顺序衔接：`实际致命结果 → 停止操作并保存死亡结算 → 死亡界面等待选择 → 玩家选择回藏身处复活 → 记录选择并开始演出 → 台词完成 → 保存复活状态 → 藏身处恢复操作`。

死亡一经确定，立即停止移动、自动寻路、连续攻击、调息、自修、睡眠、搜刮及正在执行的加工操作。关闭物品栏、对话和设施窗口，取消尚未提交的拖拽、领取和异步回调。自动关闭不额外收取开关窗口的世界tick；已完成的工作刻保留，未完成产物不发放，材料按对应作业已经提交的状态处理。

致命动作本身按原规则耗时。**死亡界面等待、培养皿演出、台词、查看损失和返回过渡都不推进世界tick。**玩家尚未选择、读字慢或切到后台不会多挨打、耗粮或改变家中生产进度。

死亡界面提供「回藏身处复活」选项，未选择前保持死亡状态，不自动播放培养皿演出或返回藏身处。选择只触发后续演出，死亡损失已在此前结算，不在点击时重复扣除。当前不扩展其他复活地点或方式。

培养皿阶段不开放地图行走、背包操作、交易和修炼。演出期间角色仍不可操作；台词完成后自动进入藏身处复活提交，不再要求另点「睁眼」或第二次确认复活。损失摘要仍可在醒来后显示，查看明细不耗世界tick。

## 5 培养皿中的地狱过场

### 与现有剧情的关系

以下是[30号剧情](30-story-outline-blackout.md)已经存在的内部设定：

- 主角是意识被提取后进入克隆体，并非原身体穿越。
- 存档对应当前身体的神经数据覆盖备用克隆体；死亡后旧体由林书瑶回收，新体在基地醒来。
- 林书瑶是驻场观测员，负责设备、旧体回收和《消耗报告》；UI来自她的设备。
- 主角从头到尾不知道自己被放进了节目，寻找归途和夺回自主权仍是主线动机。

[剧情展示页](../../tools/story-outline-zhetian.html)此前把地狱写为“数据传输几秒自循环碎片”。本次让这段断续感知有实际来源：备用体在培养皿中复苏时，主角短暂感知到液体、灯光和外面的人。无需把原身体运进培养皿救活，也不增加独立冥界或审判机制。

“地狱”作为内部设计称呼保留，游戏画面不贴出地狱招牌，不用旁白替玩家判断自己到了哪里。主角知道自己经历了异常，并不因此自动知道克隆、意识传输、外星节目或林书瑶的身份；玩家可以根据重复出现的细节自行起疑。

### 地下空间与50个培养皿的当前范围

培养装置位于主角日常生活的藏身处地下。同一个地下空间放置50个培养皿，用于主角的备用身体，使用后可继续培养补充；这部分保留为内部设定。用户已说明50个培养皿关系到后续主线，并需要与存档系统联动，具体解释由用户后续提供，不能自行补写剧情用途。

**当前这些培养皿只作场景装饰，地下装置不对玩家开放。**不做地下入口、可行走地图、设备操作、备用体清单、成熟倒计时、补充成本或轮换模拟；死亡不扣除一只装饰培养皿，不检查剩余身体数量，也不因数量不足阻止复活。此前培养周期、库存与补充流程不作为本轮设计或实施的前置条件。

当前只需支持死亡片段的视觉布置，不要求制作可通行的地下全图或检修、转运路线。此前助手提出的中央维护通道与两侧各25个培养位不作为本轮制作要求；场景构图仅解决皿内镜头实际能感知到的光线、液体和人影。

50个装置的设定保留，但死亡镜头局限于其中一个培养皿内部，只给液体、灯光和模糊人影，不拉远展示全景、数量或编号。其他设备最多作为无法辨认的光影层次候选。当前不开放探索、发现或操作地下设施的玩法，也不新增相关任务线索；后续主线如何使用它们等待用户补充。

### 镜头与声音首案

**镜头始终在培养液中，向容器外看。**不切到实验室全景，不展示整具克隆体、成排备用身体、操作面板或设备名称。地点已确定在藏身处地下；容器横卧还是直立、所在排位和外部造型仍待设计。先用视野边缘的折射与遮挡建立被包围的感觉，不预设大型立罐。

固定辨识点从盖章改为：战场声切断；低沉的液体声与少量气泡；一块被液体扭曲的灯光；模糊人影靠近，短暂遮住光。第一次可多停留一个轮廓变化，后续保留同一组视觉与声音。

光线可以偏灰绿或冷白，色相是试调，不做通屏刺眼闪光。轮廓和材质仍服从项目的手绘色块与深色外线；液体折射只作为独立表现层，不拉伸或改写现有人物原图。外部人影不能直接借用清晰可辨的林书瑶棋子、姓名标签或立绘暴露身份。

液体声按隔着容器听见的感觉处理，短促、不堆叠。台词采用下文唯一的一句，说话者、声音身份及具体呈现方式留待后续确定，不沿用此前助手写的短句或旁白。静音时，气泡、灯光和失焦变化仍须可读，台词完成判定不依赖是否开启声音。

### 分镜与触发顺序

流程顺序与单句台词已确认，具体秒数随这句话的呈现节奏再定。致命一击沿用正式战斗反馈；培养皿过场的起点是玩家选择「回藏身处复活」，不能从致命接触帧自动计时进入培养皿。

| 阶段 | 画面与声音 | 交互与结束条件 |
|---|---|---|
| 死亡结果 | 播完实际致命反馈，显示死亡界面 | 等待玩家选择「回藏身处复活」 |
| 玩家选择后 | 场景暗下，进入皿内视角，液体低响 | 只接受一次选择，不能重复开启演出 |
| 培养皿演出 | 气泡、失焦灯光、靠近的人影；保持既定信息边界 | 随演出进入台词阶段，主角不能操作 |
| 台词阶段 | 只呈现「变...求...{死亡次数编号}号，...准」 | 这一句结束后进入复活，不追加批准回复或其他台词 |
| 藏身处复活 | 过渡到藏身处安全位置，恢复正式界面 | 复活保存成功后恢复玩家操作 |

此前首次4～6秒、重复死亡2.4秒的总时长不再作为本版计时要求。单句的显示、停顿及快进方式留待表现设计，不设置多轮对话；当前不预设可直接跳过台词复活的按钮。选择复活的点击或长按不能穿透到演出台词或复活后的地图操作。

低动态模式取消镜头摇晃、明显波动折射和瞬间明暗冲击，保留缓慢气泡、柔和淡入淡出和灯光遮挡。后台暂停演出和台词推进，不追赶世界时间；恢复后继续当前阶段，不因后台现实时间流逝提前复活。

### 唯一台词与死亡次数编号

用户确定整段演出只需一句话，保留原文及停顿标记：

> 变...求...0000X号，...准

`0000X`是玩家累计死亡次数的显示占位，包含本次死亡，不是字面字母X。按五位、不足补前导零处理：第一次死亡显示「变...求...00001号，...准」，第十二次为「变...求...00012号，...准」。超过五位时保留完整数值，不截断或循环；编号与50个培养皿不做映射。

演出只读取死亡次数变量，不在播放、选择复活、续播或台词结束时增加次数。接入建议：新游戏计数从0开始，每次真实死亡随死亡结算成功保存时加1，并在本次死亡记录中固定该值。保存失败与其他结算一同回退，重复回调、刷新和读档续接同一次死亡不重复累加。变量名及存档接入见第8节；不另建跨存档的全局计数机制。

这一句结束后直接衔接藏身处复活，不补充「批准」回复、旁白、主角回应或醒来问候。字幕和语音形式、说话者与声音身份仍待确定。继续遵循皿内感知与信息边界，不解释克隆、备用体、节目或观测员身份，不凭死亡过场提前解锁剧情知识。

### 线索与信息边界

- 每次出现相同的灯光轮廓或人影动作，可供玩家自行辨认；不弹出“发现克隆秘密”。
- 增加线索只跟随已发生的剧情和玩家已经获得的知识，不按死亡次数自动解锁真相，也不要求玩家刷死亡推进主线。
- 《消耗报告》、备用体和观测员属于内部解释；若以后让玩家读到相关物件，须另设计实际可达的发现过程，不能直接印在死亡结算页上。
- 培养皿片段中不使用正常战斗HUD。回到基地后正常恢复界面，不提前照搬终局“面板逐层消失／重现”的整套揭示演出。
- 克隆复苏解释的是换身体，随身实物不会随意识一起传送。装备丢失沿既定玩法处理，不将装备消失称为神经数据传输损耗，也不新增取回原身体搜装备的入口。

### 损失记录

首版建议在藏身处醒来后显示简短损失摘要，沿正式界面的既有样式，可展开明细、直接收起或继续操作，不增加必须确认的第二个结算窗口。默认内容限于死因、随身损失摘要、发生变化的战斗技能及作废的未结算报酬。已到账潜能没有损失，不绘制余额扣除动画。

示例中的数值仅用于排版：

> 胸部重创
>
> 随身装备与物品已失去
>
> 基本拳脚　120 → 108
>
> 未结算探索报酬　8,420 → 0
>
> ［损失明细］　［收起］

物品按死亡前已知名称显示，不借损失清单鉴定物品。背包和内部物品分层列出，避免把背包汇总与内容再次相加造成重复计数。零损失条目不凑表；已标记回收袋若存在，按实际保存结果显示已交接数量。知识与永久成长无需每次刷一屏“保留”提示。

## 6 复活状态提案

返回已解锁的藏身处安全位置，优先床边的可站立格；床占1×2格，不能把角色放进床体或墙里。地图配置声明复活锚点，并检查通行、设施和单位占用；主锚点不可用时使用同室预设备用格。没有可用点时保持地狱界面并报告加载问题，不能随机投到地图外。

若剧情尚未解锁藏身处，建议由该剧情阶段声明安全返回点，不能通过死亡提前开仓、解锁设施或跳过剧情。此项与复活锚点一并配置和验收。

| 内容 | 复活值 | 状态 |
|---|---|---|
| 装备与随身容器 | 空，不调用新游戏初始化 | 既有规则 |
| 七部位损毁 | 去装备和扣技能后重新计算上限，再设为各自上限50%；整数向下取整，确保低于失能阈值 | 50%沿用既有规则；取整为细化提案 |
| 体力、底气、饱食、饮水 | 各自最终上限50% | 既有规则 |
| 心情 | 正常中心值 | 既有03规则；不另叠加旧稿未定的死亡扣心情 |
| 精力、疲劳 | 各自量表50% | 新增细则待评价，防止复活即因耗尽或疲劳继续失能 |
| 体温 | 角色标准体温 | 新增细则待评价 |
| 疼痛、眩晕、昏迷及致死倒计时 | 清零 | 新增细则待评价；疼痛已有复活清理接口 |
| 临时药效、战斗增益、护盾和当前气力条 | 结束当前临时状态；非战斗气力交回呼吸法初始化规则 | 新增细则待评价，不复制死亡前护盾 |
| 药物毒性 | 清零；成瘾累积保留并重新派生对应状态 | 新增细则待评价，不能用整个药物状态重置函数误清成瘾 |
| 体重、营养、脏污、长期身体成长 | 保留 | 新增恢复边界待评价 |
| 已知动作和技能配置 | 保留原配置意图，重新校验当前等级和装备；丢失实例绑定清空，不自动改绑其他物品 | 新增细则待评价 |

身体“恢复功能”不代表完全治愈，50%损毁仍需靠现有休养与药物恢复。返回后不追加限时无敌、免费装备或强制休息剧情。具体恢复值集中配置，避免两套界面各算一份。

培养皿设定不自动把复活改成满状态。新体为什么仍有50%损毁、如何承接长期体质和肌肉成长，需要后续补足叙事解释；可以研究复苏与适应过程，但不能先把“校准尚未完成”写成已定科学原理或把既有实际损毁偷偷改名为另一种数值。

培养装置位于藏身处地下，50个培养皿可继续培养补充作为背景保留。当前只需通过死亡片段衔接藏身处醒来，不模拟补充、地下转运、培养耗材、备用生命次数或真实时间等待。培养皿与后续主线、存档的关系等待用户说明，不把这些机制当作本轮演出的依赖，也不据此补定遮天后复苏规则或主角最终去向。

## 7 敌人死亡演出

敌人致命结果先落地，立即退出AI、攻击与占位判定；视觉允许短暂保留其最后一击的接触帧。首版建议在约0.15～0.30秒内淡去完整站立棋子，同格显现现有尸体袋和独立阴影。尸体交互在转换结束后开放，不再收一个额外“等死亡动画”的世界tick。

普通敌人和头目都沿用既有共用尸体袋及标记态，不新增各敌人的倒地人形图。正在处理的是死亡表现，不改变现有尸体内容生成、搜索、标记、抽成和回收规则。尸体袋当前使用v3素材，仍保留其待用户美术复核的原状态。

敌人死亡不播放玩家地狱过场，不让全场镜头为每个小敌人停顿。头目首版也不额外锁门、清场或强制抢镜。多个死亡分别依附实际事件，不能因表现合并而少掉尸体或重复生成。

主角死亡只在原画面短暂保留当前真实伤态，再转入暗场；不把“七部位全毁”的D127图当作统一死亡姿势，不横转站立PNG伪造倒地。若后续需要完整倒地动画，另做符合60号标准的素材方案，不挪用失能状态伪造额外断肢。

## 8 保存与两套界面接入约定

### 实时存档的责任边界

2026-11-02用户明确：存档码只用于换设备，后续交易完全离线，只交换交易码；不防范通过游戏外手段复制、替换或修改存档。本节保证正常游戏流程中死亡结算、死亡次数、演出与复活保存一致，不为外部复制增加联网检查、设备限制或额外死亡条件。

正常关闭、刷新、异常中断和保存失败仍属于恢复设计范围；重复操作不能再次扣除或增加死亡次数。运行补齐前不得把正常存档恢复能力说成已完成每次行动的可靠保存。交易与存档的边界分别见[13号](13-p2p-trading.md)与[14号](14-implementation.md)。

### 当前死亡保存与后续培养皿联动

本节只设计死亡结算、玩家选择、演出进度与复活的正常保存，保证刷新、连点或重复结束回调不重复扣除、也不重复复活。培养皿目前是装饰，不写入逐皿库存、成熟状态、备用体身份或与存档对应的编号。

用户已要求未来50个培养皿与存档系统联动，这项需求保留，具体含义等待后续主线说明；不预设一皿对应一个存档、50个存档槽、每次保存消耗身体或读档切换培养皿。也不为尚未明确的关系提前建立占位存档结构或迁移玩家数据。

### 地牢中途关闭的启动检查方案

**2026-11-02用户确认该方案及下表中的关闭、刷新／崩溃、后台、撤离与防重复边界。死亡保存失败停留在处理界面重试，不放回地牢继续操作。**当前为已确认设计，尚未修改运行代码。

核心做法是**保存尚未结束的出征，在重新进入游戏时处理**，不依赖关闭窗口时成功执行代码。现有`run.id`与`run.status`可作为识别基础；不额外维护一份容易与出征状态矛盾的独立死亡标志。

1. **进入地牢**：门票消耗、玩家位置、本次出征编号及`active`状态一并保存成功，再开放地牢操作。保存失败则未成功入场。
2. **探险期间**：持续保存已完成行动、当前携行物与出征进度。退出事件可补存，但不能成为判定中断的必要条件。
3. **正常撤离**：出征结束状态、返回位置、报酬及交接记录一并保存成功。之后重新进入不判死；未保存成功不能向玩家报告撤离完成。
4. **重新启动**：恢复完整进度后，先检查已有死亡记录；已死则续接原死亡阶段。只有未死且出征仍为`active`时，才按“出征中断”请求一次正常死亡结算。此时尚不开放地图、战斗、自动作业或交易操作。
5. **死亡提交**：以该出征编号关联唯一死亡记录，正常死亡扣除、次数加1、出征终止及`awaiting_revival`阶段一起保存。成功后显示死亡界面；保存失败停留在处理阶段重试，不以未处理状态进入游戏。
6. **再次关闭或重复启动**：已经提交死亡的同一趟出征不重复扣物、扣级或增加次数；停在复活选择或演出阶段的，继续既定阶段。

判定依据是最后成功保存的出征状态，不要求知道关窗的准确时间，也不补算离线战斗。实现不能把启动检查放入通用`applySnapshot`或`DungeonRuntime.restore`：原子保存失败回退也调用这些接口，回退本身不是退出游戏。建议在正常启动的`loadRealtime`完成后、恢复操作与自动推进前执行；保存时必须已退出载入锁。

已确认的事件边界：

| 情境 | 处理 |
|---|---|
| 地牢中关窗后重开 | 按用户方向执行一次死亡结算 |
| 刷新、崩溃、断电或系统回收后重新加载 | 统一视为出征中断，按死亡结算；不依赖区分主动与被动关闭 |
| 只切标签、最小化或切后台，原游戏会话仍在 | 不因失焦直接判死；若会话被系统回收而重新加载，再走启动检查 |
| 正常撤离已成功保存，或位于普通地图 | 不触发出征中断死亡 |
| 本次死亡已结算，停在复活选择或演出中 | 续接同一死亡，不再加一次 |

补充实施提案，未作为上述确认范围自动定稿：

| 情境 | 建议处理 |
|---|---|
| 同设备另开窗口而原会话仍运行 | 先处理同一存档的单窗口写入资格，不把第二窗口当作原玩家已退出 |
| 换设备导入含未结束出征的存档 | 建议同样结算中断死亡；存档码迁移不授予地牢中途续玩的例外 |

页面历史缓存恢复也须按会话是否真正离开区分，不能因跳过重新初始化而绕过入口检查；单纯切后台与结束会话分别处理。补充提案在实现时与既定规则衔接，当前未修改运行行为。

### 同一笔死亡只结算一次

新增一份共享死亡记录，最少包括唯一死亡编号、本次死亡对应的累计次数、原因、地点、真实结算组、死亡前已知信息、损失前后值、出征状态以及当前阶段。唯一死亡编号用于防重复，台词里的需求编号使用累计死亡次数，两者不要混用。阶段建议为：`awaiting_revival`（死亡已结算，等待选择）、`revival_scene`（已选择，播放演出与台词）、`revived`（台词已完成并已在藏身处复活）。渲染器只读这份记录，不在演出结束回调里扣物品或技能。

累计死亡次数建议字段名为`deathCount`，随正式角色存档保存；演出读取本次死亡记录固定的次数，以`String(deathCount).padStart(5, '0')`格式化。当前尚未接入该计数，旧档缺失时不从技能损失或培养皿数量猜测历史死亡次数，迁移基线在接入时明确。

死亡提交一次性保存：致命动作结果、随身物品清理、技能变化、潜能处理、出征终止、标记袋交接、死亡次数加1及等待选择的死亡记录。选择「回藏身处复活」时保存已选择的演出阶段，此时不恢复资源、不解除死亡状态、不允许在藏身处行动。台词完成后，才一次性保存恢复值、藏身处位置、解除死亡状态和复活阶段。各次提交使用正式存档的原子保存路径，不另建一份死亡专用浏览器存储。

死亡记录以真实结算组为边界。在同速组提交完之前，`Survival.setDead()`不能直接触发清包和出征结束；普通逐段结算则要及时阻止死者的后续行动。所有致死入口只请求同一编排器处理。

### 刷新和失败

| 情境 | 恢复方式 |
|---|---|
| 地牢探险中关闭后重新打开，未结束出征尚无死亡记录 | 按本节启动检查提交一次死亡，再等待选择复活 |
| 死亡已保存，但尚未选择复活时刷新或退出 | 回到死亡界面等待选择，不自动播放演出，不重复扣除 |
| 已选择复活，在演出或台词中刷新或退出 | 恢复同一死亡的演出阶段，按已保存进度衔接台词；不再次要求选择，不直接变成已复活 |
| 连点「回藏身处复活」或两套界面同时收到选择 | 同一个死亡编号只开启一次演出 |
| 台词结束回调重复触发 | 同一个死亡编号只执行一次复活提交 |
| 复活已保存，淡入尚未播放完 | 读档后处于藏身处，不再返回地狱 |
| 死亡保存失败 | 撤回本次未提交变更，保留冻结状态及同一待提交结果；只提供重试保存，不能让角色携带半清空物品继续行动 |
| 复活选择保存失败 | 留在死亡界面，允许重试选择，不提前开始演出 |
| 台词结束后的复活保存失败 | 留在演出完成状态重试保存，不重播台词、不再次扣技能或重复发放恢复资源 |
| 旧档只有 `isDead`，没有死亡记录 | 按明确的存档版本识别已经执行过的清包步骤，建立一次性迁移记录；不猜测、不重复补扣不明惩罚 |
| 载入普通地图的正常旧档 | 不触发死亡，不补发装备，不重置知识；含未结束地牢的旧档按启动检查及明确的兼容范围处理 |

保存失败后的重试必须复用已经确定的结果、随机掉落和尸体分配，不能重掷致命攻击。持久保证以最后一次成功写入为边界，不能声称未写入磁盘的状态可以跨强制退出恢复。

## 9 实施顺序与验收

死亡判定与潜能规则已确认。建议下一阶段做隔离存档的完整演出试玩，再接入正式运行。试玩应能切换战斗致命、脱水、同归于尽、重复死亡和保存失败；只读正式美术与规则，禁止读写玩家存档。

美术首轮只制作死亡演出所需的皿内主观构图、液体与气泡、模糊外部灯光和人影，不制作值班室资产、可探索地下地图或50套独立培养状态。二维过场延续[77号](77-grid-scene-art-standard.md)的画风，独立于棋盘占格。清晰人形新增时遵循[60号](60-pawn-quality-standard.md)，不恢复骨骼拆装。验收覆盖过场实际显示尺寸、返回棋盘的125%主角、窄屏、静音与低动态模式。本稿没有生成或批准新素材。

正式接入验收覆盖：

- 致命阈值前后、四肢失能仍存活、昏迷可继续原流程；生存与药物原因都能到达地狱和复活。
- 先手致命取消还击、连段致命不补打、同速同归完整提交、多原因只结算一次。
- 装备包和关闭包内容、组合物品、水壶、拖拽载具完整清除；家仓、已放地面包、生产存货、知识和永久成长符合归属表。
- 等级120、19、1、0的扣除，技能依赖夹紧，自修进度和降级后装配；已到账潜能原数保留，未结算探索报酬不发放，资料台潜能与其他来源一视同仁。
- 死亡不发探索结算，已标记尸体继续回收且不重抽，已用资料台不再奖励，新出征不复用死亡楼层。
- 死亡、选择和复活各次保存失败，各阶段刷新与退出续读，重复选择及台词结束回调，长按不穿透，旧死亡档迁移。
- 地牢入场／撤离保存失败，探险中关闭／刷新／崩溃后重启判死，仅切后台不判死，同一出征连续重启只结算一次，死亡阶段重进不再加次数，内部快照回退不触发中断死亡；多窗口和换设备补充边界在接入时核对。
- 未选择前保持死亡界面；选择后才开始培养皿演出；台词未结束不复活；台词结束后直接在藏身处复活，不追加第二次确认按钮。
- 整段只有已定一句台词；次数1、12、999999、1000000显示正确，编号包含本次死亡；多个致死原因、重复选择／回调、读档续播和保存失败重试不重复累计，不改变同一次演出的编号。
- 死亡等待、演出与台词阶段不耗世界tick；生产与腐坏不因现实演出时长额外推进；死亡自动关闭面板不追加开关费用。
- 复活后安全落点、无默认装备、身体功能恢复且损毁为50%、不会因旧致死计时立即再次死亡。
- 两套正式界面、正常与窄屏、后台恢复、静音、低动态模式；敌人尸体交互和现有战斗特效不被截断或重复播放。
- 培养皿全程保持皿内视角，无克隆或节目文字、设备诊断HUD、全景、明确身份标签；损失摘要在返回后显示，线索不由死亡次数自动解锁。
- 地下装置无入口或交互；培养皿不建立库存、消耗或成熟状态，不凭50个装置限制复活或推定50个存档槽。正常死亡保存与后续主线存档联动分清范围。
