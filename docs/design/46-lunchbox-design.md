> 来源：46 口述（新思路，以本稿为准）＋ 旧设定补充（`43-food-digestion.md` §六、`48-meal-balance-attribute-exp.md` §八 / k75）

## 设计目标

- 饭盒是**手动烹饪的福利**：只有手动烹饪才有装饭盒的选项，自动烹饪没有。
- 让玩家有意识地配齐一餐（主食+荤+素），饭盒 = 便携的"一餐打包"。

## 核心规则（新思路）

- 饭盒是挂在灶台上的挂件（类似厨房灶台的挂件）。
- **获取**：空饭盒是道具，**走配方、从制作台制作**；分小/标准/大三档（具体配方与解锁节奏待配，档位见旧设定容量升级线）。
- 玩家可自选挂几个，**每个灶台最多同时挂 3 个**（各灶台独立计算——藏身处主台与野外临时台各挂各的）。
- 挂好饭盒、开始**手动烹饪**时：
  - 每烹饪完成一份料理：**根据该菜品的属性提示它占几个格子**，弹提示由玩家**选择要不要装盒、装进哪个挂载盒**（提示该菜占 X 格、目标盒剩余 Y 格）；**装不下的盒显示但置灰（不可选）**，不弹额外拒绝提示（2026-09-04 拍板，UI 层定稿）；
  - 装盒的"一部分"是**额外生成**的，**不影响该份料理的正常出产**（不扣成品，等于附赠一份可装盒的量）。
  - （早前口述"做一份只填一格"为简化说法，以本条为准：占格数由菜属性决定，可占多格。）
- **装盒时机**：只能**在饭盒安装在灶台上（挂载中）**的时候装；取下后（携带/丢弃期间）不能再往里装；**只能装挂载后新出锅的菜**（中途才挂上的盒不能补装此前已出锅的菜）。

## 食用行为（满盒 / 半盒通用）

- **取下**：可**随时取下**，不必装满——半盒（未满）也可取下携带；想继续攒满就把盒留在灶台上（挂载状态持久化，不丢）。
- **挂回必须清空**：拿下来的饭盒要再挂回灶台，**必须先清空**（吃光或倒掉 → 空盒）——只有**空盒**可以挂载；带内容的盒不提供"搬进度挂回"。
- **吃饭盒 = 一次吃光盒内现存全部菜**（无论满盒半盒）：
  - 吃下盒内每一道菜、享有各自 buff；
  - **结算方式：逐菜多次结算**（相当于连续吃了盒内每道菜，每道菜各走一遍普通食用逻辑）；
  - 吃光后**空盒返还**（可再挂灶台装盒）；
  - **均衡/营养价值由"吃下后盒内菜的构成"决定**（44 § 复用，扫描活性消化构成）——满盒通常能配齐主食+荤+素 = 完整的"一餐打包"；半盒内容少，往往只有维持。是否均衡不看满/半，只看构成；
  - 食用耗时 **5 tick**（固定，与盒内内容多少无关）；
  - **不可放入快捷栏**；战斗中能否食用**不做额外限制**（不特判禁用，按常规物品规则即可）。
- **携带**：任何非空饭盒（半盒/满盒）都可携带在身上，作为物品有"食用"选项。
- **倒掉**：可选择倒掉 → **清空整个饭盒**（不是倒一格）；清空后**空盒返还**，可再次挂灶台使用。
- **丢弃**：可丢弃在地上，正常走物品规则，**但要记录饭盒的状态**（内部内容随物品走）。

## 物品状态与流通

> 数据结构模型已确认（对话拍板：一份数据 + 格子引用）；空盒复用/整盒腐败/丢弃拾取为推导结论，仍可随时调整。

**流通形态：空盒 ⇄ 非空盒（半盒 / 满盒同构）**
- 饭盒是带容量与内容列表的容器物品：**内容为空 = 空盒**（可挂灶台）；**内容 1 格 ~ 满 = 非空盒**（可携带/食用/倒掉/丢弃）。半盒与满盒没有本质区别，只差装了多少。
- **装盒只发生在灶台挂载中**（#4）：非空盒取下后不能再装——要么吃光（空盒返还）、要么倒掉；想继续攒满就把盒留在灶台上。**拿下来的盒要再挂回，必须先清空为空盒**（只有空盒可挂载）。**挂载中的盒也可直接在灶台倒掉清空**（腾挂位，不须先取下）。
- **持久化**：灶台挂载状态（挂了哪些盒 + 各自的装盒进度）**随灶台保存**，下线/重进保留；背包/地面中的非空盒同样按实例状态保存。

**空盒可复用**
- "倒掉 = 清空整盒"的措辞表明清空 ≠ 销毁盒：吃饭盒（吃光盒内全部内容）或倒掉后，**空盒返还**为容器道具，可再挂灶台装盒。
- （若意图是"一次性饭盒"，需推翻本条。）

**数据结构：记录列表（真源）＋ 格子视图（显示/引用）**

以 4 格大盒装 [宫保鸡丁(1 格), 佛跳墙盛宴(3 格)] 为例：

```text
装盒记录列表（真数据，每道菜一条，无论占几格）：
  [0] { item_id: 宫保鸡丁,  slots_taken: 1 }
  [1] { item_id: 佛跳墙盛宴, slots_taken: 3 }

格子视图（容量格数组，只存"记录索引"，不存数据本体）：
  格0 → 记录[0]
  格1 → 记录[1]   ← 大菜只存在一条记录，多格共用同一引用
  格2 → 记录[1]
  格3 → 记录[1]
```

- **占多格的菜只存一条记录**，多个格子引用同一索引——无重复拷贝，逐菜结算天然不会把大菜算多次。
- 剩余空间 = `容量 − Σ slots_taken`（装盒先查余量，装不下即拒绝）。
- 装盒 = 列表尾部 push 一条；食用/倒掉/丢弃 = 对**整份列表**操作（无逐格操作，格子视图自动跟随）。
- 对应旧字段 `packed_meal_items` 升级为此结构（原为扁平 item_id 列表）。
- 目前整盒统一腐败 → 记录内暂不需要逐菜腐败字段；将来若做逐菜保鲜差异，在记录里加字段即可，模型不塌。

**饭盒实例状态**（流通时携带；内容为空 ~ 满均可）

| 字段 | 内容 |
|---|---|
| 盒档 | 小 / 标准 / 大（容量 2/3/4）——若三档为不同 item_id 可免记 |
| 装盒记录列表 | `packed_meal_items`：`[{ item_id, slots_taken }, …]`（可为空 → 空盒） |
| 腐败计时 | **整盒统一、自第一份装盒起算**（挂载中与流通中均持续计时）：由盒型决定腐速（普通盒照常腐败 / 保温密封高级盒保鲜），不为盒内单菜单独计时；**盒腐坏 = 整盒内容一并腐坏** |
| ~~开封 / 来源~~ | **不需要**：吃饭盒 = 一次吃光盒内全部，不存在吃一半；来源灶台无意义 |

**丢弃与拾取（#8）**
- 丢弃：带内容的饭盒（半盒/满盒）作为**带内部状态的物品实例**落地，地上保留完整盒内内容（记录列表随物品走）；
- 拾取：任何人捡起 → 还原为完整状态（这正是"记录状态"的意义）；
- 归属：跟随现有地上物品通用规则（无主物、谁都能捡，不做特殊所有权）。

**默认处理项（推导默认，未逐条拍板；如无异议即生效）**
- **空盒可堆叠**（无状态道具）；**非空盒（半/满）各占背包 1 格、不可堆叠**（带状态物品，跟随现有规则）。
- UI：非空盒显示"内含 X/Y 格"，非空即可食用。
- 重复食用的"刷新" = 把该 buff 时长**重置为满时长**（不叠层已定，自然推得）。
- 整盒腐坏后 → 跟随现有腐败食物食用规则（腐坏盒照常可吃但效果打折/不可吃，按现有口径，不特判）。
- 5 tick 食用动作可否被打断（移动/战斗）→ 跟随现有食用动作规则。
- 挂/取饭盒动作即时、不额外耗时（跟随家具交互惯例）。
- **食用须先取下**（挂载中的盒是"装填中"状态，不提供直接食用；要清空可在灶台直接倒掉）。

## 旧设定补充（43 §六 / 44 §八，k75）

以下为旧设定，供对齐；与新思路冲突处见"差异对照"。

- **容量升级线**：饭盒按容量分档 —— 小 2 格 → 标准 3 格（主食+荤+素模板）→ 大 4 格（塞 4 格大菜）。→ 可回应 46 口述"一个饭盒有几格"。
- **整数占格（出锅提示依据）**：每道菜配 `slots_taken`（占盒格数，整数）：小食/家常/精致 1 格，宴席 2-3 格，盛宴 3-4 格——出锅时按此属性提示"这道菜占 X 格"，玩家据此决定是否装盒（装不下/不想装可不装）。
- **数据字段**：每道菜配 `slots_taken`；饭盒成品记录 `packed_meal_items: [item_id...]`（盒内装的菜）。
- **腐败照常**：普通盒菜照常腐败；高级盒（保温/密封）保鲜——与仓库冷藏同钩。
- **不豁免暴食**：盒只是打包，不改变胃容量（吃盒按盒内实际构成进胃，过量照常触发消化不良）。
- **均衡天然复用**：一餐 = 盒内构成，均衡判定直接复用——**盒 = 打包的活性消化集**；配齐 = 均衡爬升，乱装 = 只有维持。
- **不豁免消化规则**：消化 buff 走现有消化曲线，异菜叠加适用；**同种菜重复 = 刷新持续时间、不叠层（46 裁定，全局生效——替代 21/43 旧的"同 buff_id 拒吃"）**。

## 待确认 / 开放问题

1. ~~装盒的"一部分"来源~~ **已定**：装盒部分是**额外生成**，不扣成品出产。
2. ~~一份 vs 一格~~ **已定**：出锅后按菜属性（`slots_taken`）提示占几格，玩家选择要不要装盒；占格数值沿用旧设定档位表（小食/家常/精致 1，宴席 2-3，盛宴 3-4）。
3. ~~盒内容量升级线~~ **已定**：沿用升级线 小 2 / 标准 3 / 大 4 格；"装满" = 盒内格子全满。
4. ~~装满取下后能否继续装~~ **已定**：装盒只发生在饭盒**安装在灶台上（挂载中）**时；取下后（携带/丢弃期间）不可再装。**拿下来的盒要再挂回灶台必须先清空为空盒**（2026-09-03 拍板：只有空盒可挂载，无"搬进度挂回"）。
5. ~~旧"直接合成 + 批量制作"模式~~ **已定**：旧的"直接合成"废弃；装盒只发生在灶台挂盒 + 手动烹饪流程中。
6. ~~复合料理吃下后 buff 叠加的冲突/上限~~ **已定**：
   - 盒内**允许重复菜**；同种 buff 在**身上只存在一个**，重复食用只会**刷新持续时间**（不叠加、不拒吃）。
   - 身上已有同款 buff 时仍**能吃**，同样只刷新该 buff 的持续时间。
   - **吃饭盒（满/半）食用 = 逐菜多次结算**（方案 B）：相当于连续吃下盒内每道菜，每道菜各走一遍普通食用逻辑。
   - **全局口径（连带修订 21/43 旧结论）**：**普通吃同款菜也一样刷新时长**——"同 buff_id 重复食用"由旧的"禁止/拒吃"统一改为"刷新持续时间、不叠层"。
7. ~~"记录饭盒的状态"具体字段与数据结构~~ **已定**：**记录列表（真源）＋ 格子视图（显示/引用）**——每道菜一条记录（`{item_id, slots_taken}`），占多格的菜由多格引用同一索引；饭盒实例带状态（盒档 + 记录列表〔可为空~满〕+ 整盒统一腐败计时）。详见"物品状态与流通"。
8. ~~丢弃后拾取规则~~ **已定**：带内容的饭盒以带状态实例落地，任何人捡起完整还原，跟随现有地上物品规则。
9. ~~饭盒可否放快捷栏/战斗中食用~~ **已定**：**饭盒不可放入快捷栏**；战斗中能否食用**不做额外限制**（不特判禁用，跟随常规物品规则）。
10. ~~半盒能否取下/食用~~ **已定**：**可随时取下、非空即可食**——吃盒 = 一次吃光盒内现存全部（半盒/满盒同），吃光后空盒返还；想继续攒满就把盒留在灶台上（持久化）。半盒**不提供挂回续装**（取下即不能再装，挂回须先清空为空盒，#4 不变）。
