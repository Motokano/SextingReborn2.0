# 农业种植与灌溉系统（草案）

本文记录农业系统第一阶段已经确认的规则，重点覆盖农业入口、11x11 农业地图、水池、水渠、主干/支流识别、供水分配与作物受水来源。当前目标是先支持一版“挖水渠”HTML demo，用来试玩规则手感。

---

## 1. 农业入口与界面

- 玩家拥有一个固定农业互动点。
- 农业互动点走 NPC 管线：玩家与对应设施 NPC / 互动 NPC 对话后打开农业界面。
- 农业界面内包含一张 `11 x 11` 的农业地图。
- 地图坐标范围固定为：
  - `x = 0..10`
  - `y = 0..10`
- 不存在负数坐标。
- 玩家可以选择任意非水池、非水渠、非不可操作地块进行农业操作。

---

## 2. 地块基础属性

### 2.1 水池

- 水池默认位于最左上角：`(0, 0)`。
- 水池第一版不可操作：
  - 不可种植。
  - 不可改造成水渠。
  - 不作为普通土地使用。
- 水池可升级（材料 + 面板内工程 tick，无农业商店金钱）；升级主特效见 **§8.4 支流窃流**、**§8.5 蓄水池**（配合主游戏天气）。
- 水池基础属性：
  - `基础水分滋养度 = 200`（等级 1 常态灌溉预算；更高等级见 `data/agriculture-pool-upgrades.json`，首版可不抬该常数）
- 水池等级梯（首版）：
  - **2**：解锁支流窃流（`transfer_cap = 2`）。
  - **3**：解锁蓄水池（旱涝缓冲，见 §8.5）；窃流 cap 仍为 2。
  - **4**：窃流 `transfer_cap = 4`；**窃流溢流回蓄**（§8.6）；蓄水池能力保留。
- **升级消耗**：主游戏见 `data/agriculture-build-costs.json` → `upgrades.pool_level`（材料 + 工程 tick）；Demo 见 §8.5 Demo 注。

### 2.2 高度

- 每一个地块拥有属性：`高度`。
- 高度按行分布：
  - 同一行内所有地块高度一致。
  - 水池所在行高度最高。
  - 后续每一行依次降低。
- 因此当前可理解为：
  - `y = 0` 行最高。
  - `y = 10` 行最低。
- 农业地图地块高度固定，不会被玩家行为改变。

### 2.2b 土壤种类与锁值（锁水 / 锁肥 / 锁微量元素）

- 每一个已开垦耕地维护 **`soil_id`**（展示名 `土壤种类`）；客土改良、制造链 **`grants_soil_id`** 物品写入该字段。
- 第一版地图默认 **`soil_saline_alkali`**（展示名 **盐碱土**，西北内陆/滨海）。
- 土壤模板主表（建议）：**`data/agriculture-soils.json`** → `soils[soil_id]`。

#### 土壤的两条独立作用轨（勿混用）

| 作用轨 | 时机 | 影响 |
|--------|------|------|
| **锁值（本小节，默认）** | 生长中**每 tick** 吸收水分 / 微量元素 / 施肥值时 | 决定「外部供给 → 作物累计条」的**基础转化效率**（`water/fertilizer/trace_retention`） |
| **土性融合（§2.2g，`fusion_gated`）** | 场上**至少一座超融合**时，与文丘里 A 面**同一全局条件** | `absorption_modifiers`、`special_effect` 及关联轮作/tick 修正；**拆除超融合后立即关闭** |
| **土种偏好（§4b.3 `soil_scoring`）** | **成熟收获**算生长分时 | 偏好土 **+1** 分、不适土 **-1** 分；**始终生效**，与是否超融合**无关** |

#### 锁值字段（每 `soil_id` 必配）

| 字段 | 含义 | 取值 |
|------|------|------|
| `water_retention` | **锁水率**：灌溉供给转化为作物水分的比例 | `0.0～1.0`（展示可写百分比） |
| `fertilizer_retention` | **锁肥率**：埋地陶瓮等施加的施肥值转化为作物累计的比例 | 同上 |
| `trace_retention` | **锁微量元素率**：渠内海藻精浓度转化为作物累计的比例 | 同上 |

缺省实现：未登记 `soil_id` 时三类锁值均回退 **`1.0`**（100%，与改前 demo 行为一致）。

#### 每 tick 转化公式（与 §4.1 一致：不作用于土地本身）

锁值只乘在**作物吸收步**，不改变水渠格上的 `W` / 海藻精浓度 `C`，也不在土地上累积「滞留水分池」。

- **水分**（§4.2，来源格实际水量 `W_src`）  
  `ΔwaterAbsorbed = W_src × water_retention(soil_id)`  
  例：锁水 **80%**、来源水渠本 tick 水量 **2.0** → 作物 **+1.6** 累计水分。
- **微量元素**（§4b.1c，来源格浓度 `C_src`）  
  `ΔtraceAbsorbed = C_src × trace_retention(soil_id)`（作物模板另有 `trace_absorption_multiplier` 时先乘模板再乘锁值，或等价合并为一条乘区，实现择一即可）。
- **施肥值**（§4b.1d，单瓮施加量 `F_pt`）  
  `ΔfertilizerAbsorbed += F_pt × fertilizer_retention(soil_id)`（超融合激活时，再乘 `fusion_gated.absorption_modifiers.fertilizer_multiplier`，缺省 1）；多瓮八邻叠加时，**每瓮贡献各自乘锁值后再相加**。
- **微量元素 / 施肥值乘区**：`fusion_gated.absorption_modifiers` 的 `trace_multiplier` / `fertilizer_multiplier` 仅在 **`anySuperFusionOnMap === true`** 时叠乘；未激活时只用三项 `*_retention`。

计算过程保留小数；写入作物累计条时 **保留 1 位小数**（与现有 `waterAbsorbed` / `traceAbsorbed` / `fertilizerAbsorbed` 一致）。

| 值 | 含义 | 生长分 / 土种 |
|----|------|----------------|
| `xeric` | 耐旱忌涝；完美水分窗偏低；超 `waterlogged_above` 生长分 0 | 偏好盐碱/黄绵/褐土；不适水稻土 |

#### UI 与对玩家可见性

- 选中耕地：展示当前 `土壤种类`、三项锁值（百分比）、以及 **土性是否已融合**（场上有超融合时显示 `fusion_gated.special_effect` 摘要）。
- 作物详情（可选）：本 tick 有效吸收可展示「来源供给 × 锁值 = 实际入账」（调试层即可，非强制）。

#### 与 §23 肥料桶 / 地块肥力的关系

- **§23.7** 的 `soil_fertility`、`growth_time_mult` 为地块**限时肥力 buff**（缩成熟时间），与 **`fertilizerAbsorbed` 累计条**、与本节**锁肥率**分轨；同 tick 若两套并存，各自按各自规则结算，禁止合并为单一「肥力」真相。

### 2.2c 耕地与上一轮作物

- 种子只能种植在已经开垦过的耕地上。
- **种子物品**：`data/items/seeds_farming.csv` → `items.json`（`category: seed`，`harvest_item_id` 指向对应产物如 `herb_peanut`；列 **`seed_tier`** 为 1～5 档）；农业 demo 商店表 **`data/agriculture-seed-shop.json`**（每种种子含 **`tier`**、**`price`**、**`grow_note`**；维护脚本 **`node tools/seed-tier-classification.mjs`**）。
- **五档口径**（现实价值 + 种植难度，每档 10 种）：**1 大宗易种**（玉米/稻/麦/土豆等主食与常见菜）→ **5 珍稀高值**（八角/樱桃/扁桃等多年生或精细管理作物）。档次越高：**种子售价越高**（约 6～24 金）、后续作物模板宜配置更长生长周期、更窄水分/微量元素窗口、或池栽/嫁接等前置（具体数值在种植篇按作物落地）。
- **售价基准**：二档 **花生种子 10** 金为锚点；同档内按现实批发/零售价差微调，非精确汇率。
- **生长默认参数**：`data/agriculture-crop-defs.json`（`tools/gen-agriculture-crop-defs.mjs` 由种子表生成）。设计原则：**成熟区间宽裕**（枯/淹阈值宽，普通成熟易达成）；**高分水分窗**随档位略收窄；**产量由生长分连续映射**（§4b.3），不设玩家可见的「完美」档位。档位摘要：

| 档 | 生长 tick（约） | 成熟水分带 | 高分水分窗 | 生长分参与维（典型） | 理论正分上限（约） |
|----|----------------|------------|------------|----------------------|-------------------|
| 1 | 40～95 | 很宽 | 很宽 | 水 + 土 + 轮作 | 6 |
| 2 | 98～100 | 中等 | 中等 | 水 + 土 + 轮作；部分 + 微量（番茄/花生/甘蔗等） | 8 |
| 3 | 108～120 | 略窄 | 中等 | 水 + 微量 + 肥 + 土 + 轮作 | 8 |
| 4 | 124～140 | 中等 | 较窄 | 全维；可登记海藻精 + 液态肥 | 8 |
| 5 | 142～175 | 仍宽裕 | 最窄 | 全维最严；果树/香料多不适红壤/盐碱土 | 8 |

- 形态修正：豆芽 **fast**（短周期）；稻/芡实/莲 **aquatic**（提高需水但放宽淹上限）；果树类 **tree**（周期 ×1.22，上限 175 tick）；香料 **spice**（微量门槛略降）。
- 农业 demo 从该表加载 **`CROP_DEFS`**，耕地建造菜单按背包种子动态列出种植按钮。
- 普通土地可通过地块操作开垦为耕地。
- 已开垦且未种植作物的耕地可以拆除，拆除后还原为普通土地。
- 开垦 / 拆除耕地均为 `10 tick` 工程，每 `1 tick` 消耗 `5` 体力。
- 每个地块拥有属性：`上一轮作物`。
- `上一轮作物` 记录该地块最近一次「已结束种植周期」的作物 id：包括**正常收获**写入，以及**生长中健康度归零枯萎**时写入（作物从格子上消失，耕地与开垦状态保留，可再播种）。
- 当前 demo 已记录该字段；**生长分**轮作维读取它（跨 group 或豆科后种非豆科 +1 分，连作 0 分）。

### 2.2d 文丘里施肥器（地块设施）

- **定位**：种植地图上的独立地块类型（与水渠、耕地互斥同格）；不参与水渠连通寻路，也不可种植。
- **建造**：工程 **10 tick**，每 **1 tick** 消耗 **5** 体力；开始时支付 **20** 金钱（与客土改良「先扣道具」同理，取消工程应退回金钱）。
- **拆除**：工程 **10 tick**，每 **1 tick** 消耗 **5** 体力；不另收金钱。拆除完成后肥液若有剩余，应退回背包（若背包满则按项目规则丢失或阻塞拆除，首版 demo 可优先「可退尽退、否则提示」）。
- **投料（仅海藻精）**：仅允许注入 **`liquid_seaweed_extract`（海藻精）**；物品模板须 **`agriculture_venturi_injectable: true`** 且登记 **`inject_facility = venturi_fertilizer`**（或等价字段，禁止装入埋地陶瓮）。**液态氮肥等其它液态肥不可注入文丘里**。
- **罐内口径（海藻精）**：
  - 注入时消耗背包 **1** 个道具，施肥器进入持续效果 **5000 tick**（`agriculture_venturi_effect_duration_ticks`），每全局 tick 递减；归零后效果消失（不退道具）。**再次注入**同种道具将倒计时**重置为 5000 tick**（仍消耗 1 个道具）。
  - 罐内仅允许一种 `item_id`；换液前需等效果结束或拆除。
- **所属水流（只看水流）**：结构重算后，自施肥器格**四邻接有水水渠**（若有）沿已归类路径回溯到水池，得到唯一 **水流归属**（主流 / 第一支流 / 第二支流 …，与 §6、§7 一致）。**不看**邻接耕地。无邻接有水水渠 → 无归属，**不输送**（§15）。
- **等级与浓度 UI**：施肥器共 **3** 级；每次升级 **5** 金钱（升级工程 tick/体力与建造口径一致时另表）。玩家在施肥器 UI 调节 **`海藻精输送浓度`**（设定浓度）；可调范围随等级固定为：

| 施肥器等级 | 设定浓度可调范围（含端点） |
|------------|---------------------------|
| **1 级** | **5～10** |
| **2 级** | **3～15** |
| **3 级** | **1～20** |

  - 默认值实现取当前等级区间内一点（建议 1 级默认 **5** 或 **7**）；升级后若当前设定值超出新等级范围，应夹紧到新范围内。
  - **不设**单格海藻精浓度硬顶，由玩家通过设定浓度自控。
- **设定浓度与渠内状态**：向水渠「注入」语义见 §15.4（持续状态 + 入口后均分），非单次脉冲后消失。

### 2.2e 埋地陶瓮（地块设施）

- **定位**：种植地图上的独立地块类型（与水渠、耕地、文丘里施肥器互斥同格）；不参与水渠连通寻路，也不可种植。
- **建造**：工程 **10 tick**，每 **1 tick** 消耗 **5** 体力；开始时支付 **20** 金钱（取消工程应退回金钱）。
- **拆除**：工程 **10 tick**，每 **1 tick** 消耗 **5** 体力；不另收金钱。拆除时**存量型**肥液剩余单位退回背包（与文丘里一致）；**持续效果型**不退道具。
- **投料（仅液态肥）**：仅允许注入**液态肥**类物品（如示范 **`liquid_fertilizer_n`**）；物品模板须 **`agriculture_buried_jar_injectable: true`** 且登记 **`inject_facility = buried_pot_jar`**。**海藻精不可注入埋地陶瓮**。
- **罐内口径（存量型）**：
  - 多次注入同 `item_id` 合并 **`units`**；拆除时可退回背包。
  - 不同 `item_id` **不可混装**。
  - 每种肥液配置 **`agriculture_fertilizer_per_tick`**（每 tick 向八邻生长中作物累加的施肥值；demo：`fertilizerPerTick`）。
- **邻接口径（施肥专用）**：向**八方向**（含四斜角）邻格施加；与 §3.1 四向供水**分离**，不用于水渠/水池滋养判定。
- **每 tick 施肥**：罐内肥液**生效中**时，对每个八邻格 **`kind = land` 且生长中作物**（未进入成熟结算）累加该肥液的 **`fertilizerPerTick`** 到作物 **`累计施肥值`**（`fertilizerAbsorbed`）；**已成熟待收获**不累计。示范液态肥 demo 默认 **`fertilizerPerTick = 0.5`**。
- **多瓮叠加**：每个 tick 遍历**所有**埋地陶瓮，各自向八邻施加；同一株作物若在多个瓮的八邻范围内，**按瓮数累加**（例如 3 瓮各邻接 → 本 tick `fertilizerAbsorbed += 0.5 × 3`）。各瓮**独立**消耗存量（每瓮本 tick 至少命中一株邻格生长中作物则该瓮扣 **1** 单位）。
- **存量型消耗**：本 tick 若对**至少一株**邻格生长中作物成功施加施肥值，消耗罐内 **1** 单位；无邻格作物或邻格无生长中作物时不消耗。
- **与渠内海藻精**：埋地陶瓮**不**写水渠浓度、**不**参与 §15 输送；作物可同时获得渠内微量元素（§4b.1c）与本设施施肥值（§4b.1d），两套累计独立。

### 2.2g 超融合（地块设施）

- **定位**：种植地图上的独立地块类型（与水渠、耕地、文丘里、埋地陶瓮互斥同格）；不参与水渠网络；**不可种植**。
- **建造**：工程 **10 tick**，每 **1 tick** 消耗 **5** 体力；开始时支付 **200** 金钱（取消工程退回金钱）。
- **拆除**：工程 **10 tick**，每 **1 tick** 消耗 **5** 体力；不另收/退金钱；无罐内物资。
- **全局效果（与坐标无关；多座不叠加）**：地图上**存在至少一座**超融合时：
  1. **文丘里**：全场海藻精输送切换 **A 面**（§15.1～§15.3，检测作物请求）；无超融合时默认 **B 面**（§15.6，常注）。
  2. **土性融合**：全场已开垦耕地的 **`fusion_gated`** 特性激活（吸收乘区、`special_effect` 关联的轮作/tick 修正等，§2.2b）。

  - 水渠容量不能降为 `0`；当前容量为 `2` 的水渠不能再降级。

## 3. 邻接与有效供水

### 3.1 邻接口径

**四方向**（不含斜角）：水池、水渠、作物**水分 / 微量元素**滋养来源、水渠结构连接。

**八方向**（含斜角）：仅 **§2.2e 埋地陶瓮** 向邻格作物施加施肥值；不用于供水网络。

四方向邻接定义：

- 上
- 下
- 左
- 右

斜角不算邻接。

方向扫描顺序在同等条件下固定为：

`下 -> 右 -> 左 -> 上`

### 3.2 结构相连与有水相连

水渠之间需要区分两种状态：

- `结构相连`：两格水渠上下左右邻接即可，不看高度。
- `有效供水相连`：水能从来源格流入目标水渠，需要满足高度条件。

有效供水条件：

`目标水渠高度 <= 来源格高度`

因此：

- 同高度可以供水。
- 从高处可以流向低处。
- 不能从低处流向更高处。

如果玩家在有水水渠的上方建一格水渠：

- 两者结构相连。
- 新水渠高度更高。
- 新水渠不能获得水。
- 该新水渠是无水水渠。

### 3.3 有水水渠与无水水渠

一格水渠是否有水，取决于它是否能通过有效供水路径连接到水池。

- 直接邻接水池且高度不高于水池：可以有水。
- 通过连续水渠链连接水池，且路径每一步都满足高度条件：可以有水。
- 不邻接水池，也不连接任何有水水渠：无水。
- 结构连通但高度方向不允许供水：无水。

无水水渠：

- 滋养度为 `0`。
- 不滋养作物。
- 不占用水池水量。
- 结构上仍然可以归入主干或支流网络。

## 4. 水池与水渠对作物的滋养

### 4.1 作用对象

水池与水渠的滋养效果只作用于“邻接地块上的作物”。

强约束：

- 不作用于土地本身。
- 不给土地增加水分或湿度。
- 不滋养自己所在格的作物。
- 水渠格本身默认不能种作物。

### 4.2 Tick 效果

每 `1 tick`：

- 水池根据当前实际滋养度滋养上下左右邻接地块上的作物。
- 有水水渠根据自身当前实际水量滋养上下左右邻接地块上的作物。
- 无水水渠不产生滋养。
- 作物入账水分 = 来源格实际水量 × 该地块 **`water_retention`**（§2.2b）；**不**扣减来源格水量，**不**写入土地湿度。

水量精度：

- 计算过程中尽量使用原始数值。
- 每个格子的最终实际水量落格时保留 `1 位小数`。
- UI 显示 1 位小数。

水池剩余滋养度不能为负，最低为 `0`。

### 4.3 水藻爆发（水量与海藻精浓度）

有水水渠在**本 tick 步骤 ① 清水分配、② 海藻精维持均完成后**的落格数值上，**实时运算**是否处于 **水藻爆发**（`algae_bloom`）；**不**做跨 tick 锁存，每 tick 步骤 ③ 按当前 `W`、`C` 重算。判定仅依赖该格 **`当前实际水量`**（§4.2，记 `W`）与 **`海藻精浓度`**（§15.4 格上总浓度，记 `C`；**含多施肥器异来源叠加后的总值**）。

**策划常量（可调，首版可硬编码）**

| 常量 | 默认值 | 说明 |
|------|--------|------|
| `algae_bloom_concentration_ratio_threshold` | `2.5` | 爆发阈值：`C : W` 高于 `阈值 : 1` 时爆发 |
| `algae_bloom_health_loss_per_tick` | `2` | 生长中作物每 tick 基础健康扣减 |

实现须留**开放接口**：扣减值经统一入口汇总 Buff/装备等对「水藻爆发伤害」的修正，**最终扣减 ≥ 0**；结算后健康度 **clamp 至 `[0, 健康上限]`**。

**爆发条件（强制）**

- 仅对**有水**水渠格判定（`W > 0`）。
- 当 **`C : W` 高于 `阈值 : 1`**（默认 **`2.5 : 1`**）时爆发（浓度过高、相对水量不足）：
  - 比例口径：`C : W > 2.5 : 1`（`W`、`C` 与 §4.2 / §15.4 同单位、同刻度直接比较；玩家通过降低施肥器设定浓度、拉长入口后流经格数稀释 `C`，或提高 `W` 来规避爆发——**施肥器等级越高可调浓度上限越大，越容易触爆发**，属预期策略风险）。
  - 等价判定：`C > 0` 且 **`C > 阈值 × W`**；**`C <= 0` 永不爆发**（纯清水渠不会爆发）。
- **恢复**：当 `C <= 阈值 × W` 时本 tick **不爆发**。恰为 `2.5 : 1` 时不算「高于」。
- 施肥器效果结束、§5 重算清空浓度、`W`/`C` 变化导致比例回落时，**当 tick 即按新值重算**，可能当 tick 解除爆发。

**对作物的影响**

- 仅当作物本 tick 存在 §12 **唯一滋养来源水渠**，且该格 `algae_bloom === true` 时生效；**无受水来源**（无邻接有水水渠等）的耕地上的作物**不受**爆发伤害。
- **不区分**作物是否 `requests_seaweed_extract`：只要来源渠爆发即可能扣血。
- 对象：仅**生长中**作物；**已成熟待收获**不扣健康（§4b.1c 亦不吸收微量元素）。
- 每 tick 基础扣减 **`algae_bloom_health_loss_per_tick`**（默认 `2`），经开放接口修正后自健康度扣除；健康降至 `<= 0` 时走 §4b.1b **健康枯萎**（与其它扣血同源，不单独死法）。
- **同 tick 顺序**（§15.0）：步骤 ⑤ **先**按来源格浓度**照单全收**累加微量元素（爆发不减免、不停止吸收），步骤 ⑥ **再**结算爆发扣健康。
- 不扣减渠内 `W` / `C`；**不阻止**施肥器对本格或该水流继续维持浓度（爆发为玩家浓度/水路策略后果）。

**与 §15 施肥器**

- 多来源叠加后的 `C` 再参与比例判定（§15.4）。
- 渠格已爆发时，施肥器**仍允许**维持 / 注入海藻精。

**表现（强制）**

- 农业地图（含 HTML demo）须**可视化**爆发中的有水水渠（如专用样式 / 图例项 `algae_bloom`）；**不要求**向玩家推送提示条、飘字或游戏日志（调试日志可选）。

**与水池**

- 水池格不适用本节；仅**有水水渠**。

## 4b. 作物种植与成熟结算

### 4b.1 种子与作物

- 种子只能种植在已开垦的耕地上。
- 种子被种入地块后转化为作物。
- 作物拥有以 `tick` 为单位的生长周期。
- 作物种下后自动随游戏时间倒计时。
- 生长周期结束后进入结算阶段。
- 作物进入结算阶段后状态冻结，属性不再变化，直到玩家收获。

### 4b.1a 海藻精请求（作物模板属性）

- 作物定义（模板 / `crop` 配置）可携带布尔属性 **`requests_seaweed_extract`**（是否请求海藻精；缺省视为 `false`）。
- 仅当 **`requests_seaweed_extract === true`** 时，该作物可参与 §15 的施肥器检测；为 `false` 的作物**从不**向水网发送请求（但若邻渠有浓度，仍可按 §4b.1c **吸收**）。
- **登记前提（强制）**：作物必须**四邻接至少一格有水水渠**，且能按 §12 得到受水归属，才允许登记请求；**无邻接有水水渠时不登记**（播种瞬间无水亦然）。
- **登记时机**：满足前提后自动登记（无需玩家操作）——可在**首次满足前提的 tick**登记，或在 §5 水道重算之后同步登记；**不在**无邻接有水时登记。
- **登记目标**（与受水归属一致）：
  1. **主流（主干）**：始终向当前供水网络中的**主流**登记一条活跃请求；
  2. **所属支流**：若受水归属为**支流 #N**（非主干），则**同时**向**支流 #N** 再登记一条。
- 仅归属主干、无支流结构时：只向**主流**登记。
- 请求与作物实例绑定：作物仍在该地块上存活期间（含**生长中**与**已成熟待收获**）保持活跃；**收获、枯萎移除、拆除耕地清除作物**时撤销。
- **§5 重算顺序**：水道 / 主干支流 / 清水可达**先**算完，**再**同步本节的请求登记与撤销；受水归属变更时撤销旧支流请求并按新归属重登（主流请求通常保持）。

### 4b.1b 健康度（demo）

- 作物拥有 `健康当前值 / 健康上限`，默认 `100 / 100`；作物定义未单独说明时使用该默认。
- 生长中（未进入结算）若健康当前值 `<= 0`：视为**健康枯萎死亡**，该地块上的作物对象立即移除（格子不再显示作物），**不进入**按水分结算的成熟阶段；地块仍保留耕地与 `上一轮作物` 记录（写入本次枯萎的作物 id）。
- 每 tick 在吸收水分、吸收微量元素与生长倒计时**之前**与**之后**各检查一次，避免「本 tick 结束时健康已为 0 却仍被水分结算拉入成熟阶段」的竞态。
- 健康度的扣减来源包括 **§4.3 水藻爆发**（经开放接口修正、clamp 后扣减；归零走本节枯萎）；其它来源可由后续系统接入。

### 4b.1c 微量元素吸收（与水分同机制）

- **作用阶段**：仅在**生长周期内**（未进入 §4b.1 成熟结算阶段）每 tick 自动吸收；**已成熟待收获**不再吸收、不增加 **`累计微量元素`**（`traceAbsorbed`；渠内海藻精仍可流经，见 §4b.1a / §15）。**不得**累加到 `fertilizerAbsorbed`。
- **每 tick 顺序**：在全局农业 tick 中位于 **清水分配 → 海藻精维持（§15）** 之后（见 §15.0），与 §4.2 吸水同一轮。
- **每 tick 流程（与 §4.2 水分对齐）**：
  1. 按 §12 为作物选定本 tick 唯一滋养来源水渠（与吸收水分**同一来源、同一 tick**）。
  2. 读取该来源格当前 **`海藻精浓度`**（§12.1）。
  3. 本 tick 吸收量 = 该浓度值 × 耕地 **`trace_retention`**（§2.2b）；作物模板另有 `trace_absorption_multiplier` 时纳入同一乘区。
  4. 累加到作物实例 **`累计微量元素`**；展示保留 **1 位小数**。
- **不扣减渠内浓度**：吸收只读来源格浓度，**不**降低该格或其它格的海藻精浓度（与吸水不扣渠内水量同构）。
- **不作用于土地**：只作用于邻接水源的**作物**。
- **与请求的关系**：`requests_seaweed_extract` 仅管是否**登记输送请求**；**吸收**只看来源格浓度——**凡生长中作物**每 tick 均按本节累计（与是否发送请求无关）；`false` 模板不登记但仍可吸收。
- **成熟结算（可收获硬门槛）**：各作物单独配置水分枯/淹阈值；severe 微量达 `trace_fail_harvest_at` 绝收。**通过门槛后**才计算 **§4b.3 生长分** 决定产量；未配置微量/施肥评分的作物该维不参与计分。**水藻爆发不参与**生长分（仅影响健康与当 tick 吸收量）。

### 4b.1g 微量排斥作物（海藻精累计 `traceAbsorbed`）

部分作物**不可承受过量微量元素**（与液态肥 `fertilizerAbsorbed`、埋地陶瓮**无关**）。模板字段：

| 字段 | 说明 |
|------|------|
| `trace_sensitivity` | `lethal`（绝对致死）或 `severe`（严重排斥）；缺省视为无排斥 |
| `trace_safe_max` | 安全上限：排斥作物微量维 **≤ 此值得 2 分**；超过则 0 分（severe 达 `trace_fail_harvest_at` 仍绝收） |
| `trace_lethal_at` | 仅 `lethal`：累计 **≥** 此值本 tick 按致死扣血（常伴随健康归零枯萎） |
| `trace_stress_loss_per_tick` | `lethal` 且 `safe < trace < lethal` 时每 tick 扣健康 |
| `trace_lethal_loss_per_tick` | `lethal` 且 `trace ≥ lethal` 时每 tick 扣健康（宜一次致死） |
| `trace_fail_harvest_at` | 仅 `severe`：成熟结算时累计微量 **≥** 此值 → 无果实（盐害/落果） |
| `trace_toxic_health_loss_per_tick` | `severe` 且 `trace > safe` 时每 tick 扣健康 |

**阵营（首版登记）**

| 类型 | 作物 id |
|------|---------|
| **绝对致死** | `sprout`（豆芽）、`lotus_seed`（莲子）、`euryale`（芡实） |
| **严重排斥** | `apricot`、`cherry`、`almond`、`pear`、`lemon`；`green_beans`、`garrofo`、`beans_white_haricot` |

**规则摘要**

- 排斥作物 **`requests_seaweed_extract` 恒为 false**（不向水网登记海藻精需求）；邻渠有浓度仍会因 §4b.1c **被动吸收**，故须**清水灌溉或极低浓度**，与 B 面常注风险相关。
- **微量生长分**：排斥作物为「低微量高分」——`trace ≤ trace_safe_max` → 2 分，否则 0 分（非 `perfectMinTrace` 下限）。
- **吸收后**每 tick 在步骤 5 之后执行排斥扣血（demo：`agriTickStep5aTraceSensitivity`）。
- 数据表：`data/agriculture-crop-defs.json`（`tools/gen-agriculture-crop-defs.mjs`）。

### 4b.1f 液态肥请求（埋地陶瓮，与 §4b.1a 对称）

- 作物模板可携带布尔属性 **`requests_liquid_fertilizer`**（是否向埋地陶瓮「登记施肥需求」；缺省 `false`）。
- **登记前提**：该地块有**生长中或待收获**作物且模板为 `true`，且作物格 **八邻接至少一格 `buried_pot_jar`**（罐内有无肥液均可登记，与瓮后建/后注肥兼容）。
- **登记时机**：播种后、埋地陶瓮建成或拆除后、每 tick 全表同步（与 §4b.1a 海藻精请求同级的 `syncCropFertilizerRequests`）；收获 / 枯萎 / 清作物时撤销。
- **与施加的关系（demo 口径）**：
  - **`requests_liquid_fertilizer === true`**：该作物在陶瓮 **八邻**范围内时，才接收 §4b.1d 的 `fertilizerPerTick` 累加（陶瓮本 tick 可扣单位）。
  - **`false`**：即使紧贴陶瓮也**不**累加施肥值（与海藻精「不登记仍可吸收渠内浓度」不同——液态肥无渠网，只有瓮邻施加这一条路）。
- **施肥生长分（可选）**：模板可配 **`perfectMinFertilizer`** / **`perfectMaxFertilizer`**；闭区间内 2 分、可收获但未进窗 1 分；**未配置则该维不参与生长分**。

### 4b.1e 微量元素与施肥值分轨（强制）

| 累计条 | 存档字段 | 唯一来源 | 禁止写入 |
|--------|----------|----------|----------|
| **累计微量元素** | `traceAbsorbed` | §12 滋养来源水渠格的 **海藻精浓度**（文丘里 + 海藻精，§4b.1c / §15） | 埋地陶瓮、液态肥 |
| **累计施肥值** | `fertilizerAbsorbed` | §2.2e 埋地陶瓮八邻 **液态肥** `fertilizerPerTick`（§4b.1d） | 渠内海藻精浓度、文丘里 |

- 两字段**独立累加、独立展示**；**可收获**由水分枯/淹与 severe 绝收等硬门槛决定；**微量元素** / **施肥值** 是否参与生长分由模板是否配置 `perfectMinTrace` / `perfectMinFertilizer` 决定（未配置不参与）。花生示范可同时请求海藻精与液态肥（见 §4b.2 与作物表）。

### 4b.1d 施肥值（埋地陶瓮）

- **作用阶段**：仅在**生长周期内**每 tick 累加；**已成熟待收获**不再增加 **`累计施肥值`**（`fertilizerAbsorbed`）。**不得**累加到 `traceAbsorbed`。
- **每 tick 顺序**：位于 §15.0 步骤 **5**（微量元素）之后、步骤 **6**（水藻爆发扣健康）之前。
- **每 tick 流程**：
  1. 遍历所有 **`buried_pot_jar`** 格，若罐内肥液未生效则跳过。
  2. 读取该肥液登记项的 **`agriculture_fertilizer_per_tick`**（demo：`fertilizerPerTick`）。
  3. 对陶瓮格 **八邻接**每一格：若为 `land` 且存在**生长中**作物，则 `fertilizerAbsorbed += fertilizerPerTick × 该地块 fertilizer_retention`（§2.2b；展示 **1 位小数**）。**所有瓮每 tick 各执行一遍**；同株作物可被多瓮叠加。
  4. **存量型**：本 tick 若步骤 3 至少命中一株作物，**该瓮**罐内 **`units -= 1`**；`units <= 0` 则清空该瓮肥液。
  5. **持续效果型**：不在此步扣道具；倒计时在步骤 7 与其它罐内效果一并递减。
- **不作用于空耕地**：无作物邻格不累计；有作物才累计。
- **与微量元素**：独立字段、独立来源；生长分各维由作物模板与 §4b.3 统一结算。

### 4b.3 生长分与产量（收获量）

- **时机**：仅当作物已通过 **§4b 可收获硬门槛**（水分在成熟带内、未枯死、未 severe 绝收等）之后计算；**只决定收获数量**，不向玩家展示分数或「完美」档位名。
- **单维得分**（参与则计入；未配置微量/肥维**不参与**）：

| 维度 | 2 分 | 1 分 | 0 分 | 特殊 |
|------|------|------|------|------|
| **水分** | 闭区间 `[perfectMinWater, perfectMaxWater]` | 在 `[minWater, maxWater]` 内但未进高分窗 | （绝收，不进评分） | 必参与 |
| **微量元素** | 配置窗内或排斥作物 `≤ trace_safe_max` | 可收获但未进窗 | 排斥作物超 safe 未绝收 | 未配 `perfectMinTrace` 且无 `trace_sensitivity` 不参与 |
| **施肥值** | 闭区间 `[perfectMinFertilizer, perfectMaxFertilizer]`（缺上限仅看下限） | 可收获但未进窗 | — | 未配 `perfectMinFertilizer` 不参与 |
| **土壤** | — | — | — | 偏好土 **+1**；不适土 **-1**；其余 **0**（`soil_scoring`） |
| **轮作** | — | 跨 `group` 或豆科后种非豆科 **+2**（高山草甸土融合跨组 **+3**；黄绵土融合豆科后茬 **+3**） | 连作/同组/首开垦 **0** | 读 `上一轮作物` |

- **产量倍数**：
  - `正分 = Σ(各维 score > 0)`；`负分 = Σ(|score| where score < 0)`（当前仅不适土产生负分）。
  - `yieldMultiplier = 1 + 0.25 × 正分 − min(0.25 × 负分, 0.50)`。
  - `baseCount` 在 `harvestMin～harvestMax` 随机；`harvestCount = max(1, floor(baseCount × yieldMultiplier))`。
- **后台**：可存档 `growthScorePositive` / `growthScoreNegative` / `yieldMultiplier` 供调试；UI 仅显示收获数量与「成熟」。
- **数据**：`data/agriculture-crop-defs.json` 含 `growth_score_rules` 与各作物 `group`、`soil_scoring`、`nitrogen_fixing`。

### 4b.2 花生（二档）

- 种子：`花生种子`（二档经济作物；**非**全维示范田）。
- 作物：`花生`；**豆科**（`nitrogen_fixing`），利于轮作后茬。
- 生长周期：与同档一致（约 `98 tick`，由 `gen-agriculture-crop-defs.mjs` 生成）。
- 生长分参与：**水分 + 微量（二档田园接入）+ 土 + 轮作**；**不**登记海藻精 / 液态肥请求（与番茄、甘蔗等同档口径）。
- 成熟结算：与其它作物相同——先过水分枯/淹硬门槛，再按 **§4b.3** 计产量；基础收获 `2～4`。
- 玩家左键点击已结算、可收获的作物时，弹出收获选项。
- 点击收获后，地块作物被移除，地块恢复为无作物状态，并记录 `上一轮作物`。

## 5. 水渠网络重算

水渠网络不需要每 tick 重新寻路。

触发重算的变化：

- 新建水渠。
- 拆除水渠。
- 修改水渠容量。
- 修改水池基础水分滋养度。
- 修改水池位置或水池存在状态。

**重算后的固定顺序（强制）**：

1. 完成水道网络、主干 / 支流、清水可达与每格水量（§6～§11）；
2. **立刻清空**所有有水水渠上的 **海藻精浓度**（§15.4）；
3. 再同步作物海藻精**请求**登记 / 撤销（§4b.1a）。

不触发重算的变化：

- 地块高度变化，因为高度固定，不会改变。

每 tick 只根据已缓存的主干 / 支流结构进行水量分配和作物滋养。

## 6. 主干道算法

### 6.1 目的

玩家不一定会挖规则水渠，因此系统需要从实际水渠网络中自动识别一条主干道。

主干道用于表示主要承担纵向引水的供水骨架，并在供水时优先于所有支流。

### 6.2 主干目标选择

在可有效到达水池的水渠格中选择主干目标：

1. 优先选择高度最低的水渠格。
2. 如果有多个同样最低高度的水渠格，选择 `x` 最小的格子。

因为地图不存在负数坐标，所以 `x` 越小表示越靠近 `x = 0` 这一列。

### 6.3 主干路径

主干道是从水池出发，通往当前可有效到达的最低水渠目标的一条完整有效供水路径。

主干道规则：

- 从水池出发。
- 优先向高度更低的方向延伸。
- 在无法继续向下延伸时，允许横向绕行。
- 路径整体尽量靠近 `x = 0`。
- 只要某格位于通往主干目标的最终选定路径上，即使它是横向绕行格，也计入主干。
- 不在最终选定路径上的横向扩展格，视为支路。

示例：

```text
x=0 x=1 x=2
[水][ ][ ]
[A][B][ ]
[ ][C][ ]
[ ][D][E]
```

该结构中：

- 主干道为 `A -> B -> C -> D`。
- `E` 不在通往最低目标 `D` 的选定路径上，是从主干末端横向分出去的支路，不属于主干道。

例如玩家依次建造 `(0,1)(1,1)(2,1)` 时，`(0,1)` 是主干，`(1,1)` 与 `(2,1)` 会按支流归类；但后续在 `(2,2)` 建造水渠后，最低目标变为 `(2,2)`，选定路径为 `(0,1)->(1,1)->(2,1)->(2,2)`，这四格都会被重新归为主干。

## 7. 支流算法

### 7.1 支流定义

支流是主干之外的水渠结构，用于归类所有可达的非主干水渠。

支流候选需要满足：

- 可从水池、主干、或更高优先级支流到达。
- 不属于主干道。
- 结构上是水渠。

支流结构可以存在但没有水。

### 7.2 支流终点选择

支流按顺序生成：第一支流、第二支流、第三支流，依此类推。

选择某条支流终点时：

1. 只在可到达、非主干、尚未作为支流终点的水渠格中选择。
2. 优先选择高度最高的格子。
3. 同高度时选择 `x` 最小的格子。
4. 如果某个最高高度层候选都已经用完，则自动往下一高度层继续轮询。

当系统选定某格作为支流终点时，场上不应再存在：

- 未被分配；
- 高度更高；
- 或同高度但更靠近 `x = 0`；

的支流终点候选。

换句话说，支流终点严格按：

`高度从高到低，同高度 x 从小到大`

依次轮询。

### 7.3 支流路径与共享流经点

- 某个水渠格可以作为多个支流的流经点。
- 支流不是互斥占格。
- 一个水渠格作为流经点可以被多条支流共享。
- 一个水渠格作为支流终点只应被选择一次。

选择下一条支流终点时：

- 排除主干格。
- 排除已经作为支流终点的格子。
- 不排除已经作为其他支流流经点的格子。

已由主干或更高优先级支流供水的共享流经格：

- 不参与当前支流均分对象数量。
- 不重复占用水池水量。
- 不重复产生滋养度。
- 不被后续支流覆盖归属编号；例如 `(0,1)(1,1)(2,1)` 中，若 `(0,1)` 为主干，则 `(1,1)` 归第一支流，`(2,1)` 归第二支流。

### 7.4 全量归类

所有可达、非主干的水渠格，最终都应被归入某条支流结构。

即使供水时拿不到水，也仍然是结构支流；当前 tick 滋养度可以为 `0`。

## 8. 供水分配规则

### 8.1 总顺序

水池供水总顺序：

1. 主干道。
2. 第一支流。
3. 第二支流。
4. 第三支流。
5. 依此类推。

不按比例分水。更高优先级路径先计算，剩余水量再给下一条路径。

### 8.2 水池不受水渠容量反向限制

水池是供水源头，不受水渠容量反向限制。

水池当前滋养度只受以下因素影响：

- 自身基础水分滋养度。
- 主干不足均分。
- 实际分配给有水水渠的占用量。
- 水渠网络断开 / 重算结果。

### 8.3 按实际分配占用水池水量

水渠占用水池水量时，按本 tick 实际获得的水量计算，而不是按自身容量直接扣除。

例如：

- 某水渠容量为 `4`。
- 因上游瓶颈实际只获得 `2`。
- 则它只占用水池 `2`。

共享流经点即使被多个支流经过，也只按实际水量占用一次。

## 8.4 支流窃流（池升级特效）

**定位**：在同一 tick、**不增加** `basePoolWater` 的前提下，把**牺牲支流**本 tick 已落在渠格上的清水总量减少，再把等量（首版无损耗）灌入**受益支流**的渠格；每格仍受 **`capacity` 硬上限**。

### 8.4.1 玩家设置（存档）

`agriculture_map.pool_theft`（池等级 ≥ 2 且升级解锁后可用）：

| 字段 | 含义 |
|------|------|
| `enabled` | 是否启用 |
| `victim_branch_index` | 牺牲支流编号（与 `branch.index` 一致，从 1 起） |
| `gain_branch_index` | 受益支流编号 |

**约束**：`victim_branch_index < gain_branch_index`（只从**分配顺序更靠前**的支流扣，补给更靠后的支流）；**不得**选主干道；两指数不同且对应支流本 tick 存在。

### 8.4.2 扣水：整条支路总水量（比例缩）

在 §8.1 清水分配**完成之后**（§15.0 步骤 **1b**）：

1. 收集牺牲支流上所有渠格（`branchIndex === victim`，且非 `isTrunk`），求 **`W_victim = Σ water`**。
2. `transfer = min(THEFT_TRANSFER_CAP, W_victim)`（`THEFT_TRANSFER_CAP` 由池等级查表，如 2～4）。
3. 若 `W_victim > 0` 且 `transfer > 0`，对牺牲支流**每一格**（同上集合）：
   - `water := round1(water × (W_victim - transfer) / W_victim)`  
   即该支路**总水量减少 `transfer`**，各格按原比例同步缩小（不是从终点逐格抠）。

不扣：池 `poolCurrent`、主干道渠格、其它支流、作物 `waterAbsorbed`；不搬 `seaweedConcentration`。

### 8.4.3 加水：按 headroom 比例灌入受益支流

1. 收集受益支流同类渠格，算 `headroom_i = capacity - water`，`H = Σ headroom`。
2. 若 `H = 0`，本 tick 受益侧**实际灌入 `delivered = 0`**；`pool_level < 4` 时未灌入的 `transfer` **作废**；`pool_level >= 4` 时见 **§8.6**（溢流进蓄水池）。
3. 若 `H > 0`：每格增加 `transfer × headroom_i / H`，落格 `round1`，且 **`water ≤ capacity`**；记本 tick 受益侧实际灌入总量为 **`delivered`**（实现按落格增量汇总，含舍入误差）。
4. **`pool_level >= 4`**：`overflow = max(0, transfer - delivered)`，按 **§8.6** 计入 `pool_reservoir`（`delivered` 已含 `H < transfer` 时只灌满空余的情形）。

### 8.4.4 与 §9、浓度的关系

- §9 主干不足时，支流格上 `water` 可能为 0 → `W_victim = 0`，本 tick 窃流无效。
- 牺牲支路缩 `W` 后 `C` 不变，可能出现 **C/W 升高**、更易爆发；窃流只挪清水。

## 8.5 蓄水池（池三级 · 配合天气）

**定位**：不提高常态 `基础PoolWater = 200`。主游戏**游戏内一日**根据天气/事件给出当日池预算 `pool_budget_effective_day`；农业地图**每个全局 tick** 用同一数值，在清水分配前与蓄水池结算，得到本 tick 用于 §8～§11 的 **`pool_budget_for_allocation`**（仍常以 200 灌渠，旱时由蓄水池补差）。

**解锁**：`pool_level >= 3`（配置见 `data/agriculture-pool-upgrades.json` → `reservoir`）。

### 8.5.1 输入（主游戏 → 农业）

| 字段 | 含义 |
|------|------|
| `pool_budget_effective_day` | 当日天气/事件后的池预算（无事件时 = 200）。**同一游戏日内所有农业 tick 相同**；跨日由天气系统更新。 |

农业模块**不**自行 roll 天气；只读主游戏注入（或 demo 调试覆盖）。

### 8.5.2 蓄水池存档

`agriculture_map.pool_reservoir`：

| 字段 | 含义 |
|------|------|
| `stored` | 当前蓄水量，`0 .. capacity_max` |
| `capacity_max` | 上限，首版 **50000**（升级表可读） |

常态基线 **`baseline_pool_water = 200`**（与 §2.1 一致）。

### 8.5.3 每 tick 结算（步骤 0，早于 §8.1）

记 `E = pool_budget_effective_day`，`B = baseline_pool_water`（200），`R = pool_reservoir.stored`，`Cap = capacity_max`。

1. **涝（`E > B`）**  
   - `surplus = E - B`  
   - `R := min(Cap, R + surplus)`；若 `R + surplus > Cap`，超出部分**浪费**（不进渠、不回池面）。  
   - `pool_budget_for_allocation = B`（本 tick 灌渠仍按 200，不因暴雨本 tick 变为 230）。

2. **旱（`E < B`）**  
   - `deficit = B - E`  
   - `draw = min(deficit, R)`；`R := R - draw`  
   - `pool_budget_for_allocation = E + draw`（最多补回 **B**；蓄水池空则低于 B）。

3. **平（`E === B`）**  
   - `pool_budget_for_allocation = B`；`R` 不变。

本 tick 清水分配、§9 主干不足判定、池 `poolCurrent` 初始可分配量均以 **`pool_budget_for_allocation`** 为源头预算（实现可与 `state.basePoolWater` 本 tick 快照对齐，勿与升级表静态 `base_pool_water` 混名）。

### 8.5.4 与其它规则

- **§8.4 窃流**（步骤 1b）：仅挪支路渠格清水；**默认**不改动 `pool_reservoir.stored`。**例外**：`pool_level >= 4` 且本 tick 窃流产生 **§8.6 溢流** 时，在 1b 末尾回蓄。
- **不抬永久 200**：天气只改当日 `E`；蓄水池为**跨 tick / 跨日**缓冲。
- **Demo**：可无完整天气；侧栏下拉注入 `pool_budget_effective_day`（如晴 200 / 雨 230 / 旱 150）验证蓄放；金币升级 **1→2：100、2→3：200、3→4：350**（`tools/agriculture-irrigation-demo.html`，与主游戏材料表分离）。

## 8.6 窃流溢流回蓄（池四级）

**定位**：与 **§8.5** 共用同一 `pool_reservoir`；不提高常态 200，不在本 tick 因溢流而额外灌渠。

**解锁**：`pool_level >= 4`（`data/agriculture-pool-upgrades.json` → `theft_overflow_to_reservoir: true`）。须已具备 §8.5 蓄水池（四级配置保留 `reservoir.enabled`）。

### 8.6.1 触发与计量

在 **§8.4** 本 tick 已扣牺牲支路水量、并完成 **§8.4.3** 向受益支路灌入后：

- `overflow = max(0, transfer - delivered)`  
  - `transfer`：本 tick 计划从牺牲支路移出的水量（§8.4.2）。  
  - `delivered`：受益支路渠格**实际增加**的水量之和（含 `round1` 汇总；`H = 0` 时为 0）。

### 8.6.2 回蓄规则

- 若 `overflow > 0`：`pool_reservoir.stored := min(capacity_max, stored + overflow)`。
- 若 `stored + overflow > capacity_max`：超出 **capacity_max** 的部分**浪费**（与 §8.5.3 涝溢一致）。
- **不进**本 tick `poolCurrent`、不直接加受益/牺牲支路其它格、不搬 `seaweedConcentration`。
- 旱日步骤 0 可从 `stored` 扣减以补 `pool_budget_for_allocation`（§8.5.3），与天气入蓄共用同一库存。

### 8.6.3 与等级梯关系

| 等级 | 窃流 cap | 蓄水池 | 窃流未灌满时 |
|------|----------|--------|----------------|
| 2 | 2 | — | 作废 |
| 3 | 2 | 天气涝/旱 | 作废 |
| 4 | 4 | 天气涝/旱 | **溢流回蓄** |

## 9. 主干供水不足

### 9.1 触发条件

当水池基础水分滋养度不足以满足整个主干道满水需求时，进入主干不足分配。

条件：

`水池基础水分滋养度 < 主干道容量总和`

### 9.2 平均分配

主干不足时，总水量在以下对象之间平均分配：

- 水池自身。
- 主干道上的每一格水渠。

公式：

`单对象滋养度 = 水池基础水分滋养度 / (1 + 主干道水渠格数量)`

结果：

- 水池当前滋养度 = 单对象滋养度。
- 每格主干水渠当前滋养度 = 单对象滋养度。
- 所有支流当前滋养度 = `0`。

该平均分配按对象数量计算，不按容量比例。

## 10. 容量传递限制

### 10.1 基本规则

任意水渠的实际水量都受来源格限制。

统一公式：

`某格水渠实际水量 = min(自身容量, 来源路径上的上游瓶颈, 当前剩余可分配水量)`

水池作为源头时，水池基础水分滋养度是整条路径的初始上限。

### 10.2 主干示例

主干顺序：

`水池 -> A -> B -> C -> D`

如果：

- `A.容量 = 2`
- `B.容量 = 4`

即使 `B` 自身最多能装 `4`，但它的水来自 `A`，而 `A` 最多只能形成 `2` 的水流能力。

因此：

`B.当前水量最多 = 2`

### 10.3 支流同样适用

支流也遵循相同容量传递限制。

例如：

`主干格 M -> 支流 A -> 支流 B`

如果：

- `M.当前水量 = 3`
- `A.容量 = 2`
- `B.容量 = 5`

则：

- `A.实际水量 = min(2, 3) = 2`
- `B.实际水量 = min(5, 2) = 2`

下游不能因为自身容量更大就超过上游来源格的实际水量 / 可传递上限。

## 11. 支流供水不足

### 11.1 触发条件

当某条支流获得的可分配水量不足以充满该支流路径上的所有水渠时，进入支流不足分配。

条件：

`支流可分配水量 < 支流路径水渠容量总和`

### 11.2 平均分配

支流不足时，按该支流中尚未由更高优先级路径供水的路径格数量平均分配。

公式：

`支流单格水量 = 支流可分配水量 / 当前支流参与均分的水渠格数量`

参与对象：

- 当前支流路径上的水渠格。
- 不包括水池。
- 不包括主干道。
- 不包括已经由主干或更高优先级支流供水的共享流经格。

支流入口来源格不被支流抽干：

- 入口格水量只提供支流每格可获得水量的上限。
- 真正减少的是水池总可分配额度。

### 11.3 小容量格限制下游

支流内部按路径顺序传水。某格容量较小时，会限制它之后的下游水量，但不会反向限制它之前的上游格。

例如支流路径：

`A -> B -> C`

如果均分基准为 `2`：

- `A.容量 = 1`：`A = 1, B = 1, C = 1`，整条支流实际消耗 `3`。
- `B.容量 = 1`：`A = 2, B = 1, C = 1`，整条支流实际消耗 `4`。
- `C.容量 = 1`：`A = 2, B = 2, C = 1`，整条支流实际消耗 `5`。

可记为：

`某格实际水量 = min(均分基准, 自身容量, 上游实际水量)`

如果支流入口来源格只能提供 `2` 的水量上限，则该支流均分后的每格水量也不能超过 `2`。

## 12. 作物受水来源

作物不会叠加多个水源的滋养。

即使一个作物同时邻接水池和多个有水水渠，也只接受一个来源的滋养。

作物受水来源从已计算出的主干和支流中选择：

- 只考虑当前供水网络中已归类且有水的路径。
- 不直接从任意结构水渠取水。

唯一滋养来源选择规则：

`作物受“去往水池最短路径上的、最靠近 x=0、并且高度最高的有水水渠”滋养。`

当前可执行理解：

1. 找出作物上下左右邻接的有水水渠。
2. 这些水渠必须属于主干或支流路径。
3. 在候选中，优先选择其回到水池的路径最短者。
4. 若路径长度相同，选择路径上更靠近 `x = 0` 的候选。
5. 若仍相同，选择高度更高的候选。
6. 作物只获得最终来源水渠的当前实际水量对应的滋养。

### 12.1 微量元素来源（与受水同源）

- 作物吸收**渠内海藻精（微量元素）**时，**不**单独再选一套邻接规则；与 §12 使用**同一株作物、同一 tick** 下选定的**唯一有水滋养来源水渠**（同一格邻接水渠）。
- 该来源格上的 **`海藻精浓度`**（§15.4，不同来源叠加后的格上总浓度）即本 tick 可供吸收的**对应浓度**；来源格无水或浓度为 `0` 时，本 tick 微量元素吸收量为 `0`。
- 不叠加多格浓度：即使邻接多格有水且各有浓度，作物每 tick 只从 §12 选定的那一格取浓度，与水分「只吃一源」一致。

## 15. 文丘里施肥器：海藻精检测与渠内输送

本节约定 **海藻精**（`liquid_seaweed_extract`）在施肥器**持续效果生效期间**（见 §2.2d）是否向水渠输送，以及浓度在渠内的**持续状态**。输送分两套逻辑：

| 逻辑 | 标识（demo） | 概要 |
|------|----------------|------|
| **B 面**（**默认**） | 无超融合时 | §15.6：**有水 + 罐内海藻精效果存续**即向归属水流维持（不检测作物请求）。 |
| **A 面** | 场上有 **超融合**（§2.2g）时，**全场**文丘里切换 | §15.1～§15.3：先扫描**已登记且可达**的作物请求，无请求则不输送。 |

效果 tick 归零后，该施肥器不再维持渠内浓度。**无邻接有水注入口**或**沿水流不可达终点**时两种逻辑均**不输送**。A 面另加「无请求则不输送」。顶栏药丸显示当前有效逻辑（是否因超融合切到 A 面）。

### 15.0 每 tick 结算顺序（农业地图）

每个全局 tick，农业地图相关结算**固定顺序**为：

0. **蓄水池与当日池预算**（§8.5，`pool_level >= 3`：由 `pool_budget_effective_day` 与 `pool_reservoir` 得出 `pool_budget_for_allocation`；未解锁则 `pool_budget_for_allocation = 200` 或当日 `E` 若主游戏已统一注入）；
1. **清水分配**（§8～§11，含水池 / 主干 / 支流水量；源头预算为步骤 0 的 `pool_budget_for_allocation`）；
1b. **支流窃流**（§8.4～§8.6：牺牲支路比例缩 → 受益支路按 headroom 灌入；`pool_level >= 4` 时未灌满的 `overflow` 记入 `pool_reservoir`）；
2. **海藻精维持 / 注入**（§15.1～§15.4，所有生效中的施肥器）；
3. **水藻爆发判定**（§4.3，逐格更新有水水渠 `algae_bloom`）；
4. **作物吸收水分**（§4.2）；
5. **作物吸收微量元素**（§4b.1c，仅生长中）；
5a. **微量排斥结算**（§4b.1g，仅 `trace_sensitivity` 作物）；
5b. **埋地陶瓮向八邻格作物施肥**（§4b.1d / §2.2e，仅生长中）；
6. **水藻爆发扣健康**（§4.3，生长中且来源渠爆发：健康 −2）；
7. 其余（生长倒计时、**文丘里 / 埋地陶瓮**罐内持续效果 tick 递减、健康度归零检查等，见 §4b.1b）。

### 15.1 总原则（A 面）

以下 §15.1～§15.3 仅适用于 **A 面**；**B 面**见 §15.6。

- 施肥器先确认自身 **水流归属**（§2.2d，只看邻接有水水渠），再在 §15.2 范围内扫描**已登记且可达**的海藻精请求。
- **注入语义（持续状态）**：在罐内海藻精效果存续期间，只要本 tick 对某条水流满足输送条件，即对该次路径上的有水水渠施加 / **维持**海藻精浓度状态（按 §15.4 均分后的份额）；效果 tick 内**稳定保持**该份额，而非仅当 tick 脉冲一闪即逝。本 tick 条件不满足时，该施肥器在该水流上**不维持**（不写浓度）。
- **无请求则不输送**：扫描范围内没有任何「可到达且已登记请求」的作物 → **不**向水渠写入 / 维持浓度。
- **有请求才输送**：见 §15.3（同一水流最多响应一株）；执行 §15.4：**先判定注入方向** → **唯一**邻接有水水渠为入口 → 沿水流维持至终点。

### 15.2 检测范围（按施肥器水流归属）

扫描哪几条水流，由施肥器绑定的归属决定：

| 施肥器归属 | 检测的水流（顺序） |
|------------|-------------------|
| **第二支流** | 仅 **第二支流** |
| **第一支流** | 仅 **第一支流** |
| **主流（主干）** | **主流 → 第一支流 → 第二支流 → …**（按编号递增，直至当前网络已识别的全部支流） |

归纳：

1. 若施肥器属于 **支流 #N**（如第二支流），则**只检测支流 #N** 路径上的作物请求。
2. 若施肥器属于 **主流（主干）**，则按 **主流 / #1 / #2 / …** 依次检测；**可对主流、#1、#2… 各执行至多一次注入 / 维持**（每条水流独立判定，§15.3、§15.4）。

支流编号、主干路径定义见 §6、§7。作物请求登记须邻接有水水渠（§4b.1a）；作物与水流对应关系与 §12 一致。

### 15.3 作物「请求海藻精」与可达性

- **请求来源（与 §4b.1a 一致）**：仅 **`requests_seaweed_extract === true`** 的作物会登记请求；施肥器**只响应**当前检测水流上**已有活跃登记**的请求，未登记则不计入 §15.1。
- **请求挂在哪条水流上**：播种时该作物向**主流**登记；若受水归属为支流 #N，还向**支流 #N** 各登记一条（同一株作物可在主流 + 一条支流上各有一条请求记录，供不同归属的施肥器扫描）。
- **施肥器如何看到请求**：
  - 归属**支流 #N** 的施肥器（§15.2 只扫 #N）：只匹配登记在**支流 #N** 上的请求作物（含「归属 #N、且已向 #N 登记」的株）。
  - 归属**主流**的施肥器（§15.2 扫主流 → #1 → #2 …）：可匹配登记在**主流**上的请求，以及按 §15.2 顺序扫描到的各支流上已登记的请求（同一株若同时登记主流与支流，主流施肥器在扫到对应支流时也可命中该株）。
- **路径计算**：对每一株在本轮检测水流上命中的候选作物，以**该次检测所对应的水流**（主流或某支流）为输送服务对象，以 §15.4 选定注入方向上的**那一格**邻接有水水渠为起点，按 **§3.2 有效供水** 沿该水流朝向**该水流终点**（§6.3、§7.2）计算到达路径。
- **高度约束（与清水一致）**：海藻精在水渠中只能流向**不高于**当前格高度的邻接有水水渠（与清水有效供水方向一致）。路径上若出现需经过**向上**（目标格高度 > 当前格）的水渠才能抵达该作物，则判定**无法到达**，该作物不计入可输送目标。
- **同一水流内至多一株**：每条水流（主流或某支流 #N）在本 tick 内**最多响应一株**「已登记、可达」的请求作物；多株候选时按 §15.2 扫描顺序取**第一株**命中者，其余本 tick 不服务。
- 施肥器**四邻接无任何有水水渠** → 本 tick **不输送**（即使远处有请求）。
- 已**成熟待收获**的作物：请求**保留**，施肥器仍可为流经其所在水网的渠格**维持浓度**；但该作物**不再吸收**微量元素（§4b.1c）。

### 15.4 注入、流动终点与浓度均分

**注入方向（先判定向哪里注，且只注一个方向）**

- 确认存在可到达的请求作物后，**先**在施肥器四邻接（上/下/左/右，§3.1）中判定**唯一注入方向**：该方向上的邻格必须是**有水水渠**，且从该格出发能沿 §15.3 规则抵达本次要服务的请求作物 / 对应水流终点。
- **单方向硬约束**：每个施肥器每 tick（或每次输送结算）**只向一个方向**注入；即使四向都有邻接有水水渠，也**不得**同时向多格注入。
- 若四向中有多向均满足「可达」，择向规则（强制）：**先**按本次水流优先级（主流先于 #1 先于 #2……），**同水流内**按 §3.1 `下 -> 右 -> 左 -> 上` 取第一个合法方向。
- 若**没有任何**邻接方向能同时满足「邻格有水水渠」且「从该格可达目标」，则本 tick **不注入**（与 §15.1 无输送一致）。

**注入点**

- 方向判定完成后，仅向该方向上的**那一格**有水水渠注入海藻精；其它三向邻接水渠本 tick 不参与入口浓度。

**流动方向与终点**

- 注入后，海藻精沿**该次输送所服务的水流**在渠内前进，规则与清水一致：仅沿有效供水方向（高度不升）在**有水水渠**上扩散，直至该水流的**终点**（该支流或主干路径的终点格，§7.2、§6.3）。
- 浓度分配以**注入口之后**至该水流终点之间、海藻精实际流经的有水水渠格为准（**不含**注入口格本身，见下）。

**设定浓度、均分与持续状态**

- 施肥器使用 UI 设定的 **`海藻精输送浓度`**（设定浓度）；对该次「注入口 → 水流终点」路径写入**持续状态**：在效果 tick 存续且本 tick 该水流仍满足 §15.1 时，**每 tick 按相同份额刷新**（同来源覆盖，不累加）。
- **均分（入口后）**：
  - `单格海藻精浓度 = 设定浓度 / 入口后至终点之间的有水水渠格数`
  - **注入口格本身不计入**分母与分子（入口格不承载本次均分浓度，或视为 0，以实现登记为准）。
- **示例**：设定浓度 `10`，入口后途经 `10` 格有水水渠至终点 → 每格 `1.0`。
- 无水水渠不参与均分、不承载浓度、不传递。
- **§5 水道重算**：重算完成瞬间**立刻清空**全场渠内海藻精浓度；本 tick 后续在 §15.0 顺序中再按新网络重新维持。
- **不设**单格浓度上限（玩家通过调低设定浓度自控）。

**来源、叠加与不叠加（强制）**

- **来源**定义：一次完整的「某施肥器在本 tick 对**一条水流**向唯一方向维持 → 沿该水流均分至终点」为**一条来源**。**不同施肥器**、**同一施肥器同一 tick 对主流与 #1 / #2 的多次维持**，均视为**不同来源**（可叠加）。
- **同来源不叠加**：同一来源对同一格有水水渠，在本 tick 内**只计一份**均分贡献。该来源的均分链若因网络结构使同一格被途经多次、或重复参与结算，**不得**把同来源贡献相加；以该来源本次输送按 §15.4 算出的**单格份额**为准（写入时覆盖同来源在该格的旧值，而非累加）。
- **不同来源才叠加**：格上展示的 **`海藻精浓度`** = 各**不同**来源贡献之和：
  - `格上海藻精浓度 = Σ_k c_k`（`k` 为来源编号；每个来源对应该格至多一项 `c_k`）。
  - **禁止**对不同来源做 max、禁止后写入来源覆盖先写入来源；**禁止**把同来源多次命中同一格累加。
- 结算顺序建议：先按来源各自完成均分，得到该来源在途经每格的 `c_k`（每格唯一）；再对同一格将不同来源的 `c_k` **相加**。
- **示例（不同来源叠加）**：施肥器 A 设定浓度 `10`、流经 `10` 格，每格贡献 `1`；施肥器 B 设定浓度 `6`、流经 `3` 格，每格贡献 `2`。两股在某格交汇 → 该格 `1 + 2 = 3`。
- **示例（同来源不叠加）**：仅 A 输送且某格在路径上只应分到 `1`；即使实现上对该格触发了两次同来源结算，该格来自 A 的贡献仍为 `1`，不是 `2`。
- 计算过程可保留小数；**落格显示**可与清水水量一致，保留 **1 位小数**（§4.1）。实现上可为每格维护 `来源 id → 贡献` 映射，再求和得到总浓度。

**与清水关系**

- 海藻精流动**不替代**清水供水与滋养结算；作物侧每 tick 按 §4b.1c、§12.1 从来源格浓度吸收微量元素，与 §4.2 水分并行、互不抵扣。
- 同一格同时有清水水量与海藻精浓度时，两者独立存储；清水仍受容量与 §8～§11 分配约束。
- 水量与浓度比例触发 **§4.3 水藻爆发**（叠加后的 `C` 与 `W` 实时比较）；爆发**不**清除浓度、**不**阻止维持注入。

### 15.6 B 面逻辑（无作物请求检测）

与 A 面**共用** §15.2 水流扫描范围、§15.4 注入方向 / 均分 / 多来源叠加、§15.0 tick 顺序；**唯一差异**为输送前置条件。

**每 tick、每条归属水流**（主流施肥器仍可对主流 / #1 / #2… 各维持一次），当且仅当同时满足：

1. 施肥器 **罐内海藻精效果存续**（`liquid_seaweed_extract` 持续型，与 A 面相同）；
2. 施肥器 **四邻接至少一格有水水渠**（有「水」可注）；
3. 能解析 **水流归属**（§2.2d）；
4. 能在四邻中选出 **唯一注入方向**：邻格为归属该水流的**有水水渠**，且从该格沿该水流**有效供水方向**可抵达该水流**终点**（§6.3、§7.2；**不要求**途经或指向任何作物）。

则对该水流执行 §15.4 维持（设定浓度均分至注入口后至终点之间的有水渠格）。**不读取** `seaweedRequests`、**不调用** §15.3 请求扫描；`requests_seaweed_extract` 与是否登记请求**不影响** B 面输送。

**仍不输送**的情况（与 A 面部分相同）：

- 无海藻精效果 / 四邻无有水渠 / 无水流归属；
- 无任何注入方向能抵达该水流终点；
- 入口后至终点之间无有水渠格（分母为 0）。

**与作物吸收**：渠内浓度维持后，生长中作物仍按 §4b.1c 从 §12 滋养来源吸收微量元素；B 面可在**无种植、无请求**时仍润渠（例如空渠预调浓度），已成熟作物仍不吸收。

**存档 / 配置**：demo 由 `anySuperFusionOnMap()` 推导有效逻辑，**不**单独存档 per-venturi 面；正式服以场上超融合数量/建筑为准。

**与 §2.2g 超融合**：场上有超融合 → 本节 A 面；无超融合 → 默认 B 面（§15.6）。

### 15.5 实现待挂钩（占位）

- 各作物 **`累计微量元素`** 成熟 / 完美区间：种植篇按作物单独配置；与水分 **AND**（§4b.1c）。
- 施肥器等级与浓度范围见 §2.2d 表。
- §4.3 常量表与 `algae_bloom` 地图样式：农业实现 + demo 必须；**不要求**玩家向提示/日志。
- 农业 UI **不要求**调试层展示请求标记 / 注入方向 / 逐格浓度（策划对账用日志可选）。

## 16. 本体接入：库存与建造（已定案）

本节单独阅读即可把握本体移植的 tick 分工、库存扣物、入口与首版范围；规则细节仍以 §1～§15 与下列数据表为准：

- **`data/agriculture-crop-defs.json`**：作物模板、生长分、收获产出
- **`data/agriculture-soils.json`**：土壤锁值与土性融合
- **`data/agriculture-build-costs.json`**（`schema_version` 2）、**`data/agriculture-item-params.json`**

§2.2d～§2.2f 等小节中残留的 **Demo 金钱 / 临时背包 / 商店** 表述**不适用于本体**；本体建造与升级以 **§16.5** 材料表为准。

### 16.1 入口、地图与首版范围

- **单图 `11×11`**（`x,y = 0..10`，水池 `(0,0)`，默认盐碱土等见 §1）；**不以**旧索引或 demo 中的 33×33 为准。
- **入口**：仅藏身处农业 NPC；玩家**邻格点格** `interactNpc` 打开农业面板（新内容走 NPC 管线，直开面板仅作旧内容兼容）。
- **首版全量（一次交付）**：种植 + 收获 + 灌溉 + 文丘里 / 埋瓮 / 超融合 + 客土 + 耕地建造物；**不分**「无灌溉先试玩」阶段。

### 16.2 全局 tick 与工程进度（分工）

- **作物生长（全局）**：玩家解锁农业后，**每个 world tick** 须执行 **1 次** `runAgricultureMapTick`（任意当前地图、**面板开闭无关**）；地图内结算顺序见 **§15.0**。
- **工程（仅开面板）**：挖渠、拆渠、开垦、文丘里 / 埋瓮 / 超融合 / 耕地建造物等**工程 task 的 tick 推进**，仅在 **`agriculturePanelOpen === true`** 时结算；**关面板冻结工程进度**，作物仍随全局 tick 生长。
- **面板内耗时操作**：须调用与制肥一致的统一 **`advanceTick(n)`** 推进 world tick；**禁止**农业私有时钟。

### 16.3 库存与扣物

- **无独立农业经济**：不实现 Demo 的金钱、商店、交易额；种子与投入品仅来自主游戏物品链。
- **库存范围**：扫描并扣减 **口袋 / 背心 / 背包 / 载具**（`inventory_vehicle` 在已绑定载具时）及 **`hideout_warehouse`**（藏身处账号仓库，见 [29-hideout-warehouse.md](29-hideout-warehouse.md)）。**玩家可选「优先扣仓」**（`prefer_deduct_warehouse`）；未勾选时默认先扫身上四容器。扣物仍走 **`AgriculturePlayerItems`** 统一枚举，农业业务逻辑不改。
- **扣物唯一入口**：`AgriculturePlayerItems` + `AgricultureConfig`（`js/agriculture-player-items.js`、`js/agriculture-config.js`）；**禁止**农业 UI 自写扣物逻辑。
- **种子列表**：`items.json` 中 `sub_category === 'seed'`（或等价 tags）；农业 UI 只列出上述容器内 `count > 0` 的种子，播种扣 1。
- **客土**：制造产物，物品带 **`grants_soil_id`**（缺省时见 `data/agriculture-item-params.json` → `soil_amend_fallback`）；对空茬耕地使用并扣 1 件。
- **海藻精 / 液态肥**：同上容器；注入资格与数值读物品模板，缺省读 `agriculture-item-params.json` → `injectables`。埋地陶瓮 **`agriculture_fertilizer_per_tick`** 按沤肥三档产物区分（示例 id：`fertilizer_basic_low` / `fertilizer_basic` / `fertilizer_compost_plus`）。

### 16.4 收获、累计条与熟练度

- **`traceAbsorbed` / `fertilizerAbsorbed` 分轨**：渠内微量元素与埋瓮施肥值各自累计（§4b.1c / §4b.1d），**禁止**混写或互相抵扣。
- **收获熟练度**：实际**入背包成功**的 **`harvestCount` 份** → `life_planting` 熟练度 **+harvestCount**；调用 `incrementSkillMoveUsage('life_planting', 'harvest', n)` 后须 **`recalcCharacterStats()`**（背包满导致未入袋的份数不计）。

### 16.5 建造与升级

- **不扣金钱**；开工扣 **`data/agriculture-build-costs.json`** 的 `inputs`，工程消耗 **`task_ticks` × `stamina_per_tick`**（默认 10 tick × 5 体力）；文丘里升级同理（材料 + tick）。取消工程且条目 `refund_inputs_on_cancel` 时退回已扣材料。
- **建造材料（已定案，`schema_version` 3）**：仅用 `items.json` 已有 id——竹木：`wood_bamboo_green` / `wood_plank_soft` / `wood_shrub_dry`；陶：`ore_clay_raw`；绑扎：`supply_rope_hemp_short`；堆肥基质：`compost_matrix_grade_low`（开垦/填渠）/ **`compost_matrix_grade_high`**（超融合）；**挖渠**：青竹杆；**开垦**：枯灌木+散碎腐熟基质；**升级水渠**：陶土抹渠壁+竹加固；**文丘里**：陶+竹+轻木板+绳；**埋地陶瓮**：陶土×4 + **`tool_pickling_jar_cooking`（腌缸广口密封，不扣灶台饭锅/酸奶发酵坛）**；**超融合**：木板+竹+陶+绳+细腐熟基质；文丘里 2→3 级 **`ore_iron_raw`**×1。拆除不耗材。完整条目见 **`data/agriculture-build-costs.json`**。
