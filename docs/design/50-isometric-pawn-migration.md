# 50. 棋子式斜俯视改造：C / 45°

> 2026-09-14 美术定稿补充：新制/重制棋子以[棋子形象与落地表现规范](51-pawn-art-direction.md)及通勤装v4为准。下文占位棋子说明属于第一阶段历史记录。

状态：第一阶段正式游戏试用版已接入，等待实玩反馈。2026-09-13。
目标：用真实地图、角色、视野与交互验证 C / 45° 棋子视角；通过体验验证后再逐步补美术。

## 1. 已确认的决定

- C：菱形棋盘、镜头与地面夹角 45°。B 与 70°/80°是探索历史，不是最终选择。
- 地块厚度 30，指原型基准地块尺度下的视觉参数，不是新增高度规则。缩放时等比调整。
- 棋子保持直立、简化人形、底座和接触阴影；这是风格化二维表达，不需要真实三维模型或俯视头顶素材。
- 内部等高格子用细缝和轻微倒角连成整体。完整侧壁仅用于真实地形边缘；不可把每格画成独立键帽。
- 保留地图方向 WASD：W 地图北，在屏幕上为右上；A 左上；S 左下；D 右下。组合键沿用正式游戏既有对角移动规则。屏幕方向映射已弃用。
- 移动同步更新朝向与视野。
- Shift + 点击周围格子：原地转向，不移动、不攻击、不交互。点击自己不操作。周围格按八邻格实施；非邻格 Shift 点击忽略，避免误触其他动作。此八邻格边界是落实“周围格子”的实现口径。
- 格内有敌人或设施时 Shift 点击仍只转向。允许面向邻接障碍格；转向不等于通行。
- 不引入 Shift+WASD 转向方案。
- 移动和转向耗时沿用现有正式规则；先查代码与设计，再复用，不能从原型推导新数值。

## 2. 第一阶段交付范围

实现可供用户真实游玩的新视角，保留旧视角切换供对照与回退；无需重建游戏规则或整个美术库。

1. 统一地图到屏幕投影、反投影、格子顶点、中心、实体脚底锚点、镜头定位与可视区域裁剪。
2. 正式地图地面以菱形绘制，显示合理侧壁与落地阴影；支持已有非方形地图、切地图及视口变化。
3. 玩家和 NPC/敌人接入直立棋子/占位素材，保持既有身份与可识别信息。已有专用素材不得无理由删除。
4. 原有点击、悬停、采集、设施、敌人等交互转到统一拾取；Shift 转向必须先于普通点击分发。
5. 正式 WASD、长按、组合键、输入焦点、对话/弹窗/禁行动条件全部保持原规则；处理失焦松键，避免粘键。原型不是输入系统实现模板。
6. 朝向标记根据投影后的向量绘制，不能直接拿世界角度画屏幕箭头。
7. 迁移真实视野、昼夜光照、地形遮罩、距离衰减、对象识别/细节与背后隐藏；同一世界状态下可见集合不应因视角改变。
8. 饥饿脚下效果投影到当前地面，棋子直立。动作气泡、文字提示保持屏幕正向和可读。
9. 接好已有战斗/移动特效的位置与遮挡，不能让既有功能消失。新的攻击美术体系不属于第一阶段必交付。

## 3. 不变的世界规则

地图坐标、邻接、寻路、碰撞、攻击距离、视野判定、时间消耗、存档数据保持原义。视角是表现，不是地图旋转或地图 JSON 重写。

键盘方向优先在世界坐标产生意图，再投影到屏幕。Shift 转向产生朝向意图后由现有动作/时间通道结算，不能直接绕过规则改状态。

所有对象隐藏遵循当前认知/识别限制：不应通过轮廓、底座、阴影、特效、悬停文字泄露不可见敌人。仅“可见但被美术遮住”的角色可使用淡化或轮廓提示。

## 5. 关键风险与实现建议

- 当前很多格子和遮罩按同一个 cellPx 计算宽高。不能仅用 CSS 旋转压缩整张画面，否则文字、人物、点击和阴影会错位。
- 格子反投影须包含镜头偏移和缩放；边缘与格缝拾取需稳定。厚度侧壁不得误算成地图外邻格。
- 实体伸出脚下格子，局部清格可能擦掉邻格棋子或留下残影。初版可以对视口内动态层完整重画，再依据性能验证优化。
- 实体按脚底投影深度排序。遮罩应隐藏实体整体，不能只盖住脚底格导致头露在视野外。
- 地块侧壁与暗区一起处理。原型在 C 的右侧壁遮罩、背景投影处仍可能有漏亮，不能照抄为正式完成版。
- 视野边界不是物理悬崖，不能在可见/不可见交界自动加厚侧壁。
- 原型中镜头未跟随角色、点击可瞬移、攻击可远距离示意、碰撞为临时规则，均不可推广到正式游戏。
- 原型固定每 180ms 一步，只为比较映射手感；不能修改正式耗时来匹配它。
- 原型视野不是完整正式渲染链，尤其完整夜间光照层未迁入。正式验收不能拿原型截图当规则金标准。
- 保留用户认可的饥饿“下垂褶皱—短促抽紧—缓慢松开”。动画偏好优先于系统减少动态设置，仅明确选择播放时覆盖；切视角/刷新后偏好仍有效。

## 6. 建议实施顺序

1. 审查当前工作区和输入/视野调用链，确定共享投影接口，保留旧渲染出口。
2. 接通真实地图、新投影、镜头、拾取与占位棋子，先验证移动和切图。
3. 接通正式朝向、Shift 点击转向与视野/光照。
4. 处理深度排序、厚度暗区、饥饿及已有特效、悬浮提示。
5. 做有意义的自动验证与浏览器实测，记录未完成项；再请用户体验。

不要为了原型观感削减真实玩法功能。遇到既有行为与设计不一致时记录事实与最小解决方案，不要顺手改战斗平衡。

## 7. 验收清单

- 新旧视角可切换；C 默认视觉参数 45°/30；地图、角色状态与存档不因切换改变。
- 投影与反投影在八方向、边界、非方形地图、镜头移动后吻合；棋子脚底准确落格。
- WASD 四方向和组合键符合地图方向；长按和松键可靠；文本输入/弹窗期间不误移动。
- Shift 点击八邻格只转向，自己/非邻格不操作，敌人/设施不触发交互；转向时间结算与原规则一致。
- 同一人物、位置、朝向和时间，旧新视角可见/识别结果一致；测试前侧后、背后三邻格、昼夜切换。
- 被规则隐藏的实体没有头像、底座、阴影、文字和特效泄露；遮挡后的重画无残影。
- 移动、交互、切图、尺寸变化后，饥饿效果、气泡和方向标记不漂移。
- 动画设置跟随系统、播放、静态均可用，刷新恢复；不能仅凭截图宣称动画已运行。
- 测试常见设施、NPC、敌人、地面物品和原有动作；测试有代表性的大地图，记录实际性能而非猜测帧率。
- 有意义的测试聚焦投影往返、事件互斥、方向/耗时与视野一致性；不要写镜像实现的无价值测试。

## 8. 后续方向（不是本轮扩项）

多种持续异常状态按完整动作顺序轮播，严重程度影响出现频率，新出现/恶化优先一次；突发受击即时反馈，暂让持续状态淡出，结束恢复。仅设计共识，尚未完整实现。
攻击强调意图、动作、结果；命中/格挡/落空需形状与运动区分。此次原型只是示意，并未定正式美术。
美术采用固定视角棋子和模块化场景逐步补充，未测量整套 token 消耗，也没有承诺固定工期或倍数。

## 9. 第一阶段实施记录（2026-09-13）

已完成：

- 新增 `js/core/map-projection.js`，统一旧俯视和 C / 45° 的格中心、顶点、世界方向投影、反投影拾取及地图画布尺寸。C 视角地块厚度固定为 30。
- `js/core/tile-renderer-v2.js` 已用共享投影绘制菱形地面、真实地图外缘侧壁、邻格/步法/玩家格覆盖层，并按棋子脚底屏幕深度绘制 NPC 与敌人占位棋子。新视角动态层整层重画，避免直立棋子跨格后的局部擦除残影。
- `js/scene-renderer.js` 的镜头、点击、悬停、昼夜层、不可视遮罩、距离暗化与现有动作特效已接共享投影；视野与识别仍在原世界格坐标中计算。
- 玩家使用固定屏幕朝向的直立棋子占位图，脚底落在玩家格中心；饥饿效果裁成脚下菱形，动作气泡保持正向。
- 窗口列表新增“地图视角”：`棋子视角 C · 45°` / `原俯视视角`。选择保存在本机，刷新后恢复；默认使用棋子视角，也可用 `?view=legacy` 临时打开旧视角。
- Shift 点击分发优先于蹑步、攻击、NPC、设施和移动。八邻格可转向，自身与非邻格忽略，障碍/敌人/设施格只改变朝向。
- 正式代码此前没有独立原地转向的耗时动作；本次复用既有 `setFacingDir`，不额外推进世界 tick，避免擅自新增战斗时间成本。若以后设计确定转向耗时，应在统一动作时间系统增加规则。
- 新增 `npm run test:isometric-map`，覆盖新旧投影在方形/非方形地图的中心点往返、地图外拒绝、WASD 屏幕象限、厚度 30 和八邻转向边界。

已验证：投影测试通过，并明确断言 `tileHeight / tileWidth = sin(45°)`；四个改动脚本通过 `node --check`；Chrome 内核正式页面无控制台错误；新旧视角切换与刷新持久化已实测；夜间视野、NPC 棋子、地图侧壁与玩家脚底对齐已在真实存档画面检查。

仍需用户实玩确认：长按/组合键手感、各种地图切换、敌人密集战斗时的深度遮挡，以及不同饥饿阶段的菱形脚下动画观感。第一阶段仍使用占位棋子和文字设施，不代表最终美术品质。
