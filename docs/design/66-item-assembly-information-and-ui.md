# 66 组合物品的信息显示与装配界面

状态：2026-09-22 已完成第一版正式接入，对应 k278 第四阶段。

本阶段把[65号设计](65-item-assembly-and-combined-weight.md)中的真实连接树接入玩家信息系统和背包装配操作。连接数据仍由 `ItemAssembly` 管理；显示层不复制连接状态，也不另建钓鱼专用装配表。

## 1. 单一显示入口

`js/item-assembly-display.js` 是连接结构的显示适配器，负责生成同一份玩家视图：

- `buildView` 从真实连接树生成认识档名称、槽位、完整性和组合重量；
- `renderAssemblyHtml` 供悬浮说明、背包详情和后续玩法窗口共用；
- `listCompatibleCandidates` 从玩家携带容器读取当前候选，不缓存库存副本；
- `messageForReason` 将装卸失败原因转换为玩家文案。

悬浮说明使用只读模式。背包详情使用可操作模式。脚下物品保持只读，需要先捡起再装卸。组合重量继续占用通用重量主显示位，装配区不重复显示同一个数值。

## 2. 玩家可见信息

连接关系属于拿在手中可以直接检查的物理事实。正式视图显示：

- 已认识的名称，或现有认识档提供的外观称呼；
- 可见连接位置及其当前是否有部件；
- 必要连接是否齐全；
- 整个组合的实际重量；
- 可以执行的连接、拆下操作。

正式视图不显示：

- `instance_id`；
- `assembly_types`、`accepts` 等内部兼容代码；
- 部件的隐藏性能、承载值、磨损原因或玩法结论；
- 根据隐藏性能生成的整套评分、弱点诊断或自动推荐。

名称仍调用 `InventoryEquipment.getItemDisplayTier/getDisplayName`。部件性能继续交给字段规则和信息模块按角色认知过滤。装配显示不会绕过这些规则读取并输出性能。

当前候选筛选依据结构连接类型，视为可以从外形和接头直接判断的机械兼容。以后若增加无法靠检查判断的暗槽、鉴定型接口或伪装部件，必须在显示适配器增加明确的可见性政策，不能直接复用当前筛选。

## 3. 正式背包操作

组合根及连接后代都可以在同一棵详情树中操作：

1. 空槽显示玩家当前携带容器中的兼容候选；
2. 连接调用 `ItemAssembly.attachFromContainer`；
3. 已占用槽位调用 `ItemAssembly.detachToInventory`；
4. 操作完成后重新从权威库存生成详情；
5. 失败原因使用统一文案，库存事务由65号契约负责回滚。

因此多层组合无需先把中间部件拆成顶层物品。例如鱼钩仍连在子线上时，可以直接在鱼钩的“钩上物”位置装卸鱼饵。拆下子线则鱼钩和鱼饵作为整棵子组合一起进入库存。

拆下后无收纳空间、候选位置已经变化、结构不兼容、循环连接或归属审计失败时，界面只报告结果，不自行补偿或修改连接树。

## 4. 重量与布局

`SceneUi.formatItemAttributes` 在实例已有连接后显示组合重量，调用 `getItemCombinedWeight`；未连接实例仍显示自身重量。装配模块只显示连接结构，避免同一信息出现两次。

正式背包沿用现有详情区样式：

- 连接状态使用“连接完整／尚未接全”；
- 层级缩进表达宿主与子部件关系；
- 空槽就地显示候选选择和连接按钮；
- 已连接部件就地显示拆下按钮；
- 不在玩家界面显示调试身份。

## 5. 验收

自动检查：

```text
npm run test:item-assembly-display
npm run test:item-assembly
npm run test:item-instances
npm run test:item-attributes
```

显示检查覆盖：

- 缺少必要部件时显示未完成；
- 候选中不出现不兼容的鱼饵；
- 玩家可见文本没有实例身份、类型代码和兼容表字段；
- 组合重量在正式悬浮说明中只出现一次；
- 认识档名称由现有物品认识接口提供。

浏览器验收仍使用 `tools/item-assembly-acceptance.html`。其中“正式玩家信息”调用游戏内同一个显示模块，可以现场拆下并接回部件；浮漂拆下后重量从 `0.526 kg` 变为 `0.506 kg`，接回后恢复。

## 6. 后续范围

本阶段完成通用显示和背包装卸，不自动向正式存档发放钓组。后续的投放、挂饵消耗、磨损、受力、断线和按实际断点损失已由[67号设计](67-fishing-session-and-real-rig-loss.md)接入；作业中同一连接树会被锁定，收回或结算后才能继续拆装。钓鱼见闻与推测仍需独立建立证据状态；连接界面不能替代玩法认知系统。
