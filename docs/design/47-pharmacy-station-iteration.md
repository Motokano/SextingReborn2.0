## 2026-11-03 底栏与帮助精简

后续制作结果卡右上角增加「×」关闭按钮，成功、失败及注射液结果共用。关闭仅隐藏本次会话的当前结果，普通重绘或重开面板不再弹出，下次制作生成新结果后正常显示；不清除实际所得、日志或设备栏损坏提醒，不新增存档字段。

用户要求直接删掉帮助，体力复用主界面的体力条，等待几秒不再提示。两套正式面板移除帮助入口、帮助内容及相关文案；底栏使用主界面同款 `metric`／`track` 样式，显示实际体力与上限，订阅状态刷新同步更新数值和条长。设备损坏率与体力条并列，数字突出显示。

取消预计等待、剩余秒数及开工消息中的时长，普通制作进行时只显示进度条和「制作中」。本节覆盖下文有关帮助及等待秒数的展示约定；实际等待仍为1000毫秒推进1世界tick，体力扣除、开工校验、设备损坏和制作所得均不变，注射液仍即时结算。

`npm run test:pharmacy` 通过两套界面的帮助移除、主界面与制药体力条数值／上限／比例同步、开工后体力刷新、等待秒数隐藏及原有1000毫秒计时和产物结算检查。

## 2026-11-03 设备入口与安装提示

用户认可将不显眼的右上角设备入口移到右侧工艺区域。新增紧凑常驻设备栏，未装设备时显示「尚未安装制药设备」与金色「安装设备」；装好后显示真实设备名称与「管理设备」；本次所用设备损坏后显示名称及金色「重新安装」。没有可用工艺时收起空工艺行，注射液模式隐藏整个设备区域。

按钮在原地展开设备清单，已安装与背包可安装分别显示。可装设备每行直接展示名称、数量、对应工艺和安装按钮，例如「木擀杖 → 粉碎」；没有候选时明确显示「背包中没有可安装的设备」。取消原下拉选择及底部重复入口。沿用真实库存与装卸检查，不赠物，不改变工艺可见条件和损坏规则。使用中的设备仍不可卸下；替换完成取消设备栏损坏提醒，已做出的药品和原结果卡保留。

两套正式界面共用，支持键盘焦点与展开状态，窄屏控件换行。8045纯内存预览另备木擀杖、粗陶研钵各一件，方便试装与替换；正式存档不受影响。`npm run test:pharmacy` 覆盖无设备、安装／卸下与工艺变化、空库存、旧按钮重复点击、损坏后替换、注射液隐藏及原有生产／保存功能。外观等待用户评价。

## 2026-11-02 取消燃料与按批设备损坏

本节覆盖下文旧燃料及工具永久使用规则。普通制药不再需要或消耗燃料，正式工艺表、配方覆写、生成器和两套界面同步取消；背包里的燃料物品及烹饪用途保持。旧存档的制药燃料数值仅作兼容，不返还或转换为其他资源。

每批完成时，成功与失败都对本次工艺使用的已装设备结算一次损坏。概率为 `max(0, 20% − 制药等级 × 0.15个百分点)`：0级20%、1级19.85%、100级5%；不按投料件数、产量或经过的tick重复判定。不消耗材料的拒绝开工不判定。设备损坏后从装配清单移除，需要重新安装一件才能再次使用对应工艺，已产出的药品／药渣照常到账。

开始制作时按当时等级保存 `active_craft.equipment_wear = {item_id, chance, broken}`，结束时才执行损坏；正常存读档及存档码沿同一快照保留结果，不重抽。旧进行中批次没有该字段，在首次完成时判定一次。制作期间禁止卸下当前所用设备，其他设备不受影响；重复完成回调不再次发物或损坏。装配清单沿原存档保存，本轮不改变普通保存触发覆盖范围。

界面「设备」区不再显示燃料入口；制作消耗区显示当前设备损坏率，右侧本次结果及日志显示实际损坏名称，对应工艺立即隐藏。未新增耐久、维修、残骸或补偿。即时注射液配置沿原规则没有使用设备，不凭空指定设备或损坏无关配件；注射液隐藏开关保持。

基础概率和每级减免集中在 `data/pharmacy-system-config.csv`。`npm run test:pharmacy` 新增两套界面与真实运行回归：零燃料及旧成本覆写、概率端点、拒绝开工不消耗、成功／失败结算、只损坏所用设备、制作中禁止卸下、产物保留、工艺隐藏与重新安装、读档固定结果及旧批次兼容。

## 2026-11-02 等待秒数与本次制作结果

用户要求1 tick对应1秒等待，并在右侧提示本次制作所得。普通制药的自动工作间隔独立固定为1000毫秒，每次仍推进1世界tick；工时数值、材料、体力、燃料及原有其他动作推进规则不变，不调整采集／调息等系统的节奏。制药耗时与剩余时间改显示为秒。原本没有tick成本的注射液配置保持即时结算。

右侧新增「本次制作获得」结果卡，普通制药和注射液配置共用。结果来自实际发放，包含名称、实际数量、额外产物与「已收纳／已放在脚下」；失败显示实际药渣，不把预计产出当作所得。开始下一次有效制作时清除旧结果，单纯刷新或改选材料保留；已消耗材料的配伍失败也清空本次投料。结果只作本次会话提示，不新增存档历史，关闭注射液开关后隐藏其结果。

回归 `npm run test:pharmacy` 增加两套界面的定时器间隔、逐刻倒计时、完成前不发物、实际产物／额外产物、失败药渣、背包满落地和注射液结果检查。

## 2026-11-02 注射液系统发现开关

用户要求先隐藏注射液系统，后续再指定能打开它的事件或物品。本次仅接入一个开关，不指定解锁来源、不添加剧情或知识奖励。

唯一开关为 NPC 剧情标记 `pharmacy_injection_unlocked`，缺失视为关闭；新档、未包含此标记的旧档均默认关闭。它随现有 `player.npcDemo.flags` 保存及存档码迁移，不新增独立存储。制药等级、修复制药台、持有药粉或旧注射液均不自动打开它。

- 关闭时制药台只显示原有制作功能，不显示「注射液配置」页签、灰色锁定提示、配药帮助或浓度条。
- 两套物品详情共用过滤：隐藏配药成分、浓度、助溶及药粉配伍参数，普通成品的药效和一般风险继续显示。通用药品说明中涉及沉淀、针具的提示也受此开关控制。
- 正式制作入口、动态实例生成、注射使用入口均复核开关；关闭时不扣料、不耗时、不施加药效。已存在的物品不删除、不改名，已生效药效不撤销。
- 在配药页关闭开关后，下次刷新或点击会返回普通制作并清空尚未提交的选料，旧点击不转成普通工艺提交；打开开关后，下次面板刷新或打开恢复现有注射液功能。

后续事件可使用现有结束效果：

```json
{"type":"setFlag","params":{"flag":"pharmacy_injection_unlocked","value":true}}
```

物品或知识获得流程可调用 `NPCSystem.setDemoFlag('pharmacy_injection_unlocked', true)`，并与该次获得／消耗一起通过既有原子保存提交；失败回滚整个操作。查询使用 `PharmacyCompounding.isUnlocked()`。设为 `false` 可重新关闭，当前没有玩家可操作的开关或自动解锁来源。

回归：`npm run test:pharmacy` 包含 `tools/test-pharmacy-unlock.mjs`，验证两套正式界面隐藏／显示、帮助及物品详情不提前披露、入口拦截不消耗、关闭时旧点击、旧物品保留、存读档、缺标记旧档、保存失败回滚与重开清除。既有制药 104 组断言继续在已解锁状态验证原规则。

## 两个入口

- 药粉与成品制作：现有工艺、已学配方快捷填料，生产药粉及非注射成品。
- 注射液配置：只使用原有配药投料白名单，支持单方和复方。隐藏工艺选择与固定配方快捷项，保留浓度及材料选择。不满足配置校验时禁用配置按钮并显示原因。

## 分级判断

| 等级 | 面板提供的信息 |
|---|---|
| 0 | 浓度、明显混浊/分层/沉淀。没有明显异常不代表安全 |
| 1 | 底液错配、助溶需要/供给/缺口 |
| 2 | 常见成分类别相冲及涉及材料；药效名称、基础起效/总窗口 |
| 4 | 已解锁相冲的轻重程度、基础净毒性和药效模板说明 |
| 6 | 完整现有配伍规则，以及换底液/分开成分的调整建议 |

复杂规则暂指定 acid_glycoside、glycoside_tannin、volatile_oil_mineral，6级揭示成因；可见沉淀不因此隐藏。glycoside_mineral不作为肉眼可观察相冲，需相应判断等级。以上是游戏规则投影，不是现实化学判断。

判断来自同一套实际配置解析，低等级返回结果不包含被锁定的风险明细与毒性数字。净毒性预测不含额外针具卫生负担，也不把独立相冲状态并入体内毒性数字。时长读取当前模板，包含起效等待，免疫延长另计。
