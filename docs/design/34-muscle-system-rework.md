## 1. 设计动机：四个系统的最终分工

战斗内容的四类来源，各司其职、互不重叠：

| 来源 | 负责的维度 | 一句话 |
|------|-----------|--------|
| **玩家数值成长** | 招式的**基础数值** | 五维、技能等级 Base(L)、招式熟练度、技艺总熟、实战经验 → 基础威力与命中/速度相关量 |
| **招 式** | 攻击的**形态 + 内建效果** | 这一招**怎么用**（抓 / 打 / 投），以及招式**天生自带**的效果（击退、失衡、试探…） |
| **肌 肉** | **永久数值 + 大型被动容量** | 双面：解锁肌肉 → 永久数值（小步）；解锁完整肌群 → 1 个「大型被动容量」（肌群专属槽） |
| **装 备** | **多方面补足** | 补属性以激活门槛、词条修正、杂项（具体口径在装备设计时定） |

**核心解耦原则**：
- 招式**不再携带任何数值成长**（基础数值全部由玩家养成状态决定）；
- 招式**自带的效果留在招式**（击退/失衡/试探等形态绑定效果）；
- **规则级、独一无二的被动**（强制先手、驱散、新机制）→ **大型被动**，装配在肌群槽上；
- 装备补足属性 → 激活门槛（检查口径见 §6 未决项）。

## 2. 肌肉系统：22 肌群 × 478 肌肉（解剖学命名肌肉完整版）

### 2.1 肌群划分（解剖 14 区，左右拆分）

**22 个肌群 = 6 个中轴肌群（不分左右）+ 8 个侧区 × 左右 = 16 个侧肌群**

| # | 肌群 | 类型 | 对应解剖区 | 与七部位对齐 |
|---|------|------|-----------|-------------|
| 1 | `head` 头 | 中轴 | 头（表情/咀嚼/眼/舌/咽/腭/耳） | — |
| 2 | `neck` 颈 | 中轴 | 颈（含喉肌） | — |
| 3 | `back` 背 | 中轴 | 背（含枕下/深层） | — |
| 4 | `chest` 胸 | 中轴 | 胸 | — |
| 5 | `abdomen` 腹 | 中轴 | 腹（核心） | — |
| 6 | `pelvis` 盆底会阴 | 中轴 | 盆底/会阴 | — |
| 7 | `shoulder_l` / `shoulder_r` | 侧 | 肩带 | 绑 `lhand` / `rhand` |
| 8 | `upperarm_l` / `upperarm_r` | 侧 | 上臂 | 绑 `lhand` / `rhand` |
| 9 | `forearm_l` / `forearm_r` | 侧 | 前臂 | 绑 `lhand` / `rhand` |
| 10 | `hand_l` / `hand_r` | 侧 | 手 | 绑 `lhand` / `rhand` |
| 11 | `hip_l` / `hip_r` | 侧 | 髋 | 绑 `lfoot` / `rfoot` |
| 12 | `thigh_l` / `thigh_r` | 侧 | 大腿 | 绑 `lfoot` / `rfoot` |
| 13 | `calf_l` / `calf_r` | 侧 | 小腿 | 绑 `lfoot` / `rfoot` |
| 14 | `foot_l` / `foot_r` | 侧 | 足 | 绑 `lfoot` / `rfoot` |

**规则**：
- **侧肌群左右方向与现有七部位一致**：上肢侧群绑 `lhand`/`rhand`，下肢侧群绑 `lfoot`/`rfoot`。
- **中轴肌群**：肌肉左右成对的两条（id 带 L/R）**同归一个肌群**；大型被动装中轴肌群 = 左右同生效。
- **正中单条肌肉**（膈肌、舌内肌、肛门外括约肌等）：无 L/R 后缀，归所属中轴肌群。

### 2.2 肌肉数据模型（478 块完整版）

**口径**：478 块 = **全部解剖学命名肌肉**（成对肌肉左右各一条分别计数、正中单条不展开）。不再按节段/分部分细分到字面 639（肋间肌 33 段、多裂/回旋/横突/棘间按椎节等分节计数无玩法意义）。

**生成**：`tools/build_muscles.js` 内含肌肉清单，运行时生成 `data/muscles.json`。

**肌肉条目结构**：

```json
{
  "id": "chest_pectoralis_major_L",
  "name": "胸大肌（左）",
  "group": "chest",
  "effects": [{ "type": "jingu", "delta": 2 }],
  "unlock_cost": 1
}
```

- `effects`：`maxQi`（底气上限）、后天四维（`jingu/flexibility/breath/dexterity`）——**全部计入后天**；**肌肉不奖励 `focus`（专注）**。
- **模板化**：效果按肌群模板（`TPL`）分配，个别肌肉（如膈肌 maxQi+10）覆盖。
- `unlock_cost`：解锁消耗（资源名 `muscle_points`「肌力点数」，来源待定）。

### 2.3 后天四维总预算（强制，防止属性爆炸）

478 块肌肉若每块都给四维，必须设**总预算**：
- **约定**：全部肌肉点满后，后天四维总增量落在**有界区间**，且各维大致均摊（当前配表：筋骨 **+128** / 身手 **+126** / 呼吸 **+125** / 柔韧 **+133**，偏差 ±4%）；专注**不参与**肌肉奖励；
- **约束**：`sum(所有肌肉的 bone delta) ≤ 预算_bone`，配表校验器在加载时断言（待建）；
- 与 `05` 成长区间衔接：肌肉线是**长期保底**，不应单独撑起后期数值。

### 2.4 肌群全通奖励：大型被动容量

- **每解锁一个完整肌群（该群全部肌肉点亮）→ 获得 1 个「大型被动容量」**（该肌群专属被动槽）；
- 22 个肌群 → **最多 22 个大型被动容量**；
- 槽与肌群绑定：`shoulder_l` 全通 → `shoulder_l` 槽；`chest` 全通 → `chest` 槽；
- **容量是稀缺资源**：玩家不可能全通所有肌群（资源有限）。

## 3. 大型被动（规则级、独一无二、可拆卸）

### 3.1 定义与定位
- **大型被动** = 规则级效果（改变结算规则、提供全新机制），**不是**数值小加成；
- **来源（已定）**：原「后遗症」（`post-effects.json` 规则级）**迁移**进本系统——后遗症的本质是**给招式附带额外效果**（如「不假思索」= 本击先手判定始终优势），符合大型被动"规则级、独一无二"的定位；
- **变式不迁移（已定）**：变式（`move-variants.json`）是**改变招式形态**的"招式自身被动"（如「化掌为刀」= 摆拳 钝击→劈砍），保留在招式形态层，继续走招式槽/招架槽装配体系，与肌群槽无关；
- **普通数值类加成**不进大型被动（数值维已由属性/装备负责）。

### 3.2 装配声明（已定）

> 数据表：`data/muscles.json` 的 `passives` 段（与肌肉同文件原子加载，`tools/build_muscles.js` 生成）；效果层仍引用 `data/post-effects.json`（`post_effect_id`）。

```json
{
  "id": "post_no_second_thought",
  "name": "不假思索",
  "allowed_groups": ["hand_l", "hand_r", "upperarm_l", "upperarm_r", "shoulder_l", "shoulder_r", "forearm_l", "forearm_r"],
  "slots_cost": 1,
  "effect": { "type": "initiative_always_first", "valid_move_ids": ["jab"] }
}
```

> 注：允许槽 = 刺拳/摆拳（挥拳形态）调用的**同侧侧群**（§4 映射表）；不含中轴肌群 → 保持单侧生效（§3.5）。

| 字段 | 语义（已定） |
|------|-------------|
| `allowed_groups` | 可装配的肌群集合 |
| `slots_cost` | 占用槽数。**=1**：装在任一允许槽；**=n**：**同时占用** allowed 内 n 个肌群槽（排他） |
| 唯一性 | **同一被动全局只能装 1 份** |
| 装卸 | **免费自由装卸** |

**强力被动示例**：`slots_cost: 3`、`allowed_groups: [shoulder_l, upperarm_l, chest]` → 同时占用 3 槽（排他）。

### 3.3 装配校验（伪代码）

```js
function canEquipPostPassive(passive, equippedMap, unlockedGroups) {
  for (var g of passive.allowed_groups) if (!unlockedGroups[g]) return false; // 槽不存在
  for (var g of passive.allowed_groups) if (equippedMap[g]) return false;   // 槽被占
  if (equippedAnywhere(passive.id)) return false;                           // 全局唯一
  return true;
}
```

### 3.4 触发：形态自动匹配
- 招式定义**调用哪些肌群**（见 §4 形态层）→ 大型被动装在肌群槽上 → 招式调用该肌群时自动触发（`valid_*` 二次校验）；
- **阶段三落地口径**：招式 `form.muscle_groups`（阶段四）尚未配表前，触发以 **`valid_move_ids` 二次校验**为主——已装配的大型被动其效果层条目（`post-effects.json`）声明 `valid_move_ids`，命中该招式时生效；生效来源为 `Muscles.getEquippedPostEffectIdsForAttack()`（替代旧肢体槽 `post_effect_sequences`），生效边界见 §3.5；
- **取代**旧后遗症按 `skill_id`/肢体槽硬编码装配的机制。

### 3.5 生效边界（已定：肌群调用）

大型被动的生效范围**不是**"装配的肢体"，也不是无差别全局，而是 **招式形态调用的肌群集合**（§3.4 触发口径）：

- **侧肌群槽**（如 `hand_l`）：仅**该侧**出招且形态调用该肌群时生效（`hand_l` ↔ 左手挥拳类招式）；
- **中轴肌群槽**（如 `chest`）：**左右同生效**（中轴肌群被两侧招式共同调用，§2.1）；
- **跨双侧形态**（投/摔/擒拿/锁）：调用双侧肌群，装配集合内任一肌群即可触发；
- **二次校验**：效果层 `valid_move_ids` / `valid_skill_ids` 仍逐击校验（如「不假思索」仅刺拳生效）。

**中间态口径（阶段四前）**：招式 `form.muscle_groups` 未配表前，用「招式 `required_limb_tags`（挥拳/踢击/掌击/…）× §4 映射表 × 出招肢体侧别」近似判定调用肌群；无法分类的招式**保守放行**（不过滤）。敌人侧无肌群体系，等价 `post_effect_ids` 整单位生效，不受本边界约束。

## 4. 招式设计规范（数值 / 形态 / 效果 三维）

| 维度 | 内容 | 来源 |
|------|------|------|
| **数值** | 基础威力、命中相关量、消耗（呼吸条档位/底气） | 玩家养成状态 |
| **形态** | 怎么用（抓/打/投）、动作标签、伤害类型、段数、部位权重、**调用肌群** | 招式定义 |
| **效果** | 招式内建效果（击退/失衡/试探）+ 装配的大型被动 | 招式自带 + 肌群被动 |

**招式数据字段建议**：

```json
{
  "id": "jab",
  "name": "刺拳",
  "form": {
    "action_tag": "挥拳",
    "usage": "打",
    "damage_type": "blunt",
    "hit_segments": 1,
    "hit_part_weights": { "head": 0.1, "chest": 0.5 },
    "muscle_groups": ["shoulder_l", "upperarm_l", "chest", "hand_l"]
  },
  "builtin_effects": [{ "type": "on_hit_apply_buff", "buff_id": "buff_probe" }],
  "move_power_multiplier": 0.8
}
```

### 招式形态 → 肌群调用映射表（配表用）

| 招式类型 | 调用肌群 |
|---------|---------|
| 刺拳/摆拳（挥拳·打） | 同侧 `shoulder/upperarm/forearm/hand` + `chest` + `abdomen` |
| 正蹬/鞭腿（踢击） | 同侧 `hip/thigh/calf/foot` + `abdomen` |
| 掌击/推 | 同侧 `hand/forearm` + `chest` |
| 擒拿/锁 | 双侧 `hand/forearm` + `back` + 核心 |
| 头槌 | `head` + `neck` |
| 投/摔 | 双侧 `shoulder` + `back` + `hip` + `abdomen`（全身） |
