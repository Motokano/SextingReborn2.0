## 1. 设计动机：四个系统的最终分工

战斗内容的四类来源，各司其职、互不重叠：

| 来源 | 负责的维度 | 一句话 |
|------|-----------|--------|
| **玩家数值成长** | 招式的**基础数值** | 五维、技能等级 Base(L)、招式熟练度、技艺总熟、实战经验 → 基础威力与命中/速度相关量 |
| **招 式** | 攻击的**形态 + 内建效果** | 这一招**怎么用**（抓 / 打 / 投），以及招式**天生自带**的效果（击退、失衡、试探…） |
| **肌 肉** | **永久数值 + 大型被动容量** | 双面：解锁肌肉 → 永久数值（小步）；解锁完整肌群 → 1 个「大型被动容量」（肌群专属槽） |
| **装 备** | **多方面补足** | 补属性以激活门槛、词条修正、杂项（具体口径在装备设计时定） |

**核心解耦原则**：
- 招式**不再携带任何数值成长**（基础数值全部由玩家养成状态决定）；
- 招式**自带的效果留在招式**（击退/失衡/试探等形态绑定效果）；
- **规则级、独一无二的被动**（强制先手、驱散、新机制）→ **大型被动**，装配在肌群槽上；
- 装备补足属性 → 激活门槛（检查口径见 §6 未决项）。

## 2. 肌肉系统：22 肌群 × 478 肌肉（解剖学命名肌肉完整版）

### 2.1 肌群划分（解剖 14 区，左右拆分）

**22 个肌群 = 6 个中轴肌群（不分左右）+ 8 个侧区 × 左右 = 16 个侧肌群**

| # | 肌群 | 类型 | 对应解剖区 | 与七部位对齐 |
|---|------|------|-----------|-------------|
| 1 | `head` 头 | 中轴 | 头（表情/咀嚼/眼/舌/咽/腭/耳） | — |
| 2 | `neck` 颈 | 中轴 | 颈（含喉肌） | — |
| 3 | `back` 背 | 中轴 | 背（含枕下/深层） | — |
| 4 | `chest` 胸 | 中轴 | 胸 | — |
| 5 | `abdomen` 腹 | 中轴 | 腹（核心） | — |
| 6 | `pelvis` 盆底会阴 | 中轴 | 盆底/会阴 | — |
| 7 | `shoulder_l` / `shoulder_r` | 侧 | 肩带 | 绑 `lhand` / `rhand` |
| 8 | `upperarm_l` / `upperarm_r` | 侧 | 上臂 | 绑 `lhand` / `rhand` |
| 9 | `forearm_l` / `forearm_r` | 侧 | 前臂 | 绑 `lhand` / `rhand` |
| 10 | `hand_l` / `hand_r` | 侧 | 手 | 绑 `lhand` / `rhand` |
| 11 | `hip_l` / `hip_r` | 侧 | 髋 | 绑 `lfoot` / `rfoot` |
| 12 | `thigh_l` / `thigh_r` | 侧 | 大腿 | 绑 `lfoot` / `rfoot` |
| 13 | `calf_l` / `calf_r` | 侧 | 小腿 | 绑 `lfoot` / `rfoot` |
| 14 | `foot_l` / `foot_r` | 侧 | 足 | 绑 `lfoot` / `rfoot` |

**规则**：
- **侧肌群左右方向与现有七部位一致**：上肢侧群绑 `lhand`/`rhand`，下肢侧群绑 `lfoot`/`rfoot`。
- **中轴肌群**：肌肉左右成对的两条（id 带 L/R）**同归一个肌群**；大型被动装中轴肌群 = 左右同生效。
- **正中单条肌肉**（膈肌、舌内肌、肛门外括约肌等）：无 L/R 后缀，归所属中轴肌群。

### 2.2 肌肉数据模型（478 块完整版）

**口径**：478 块 = **全部解剖学命名肌肉**（成对肌肉左右各一条分别计数、正中单条不展开）。不再按节段/分部分细分到字面 639（肋间肌 33 段、多裂/回旋/横突/棘间按椎节等分节计数无玩法意义）。

**生成**：`tools/build_muscles.js` 内含肌肉清单，运行时生成 `data/muscles.json`。

**肌肉条目结构**：

```json
{
  "id": "chest_pectoralis_major_L",
  "name": "胸大肌（左）",
  "group": "chest",
  "effects": [{ "type": "jingu", "delta": 2 }],
  "unlock_cost": 1
}
```

- `effects`：`maxQi`（底气上限）、后天四维（`jingu/flexibility/breath/dexterity`）——**全部计入后天**；**肌肉不奖励 `focus`（专注）**。
- **模板化**：效果按肌群模板（`TPL`）分配，个别肌肉（如膈肌 maxQi+10）覆盖。
- `unlock_cost`：旧方案的解锁消耗（资源名 `muscle_points`「肌力点数」），当前配置保留但没有正式扣费。2026-11-03 用户改定训练进度满后自动点亮，接入方案见 §8。

### 2.3 后天四维总预算（强制，防止属性爆炸）

478 块肌肉若每块都给四维，必须设**总预算**：
- **约定**：全部肌肉点满后，后天四维总增量落在**有界区间**，且各维大致均摊（当前配表：筋骨 **+128** / 身手 **+126** / 呼吸 **+125** / 柔韧 **+133**，偏差 ±4%）；专注**不参与**肌肉奖励；
- **约束**：`sum(所有肌肉的 bone delta) ≤ 预算_bone`，配表校验器在加载时断言（待建）；
- 与 `05` 成长区间衔接：肌肉线是**长期保底**，不应单独撑起后期数值。

### 2.4 肌群全通奖励：大型被动容量

- **每解锁一个完整肌群（该群全部肌肉点亮）→ 获得 1 个「大型被动容量」**（该肌群专属被动槽）；
- 22 个肌群 → **最多 22 个大型被动容量**；
- 槽与肌群绑定：`shoulder_l` 全通 → `shoulder_l` 槽；`chest` 全通 → `chest` 槽；
- **容量是稀缺资源**：玩家不可能全通所有肌群（资源有限）。

## 3. 大型被动（规则级、独一无二、可拆卸）

### 3.1 定义与定位
- **大型被动** = 规则级效果（改变结算规则、提供全新机制），**不是**数值小加成；
- **来源（已定）**：原「后遗症」（`post-effects.json` 规则级）**迁移**进本系统——后遗症的本质是**给招式附带额外效果**（如「不假思索」= 本击先手判定始终优势），符合大型被动"规则级、独一无二"的定位；
- **变式不迁移（已定）**：变式（`move-variants.json`）是**改变招式形态**的"招式自身被动"（如「化掌为刀」= 摆拳 钝击→劈砍），保留在招式形态层，继续走招式槽/招架槽装配体系，与肌群槽无关；
- **普通数值类加成**不进大型被动（数值维已由属性/装备负责）。

### 3.2 装配声明（已定）

> 数据表：`data/muscles.json` 的 `passives` 段（与肌肉同文件原子加载，`tools/build_muscles.js` 生成）；效果层仍引用 `data/post-effects.json`（`post_effect_id`）。

```json
{
  "id": "post_no_second_thought",
  "name": "不假思索",
  "allowed_groups": ["hand_l", "hand_r", "upperarm_l", "upperarm_r", "shoulder_l", "shoulder_r", "forearm_l", "forearm_r"],
  "slots_cost": 1,
  "effect": { "type": "initiative_always_first", "valid_move_ids": ["jab"] }
}
```

> 注：允许槽 = 刺拳/摆拳（挥拳形态）调用的**同侧侧群**（§4 映射表）；不含中轴肌群 → 保持单侧生效（§3.5）。

| 字段 | 语义（已定） |
|------|-------------|
| `allowed_groups` | 可装配的肌群集合 |
| `slots_cost` | 占用槽数。**=1**：装在任一允许槽；**=n**：**同时占用** allowed 内 n 个肌群槽（排他） |
| 唯一性 | **同一被动全局只能装 1 份** |
| 装卸 | **免费自由装卸** |

**强力被动示例**：`slots_cost: 3`、`allowed_groups: [shoulder_l, upperarm_l, chest]` → 同时占用 3 槽（排他）。

### 3.3 装配校验（伪代码）

```js
function canEquipPostPassive(passive, equippedMap, unlockedGroups) {
  for (var g of passive.allowed_groups) if (!unlockedGroups[g]) return false; // 槽不存在
  for (var g of passive.allowed_groups) if (equippedMap[g]) return false;   // 槽被占
  if (equippedAnywhere(passive.id)) return false;                           // 全局唯一
  return true;
}
```

### 3.4 触发：形态自动匹配
- 招式定义**调用哪些肌群**（见 §4 形态层）→ 大型被动装在肌群槽上 → 招式调用该肌群时自动触发（`valid_*` 二次校验）；
- **阶段三落地口径**：招式 `form.muscle_groups`（阶段四）尚未配表前，触发以 **`valid_move_ids` 二次校验**为主——已装配的大型被动其效果层条目（`post-effects.json`）声明 `valid_move_ids`，命中该招式时生效；生效来源为 `Muscles.getEquippedPostEffectIdsForAttack()`（替代旧肢体槽 `post_effect_sequences`），生效边界见 §3.5；
- **取代**旧后遗症按 `skill_id`/肢体槽硬编码装配的机制。

### 3.5 生效边界（已定：肌群调用）

大型被动的生效范围**不是**"装配的肢体"，也不是无差别全局，而是 **招式形态调用的肌群集合**（§3.4 触发口径）：

- **侧肌群槽**（如 `hand_l`）：仅**该侧**出招且形态调用该肌群时生效（`hand_l` ↔ 左手挥拳类招式）；
- **中轴肌群槽**（如 `chest`）：**左右同生效**（中轴肌群被两侧招式共同调用，§2.1）；
- **跨双侧形态**（投/摔/擒拿/锁）：调用双侧肌群，装配集合内任一肌群即可触发；
- **二次校验**：效果层 `valid_move_ids` / `valid_skill_ids` 仍逐击校验（如「不假思索」仅刺拳生效）。

**中间态口径（阶段四前）**：招式 `form.muscle_groups` 未配表前，用「招式 `required_limb_tags`（挥拳/踢击/掌击/…）× §4 映射表 × 出招肢体侧别」近似判定调用肌群；无法分类的招式**保守放行**（不过滤）。敌人侧无肌群体系，等价 `post_effect_ids` 整单位生效，不受本边界约束。

## 4. 招式设计规范（数值 / 形态 / 效果 三维）

| 维度 | 内容 | 来源 |
|------|------|------|
| **数值** | 基础威力、命中相关量、消耗（呼吸条档位/底气） | 玩家养成状态 |
| **形态** | 怎么用（抓/打/投）、动作标签、伤害类型、段数、部位权重、**调用肌群** | 招式定义 |
| **效果** | 招式内建效果（击退/失衡/试探）+ 装配的大型被动 | 招式自带 + 肌群被动 |

**招式数据字段建议**：

```json
{
  "id": "jab",
  "name": "刺拳",
  "form": {
    "action_tag": "挥拳",
    "usage": "打",
    "damage_type": "blunt",
    "hit_segments": 1,
    "hit_part_weights": { "head": 0.1, "chest": 0.5 },
    "muscle_groups": ["shoulder_l", "upperarm_l", "chest", "hand_l"]
  },
  "builtin_effects": [{ "type": "on_hit_apply_buff", "buff_id": "buff_probe" }],
  "move_power_multiplier": 0.8
}
```

### 招式形态 → 肌群调用映射表（配表用）

| 招式类型 | 调用肌群 |
|---------|---------|
| 刺拳/摆拳（挥拳·打） | 同侧 `shoulder/upperarm/forearm/hand` + `chest` + `abdomen` |
| 正蹬/鞭腿（踢击） | 同侧 `hip/thigh/calf/foot` + `abdomen` |
| 掌击/推 | 同侧 `hand/forearm` + `chest` |
| 擒拿/锁 | 双侧 `hand/forearm` + `back` + 核心 |
| 头槌 | `head` + `neck` |
| 投/摔 | 双侧 `shoulder` + `back` + `hip` + `abdomen`（全身） |

## 8. 藏身处健身房与缓慢点亮成长（2026-11-03，首版方案）

### 8.1 已确认方向与本版状态

用户已确认：

1. 藏身处增加健身房设施。
2. 玩家消耗体力，选择不同锻炼方式，训练不同肌群。
3. 采用点亮式成长，每块肌肉只提供一次点亮奖励。
4. 练满后自动点亮，不需要玩家再选择肌肉购买解锁。
5. 成长非常缓慢。
6. 健身房本身也需要成长，玩家收集材料添置器械、升级设施，并可反复制作杠铃片等配重（后续补充，见 §9）。
7. 器械种类决定一次能练到哪些肌肉，器械改进决定一次训练的效率。同类器械的改进不扩大受训肌肉范围。
8. 直接使用现有疲劳值限制锻炼成果；睡眠是最有效的消除疲劳手段，同时消耗饱食、饮水并恢复体力。撤下独立锻炼疲劳值、局部疲劳和现实时间自然恢复提案；其他减疲劳途径如何定位、训练收益曲线仍待定。
9. 成长循环为消耗体力训练并累积疲劳 → 消耗饱食、饮水恢复体力 → 疲劳累积后睡眠 → 睡眠继续消耗饱食、饮水并恢复体力与疲劳。目标是驱动玩家收集、生产补给来供自己变强，详见 §10.5。
10. 睡眠已按用户暂定数值接入：48 tick，每刻饱食−1、饮水−1、体力+2、疲劳−2；满体力或零疲劳仍扣费。用户确认不叠加原基础消耗，缺补给继续睡满48刻但暂停恢复。普通休息保持原规则，见 §10.6；健身房仍未实装。

以下是据此整理的首版提案。具体动作、设备、体力、时间、进度与门槛尚待评价。本次只修改设计文档，不新增地图设施、修改运行配置或玩家存档。

沿用现有肌肉 ID、属性奖励及全通肌群的被动槽规则。已点亮奖励总预算仍为筋骨 +128、柔韧 +133、呼吸 +125、身手 +126、膈肌底气上限 +10；这不是首版健身房承诺能全部取得的奖励。食物／睡眠属性经验继续是独立成长通道。

### 8.2 训练与结算

基本流程：选择动作及训练组数 → 实际消耗体力和世界时间 → 对应肌肉分别积累进度 → 达到各自门槛立即点亮 → 统一重算永久属性。

- 每块肌肉有独立训练进度，同一肌肉被多个动作训练时共用这份进度。
- 每个动作声明具体主练和辅助肌肉。面板可概括为肌群，结算不能按整个 `group` 批量赠送进度。
- 左右分别保存。首版普通双侧动作同时推进左右，双方可有不同历史进度；未来单侧动作只推进指定侧。
- 每组拟为 **2 世界 tick**，按现有挂机节奏 **3 秒/tick**，即 **6 秒/组**；1、4、8 组为可选批量，默认 4 组，可在资源和锻炼疲劳允许时连续训练。组数是游戏工作量单位，不模拟现实健身组间时长。
- 主练肌肉每完整组 **+2 训练进度**，辅助肌肉 **+0.5**。分别按 tick 执行一半体力成本和进度，可以在 tick 边界停止；已经完成的部分保留，取消不会抹掉实际劳动。
- 进度满即点亮；已点亮肌肉不重复领奖，它原本的进度增量也不转送其他肌肉。其他未点亮目标继续按原速度成长。
- 某动作的全部目标都已点亮时显示「已练成」，结束连续训练。
- 进度长期保存，首版建议离开、换动作、睡眠和死亡均不衰减；没有随机失败、点亮后额外升级或因停练掉级。死亡保留未满进度属于本版提案，已点亮记录保留沿用现行规则。

上述 +2／+0.5 是单块肌肉的起始权重。一次动作会同时训练多块肌肉，整组带来的总进度不是固定 2 点。复合动作覆盖面更广，存在总收益优势；完整配表时需结合实际目标数、属性奖励和被动槽收益校准，不能把这组权重当作已完成平衡。

### 8.4 非普通力量训练范围

- 胸部的膈肌与其他呼吸肌，需要单独的呼吸抗阻来源。
- 盆底会阴需要专项训练来源。
- 头部咀嚼肌、舌肌、吞咽相关肌属于专项功能训练候选。
- 眼肌、耳肌、喉内肌等不随普通推、拉、蹲、颈部抗阻自动获得训练进度。
- 普通健身房训练清单不能直接替代全部 478 块肌肉的成长来源；未覆盖肌肉及其他来源保留为后续设计，不增设无依据的掉落或剧情解锁。

肌群槽继续要求该群全部肌肉点亮。胸、颈等混合肌群可能需要多种来源才能全通；本版不把「已练完普通力量部分」改算成全通，也不承诺所有肌群已经有完整可达路线。首次可获得被动槽的路线必须在正式配表时单独验证。

### 8.5 非常缓慢的数值基准（提案）

肌肉点亮门槛先设三个游戏调校档，分别独立配置；不是按肌肉大小、深浅自动认定的生理难度。

| 门槛档 | 所需训练进度 | 只按主练 +2/组计算 | 每次 4 组所需训练次数 | 只按辅助 +0.5/组计算 | 纯训练现实时间（3秒/tick） |
|---|---:|---:|---:|---:|---:|
| 标准 | 1000 | 500 组 | 125 次 | 2000 组 | 50 分钟 |
| 慢速 | 1600 | 800 组 | 200 次 | 3200 组 | 80 分钟 |
| 长线 | 2400 | 1200 组 | 300 次 | 4800 组 | 120 分钟 |

说明：

- 表中「一次」指一次选择 4 组的训练批次，不是登录次数，也不是系统每天只准训练一次。
- 如果玩家每个游戏日练一次该动作，上述主练路线分别约为 125、200、300 个游戏日；玩家可以集中练习，因此这些天数不是下限或冷却限制。
- 纯训练时间只含这个动作的执行，不含恢复、睡眠、吃喝、获取食物和其他活动。500／800／1200 组本身会推进 1000／1600／2400 世界 tick，约 6.94／11.11／16.67 个游戏日；其间所需恢复另算。
- 多块肌肉并行增长。对称双侧训练常会同时点亮左右两块，不能把这张表解释成「总计只得到一块」或把单块时间乘以 478。
- 同一肌肉可以被多个动作共同推进，因此只靠辅助的列是单一路线算例，不是固定点亮时间。
- 满进度直接点亮，不等睡眠抽奖，不因跨过门槛后的余量再发一次奖励。
- 本节数值为未受锻炼疲劳折损、器械效率 1.0 的基准。用户后续要求锻炼疲劳，新增限制及恢复方案见 §10，覆盖原「首版不增加疲劳限制」提案；实际组数和间隔需重新评估。现有生存疲劳、行动限制和睡眠继续生效。

**普通 10 体力动作的一次 4 组训练**，正常温度、无其他成本修正时：

| 项目 | 数值 |
|---|---:|
| 世界时间 | 8 tick（80 游戏分钟） |
| 现实执行时间 | 24 秒 |
| 动作体力 | 40 |
| 当前站立基础体力消耗 | 另计 8 × 0.4 = 3.2 |
| 合计体力减少 | 约 43.2 |
| 动作造成的疲劳 | 40 × 0.1 = 4 |
| 每块主练肌肉进度 | +8，即标准门槛的 0.8% |
| 每块辅助肌肉进度 | +2，即标准门槛的 0.2% |

这次训练不会获得永久属性，除非某块肌肉原本已经接近门槛。小数进度需明确展示，例如 37.4% → 38.2%，让每次劳动有可见积累。

**恢复成本算例**：标准门槛 500 组、动作每组 10 体力，累计动作消耗 5000，1000 tick 的当前基础消耗约 400。若全部通过当前普通休息补回这 5400 体力，按最多 2 体力/tick，需约 2700 个恢复 tick；其额外饱食和饮水各约 2700，基础代谢与食物供应另算。按当前休息自动推进 5秒/tick，纯休息等待约 225 分钟。这只是「全部采用休息、储备持续充足」的成本例子，不是完整游玩的实测时长或最低耗时；初始体力、睡眠、药物和其他恢复来源会改变结果。

### 8.6 推撑训练算例（不计锻炼疲劳的基准）

仅用于展示数值，暂不写入正式配置。下表按器械效率 1.0、每次均有完整成长收益计算；引入 §10 后，低效率训练需要更多实际组数，恢复间隔另计：

| 肌肉（左右分别） | 每组增长 | 拟定门槛 | 连续做推撑的点亮时点 |
|---|---:|---:|---:|
| 胸大肌 | 2 | 1000 | 第 500 组 |
| 肱三头肌 | 2 | 1600 | 第 800 组 |
| 前锯肌 | 0.5 | 1000 | 第 2000 组 |
| 三角肌 | 0.5 | 1600 | 第 3200 组；抬臂等其他动作可共同推进 |

从零开始且没有其他训练来源，第 500 组会点亮左右胸大肌。按现有正式配表，每侧胸大肌为后天呼吸 +2，因此该时点合计呼吸 +4；没有在本方案中擅自将胸肌奖励改为筋骨。肱三头肌此时为 62.5%，前锯肌 25%，三角肌约 15.6%。

左右同时点亮是明确的并行收益。除了这类对称成对奖励，不刻意给所有目标设置相同门槛来制造整片同时点亮。全通肌群的速度需要按完整动作组合计算，本版尚无完整配表，不给出伪精确的首次全通时间。

### 8.7 设施操作与接入边界（提案）

- 入口复用藏身处设施交互，显示玩家已知、当前器具允许的动作；开关面板不作为训练。
- 选择动作后显示本组体力、时间、具体受训肌肉及当前进度，结果显示实际进度变化和新点亮肌肉。沿用正式肌群总览，不新增第二份肌肉解锁真相。
- 训练时停止普通休息／调息恢复状态，避免同一动作一边恢复一边训练。体力不足下一 tick 的实际消耗、所需肢体失能、死亡／昏迷、离开设施时停止；已有有效进度保留。
- 建议现有疲劳达到训练停止条件时结束队列，不消耗后续组数的体力，也不在睡醒后自动重启训练；具体门槛见 §10 待定项。
- 连续执行由前台会话推进；关闭页面或后台暂停后不补算离线训练。训练不自动帮玩家进食、喝水或睡觉。
- 每个实际训练 tick 的资源、时间、进度、点亮和属性变化一起保存，保存失败整体恢复并停止续训；重试和重复回调不能重复扣体力或发奖。明确纳入现有保存触发配置，失败行为需有回归。
- 旧档已点亮肌肉继续点亮，未点亮肌肉默认从零开始，不猜测历史训练、不倒扣旧奖励。训练进度随完整存档码迁移。
- 接入时关闭原免费手动点亮入口，保留查看进度和被动装配；现有解剖学一级的肌群查看门槛先保留，设施使用和训练知识的发现条件另定。

### 8.8 后续配表与现存差异

需要评价的重点是本版速度是否符合用户的「非常缓慢」，其次为首批动作和器具范围。正式接入前补齐：每个细分动作的精确肌肉 ID、可用肢体、成长权重、各肌肉门槛，以及首次被动槽的可达与耗时验证。

当前正式 `data/muscles.json` 已有四种大型被动（不假思索、破相、伤上加伤、痛打落水狗）；本文前面的「首批两条」是历史阶段记录。`tools/build_muscles.js` 仍只生成早期两条，重建前必须对齐，避免覆盖后加的两条。破相的实际驱散仍是占位，不属于本次训练系统已完成的功能。

§2.4 原「有限肌力点使玩家不可能全通」属于旧购买方案前提。本次采用训练进度后，是否通过来源与长期成本限制最终全通需重新设计；首版不据旧表述偷偷新增永久点数总量上限。

参考：现有肌肉数据 `data/muscles.json`；时间 `js/game-time.js`；体力与疲劳 `data/survival-config.json`、`js/survival.js`；训练分类可参考 [CDC力量训练](https://www.cdc.gov/physical-activity-basics/adding-adults/what-counts.html)、[AAOS肩带训练](https://www.orthoinfo.org/recovery/rotator-cuff-and-shoulder-conditioning-program/)、[AAOS足踝训练](https://www.orthoinfo.org/recovery/foot-and-ankle-conditioning-program)。上述训练点、门槛、动作成本均为游戏提案。

## 9. 健身房自身的成长：器械种类与器械改进（2026-11-03，方向确认、细则提案）

### 9.1 已确认的两条成长方向

用户要求健身房也是成长型设施，玩家收集材料升级自己的健身房，例如解锁更多器械、制作更多杠铃片。随后明确：**器械种类决定一次能练到什么肌肉，改进器械决定一次效率多高**。这两条分工已确认；本节具体器械、改进项目、配方和效率倍率仍是提案，未接运行。

| 建设方向 | 玩家投入 | 获得的能力 |
|---|---|---|
| 增加器械种类 | 获知方案、收集材料、制作／安装新种类器械 | 开放对应训练动作，决定一次训练涉及的具体肌肉及主练／辅助关系 |
| 改进已有器械 | 收集材料、补充配重、加固结构或改进部件 | 提高使用该器械时每组获得的训练进度；同一动作的肌肉清单及主练／辅助关系保持 |

增加配重、加固承重等属于器械改进的具体内容，不再作为与效率成长并列的独立收益路线。某次改进可以要求配重与架体同时满足条件；最终体现为该器械可用的训练效率，不把每个部件各自再乘一次成长倍率。

玩家可以按想练的部位添置器械，也可以投入材料提高现有器械效率。设施成长以实际拥有的器械种类和各自改进状态呈现，总体「健身房等级」如需显示，也不能代替实际建设条件或给予所有器械通用的额外倍率。

基本循环：探索／采集取得材料与方案 → 添置器械以扩充训练选择，或改进已有器械以提高效率 → 消耗体力长期训练 → 逐块点亮肌肉。

### 9.2 器械候选与材料方向

下表是内部建设目录。基础训练区开放方式、方案来源、用料件数与工时另定；高级建设沿用现有认知与研究规则，生活技能升级不自动公布全部器械配方。

| 建设项目 | 材料方向 | 功能与依赖 |
|---|---|---|
| 基础训练区 | 木作、纤维、少量修补材料 | 提供自重蹲起、推撑、卷腹、支撑等初期动作的设施入口 |
| 单杠／支撑架 | 金属管道、木材、连接材料 | 提供悬垂、拉动及支撑类动作；具体肌肉映射单独补表 |
| 可调哑铃一对 | 金属件、握柄、锁固结构 | 配合兼容配重开放弯举、抬臂、部分肩部与腕部抗阻动作 |
| 杠铃杆、训练凳、训练架 | 金属管道或金属件、木材、纤维、连接结构 | 分件建设；卧推等按要求同时具备杆、凳、架及配重，一根杆不直接开放整套动作 |
| 牵引装置 | 架体、机械零件、合适绳索、配重挂接结构 | 提供牵引划船、下拉等动作；配重是否共用取决于挂接结构 |
| 手足等专项附件 | 纤维、金属件、机械零件等 | 提供握捏、踝部、足趾等专项形式；具体附件和材料性能另定 |

器械方案建议同时说明其基础用法，取得方案并完成建设后开放对应已知动作。更复杂动作是否另需知识，后续按内容逐项决定。

同一器械可以服务多个动作：器械种类限定可选动作及其肌肉范围，玩家选定动作后确定本次实际受训清单，不把一次训练的收益发给该器械能够服务的全部肌肉。改进同类器械只提高效率；需要新增受训肌肉的功能附件，应作为新的器械种类或训练功能解锁登记，不混入单纯的效率改进。

### 9.3 杠铃片、组合与唯一归属

建议首版设置 **2.5kg、5kg、10kg** 三种配重片，规格为提案。相同规格可反复制作，逐片保存数量。配重的成品重量用于训练负荷；若进入随身收纳，也应计入真实负重。

- 制作时消耗材料、工时和体力，完成后取得成品。器械和配重是可反复使用的建设资产，训练主要消耗角色体力。
- 健身房显示闲置配重，以及每件器械上实际装载的配重。配重可卸下再用于兼容器械，每片同一时刻只有一个归属。
- 装在杠铃上的片不能同时算进哑铃或牵引装置；训练中的装载锁定，结束后再调整。
- 对称杠铃动作要求两侧负重相等；双哑铃动作需分别满足两只哑铃的组合条件。总重量相同不代表库存一定能组合成所需装载。
- 每件器械有自己的装载／承重上限。可用片数、左右组合、器械上限和角色当前动作资格共同决定可选负荷。
- 各规格通过对应已掌握方案开放，不因知道5kg片就自动掌握全部规格。

**例子（非定稿参数）**：一根自重10kg的杆配4片5kg片，两侧各2片，总负荷30kg。再制作2片5kg片后，可两侧各增1片，组合为40kg。如果该训练架当前上限为30kg，新片先保留为闲置配重，完成架体加固后才能在这个动作中使用40kg。另一兼容器械若满足条件，可以先使用这两片。

2.5kg片用于细调负荷和组合，10kg片用于较大负荷；是否设置杆上装片位置数量限制另定，不凭空添加容量格。

这些是配重实物与装载的候选规则。对成长的贡献统一归入 §9.4 的器械效率：库存里多出几片不直接加成，只有满足对应改进及当前使用条件才提高效率；卸下配重后按实际可用条件重新计算。公斤数不直接等于进度倍率，具体改进要求另行配表。

### 9.4 对非常缓慢成长的影响

本版将「一次效率」落实为**每组获得多少训练进度**，按以下提案配表：

**本组对某块肌肉的进度 = 所选动作对该肌肉的基础进度 × 本次使用器械的效率倍率 × 现有疲劳对应的成长收益系数。** 疲劳系数待按 §10 配表；本节原有算例按系数 1.0 计算。

- 器械种类及所选动作决定受训清单和主练／辅助关系；不在清单里的肌肉没有收益。§8 的主练 +2／辅助 +0.5 作为效率 1.0 时的试调基准。
- 器械改进只改变效率倍率，不添加肌肉，不把原动作的辅助肌肉改成主练。效果只作用于实际使用的器械；未使用的器械不会给全健身房叠加收益。
- **示例：某器械效率从 1.0 提到 1.25**，同一动作的主练由每组 +2 变为 +2.5，辅助由 +0.5 变为 +0.625，肌肉清单保持。1000 门槛的纯主练由 500 组降为 400 组，1600／2400 门槛分别由 800／1200 组降为 640／960 组。倍率仅为演算示例，未定为正式升级档位。
- 比较改进收益时先保持同一动作的组数、体力与耗时一致。此前「效率 1.25 倍同时体力 1.5 倍」的建议撤下；用户尚未确定改进会改变体力消耗或耗时，不把效率提升自动绑定为体力加价。
- 补充配重、架体加固与部件改进共同形成一个可用效率值，不另乘负荷倍率或全局设施倍率。具体改进档位、倍率上限和材料费用待配表，不允许无限堆片换取无限成长。
- **高级器械仍应保持非常缓慢的点亮节奏**。需要按最高可用效率复核达到各档门槛的组数、体力与总耗时，不能只检查初始器械的速度。
- 已有基础器械保持对应肌肉的成长能力；首版不新增「未升级器械就停止肌肉成长」的硬门槛。更高效率来自进一步建设，既有训练进度继续保留。

新增器械和动作的价值也需计入平衡：某肌肉在原动作里仅为辅助 +0.5，在新动作里可能成为主练 +2。这属于新增训练选择的收益，不能当作原器械效率升级，也需纳入最终成长速度评估。

### 9.5 现有材料、制造和设施接口

已有材料可作为候选：废铁`ore_scrap_metal`、铸铁`ore_cast_iron`、钢锭`ore_steel_ingot`、金属管道`metal_pipe`、机械零件`mechanical_parts`、木材和绳索；普通铁坯`material_iron_blank_common`可用于日用小铁件。模板存在不代表新配方、供应和经济已经配平。

- 基础修复与加固可复用现有木作、土石、金属、纤维、机件的缴料结构；玩家看到实物材料与施工描述，继续隐藏内部建造点数。
- 配重片是重复制作的成品，以具体配方记录规格、材料、产量、工时与体力；建造点数不能直接转换成任意公斤配重。
- 材料数量按79号既有玩法节奏配平，本轮不重算全游戏冶炼质量收支。成品重量必须明确，库存重量与训练负荷读取同一数据。
- 高级器械方案沿用研究认知体系；哪些归制造1级基础配方需逐项确定，不新增高技能等级自动赠送路线。
- 79号完整制造执行器仍未全部接入；当前正式铸造台主要处理武器部件，也没有这些器械与配重配方。在制造台、铸造台或健身房建设菜单执行，需在定配方时明确，不能声称已能直接生产。
- 器械、闲置配重、装载记录、部分施工进度一并保存。制作、安装、卸下、加固及保存失败回滚保证唯一归属，换动作不重复发配重。
- 藏身处建设资产建议随死亡保留；已拿入随身容器的独立器械或配重沿用随身物死亡规则。搬运、拆除和返还细则仍待定，不承诺全额回收。

本版不增加器械耐久、维修、随机损坏或定期耗材。建设、重复制作配重、训练资源及新增动作构成首轮长期投入，维护系统以后另议。

参考：[装置解锁材料规则](facility-unlock-point-list.md)、[制造系统](79-manufacturing-system.md)、[正式铸造范围](weapon-forging-runtime.md)。本次只更新设计，未改材料模板、配方或地图。

## 10. 现有疲劳、睡眠与补给循环（2026-11-03，睡眠已接入、训练待接入）

### 10.1 最新确定的方向

用户决定直接使用现有疲劳值限制锻炼成果，随后细化为：**睡眠是最有效的消除疲劳手段，睡眠消耗饱食和饮水，同时恢复体力与消除疲劳；通过持续补给需求驱动收集资源、支持变强。** 以这个最新描述为准，不直接据此前「只能睡觉」删除所有其他恢复来源；它们的效率与成本另行评估。撤下独立「锻炼疲劳」数值、每组额外 +10、40／70／100 示例分段及现实时间／离线自然恢复建议。

- 训练读取现有 `Survival.fatigue`，沿用全身共同的疲劳记录；换器械、换动作不重置。
- 现有疲劳范围 0～100，按动作实际体力支出 × 0.1 增加，吃饭与补充体力不倒扣疲劳。除非之后明确调整，训练使用同一换算，不再额外叠加另一份训练疲劳。
- 以动作成本 10 体力为例，每组增加 1 疲劳，4 组增加 4；这与已撤下的「每组 +10 独立疲劳」不同。实际体力修正仍会改变累计量。
- 肌肉实际成长继续由动作基础进度、器械效率与现有疲劳对应的收益系数共同决定。具体衰减曲线、停止门槛尚未确认。
- 现有疲倦／困倦对招式速度的作用仍是当前规则，本轮未新增额外战斗惩罚或改动它们。

### 10.2 当前已实装的床铺睡眠

| 项目 | 当前运行行为 |
|---|---|
| 入口 | 站在床铺设施邻格，通过设施菜单选择「睡觉」，确认后执行 |
| 疲劳条件 | 必须具有「疲劳」或「困得不行」状态；正常状态同步下相当于疲劳严格大于 50。50 本身不满足 |
| 状态分界 | 大于 50 且小于 80 为疲劳，招式速度 −5%；80 及以上为困得不行，招式速度 −30% |
| 游戏时长 | 固定 48 tick；每 tick 10 游戏分钟，合计 8 游戏小时 |
| 现实执行 | 每tick等待1秒后结算，共48秒；两套界面显示剩余秒数和进度，满值或缺补给不提前结束 |
| 等待与续接 | 睡眠期间限制其他操作，后台暂停，刷新按已保存进度续接；保存失败回退当刻并暂停重试，无离线补算 |
| 固定消耗 | 每刻饱食−1、饮水−1；体力满、疲劳归零或接近边界仍按该数值扣除，无比例折价 |
| 疲劳与体力 | 当刻补给足以支付时体力+2、疲劳−2，各自限制在原范围；48刻最多恢复96体力、减少96疲劳，结束不额外清零 |
| 补给不足 | 数值扣至0为止，当刻不恢复体力或疲劳，仍继续睡满48刻；发生正常死亡则中断 |
| 其他消耗 | 睡眠费用替代原基础饥渴及普通恢复转换，免站立体力消耗；消化、既有行动待结算代谢、药效及其他世界tick规则继续 |
| 属性成长 | 结束时对已有属性经验做一次升级概率结算；成功的该属性升级并清空其经验，失败保留经验，不保证每睡一次都升级 |
| 频次与时段 | 没有每日次数限制、昼夜限制或额外睡眠冷却；每次重新满足疲劳与位置等条件即可再睡 |

普通休息／调息的体力恢复不清除疲劳。睡眠没有独立的「精力回满」步骤，也没有直接治疗全部损毁；正常随 tick 的恢复、药效与其他状态仍按既有规则执行。

### 10.3 其他现有减疲劳入口与定位待定项

- **药物**：兴奋类药效仍有负 `fatigue`，通过 `BuffSystem` 调用 `changeFatigue` 生效。正本包括 `data/pharmacy-buff-matrix.json`，生成结果在 `data/buffs.json`；后续调整不能只改生成结果，避免再生成时恢复旧效果。
- **地牢休息点**：正式恢复动作逐 tick 降低疲劳；默认配置一次使用 8 tick，总共减少 20 疲劳，使用次数为 1。该点目前名为「休息」，不是藏身处床铺睡眠。
- **死亡复活**：当前疲劳设为上限 × `resourceRatio`，现配置 100 × 0.5 = 50；高疲劳复活会降低到 50，低疲劳复活则升到 50。它不是清零，但会改变训练限制，需要在复用疲劳时一并处理，不能漏作绕行途径。

最新目标为睡眠是最有效的恢复手段，其他来源需按效率、资源成本、可重复性及取得难度校准。不能仅因存在减疲劳就认定必须删除，也不能直接认定它们已经符合定位；尤其要检查可批量制作的药物与免费重复来源是否让睡眠失去价值。本轮未删除药效、改写地牢点或更改死亡配置，也未批准新增恢复手段。

### 10.4 对训练节奏的影响与待定项

按用户最新目的，反复「训练—恢复体力—睡眠—再训练」本身就是预期循环，每轮持续消耗补给，并通过收集材料提高器械效率。判断节奏时应计算点亮肌肉所需的训练量、食物、饮水与获取这些资源的投入；不能仅因物资充足的玩家能接着训练，就额外添加现实冷却或每日次数上限。用户已明确睡眠每tick需等待1秒，48秒完成48tick／8游戏小时；这段睡眠等待应计入完整成长周期。

训练停训门槛也必须与睡眠资格配套：当前睡眠要求严格大于 50。如果训练在 50 或更低就完全停止，而又不提供相应的睡眠资格，玩家可能出现不能继续有效训练、也不能直接睡觉的状态，需要通过其他活动继续累积疲劳。正式设计应明确是否接受这段安排或调整门槛。

后续配表需同时核算：疲劳对成长的影响、每轮能练多少、睡眠条件及耗时、最高器械效率、补给成本与最终点亮周期。界面复用现有疲劳值，显示它对下一组成长的实际影响，不新增第二条疲劳。

后续训练验证范围应覆盖：补体力不退疲劳、跨收益档、换动作／器械、睡眠条件与结束、原药物与地牢入口、死亡复活、存读档和保存失败。训练资源、现有疲劳、时间、肌肉进度及点亮仍应原子提交；健身房本轮仍为设计，睡眠已按 §10.6 修改运行。

现状依据：`data/survival-config.json`；`js/survival.js` 的 `consumeStamina`／`advanceTick`／`clearFatigue`；`js/scene-app.js` 的 `executeBedSleepAction`；`js/character-attributes.js` 的 `settleAttributeExpOnce`；`data/dungeon-config.json` 与 `js/dungeon/runtime.js`；制药矩阵及 `js/buff-system.js`；`data/death-system.json` 与 `js/death-system.js`。

### 10.5 训练与补给循环的细化

**用户已确认的基本循环：收集食物、饮水与材料 → 建设器械、准备补给 → 消耗体力训练并累积疲劳 → 花费饱食和饮水恢复体力 → 疲劳达到一定程度后睡眠，继续消耗补给并恢复体力、消除疲劳 → 再训练。** 材料投入扩大训练选择、提高每组效率；补给投入支持持续训练和恢复，肌肉练满后自动点亮。

各环节的分工如下，具体成本与收益仍需配表：

| 环节 | 支出 | 获得／改变 |
|---|---|---|
| 锻炼 | 动作体力及正常时间流逝成本 | 对应肌肉进度增加；实际动作体力支出同时累积现有疲劳 |
| 普通恢复 | 饱食、饮水与恢复时间 | 恢复体力；当前普通休息／调息不消除疲劳，可继续训练但疲劳接着累积 |
| 睡眠 | 48刻每刻固定消耗1饱食、1饮水，作为睡眠基础总消耗 | 补给足够的每刻恢复2体力、减少2疲劳，准备下一轮训练；见 §10.6 |
| 收集与生产 | 探索、采集、生产所需的时间与资源 | 补足下一轮食物、饮水与器械建设材料；具体途径复用已有系统 |

**睡眠已采用 §10.6 的固定费用，普通休息保持原规则。** 睡眠每刻只结算一份费用，不叠加普通休息转换或原基础饥渴消耗。补给充足时总计消耗48饱食、48饮水；体力或疲劳提前恢复完成也不减少这份费用。实际面板净变化还受食物消化、脂肪释放、既有行动代谢与药效等影响。

用户确认缺补给时继续睡满48刻，但暂停当刻恢复，结束保留剩余疲劳；已取消旧睡醒无条件清零。没有增加睡前必须满饱食、满饮水的门槛。

平衡时需关注：

- 睡眠作为主要恢复来源，要与其他减疲劳途径比较一整轮的效果和资源成本；目前没有足够配表可宣称已做到最有效。
- 普通补体力仍有用途。若任何疲劳都允许立即睡、睡眠又在时间和消耗上全面优于休息，玩家会直接反复睡觉；睡眠资格、时长与普通恢复效率需共同保留两种选择的价值。
- 物资储备充足应支持更多训练；资源短缺会推动外出收集和生产。避免饱食、饮水很快枯竭而又不给合理补给渠道，最终变成大量重复点击进食。
- 初期器械与高级器械都需计算每块肌肉的总补给投入。高效器械在相同动作消耗下提供更多成长，使材料建设也能改善单位成长的资源花费，同时仍保持长期点亮目标。
- 正式评估按完整循环统计资源，包括训练期间代谢、普通恢复与睡眠；食物自身已有的属性经验仍独立结算，不能与肌肉点亮奖励重复计入或混为同一进度。

本次修改了睡眠消耗与恢复；疲劳累积换算、普通休息、药物、地牢恢复和死亡配置保持。健身房及肌肉成长仍待接入。

### 10.6 睡眠固定消耗与恢复（已接入）

用户明确本轮需要修改的是睡眠，普通休息继续保持原规则：

- **普通休息：消耗饱食、饮水 → 恢复体力。** 已有疲劳保留。
- **睡眠：消耗饱食、饮水 → 恢复体力，并消除疲劳。** 疲劳恢复纳入睡眠本身的资源转换。

用户进一步简化并暂定数值：**48 tick 内每刻饱食−1、饮水−1、体力+2、疲劳−2，体力满或疲劳归零都不影响扣费。** 随后确认：每刻各扣1是睡眠基础总消耗，不叠加原基础消耗；缺补给继续睡满48刻，暂停该刻恢复。正式床铺已接入，两套界面共用同一入口。

固定结算边界如下，不修改原有入睡门槛：

| 当刻状态 | 当前睡眠恢复行为 |
|---|---|
| 体力未满且仍有疲劳 | 饱食−1、饮水−1、体力+2、疲劳−2 |
| 体力已满但仍有疲劳 | 饱食−1、饮水−1、疲劳−2；体力不超上限 |
| 体力未满但疲劳已为0 | 饱食−1、饮水−1、体力+2；疲劳不低于0 |
| 体力已满且疲劳为0 | 继续饱食−1、饮水−1，直到48刻结束 |
| 饱食或饮水不足1 | 仍按各扣1处理，各自最低为0；本刻不增加体力、不减少疲劳，睡眠继续 |

临近边界也不按比例收费，例如体力99.5、疲劳0.25时仍扣1饱食与1饮水，恢复到100体力、0疲劳。睡眠费用替代原基础饥渴和普通恢复，不叠加站立体力消耗。食物消化、既有行动待结算代谢、药效和其余世界系统照常，故面板净变化可受其他效果影响。

补给充足且没有其他效果时，48刻共消耗48饱食、48饮水，最多恢复96体力、减少96疲劳；从100疲劳开始结束后为4，不能再清零。基础体力上限100时从0开始睡醒为96。原疲劳严格大于50的入睡条件、合计游戏8小时、最后一次已有属性经验结算保留。正常死亡中断睡眠并停止完成提示和属性经验结算，不在死亡后继续补发恢复。

用户进一步要求完整等待48tick，每tick等待1秒。确认后不提前结算，第1秒结束才支付并恢复第1刻；第48秒结束才完成睡眠。体力满、疲劳归零、缺补给都不缩短等待。两套界面共用倒计时、进度与当前资源显示；睡眠期间限制其他操作，停止其他持续动作，其他时间推进不能加速睡眠。后台暂停，返回后继续；刷新或重新打开按已保存刻数续接，不补算离线时间，也不预发剩余恢复。

配置正本为 `data/survival-config.json` 的 `sleep_duration_ticks:48`、`sleep_tick_seconds:1`、`sleep_satiety_cost_per_tick`、`sleep_thirst_cost_per_tick`、`sleep_stamina_gain_per_tick`、`sleep_fatigue_reduction_per_tick`。`js/bed-sleep.js` 调度逐秒等待，正式 `Survival.advanceTick({source:'sleep'})` 结算每刻。不新增疲劳字段；新增可选完整存档字段 `bed_sleep` 保存本次总刻数、已完成刻数、间隔、位置及最终属性判定的随机值，旧档缺失即未在睡眠。开始、每刻与结束共用 `sleep` 保存触发器（默认开启，可在 `data/save-triggers.json` 配置）；失败回退资源、时间和进度，显示重试。第48刻的属性结算与结束状态一并保存，重试不重抽、不重复奖励；普通休息规则保持。

回归：`npm run test:sleep`。覆盖真实食物模型、满值持续扣费、缺补给、边界数值、确认取消、死亡中断、配置读取、两套正式睡眠入口、逐秒等待、操作限制、后台暂停、刷新续接、旧档兼容，以及开始／中间／结束保存失败与属性结算重试；测试使用隔离存储，不触碰玩家存档。

### 11.3 每次使用的体力、疲劳与成长

训练共用现有疲劳字段和现有动作消费管线：**本次动作疲劳增加 = 实际动作体力支出 × 0.1**，由体力消耗触发一次，不再独立追加第二笔训练疲劳。于是表内6／8／10／12／14／16体力，在没有修正时分别增加0.6／0.8／1／1.2／1.4／1.6疲劳。

表列为一组的基础动作体力，既有站立基础消耗、环境修正和世界代谢另按当前规则执行；实际显示应区分动作费用与基础消耗，疲劳不能误按体力净变化计算。器械效率改进暂只改变成长度，不自动提高同一项目的体力费用。

本节最初采用 §8／§9 的成长点试调方式；用户随后改为百分比与动作完成奖励，现以 §12 为准。已点亮目标不再领奖、不把其增量转给其他肌肉；相同肌肉被不同项目训练时合并成长度。

例如选择一组卧推：基础动作消耗10体力，通过现有规则增加1疲劳；胸大肌、肱三头肌作为主练获得成长，三角肌等按最终辅助表获得成长；不推进股四头肌等深蹲目标。增加杠铃片并完成相应加固后，可以提高卧推成长效率，其具体目标清单保持。

项目目录本轮不另定疲劳衰减曲线或停训门槛；这两项仍须与严格大于50才能睡眠的现行条件共同配表。也不把睡眠1秒/tick直接当成训练1秒/tick：§8 的2tick/组、3秒/tick仍只是待评价的训练基准，用户尚未确认训练等待时长。

### 11.4 建设顺序与初始展示

推荐建设顺序只用于安排内容，不是全局健身房等级前置：

3. **逐步补齐专项**：腿部抗阻架、手足专项附件、颈部抗阻架，提供小肌肉和特定方向的训练来源。玩家已取得相应方案和材料时，可以优先建设这些项目，不强制按此顺序。

### 13.4 解剖学与营养效率（2026-11-04）

用户确认先采用本节规则；以后可能指定某些食物Buff提高锻炼效率，具体食物与加成待指定，本次不新增。

用户指定解剖学每升一级提高2%锻炼效率，营养Buff提高10%，并确认「营养充沛」「营养极境」两档均适用。解剖学沿用现有技能`special_meridian_studies`，0级无加成，1级+2%、10级+20%，线性累计；营养只加一次10%，不按层数或两个档位叠加。

**单组肌肉成长＝动作基础奖励×器械效率×（1＋解剖学等级×0.02＋营养加成）×疲劳系数。**

例如解剖学10级、营养充沛、1级器械、疲劳≤50，俯卧撑主练奖励从0.18提高到0.234个百分点；2级器械为0.2691，疲劳>50且<80时为0.13455。主练和辅助肌肉均使用该倍率。体力、疲劳积累、每组时长、肌肉目标清单及100%封顶不变，不因加成重复发放点亮奖励。

配置与公式集中于`GymData.trainingEfficiency`。正式版读取真实技能和既有营养Buff；两套UI显示当前效率与三个来源的数字，不新增说明段落。每组开始时将效率明细和奖励一起锁入`gym.job`，组内技能／营养变化从下一组生效；存读档和失败回退保留已锁结果。旧进行中组缺少明细仍按原奖励结算，下一组采用新规则。合法高等级奖励可超过1个百分点，取消旧存档验证中的单组1%上限。

原独立Demo同步读取同一计算。它没有正式技能库存与BuffSystem，试玩设置提供仅本页生效的解剖学等级和营养值，营养档位使用`Survival.getNutritionTier`；不修改正式角色。`npm run test:gym`覆盖等级、两档营养与不叠加、器械和疲劳组合、主辅奖励、组内变化、连续组、失败回退、读档、旧进行中组、高等级封顶及试玩一致性。
