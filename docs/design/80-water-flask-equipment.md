# 80 水壶装备与构筑

2026-10-31，更新2026-11-01。状态：装备定位、普通容量、构筑来源、单独装备槽、耗材料改造、死亡丢失及青竹水源入壶量+60%已确认。独立试玩含保存、死亡丢失、重制及有限水源对照；青竹和铁皮已接现有制作台试玩。第14节补全三款属性设计，新重量、铁皮快饮、粗陶缓补及配方仍为候选。第15节已接正式卫生间装水、两款真实物品存水／水重／保存；第16节已接正式水壶槽与从壶饮用；正式制作执行器与地牢取水仍未接入。

## 1. 用户已确认

- 水壶是一类正式装备，主要用途是装水喝；玩家可以在家里的既有水源装满，再带出门使用。
- 普通水壶采用200点储水容量。此数值作为基础型号设计，不据此认定所有特殊型号容量固定为200。
- 恢复形式需要开放，以便水壶参与玩家构筑。此前建议的“每次恢复25饮水”“1点存水固定兑换1点饮水”不是整类装备的固定规则。
- 构筑能力主要来自水壶本身的型号、词条和改造。当前先围绕家中饮用水设计；没有据此确认不同液体、混合、配药或水质系统。
- 新增一个独立水壶装备槽，同一时间只能装备一只。
- 改造消耗材料；用户要求将原型的免费切换改成耗材料改造。具体配方、工时、替换与返还规则尚未定稿。
- 水壶死亡后丢失，并应提供制作配方以便重新获得。按03号已有死亡范围，装备中和随身背包内的水壶均丢失；家中仓库物品不受影响。
- 青竹基底从水源装水时，入壶量增加60%。例如水源有40点水，倒进青竹水壶增加64点存水；玩家可在地牢补水点选择装入水壶，详见第12节。

槽位决定覆盖此前助手提出的“仅作为口袋／背心内工具使用”的方案。现行游戏已按第16节新增独立水壶槽，共11个装备槽。

## 2. 型号、词条与改造的分工建议

本节为候选分工，不把三者的效果能力限制死。

| 来源 | 主要职责 | 方向示例（尚未定稿） |
|---|---|---|
| 型号 | 决定基础容量、自重、使用参数、核心恢复方式和可装改造位置 | 直接恢复型、持续恢复型；各型号保留自身取舍 |
| 词条 | 调整或扩展该件水壶的表现 | 容量、耗水、恢复量、持续时间、条件增益；特殊词条也可改变规则 |
| 改造 | 玩家选择方案、消耗材料加工，改变或补充使用方式 | 定量阀改变单次耗水；缓释内胆改变恢复过程；功能部件增加联动 |

同一基础型号应能形成不同配置，而不同型号不必只是容量大小之分。具体型号、词条池、改造数量、部件名称与材料均待后续设计。

词条是效果来源，改造是玩家投入材料的加工方式；本轮原型直接改变水壶的改造状态，未另外产出可拆装的部件物品。以后如设计实体改造件，两者仍可重叠，例如改造件本身携带词条。现有防具规定“词条来自模块”，这里只说明水壶的构筑来源，不自动确定水壶本体能否直接附魔、词条条数或生成方式，也不修改防具原规则。

## 3. 储水与效果独立配置

建议分别配置以下内容，不用一个“恢复量”字段兼任所有含义：

| 内容 | 设计含义 |
|---|---|
| 最大存水 | 装满后的资源上限 |
| 当前存水 | 这一只水壶的剩余资源，随实例保存 |
| 水源入壶倍率 | 实际取出的水源量如何换成存水；青竹为1.6，不与饮用恢复量混用 |
| 使用成本 | 单次耗水、动作耗时，以及具体型号需要的间隔或冷却 |
| 使用条件 | 手动使用或明确配置的条件触发，以及装备与角色状态要求 |
| 效果集合 | 恢复目标、恢复量、立即／持续／分次恢复及附加效果 |
| 条件修正 | 当前角色状态、其他装备或功夫如何影响本次效果 |

基础型号可以只恢复饮水；恢复体力、底气、持续恢复或附加状态均为可设计方向，尚未批准任何具体效果或数值。不得默认所有水壶都具有这些能力，也不因框架开放而自动开启被动饮用或自动补水。

每条修正注明来自哪个型号、词条或改造方案，以及作用于耗水、恢复、时长或触发条件中的哪一项。提高恢复量不自动提高耗水，减少耗水也不自动减少恢复；最终按具体配置与统一叠加规则结算。

## 4. 为构筑保留的使用规则候选

以下细则尚待确认，不是用户已定规则。

1. **装备生效**：建议只有当前装备的一只水壶提供构筑效果。携带备用壶、未装备时是否可单纯喝水、换装耗时和战斗换装规则另定。
2. **饮水满值**：不以“饮水度已满”作为所有水壶的统一禁用条件；若本次还能产生已配置的其他有效收益，应按该效果的使用条件判断。
3. **按需扣水**：此前“缺多少饮水只扣多少水”的建议只适用于明确支持按比例使用的型号。固定耗水、多种效果或条件触发不能仅按缺失饮水量把费用减为零。水量不足时是否允许部分使用按型号另定。
4. **持续效果**：需要分别设计重复饮用时是叠加、刷新、延长还是拒绝，并明确总恢复量与持续时间的关系；延长时间不默认复制一份总效果。
5. **换装与补水**：剩余水量、已发生的消耗和冷却不因移动物品或重新装备而重置。持续效果是否随卸装终止、换壶后是否共享使用间隔，须在具体效果设计中明确。
6. **装满**：建议家中水源补充存水；是否另有费用、耗时和附加触发待定，不默认同时重置冷却或给角色恢复。

“喝水1 tick”“每只装满1 tick”、空壶重量、存水与物理重量的换算、普通型号的单次耗水与恢复量均为待定，不能把之前助手的首轮建议当作已确认参数。

## 5. 与现有系统的关系

- **家中水源**：[卫生间设施](bathroom-facility.md)已提供修复后的直接饮水与洗澡。水壶需要增加装水入口，直接饮水和装入水壶是不同操作；修复与相邻交互继续使用现有设施规则。
- **已有物品与配方**：`tool_flask_iron_water`（铁皮水壶）已经存在，当前归类为工具容器，重量0.7kg、堆叠上限1，没有本设计的储水与饮用行为。本轮原型复用79号 `manufacturing.tool_flask_iron_water` 配方制作基础水壶，不新增同名物品或第二条重复配方；正式迁移为装备及补齐储水行为仍待接入。
- **装备与信息**：遵循[63号物品属性](63-item-attribute-modules.md)的大类与字段分组；展示存水、使用成本和玩家已认识的实际效果，复用既有认知规则。
- **材料加工与实体部件**：本轮水壶原型采用直接耗材加工，不建立可拆装部件物品。后续若引入可拆装实体改造件，须遵循[65号连接与组合重量](65-item-assembly-and-combined-weight.md)，每件部件保持独立身份与状态，不能以属性副本代替。耗材改造不自动改变其他装备的实体装配规则。
- **持久化**：依照[64号实例身份](64-item-instance-identity-and-transfer.md)，储水、词条、改造和相关使用状态跟随同一只水壶搬运与存档；正式接入时再定义旧档迁移，不默认给旧壶补满水或发放免费装备。

## 7. 首只铁皮水壶原型

用户要求开始做第一只原型水壶。现提供[独立试玩页面](../../tools/water-flask-prototype.html)，操作、数值、验收范围及待评价事项见[试玩记录](../../tools/water-flask-prototype-NOTES.md)。启动命令为 `npm run prototype:water-flask`，纯逻辑终端入口为 `npm run prototype:water-flask:logic`。

默认容量200，耗水25立即恢复25饮水；节流候选词条将耗水降至20，润泽将补水量提高20%。缓释内胆将补水总量提高60%并分5刻恢复；调息内胆保留即时补水，附加3刻共15底气恢复。原型只放一格词条选择与一个当前改造状态用于比较，不据此确认正式槽数、附魔位置或词条获取方式。

固定耗水、喝水／装水／装卸各1刻、持续期间禁止再饮用、已饮用效果卸下后继续，以及重量换算均为原型试值。可在试玩设置里独立修改基础耗水与补水，检验两者解耦；确认项仍只以第1节为准。

原型独立模拟单独装备槽、家中水源与饮用效果，并使用独立试玩存档保存进度；未修改正式装备栏、物品目录、卫生间交互、恢复结算或玩家存档。

## 8. 材料改造原型

用户要求改造消耗材料。现有原型改为“选择方案 → 查看效果和材料 → 点击改造”，选择只预览；完成改造时一次检查全部材料，足够才扣料、推进工时并应用效果。不足、外出或已经是同一方案时不扣材料、不耗时。

| 改造方案 | 首版材料配方 | 工时 |
|---|---|---|
| 缓释内胆 | 普通铁坯×1、分层过滤片×1、软木塞×1 | 3刻 |
| 调息内胆 | 钢丝料×1、硅叶×1、软木塞×1 | 3刻 |
| 恢复普通内胆 | 软木塞×1 | 1刻 |

以上材料使用现有物品名称与ID，但用量、工时及内胆的功能解释均为试玩提案。当前在家中加工，更换方案再次支付该方案材料，旧材料不返还；恢复普通内胆也需耗材。地点限制、返还规则及恢复普通的费用同样待评价，不视为所有装备通用规则。

加工保留同一水壶、当前存水和词条。已饮用的持续效果沿用饮用时的配置，改造工时正常推进其结算。原型内单独发放家中试玩材料，切换情境不补材料；试玩设置可补充或清空，刷新继续上次进度。未连接正式背包、家中库存、工作台、制造队列或正式配方执行；词条选择仍是免费比较入口，不代表硅叶附魔已实现。

## 9. 改装保存在具体水壶实例上

用户询问改装如何保存。本设计复用64号已实现的物品实例身份与转移原则：型号来自模板，实际词条、当前改造和存水属于这一只水壶。装备槽只指向实例，不保存另一份水壶配置；不能把改造写到角色永久属性上，也不能让同型号所有水壶共用一份状态。

| 保存内容 | 归属与规则 |
|---|---|
| 模板、实例身份 | 沿用 `item_id`、`instance_id`，装卸与存取不换身份 |
| 当前存水 | 跟随该只水壶，读档不能补满 |
| 实际词条 | 保存词条标识、已确定的数值与必要状态，读档不重新抽取 |
| 当前改造 | 保存方案标识、版本及实例特有参数；本轮耗材加工直接写入壶身状态 |
| 剩余冷却等使用状态 | 如以后存在，保存剩余世界tick或截止tick，移动和读档不清零 |
| 已饮用的持续效果 | 属于角色上正在结算的效果，独立保存来源实例、剩余总量和剩余刻数，不从当前内胆重新生成 |
| 配方知识 | 属于角色知识，不存进某只水壶，死亡后保留 |

正式字段按63号的“大类／字段组”分层：存水置于 `attribute_state.structure.liquid_storage`，改造与使用状态置于 `attribute_state.equipment.water_flask`，分别带版本号；实际词条沿用实例 `enchants`，不存第二份。第14节给出完整候选契约，具体注册与迁移在正式接入时实现。旧模板实例缺少水壶状态时按普通空壶初始化，不凭空补水、赋词条或复制其他壶的改造。真实可拆装部件若以后出现，仍遵循65号的实体身份与连接规则。

改造时将“材料扣除、改造写入、耗时和已发生的持续结算”作为同一次状态提交保存，失败不留下只扣料或免费改造的半成状态。卸下、装入背包、存入仓库和再次装备都搬运原实例；当前内胆不会因为离开装备槽而丢失。保存的是完成后的实际状态，不是重放加工事件。

本轮浏览器原型将水壶、材料、身份序号、资源、持续效果及日志整体保存到专用 `water-flask-prototype:save:v1` 键，操作后自动保存，刷新读回；`flask: null` 表示已经丢失，禁止读档时把空值当缺省而重发初始水壶。它是可丢弃试玩存档，不读取、迁移或覆盖正式游戏存档，也不表示正式保存链已接入。

## 10. 死亡丢失与重新获得

- 死亡清除装备中或随身容器内的整只水壶，词条、改造和剩余水一起丢失，不返还加工材料，也不变成一个可继续使用的空壶。把壶卸到背包不能规避损失。
- 按03号规则，家中仓库里的备用水壶和材料保留；已学基础配方以及已掌握的改造方法作为知识保留。改造方法的具体学习渠道仍待定。
- 复活后水壶槽为空，不补发初始水壶，不复制旧壶的属性；必须通过制作或其他实际获得途径补充。
- 新制作的是新的实例，默认空壶、无词条、无改造，再自行装备、装水与加工。制作水壶和改造水壶分别付料。
- 原型在死亡时清除当前持续恢复，饮水、底气、体力回到演示上限的50%；该清除策略是本轮演示细则，完整复活结算仍以正式死亡系统为准。
- 本轮不扩展或删除03号既有投保流程；水壶在保险快照中的具体归还范围留待投保接入，不提供自动恢复旧壶的例外。

原型的材料明确视为家中库存，因此模拟死亡后保留。这里只保有一只随身试玩水壶，未制作实体仓库存取或多壶管理界面；不能据此推定正式游戏最多拥有一只水壶。

## 12. 青竹基底：水源入壶量增加60%

用户明确将青竹改为取水收益型：**从水源取出X点水，装入青竹获得1.6X点存水**。例如地牢补水点40点水全部倒入容量足够的青竹，水源40→0，壶内0→64。此前回气建议撤下，不叠加到这个基底上。

这是型号固有能力，不占候选词条或改造位置。加成只在水源装入水壶时结算一次；直接从水源喝仍按原量恢复角色饮水，之后从壶里喝则按该壶当时的耗水、词条和改造结算。已有润泽与缓释作用于饮用效果，不再次放大水源入壶量。装卸、移动和读取存档不触发取水加成。

容量暂沿用200。家中充足水源把青竹装满也只有200存水，不能装成320。接近装满时，原型先采用按剩余空间取水、余水留在水源的方案：青竹已有190，补满只取6.25点水、增加10点存水，原有40点水源还剩33.75。数量按最多四位小数试算；这项满壶边界和精度是待评价的试玩规则，并非用户已确认的整数或溢出规则。

### 独立试玩与保存范围

死亡丢失整只随身壶及其词条、改造和存水，家中库存与已学方法保留；重新制作创建新身份。读档、存取、装卸、填水和改造均不重发壶、不重抽词条、不补满存水，也不清除冷却。

### 14.6 接入边界与核对

结构化草案以 `draft_version` 标明设计文件，`target_schema_version: 2` 仅说明目标目录结构；新增字段组与水壶槽仍需正式注册、消费者和认知入口，不能直接把草案当作可运行目录。正式目录仍只有青竹与铁皮的基础工具条目；现有制作与水壶试玩仍是第13节的两款行为。粗陶、铁皮快饮与本节新的自重只在设计中。

本轮核对三款模板ID不互撞、主材料均已有登记、青竹／铁皮引用实际配方、粗陶材料与工艺可引用、字段落在既有大类内、实例状态不写进模板、0 tick与空壶0存水保留，并复算40→64、满壶次数／总恢复和水重。正式接入时还须测试冷却防换壶、持续效果保存与同源重复使用、实际认知过滤及原子扣料／交付，不能用设计文件检查代替游戏验收。

## 15. 正式卫生间补水（2026-11-01）

用户要求查找并给既有卫生间接入补水。本轮正式实现“卫生间修复完成 → 给水壶装水 → 选择随身实例 → 完成后装满并保存”，详见[卫生间设施](bathroom-facility.md)。每只1 tick为当前可调值，家中水源沿既有充足供给；直接喝水和装入水壶分别操作。

仅将第14节中的存水部分正式注册：`structure.liquid_storage`内容量、初始存水、水重；`equipment.water_flask`内水源倍率。数据源是 `data/water-flask-storage.json`，不是直接加载整份三款草案。现有青竹／铁皮均容量200、初始0，倍率1.6／1，自重仍各0.7 kg。水重每点0.005 kg为沿用原型的试调换算；未把青竹候选0.4 kg、铁皮快饮或粗陶缓补一起上线。

当前水量按版本1存于 `attribute_state.structure.liquid_storage.water`；名称按语言认识、存水与容量通过物品信息和补水选择页显示。装水不改词条、改造和已有冷却，也不恢复角色饮水。零水量、身份与全部其他状态随正式存档、仓库和地面转移保留；死亡沿原随身物品清除，不免费重发。旧真实水壶只在缺少存水组时初始化为空，不读取独立试玩存档。

补水前及完成时按实例身份查找仍在身上的壶；满壶、未携带、无选择或条件不足不开始。动作中断保留已过时间、不发水；存档失败回退时间和水量。物品快照深复制修正已通过保存失败与普通读档检查。有限源40→64仅为共用取水计划的计算验收，正式地牢补水点尚未接入。

实际可操作的是随身口袋／背心／背包中的已注册水壶。单独水壶槽、壶内饮用、制造执行器、粗陶以及完整改造消费者仍待后续接入；水壶原型和制作台原型继续独立运行。验收页 `tools/bathroom-refill-check.html` 加载正式游戏与隔离存档，不修改玩家进度。

## 16. 正式从壶饮用与独立槽（2026-11-01）

用户在卫生间补水接入后要求“接入从壶饮用”。本节覆盖第15节末尾水壶槽、饮用待接入的历史状态。当前流程为卫生间装水 → 在物品栏装备水壶 → 动作菜单“从壶饮用”，也可在装备栏点选水壶后饮用。只使用水壶槽中的一只，随身备用壶可换装；装水仍可以选择未装备的随身壶。装备及卸下沿用通用装备流程，不新增换装时间规则。

正式青竹、铁皮暂沿原型基础试调：容量200；每口耗水25、即时恢复饮水25、动作1个世界tick，满壶8口。当前只承接这两款基础效果，未把第14节铁皮快饮、粗陶缓补或新重量候选一并上线。饮水不足25时仍按整口消耗，恢复截断至角色上限；完全喝饱或水不足一口则不开始。时间推进仍会正常结算自然饥渴衰减，因此UI净增量可能略低于25。基础耗水与恢复量相同只是本轮试值，不是水壶换算定律。

`data/water-flask-use.json` 经物品构建器验证后注册 `equipment.wearable.equip_slot=water_flask`，并在 `equipment.water_flask` 登记 `flask_drink_cost`、`flask_drink_ticks` 与 `flask_effects`。恢复集合沿第14节的target／total／timing／duration_ticks契约，当前执行器仅支持即时thirst；不支持的效果拒绝执行，后续扩展恢复目标与时序需同时补对应消费者与保存。保留 `pocketable=true`，使未装备水壶仍可放入口袋；不增加 `usable` 或一次性 `use_effect`，避免饮用把整只壶删掉。

实际饮用重新按实例身份查找装备槽；过期选择不能饮用替换后的另一只壶。仅修改 `attribute_state.structure.liquid_storage.water`，不替换壶、不重抽词条、不清除其他兼容状态。青竹取水倍率不再次放大饮用恢复。扣水、恢复与世界tick在同一保存事务里结算，保存失败整体回退；眩晕沿既有行动规则处理，死亡／昏迷／剧情或活动限制禁止开始。战斗中允许合法饮用，正常推进世界tick，不提供额外攻击机会；途中死亡仍按原死亡流程清除本体。

新增槽复用存档、重量、转移和死亡遍历。旧存档缺少该槽时保持空槽，旧真实水壶缺少水量组时初始化为空，不导入原型存档或发壶。卫生间已可直接补满装备中的水壶。总负重与物品详情均读取空壶重量加实际水重；喝掉25点水减少0.125 kg，喝空后空壶仍保留。

验收：`tools/test-water-flask-use.mjs` 覆盖原界面／Svelte界面的装水、装备、详情与动作菜单饮用、装备中补水、换壶、过期选择、保存回退、空壶与不足一口、8次用尽、死亡与仓库、旧档不补发及配置拒绝；`tools/test-bathroom-facility.mjs` 复核补水不受影响。`tools/bathroom-refill-check.html` 延用隔离存档，可直接体验全流程。正式制造执行器、地牢补水点、粗陶及词条／改造效果仍待接入。

### 16.1 登记到快捷动作栏

用户要求从壶饮用与其他动作一样可以登记快捷栏。动作菜单的饮用行增加📌，点击后沿既有规则登记到首个空槽，最多4格，右键清除，随 `player.sceneUi.action_bar_slots` 保存。固定标识为 `action|drink_flask`，不绑定水壶实例；换壶后使用当前装备壶。允许空槽或喝饱时预先登记，实际饮用仍执行同一校验，失败提示、不扣水、不额外推进时间。登记与清除不消耗世界时间，栏满不覆盖其他动作；不默认替玩家登记。原界面与Svelte的标签、执行和保存使用相同约定。
