## 1. 目标与精度

- 夏季的主要环境压力来自高温，冬季来自寒冷；玩家通过多种手段抵御，并可借天气、气温取得招式或呼吸法收益。
- 温度不只来自气候，也可来自地图特性、设施、特殊事件或玩家手段。
- 精度停在“地区天气 + 整张地图的环境条件”。不做逐格温差、屋内屋外识别、屋檐遮挡、热传导、风速、湿度、气压或降雨量模拟。
- 天气种类可以丰富，计算保持简单。存在暴风雨状态不意味着需要风力模拟。
- 环境层提供统一事实；各系统分别定义响应。系统知道的事实不等于玩家知道的信息。
- 不自动恢复已取消的农业天气供水、蓄水机制或畜牧气候塔。

## 2. 时钟、季节与开局

- 只随统一世界 tick 推进；沿用每 tick 10 分钟、每天144 tick、每年360天。
- 春夏秋冬各90天，全世界历法季节一致。地区之间通过气候曲线体现差异，不各设一套季节时钟。
- 普通开局为第一年春季第1天；初始天气从当地当季普通天气中抽取，不直接处于热浪或寒潮。此后正常运行，不等待玩家准备、不按角色强弱调整季节与天气。
- 特殊开局允许另行指定日期、地区与天气。
- 日期进入新季节不会直接施加冷热惩罚，也不会导致气温跳变；实际有效温度决定是否形成暴露。
- 90天是历法长度，不意味着整季持续危险。冷热持续期与强度由后续温度配置决定。
- 查看界面、现实中离开游戏不推进天气；持续动作通过已有机制推进世界 tick。睡眠、生产等长时行为需计入期间天气变化，不能只取起点或终点天气。

## 3. 天气种类与持续事件

首版天气种类：

| 类别 | 天气 |
|---|---|
| 晴阴 | 晴朗、多云、阴天 |
| 降雨 | 小雨、大雨、雷雨 |
| 雾 | 薄雾、浓雾 |
| 寒冷降水 | 雨夹雪、小雪、大雪 |
| 极端天气 | 暴雨、暴风雨 |

- 热浪、寒潮作为独立的持续冷暖事件，与当前天气组合；热浪不保证晴天，寒潮不保证下雪。
- 对外同时提供具体天气与通用分类条件：雷雨具有降雨、雷电条件；暴风雨具有降雨、风暴条件；雨夹雪具有雨、雪条件。具体标识名待配置契约确定。
- 雪类天气受地区与气温条件限制，不让所有地区逢冬必雪。
- 天气提供表现、气温修正及条件输入，不因增加一种天气就自动增加一套惩罚。
- 降雨暂不自动新增淋湿、装备受潮等机制；雾是否影响大地图视野也未确定。钓鱼观察限制沿对应设计处理，不自动扩大到大地图。

## 4. 天气过程与持久化

- 每段天气有持续时间，到期后按地区、季节、当前天气决定下一段；不每 tick 重抽，不在每天零点强制换天。
- 通过转换关系保留连续性，例如阴天较容易转雨、雨后较容易转阴；不是每天执行固定流程。
- 允许相同天气连续多段，形成跨日阴雨等过程。热浪、寒潮有自己的持续时间，期间影响气温与天气概率。
- 地区在玩家离开后仍随世界 tick 演变。返回、切图、开关钓鱼窗口都不重抽天气；存读档保持进程连续。
- 需要补算的系统可读取少量天气阶段及起止时间。不得用返回时的天气代替离开期间整段历史，也不得据内部历史生成玩家未观察到的见闻。
- 具体持续时长、概率、转换表、历史保存边界与存档字段待实现设计确定。

## 5. 地区与地图

| 地图规则 | 天气 | 温度 |
|---|---|---|
| 普通地图 | 继承地区 | 继承地区 |
| 特殊冷热地图 | 可继承地区 | 地区温度修正，或独立温度 |
| 明确与外界隔绝的地图 | 可无外界天气，或独立天气 | 独立配置 |

- 同地区普通地图共用天气进程，不同地区可以不同；不模拟天气在地图间移动。
- 天气覆盖与温度覆盖相互独立。露天特殊热地图仍可能下雨；隔绝外界的地图不因地区雷雨而自动满足雷雨招式条件。
- 不默认所有地牢都隔绝天气，不增加逐格室内外判定。整张地图按显式规则统一生效。
- 各系统读取当前地图最终生效的环境，不能绕过地图覆盖直接拿地区天气判定。
- 旧地图未声明温度时按适温处理是现有兼容口径，不作为新地图省略所属地区后自动获得安全环境的设计依据。具体旧地图迁移与缺省策略待接入时确定。

## 6. 有效温度及过渡

普通地图的目标温度结构：

**地区当季基础气温 + 昼夜修正 + 天气与冷暖事件修正 + 地图修正。**

- 地区基础气温沿一年逐渐变化；昼夜采用简单修正，不模拟日照过程。
- 目标气温与当前气温区分：同地图随 tick 逐步接近目标，不因换季、入夜、转晴或寒潮开始瞬间跳温。
- 切图后立即读取目标地图当时的环境温度，不从上一张图气温过渡；角色当前体温保持连续。
- 独立温度地图按自身规则运行。特殊事件默认逐步改变温度，也允许明确配置为骤变。
- 过渡只需可配置的每 tick 变化速度，不做热传导。
- 换装备或开启效果后，个人承受范围立即更新，但不能瞬间恢复已有体温。

## 7. 角色承受能力与效果叠加

分清三类作用对象：

| 对象 | 作用 | 边界 |
|---|---|---|
| 地图环境 | 改变有效温度或天气 | 影响所有读取当地环境的系统；不绕过敌人默认仅读取的限制 |
| 角色承受能力 | 扩大范围、减缓升降温 | 只改变该角色如何承受环境 |
| 角色当前体温 | 升温、降温、恢复 | 不改变地图气温，不能代替高温环境等功法条件 |

- 环境温度、抵御能力与利用能力独立。耐热不自动提供高温战斗加成；获得高温加成也不自动免疫过热。
- 耐寒与耐热分别计算；承受范围修正相加。
- 失温减缓与升温减缓分别计算，变化速度倍率相乘。例如两个减缓50%的效果合计剩余25%速度，不自动变成免疫。
- 普通“恢复正常”效果朝标准体温变化并在标准值停止；明确升温或降温可以过量，不能混为同一效果。
- 同源重复使用按具体效果声明刷新、延长或替换，不默认无限叠加。
- 具体温度范围、原有阈值公式是否沿用、各来源数值与极端组合边界留待数值设计。
- 防具基本穿戴属性及冷热防护的承载方式留待缝纫系统：不预先绑定衣物、材料、底材、板位、附魔或新增装备槽，不默认御寒必然降低耐热。既有战斗激活体系保留。

## 8. 暴露、身体状态与恢复

### 8.1 两种分档不能混用

- **环境暴露程度**：按有效温度超出个人最终承受范围的程度分档；超出越多，体温恶化越快。先应用范围修正、判定暴露档，再应用变化速度倍率。具体档数、边界、速度待定，替代旧的统一每10 tick变化0.1℃规则。
- **身体状态程度**：按当前体温相对标准体温的偏离程度判定，决定症状、惩罚及死亡。进入恶劣环境不等于已重度失温，离开也不等于身体恢复正常。
- 沿用当前体温与标准体温两个状态，标准体温默认37℃，允许明确物品、事件、技能修改。精确数值默认不向玩家公开。

### 8.2 已确认的身体后果

| 程度 | 失温 | 过热 |
|---|---|---|
| 轻度 | 可感知症状，无数值惩罚 | 可感知症状，无数值惩罚 |
| 中度 | 降低战斗速度 | 增加原本耗体力动作的体力消耗 |
| 重度 | 加重战斗速度惩罚，同时增加动作体力消耗 | 加重动作体力消耗，同时降低战斗速度 |
| 致命 | 触发正常死亡流程 | 触发正常死亡流程 |

- 战斗速度沿现有先手、连击、命中规则生效，不修改地图移动格数或耗时。不再额外增加通用招式威力惩罚。
- 原本不耗体力的动作不凭空增加体力消耗。增加的实际行动体力消耗照常累计疲劳；不另设天气每 tick 增加疲劳。
- 普通恢复仍走既有休息等行为的饱食/饮水转换，不新增恢复效率惩罚。移动继续不直接扣饱食或饮水。
- 不恢复冷热直接增加饱食消耗的旧规则；不额外新增饮水消耗、精力、心情、营养或底气恢复惩罚。
- 体温和疲劳的战斗速度惩罚可并存，数值阶段需共同校准。保留撤离能力，不新增冷热强制跳过行动、随机昏倒或完全禁行规则。

### 8.3 恢复

- 进入个人能承受的环境后，体温逐渐回归标准值；惩罚随当前体温逐档解除。
- 主动恢复在危险环境中也可生效，与环境造成的变化共同结算，不直接清除体温状态。
- 休息、睡眠本身不免疫冷热；没有明确防护或调温效果时，时间推进仍可导致恶化。
- 失温后进入仍会导致升温的高温环境，可以先回暖，但环境升温作用不会在标准体温停止，持续停留可能转为过热；反向同理。若温度已在个人承受范围内，则执行普通恢复并停在标准值。
- 恢复正常不退还体力、不清除累计疲劳；按原有各自规则恢复。

## 9. 耐候技能

- 保留一个耐候技能，同时提高耐寒、耐热承受能力；等级上限100。既有每级0.1℃属于当前数值基线，不在此次调整；最终与新范围表一起校准。
- 先计入装备、技能等范围修正。只有环境仍超出个人范围、并实际对身体产生升降温作用时，才积累熟练度。
- 仅身处冬季、热浪或特殊地图不构成成长条件；范围完全覆盖或完全阻止环境升降温时不成长。
- 仅减缓变化仍可成长；主动恢复抵消恶化不抹掉已经承受的环境作用。不可仅按该 tick 最终净体温变化判断是否成长。
- 符合条件时沿用每 tick +1 熟练度，更严重暴露或濒死状态不额外加速。
- 小数显示或累计方式不能把实际微小暴露误判为零；数值结算细节待实现。

## 10. 功法、敌人与其他系统

- 明确区分高温、低温、季节、天气、角色身体状态等条件，不能互相替代。冬季特殊热地图可以满足高温招式；改变目标体温不等于改变环境。
- 做好防护不取消环境加成。环境收益与角色身体惩罚分别结算。
- 具体招式、呼吸法、加成形式与数值留待后续设计；不自动为全部招式加天气修正。
- **敌人默认仅读取环境**用于条件判定，不由天气自动驱动行为、体温恶化或死亡。只有玩家通过明确手段触发时，才按该手段定义的对象、范围与后果运行。撤回自动模拟敌人长期暴露、离图累计冷热死亡等提案。
- 普通NPC先具备读取能力，具体天气行为在对应NPC设计时确定，不模拟全世界NPC生存。

| 系统 | 首版接入范围 |
|---|---|
| 玩家生存 | 环境温度、防护、体温、耐候及已确认惩罚与恢复 |
| 招式、呼吸法 | 天气、气温等条件判定入口；内容另定 |
| 敌人 | 仅读取；玩家手段触发的后果另定 |
| 钓鱼 | 统一环境输入，鱼种、水域响应按钓鱼设计接入；气温不直接等于水温，不统一雨天增益 |
| 农业、畜牧 | 可读取，不自动改现有供水和生产规则 |
| 普通NPC | 可读取，具体行为另定 |

提供接口不等于该玩法已有对应内容或已完成运行接线。

## 11. 认知与提示

- 后台真实环境、人物感受、仪器读数分别处理。精确气温不默认公开，有数字也不保证仪器可靠。
- 感受受个人防护与身体状态影响，不能固定换算成精确温度区间。
- 测量结果保留地点、时间及必要条件；精度、仪器状态与用法决定可靠性。旧读数不自动更新，不因持有温度计解锁全地区实时准确HUD；无校验依据不提示精确误差。
- 环境温度计不自动具备测量体温的能力。
- 天气只呈现当前能感知的情况，不提供完整天气目录、隐藏天气占位或准确未来预报。历法、日期、经验判断与消息同样需要知识依据；内部记录不自动变成见闻。
- 冷热惩罚通过身体表现说明，不自动公开后台档位、阈值、倍率。功法生效提示不能间接泄露未知精确气温。
- **天气变化、冷热恶化只告知，不自动暂停任何持续行动，也不新增自动惊醒规则。** 状态未变化不反复刷提示，明显变化合并简短描述；无法感知外界的地图不通知外界天气。
- 既有其他行动终止规则与正常死亡流程继续生效；本条只撤回天气提示造成的自动暂停与惊醒。

## 13. 后续数值与验收范围

待定：地区年温度曲线、昼夜修正、天气/事件概率与持续期、天气转换表、温度过渡速度、地图覆盖值、个人基础范围、暴露档数/阈值/速率、身体状态与死亡阈值、惩罚幅度、恢复速度、叠加边界。衣物与其他防护来源、具体功法、NPC行为及各生产玩法响应另行设计。

实现时应覆盖以下行为验证；本轮仅登记，不表示测试已完成：

- 季节边界、跨日、长时行动中的天气变化；同地区一致、切图/读档不重抽。
