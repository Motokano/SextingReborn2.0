# 43 · 食物与饱食重构（消化模型）

> 目标：把「吃」从**即时数值**改成**一段由胃里内容决定的曲线**——体现消化过程、餐的组成，以及「突然大暴食胃反应不过来、后期顶得难受」的现实感。
> 与 `24-attribute-experience`（进食/睡眠 = 成长主通道）、`06-survival`（饱食/营养/体重）、`21-cooking`（烹饪/配方）联动。
> 载体：现有 **34 个「消化中」buff**（`data/buffs.json`，durationTicks 8-12 + 每回合 survival_delta）——升级 `durationTicks → 消化时长`、`delta → 总量÷时长` 即得新模型，不需新机制。

## 一、餐位档（菜等级）——复杂度/等级的职责 = 定饱食

每档只定两个数：**饱食总量** + **消化时长**；每 tick 贡献 = 总量 ÷ 时长，自动推导。

| 档位 | 饱食总量 | 消化时长 | 每 tick 贡献 | 占盒格数 | 代表 |
|---|---|---|---|---|---|
| 餐前小食 | 10~15 | 20~30t | ≈0.5 | 1 | 苦草茶、水牛酸奶、咸黄瓜、蒸蛋羹、甜菜发酵饮、野果 |
| 家常菜肴 | 30~35 | 40~55t | ≈0.7 | 1 | 简单炖肉、清鱼汤、白面饼、炸土豆块、蒸鲷鱼、盐烤白鱼、香草烤土豆 |
| 精致佳肴 | 45~55 | 50~65t | ≈0.9 | 1~2 | 苹果木烤火鸡、芥末牛舌、洋葱牛肉快炒、鱿鱼快炒、芝麻蒜蓉沙拉 |
| 宴席大菜 | 65~85 | 60~80t | ≈1.1 | 2~3 | 清炖牛腩、猪蹄豆汤、白鱼汤 Deluxe、河虾软炸、莲花糯米鸡、腌肉片 |
| 饕餮盛宴 | 120~180 | **120~180t** | **≈1.1** | 3~4 | 15 道终局菜（佛跳墙、三鸟转、八宝葫芦鸭…） |

**设计意图**：
- **盛宴 = 慢而长的续航型**：每回合贡献 ≈1.1、时长拉到 120-180t——交付的总量（c×t ≈ 130-200）大部分被**同窗口的衰减（-1 × 120-180）抵消**，净变化率仅 +0.1/tick 左右，非饱腹时吃不会顶进过量区间（暴食由「过量区间」触发，见七），「一菜一餐」体现在**总覆盖时长**（一盅顶一路，下地牢全程续航），且 c>1 保证能把人从饥饿线上缓慢拉起来。
- **一餐的饱食预算**：3 道家常（≈96 总量）≈ 从 20 吃回接近满。
- **维持 vs 恢复是算出来的**：单吃低档菜净变化率仍为负（维持），配齐一餐或盛宴长线才净正。
- **快 vs 长 = 取舍**：小食快（应急/战斗粮）vs 盛宴慢（续航）。

### 1.1 苦力菜（workhorse）——压缩饼干式（新增）

- 设计一种**几乎不给经验、特别好做、唯一价值 = 高效回饱食**的料理，原型是**压缩饼干**：
  - **大量饱食**：satiety_total 高、c ≈1.3（净 +0.3/tick，真正的高效保底，单吃能把人从饥饿线上拉起来）；
  - **吃了会口渴**：`thirst_restore` 为**负值**（吃一块即时扣饮水，如 -15）——代价明确，吃压缩饼干必须配水；
  - **方便携带**：低重量、高堆叠（如 stack 上限高）、长保质（干燥食物不腐败或极慢腐败）——适合远征背一大包。
- **与饮水系统咬合**：饮水是即时恢复 → 吃饼干 → 即时口渴 → 喝水补 → 形成「压缩饼干 + 水壶」的出征组合。
- **饱食与经验解耦**：苦力菜管生存（回饱食），精致/均衡菜管成长（给经验）。
- **前期保底**：前期必须保证玩家解锁至少一道苦力菜，穷玩家永远有办法爬出饥饿坑。

## 二、消化模型（核心公式）

```
当前饱食每 tick 变化 = -1（基础衰减） + Σ(活性消化菜的每 tick 贡献 c)
```

- 吃下的菜进入「消化中」状态，持续 `消化时长` tick，期间每 tick 贡献 `c`，**多道菜叠加生效**。
- 效果结束 → 该菜退出，变化率回落。

| 场景 | 变化率 |
|---|---|
| 空胃 | -1.0 /tick |
| 单吃家常菜肴（c≈0.7） | -0.3 /tick（饿得慢，维持） |
| 单吃苦力菜（c≈1.1） | +0.1 /tick（勉强爬升，保底） |
| 三道家常同时消化（Σc≈2.1） | +1.1 /tick（一餐，爬升） |
| 单吃饕餮盛宴（c≈1.1，120-180t） | +0.1 /tick（慢续航，一盅顶一路，能拉起饥饿线） |

## 三、营养均衡（第二轴，保留）

- 每道菜带**构成标签**：`主食 / 荤 / 素 / 其他`。
- 一餐覆盖类别越多 → 均衡度越高 → **营养值档位**越高（充沛 ×1.3 潜能、极境 底气上限 +15%）→ 属性经验倍率越高——**让玩家有意识地保持荤素平衡**。
- 与餐位档**正交**：档位定强度（饱食），构成定均衡（经验）。**苦力菜构成简单（基本无均衡贡献）、经验 ≈ 0**，进一步坐实「吃好 = 配齐 = 成长」。

## 四、饮水（即时恢复，不走消化曲线）

- **喝水 ≠ 吃饭**：饮水保持**即时恢复**（沿用 `thirst_restore`），不参与消化曲线；食物带的水分（汤/饮）仍即时生效。
- 结果：渴了立刻喝（即时），饿了提前吃（规划）——两种资源两种节奏。

## 五、睡眠（普通过时间，只结算经验）

- **睡眠就是普通的睡觉度过时间**，不加速消化、不额外结算胃内容。
- 睡眠唯一职责：**结算进食已累计的属性经验**（`24` 通道：进食积累 → 睡眠判定 → 概率结算，永不 100%）。
- 消化状态在睡眠期间照常按 tick 推进。

## 六、饭盒（一餐的物品化）

- **合成式**：空饭盒（道具）+ 菜 → 合成「XX 饭盒」→ 吃 = 整盒一次触发全部菜的组合效果。**支持批量制作**（一次做多份）。
- **容量升级线**：小 2 格 → 标准 3 格（主食+荤+素模板）→ 大 4 格（塞 4 格大菜）。
- **整数占格**：小食/家常/精致 1，宴席 2-3，盛宴 3-4。
- **腐败照常**：普通盒菜照常腐败；高级盒（保温/密封）保鲜——与仓库冷藏同钩。
- **不豁免暴食**：盒只是打包，不改变胃容量。
- **效果按盒内构成决定**：配齐 = 均衡爬升，乱装 = 只有维持。

## 七、暴食与消化不良（过量区间驱动）

- **触发**：饱食进入**过量区间（100.1~150，现有 `satiety_overcap` 机制）** → 消化不良「顶得难受」：恢复倒挂（消化变慢/效果打折）、行动变慢、心情下降，直到消化完。
- **盛宴为什么不暴食**：慢释放（c≈1.0 × 120-180t）的交付总量被同窗口衰减抵消，非饱腹时吃净变化≈0，不会顶进过量区间；只有**本来就饱还硬塞大菜**（或连吃多道菜把饱食打进 100+）才触发消化不良。
- **长期后果**：持续过量 → 体重增长（`satiety_weight_gain_ticks_stuffed = 144` → +1kg）。
- 现有 `survival_satiety_overeat` / `stuffed` 的 effects 为空（desc 写了出招速度未接线）——重构时把消化不良效果真正接上。

## 八、数据字段清单

**物品（items.json / 配方输出）**：
- `meal_tier`：`snack | home | refined | banquet | feast`（餐位档）
- `satiety_total`：饱食总量（策划直接配；c = 总量 ÷ `digestion_ticks`）
- `digestion_ticks`：消化时长
- `slots_taken`：占饭盒格数（整数）
- `meal_composition`：`staple | meat | veg | other`（均衡判定）
- `workhorse`：布尔——苦力菜（几乎不给经验、高效回饱食、低成本）
- `nutrition_contribution`：营养贡献（可并入现有 `nutrition_restore`）
- `thirst_restore`：沿用（即时恢复）
- `edible_buff_id`：该菜的**效果 buff**（非消化）——零食类用高数值 buff（快速供能）
- 饭盒成品：`packed_meal_items: [item_id...]`

**生存 / Buff**：
- 饱食变化率 = `-1 + Σ活性贡献`（`-1` 保留配置键）；新增「消化中」活性状态（或直接复用 buff）
- 34 个现有料理 buff：`durationTicks → 消化时长`、`survival_delta → 总量÷时长`
- 消化不良触发：进入过量区间（100.1~150，沿用现有 `satiety_overcap` 判定）
- `satiety_overcap_max`（150）、`satiety_overcap_threshold`（90）、`satiety_weight_gain_ticks_stuffed`（144）沿用

## 九、与现有系统接线

- **「消化中」buff 已存在（34 个）**：升级数值即可，不需新机制。
- **同 buff_id 禁止重复食用（21 已定）**：同菜不叠、异菜叠加——天然支撑组合模型。
- **过量区间入口已存在**：`addSatiety` 的 `hasActiveSatietyDigestBuff` 判定沿用。
- **体重 / 饿死**：沿用（144t → +1kg；饱食 0 → 432t 死亡倒计时）。
- **饮水**：维持即时恢复，不动。
- **睡眠**：只结算经验，不参与消化。
- **批量制作**：烹饪支持批量，饭盒装盒同理。
