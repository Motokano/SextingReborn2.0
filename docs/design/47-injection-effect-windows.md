# 注射药效窗口定稿

> 镇痛更新已实装：[按比例忽略疼痛与四档时长](47-analgesic-proportional.md)。该文替代旧版布尔全压制和统一镇痛时长；真实疼痛、损毁不因用药扣除。

2026-09-10。用户已同意按药效延长注射窗口，并要求先定稿、交由 Sol 实现。本次只落地注射窗口，不代表整份制药重整提案或所有新药数值已获定稿。

## 1. 基础窗口

注射起效仍为 0 tick。下表为基础持续窗口，按各药效族分别计时；同族四个强度档共享窗口。窗口从实际赋予药效时开始，不等待进入战斗，不在脱战或切图时重置。

| 药效族 | 基础窗口（tick） | 处理 |
|---|---:|---|
| 提神 `stimulant` | 20 | 留出接敌时间，仍为集中行动窗口 |
| 续力 `strength` | 120 | 长效携行支持，直接增加负重上限；不增加筋骨 |
| 醒神 `antistun` | 40 | 覆盖一段实际交战过程 |
| 镇痛 `analgesic` | 50 | 支持带伤行动及撤离，不治疗损毁 |
| 补液 `rehydrate` | 30 | 拉长释放过程，不增加基础总恢复预算 |
| 续航 `energy` | 30 | 拉长释放过程，不增加基础总恢复预算 |
| 安神 `sedative` | 40 | 较平缓释放，保留当前作用种类 |
| 感悟/致幻 `hallucinogen` | 180 | 连续地牢探索的实战成长收益窗口；倍率不变，不保证覆盖所有规模整场地牢 |
| 增效 `synergist` | 10（保留） | 旧模板兼容；动态配药增效仍在配制结算中处理，不新增消费者 |
| 复苏 `revive` | 10（保留） | 功能储备，不在本次补消费者或宣称具备复苏能力 |
| 止血 `coagulant` | 10（保留） | 功能储备，不在本次补消费者 |

注射默认窗口 10 tick 仅作未覆盖模板的兼容回退，不再代表所有注射药统一时长。续力经后续确认改为携行药，口服基础窗口 180 tick、起效仍为 5 tick；致幻族后续调整为口服 240 tick（起效5）、吸入 60 tick（起效2）、注射180 tick（立即）。持续从赋予药效计时，包含起效等待，收益倍率不变；免疫沿用原延时规则，已有实例不主动续期。其他口服、吸入、外敷时序不变。

续力基础常效注射增加 5 kg，按途径峰值和强度档缩放。现有强效药汤增加 6 kg，强效注射液增加 7.5 kg。使用 `pharmacy_carry_capacity` 直接接入角色承载缓存，同一角色所有续力效果取最高值，不叠加剂型或强度档；较强效果到期后退回仍有效的较弱效果。免疫沿用原持续时间加成。到期恢复正常上限，由现有超重规则处理，不丢弃物品、不增加背包格数、不改变物品重量。旧存档中已有药效保留原到期时间，效果读取更新后的模板。

## 2. 恢复预算与持续增益

- 对本次延长的注射族，现有 `survival_delta` 的每一项有符号变化保持旧 10 tick 基准的总预算：新每 tick 数值 = 旧生成模板每 tick 数值 × 10 / 新基础窗口。先按旧规则计算剂型/强度及原有取整，再进行预算分配，避免因改变取整顺序产生免费收益。
- 正向恢复和负向消耗都按相同规则分摊；不另改药效种类。例如安神现有营养作用是否删除属于目录重整后续工作，本次不混入。
- 保留足够小数精度，不能把 30/40 tick 分配强行四舍五入到两位后累计偏差；应通过真实世界 tick 消费链验证，包括生存状态自身的取整规则。必要时使用局部余数累计保证预算，不修改全游戏生存取整口径。
- 属性加值、行动速度倍率、经验/潜能倍率、抗性、布尔镇痛保持原强度，不按时长反向缩放。它们获得更长可利用窗口是本次明确的平衡调整。
- 免疫继续按现有规则延长持续时间，不新增峰值增幅。以相同免疫、相同强度条件比较，逐 tick 恢复预算不应因本次窗口改动额外增长；保留现有免疫带来的持续收益。整数 tick 取整差异须测试并说明，不能宣称未经验证的精确总量。
- 属性达到上限、其他状态抵消或角色死亡仍按真实规则裁切；显示不得承诺保证恢复总量。

## 3. 固定药、复方与战斗状态

- 固定注射药和动态复方均使用同一族/途径/强度模板。复方中提神可以先结束、抗眩晕其次、镇痛最后结束，不把所有作用绑到一个最大/最小倒计时。
- 保留 `CombatEngagement.isPlayerInCombat()` 统一门禁、注射静止要求、器具卫生和原使用耗时。被追击即战斗中，不能用拉开几格绕过禁用。
- 不新增“战斗开始才倒计时”、免费刷新、重复叠层、自动脱战或战斗中注射。
- 保留旧 buff ID、物品 ID 和配方 ID。已生效实例不主动刷新起止时间；新赋予的效果使用新模板。不得因重建模板清空或补满库存、药效或负担。

## 4. 数据与实现要求

- 以 `data/pharmacy-buff-matrix.json` 为唯一时长与预算规则来源，增加按族的注射覆盖配置；生成器支持显式覆盖与合法性校验，未覆盖剂型保持原结果。
- 重建 `data/buffs.json`。不能只手改生成物或让 UI 单独计算不同的时长。
- 同步药效显示读取有效模板的窗口；复方能保留各族独立时间，不在本次强行实现整个信息显示重整。
- 原料、配方、纯度、成瘾、毒性阈值、成长曲线和未实现药效不随本次调整。

## 5. 验收

1. 所有注射族及四个强度档使用上述窗口；非注射仅续力改为上述长效携行规则。
2. 实际世界 tick 验证提神、补液、安神等逐 tick 效果的总预算，包含弱效的小数取整情况；与旧窗口同条件对照。
3. 实际复方包含至少三种不同时长作用，逐一验证仍在场/到期，不只检查 JSON 数字。
4. 免疫 0 及非零情况下核对真实持续与恢复预算；已有实例不会因配置变更被主动续期。
5. 战斗状态、制药、疼痛相关回归通过；生成过程幂等，新增配置非法时拒绝生成；文案与编码检查通过。

## 6. 实施记录（2026-09-10）

已部署到运行时与生成数据：

- `data/pharmacy-buff-matrix.json` 已增加 `route_family_overrides.inject`，四档强度共用各族窗口；`synergist`、`revive`、`coagulant` 明确保留 10 tick。
- `tools/build-pharmacy-buffs.mjs` 会校验覆盖的途径、族、有效格及正整数窗口。生成时先按旧规则完成途径/强度缩放和两位取整，再仅对延长注射的 `survival_delta` 乘 `10 / 新窗口`；非注射模板保持原生成结果。
- `js/buff-system.js` 仅对带 `pharmacy_survival_budget_quantized` 标记的注射模板做累计量子分配。0.1 精度状态按 0.1 分发，`mood` 及负向 `nutrition` 按整数分发；实例保存已分发步数及同 tick 去重状态，读档不会重置余数进度，到上限等真实裁切不会留待以后补发。
- 预算守恒口径是“旧生成模板每 tick 数值 × 10”的理论预算。旧引擎逐 tick 写回取整可能放大或吞掉小数，本次不重现该误差。例如弱效安神的 `mood` 模板为每 tick `0.75`，旧引擎逐 tick 取整会得到 10 tick 共 `+10`，新 40 tick 累计量子分配得到理论预算四舍五入后的 `+8`；弱效补液 `thirst` 则精确保留 `1.25 × 10 = 12.5`。
- 免疫仍按既有乘数延长实例到期 tick，未增加单 tick 峰值；额外 tick 继续提供原有持续收益。已存在实例在模板重载/读档时保留原 `started_tick` 与 `expires_at_tick`。
- 固定药与动态复方继续使用原 buff ID；低毒三族合法配方已通过真实 `PharmacyCompounding.buildInstance/applyInjection` 路径注射，并以真实 tick 验证 20/40/50 tick 独立到期。测试也覆盖缺少新计数字段的旧 10 tick 实例不续期、多条 `survival_delta` 在同 tick 各自结算，以及状态到上限的裁切量不会在以后补发。CombatEngagement 门禁、注射静止、针具卫生和使用耗时未改。

验证通过：`test:pharmacy`（97 组）、`test:pain`（51 项）、`test:combat-engagement`、`tools/check-i18n.js`（无 mojibake），以及连续两次生成的 SHA-256 一致性检查。
