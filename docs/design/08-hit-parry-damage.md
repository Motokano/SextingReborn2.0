## 七、命中、招架与伤害流程（普攻）

1. **命中率**：由攻防双方**速度值**（取整后）参与，**同速时**基础命中率在 80%～85%；再加速度或命中词条也**无法达到 100%**（有上界）。公式如下（常数均从配置表读取，字段见下）：
   - **速度比**：\(r = V_{\text{攻}} / \max(V_{\text{防}}, \varepsilon)\)，\(V\) 为取整后的速度，\(\varepsilon\) 防除零。
   - **基础命中率 \(P_{\text{base}}\)**：
     - **r ≥ 1**：\(P_{\text{base}} = P_{\text{eq}} + (P_{\text{base}}^{\max} - P_{\text{eq}}) \cdot \dfrac{\ln r}{L + \ln r}\)，再 clamp 到 \([P_{\text{eq}}, P_{\text{base}}^{\max}]\)。\(P_{\text{base}}^{\max} < 1\)，即再加速度也无法到 100%。
     - **r < 1**（攻方更慢，惩罚）：\(P_{\text{base}} = P_{\text{eq}} \cdot r + P_{\min} \cdot (1 - r)\)，再 clamp 到 \([P_{\min}, P_{\text{eq}}]\)。
   - **词条命中加成** \(B_{\text{命中}}\)：装备等提供的命中加成（小数）与 \(P_{\text{base}}\) 相加。
   - **最终命中率**：\(P_{\text{命中}} = \min(P_{\text{base}} + B_{\text{命中}},\ C_{\text{命中}})\)，\(C_{\text{命中}} < 1\)（如 0.99），即再加多少命中修正也无法到 100%。
   - **配置字段映射（避免歧义）**：
     - \(P_{\text{eq}}\)（同速基础命中率）← `hit_base_at_equal_speed`
     - \(P_{\text{base}}^{\max}\)（仅速度的基础上限）← `hit_base_max`
     - \(P_{\min}\)（攻方更慢时下限）← `hit_base_min`
     - \(C_{\text{命中}}\)（最终上限）← `hit_final_cap`
     - \(L\)（曲线常数）← `hit_curve_L`
     - \(\varepsilon\)（防除零）← `hit_epsilon`
2. **招架**：命中后按防方招架几率判定。基础值由**招架技能等级**（及装备等）决定，再乘以柔韧倍率 \((1 + \text{系数} \times \text{柔韧})\)，再经默认硬上限得到**最终招架几率**；若有 **失衡** 等 Debuff，在此之后叠加 **百分点修正**（见下条「失衡与招架几率」）。招架类技能**无招式**，数值随技能等级成长，见 [11-skills.md](11-skills.md) 8.3。**招架成功**则本次不造成伤害并可能触发招架特殊效果。**招架失败**则先按**卸力比例**做**硬减伤**（直接按比例扣减伤害），剩余伤害再进入减伤链（从护体层开始）。详见下条「招架」。
3. **减伤链**（招架失败且卸力结算后，从护体起依次）：底气护体 → 防具减伤 → 基础防御（柔韧动态%）→ 伤害类型微调系数（按命中部位与伤害类型）；链内保留小数传递，仅最终扣血与损毁增加值向下取整到整数。详见 5.6。**损毁写入**：若命中部位已损毁，本次损毁增加值不堆在该部位，而均分到其余未损毁部位，见 **09-body-parts.md**「已损毁部位再受击时的损毁重分配」。
   - **底气护体**：仅在有“底气护体”时生效；百分比；被减部分记到护体盾上。
   - **防具**：**头部**与**衣服**防具的减伤均按**三种伤害类型**分别配置：**劈砍、戳刺、钝击**各一档百分比（0～1）；命中头部时取头部槽防具的对应类型减伤，命中胸/腹/四肢时取衣服槽防具的对应类型减伤。配置字段建议：`damage_reduce_slash_pct`、`damage_reduce_pierce_pct`、`damage_reduce_blunt_pct`。**与词条叠加**：防具基础减伤与词条 `armor_bonus` 的减伤为**乘算**，即剩余伤害比例 = \((1 - r_{\text{基础}})(1 - r_{\text{词条}})\)，再依此类推多词条。
   - **基础防御**：由柔韧决定，动态公式 \(DR = S_{\text{柔}}/(S_{\text{柔}}+3D)\)。
   - **伤害类型微调**：命中部位与伤害类型查表 \(M_{\text{部位,类型}}\)，最终伤害 = 上步输出 × \(M\)。
4. **原始伤害**（减伤前）：**武器基础伤害** × \(W_{\text{coef}}\) × 实战经验增伤 × **环境增伤** × 暴击系数 × 底气催发系数（1～12 成；成数 **\(k\)** 取 **当前招式槽的 `power_level`**，资源不足时的扣费与算伤口径见 `07`）。其中 \(W_{\text{coef}} = W_{\text{skill}} \times M_{\text{move}} \times G \times K_{\text{试探}}\)：**技能侧** \(W_{\text{skill}}\)（`Base(L)`、招式熟练度、**\(F_{\text{呼吸法威力}}\)** 等；**基本呼吸法**的 \(F_{\text{呼吸法威力}}\) 为 **`breath_power_multiplier`**（基 **1.0**，总熟练 \(\ge 50\%\) 时 **+0.3**，见 `11` 8.3.3）、**招式模板乘子** \(M_{\text{move}}\)（配置 `move_power_multiplier`，默认 1；刺拳 0.8、正蹬 1.2、鞭腿 1.0、摆拳 1.4，见 [11-skills.md](11-skills.md) 8.3.2）、**徒手手套** \(G\)（`05`）、**试探** \(K_{\text{试探}}\)（仅摆拳 `swing_punch` 且带 `buff_probe` 时 \(=1+0.05s\)），顺序见同节。环境增伤含地形/天气等环境因素及**惯用肢体系数**（出招肢体为惯用手或惯用腿时 +10%，为非惯用手/腿时 -10%）。暴击按暴击率属性判定，成功则乘固定系数。
   - **武器基础伤害**取值（与 [11-skills.md](11-skills.md) 8.3.1 一致）：**徒手**攻击时为攻击方**筋骨**（先天 + 后天实际值，见 `05-character-attributes.md`）；**持兵器**时为所持武器配置的基础伤害字段（字段名以实现为准）。

5. **击退撞墙加伤（与 `07` 对齐）**  
   - 当本击配置了 **tick 末击退**（如 **`on_parry_failed_at_tick_end_displace_target`**）且 **`08` 上招架失败**（已进入卸力/减伤链）时，在 **tick 末** 解析位移路径；若因 **不可走 / 边界 / 占格实体** 导致 **未跑满** 配置的 **`cells`**（**含一步未动**），则对本击记 **撞阻**。  
   - **乘子**：取招式配置 **`wall_slam_final_damage_multiplier`**，未配置时 **默认 1.3**（正蹬已配 **1.3**）。  
   - **乘算位置**：在 **本条减伤链全部执行完毕** 之后、**写入 HP（扣血）之前**，将 **该击最终伤害数值**（已为整数则直接用）乘以撞墙乘子，再 **向下取整** 后扣血。**不**回退重算减伤链。多 sub-hit **每击各自**判定是否撞阻。  
   - **同 tick 多条击退** 的坍缩（**`cells` → 攻击方筋骨 → 攻击方速度 → `event_id`**）见 **`07`**，不改变「哪一击」承担撞墙判定——**始终对产生该击退队列项的那一击**结算撞墙乘子。

### 伤害类型增伤/转换（三类型后处理）

- **适用阶段**：主伤害公式产出 `rawDamage` 并确定初始 `damageType` 后开始（即减伤链前）。
- **三类型池**：统一使用 `typed = { blunt, slash, pierce }`；初始时将 `rawDamage` 注入 `typed[damageType]`。
- **取整规则**：本阶段全程保留小数；仅最终 `finalDamage` 落地时 `floor`。

#### 结算顺序（强制）

1. **前置注入（标签后、增伤前）**
   - 固定加成：`add_flat[target] += X`
   - 百分比派生：`add_from_pct[target] += typed[source] * pct`
2. **首轮类型增伤**
   - `typed[t] *= (1 + increase_pct[t])`
3. **单向类型转换（不可反向）**
   - 仅允许：`blunt -> slash`、`slash -> pierce`
   - 同源同目标多条转换：先求和再一次转换（sum once）
4. **转换后二次增伤（仅新增目标类型）**
   - 对本轮“转换得到的新增分量”应用目标类型 `increase_pct`
5. **进入减伤链**
   - 敌方减伤按三类型分别结算并汇总，再进入最终伤害落地

#### 禁止事项

- 禁止 `slash -> blunt`、`pierce -> slash` 等反向转换（防止结算递归套娃）。
- 禁止在三类型后处理阶段进行中途取整。

#### 数据字段规范（策划直填）

- 推荐承载字段：`damage_type_effects`
- 可挂载位置：`combat-skills.json` 的 `moves[]`，以及 `items.json`（或其词条源）

```json
{
  "damage_type_effects": {
    "add_flat": {
      "blunt": 0,
      "slash": 5,
      "pierce": 0
    },
    "add_from_pct": [
      { "source": "blunt", "target": "pierce", "pct": 0.2 }
    ],
    "increase_pct": {
      "blunt": 0.1,
      "slash": 0.2,
      "pierce": 0
    },
    "convert_pct": {
      "blunt_to_slash": 0.2,
      "slash_to_pierce": 0
    }
  }
}
```

- `pct` 支持两种写法：`0.2` 或 `20`（实现统一按百分比语义归一化）。
- `convert_pct` 仅接受 `blunt_to_slash` 与 `slash_to_pierce` 两个键。
- 未配置字段默认为 0（不影响原有伤害口径）。

#### 对账示例

- 输入：`20 blunt`，`increase(blunt)=20%`，`increase(slash)=20%`，`convert blunt->slash=20%`
- 过程：
  - 首轮增伤后：`24 blunt`
  - 转换后：`19.2 blunt + 4.8 slash`
  - 转换后二次增伤：`4.8 slash -> 5.76 slash`
- 结果：`19.2 blunt + 5.76 slash`（最终落地前不取整）

### 招架（细则）

- **招架效果与柔韧（乘算 + 硬上限）**  
  - 柔韧**提升招架效果**，不直接加几率。先按公式计算**未封顶值**：**招架几率_raw = 基础招架几率 × (1 + 系数 × 柔韧)**；**卸力比例_raw = 基础卸力比例 × (1 + 系数 × 柔韧)**；系数从配置表读取（如 `parry_flexibility_mult_per_point`，默认 0.005，即每点柔韧多 0.5% 倍率）。  
  - 然后对结果施加**硬上限**并得到最终生效数值：**最终招架几率 = min(招架几率_raw, 75%)**；**最终卸力比例 = min(卸力比例_raw, 50%)**。  
  - **硬上限可被突破**：上述 75%/50% 为默认封顶；某些技能/物品/效果可以在自身条目中明确声明“可突破该硬上限”（例如临时提高封顶值、或在特定条件下不受封顶约束）。具体突破幅度、持续时间与叠加规则以该效果/物品/技能的设计为准。  
  - 示例：基础招架成功率 10%、卸力比例 10%，系数 0.005，10 点柔韧 → 招架几率_raw = 10%×1.05 = 10.5%，卸力比例_raw = 10%×1.05 = 10.5%，均未触顶；若数值极高导致 raw 超过上限，则分别被封顶在 75% 与 50%。  
  - 减伤链各步与最终扣血/损毁的取整规则与本文档 5.6 等保持一致；招架成功率与卸力比例在参与公式时保留小数，仅在需要展示或判定时按实现约定取整。上述硬上限在进入判定与结算前已经应用。

- **失衡与招架几率（百分点修正）**  
  - 在已得 **最终招架几率**（含柔韧倍率与**默认**硬上限 75%）之后，加上 Debuff 等提供的 **百分点之和** \(\Delta p\)（通常为负；例如 **失衡** 每层 −5%，由 `BuffSystem.getParryChanceDeltaPercent(防方)` 汇总，见 [11-skills.md](11-skills.md) 8.3.2 鞭腿 / `18-buff-system.md` `parry_chance_delta_percent`）。  
  - 再对结果 **clamp** 到 \([0,\,75\%]\)（或当前生效的招架几率上限，若被效果突破封顶则按该效果改写上界后再 clamp）。  
  - **与命中顺序**：若某招式声明「命中 roll 成功即对目标叠失衡」，则 **即使本次随后招架成功、伤害为 0**，失衡仍叠加（与 [11-skills.md](11-skills.md) 鞭腿条目一致）。

- **招架等级与数值成长**  
  - **招架技能等级不单独计算**，与**本体战斗技能**等级一致（装备在某肢体上的招架来自某条战斗技能时，招架等级 = 该战斗技能等级）。  
  - **招架相关数值**（如基础招架成功率、基础卸力比例）**随该技能等级线性提升**，具体数值与曲线在**设计该技能时**在技能配置中定义。

- **招架来源与技能设计约定**  
  - **招架类技能**无招式，招架数值随**该技能等级**在技能配置中定义（见 [11-skills.md](11-skills.md) 8.3）。  
  - **徒手/兵器**技能若某**招式**可参与招架，须在技能/招式配置中声明：是否用于招架；各等级或等级区间的**基础招架成功率**、**基础卸力比例**（随等级线性提升，具体在设计时定）。  
  - 若有招架成功时的特殊效果（如回复底气、反击等），须在对应配置中声明：效果内容；条件判定须符合 `11-skills` 8.3.1 开放接口约定；该效果是否受柔韧的招架效果加成（是则数值按上述柔韧公式参与计算）。  
  - 实现上保留“招架特殊效果”的调用接口（如按技能 ID 或标签触发效果结算），便于扩展。

- **卸力的定位与顺序**  
  - **卸力**在**招架判定失败后**生效，是一种**硬减伤**：按卸力比例直接扣减本次伤害，剩余伤害才进入后续减伤。  
  - 顺序为：招架判定失败 → **先按卸力比例硬减伤** → 剩余伤害进入**底气护体层**（有护体则先扣护体）→ 防具减伤 → 基础防御（柔韧）→ 伤害类型微调。即卸力在护体之前，护体、防具、基础防御、伤害类型微调均在卸力之后。
- **与流程的衔接**  
  - 命中后，防方招架几率 = 基础招架几率（招架技能等级或招架用招式配置 + 装备等）× (1 + 系数×柔韧)，判定成功则本次不造成伤害并可能触发招架特殊效果；失败则先按 卸力比例 = 基础卸力比例×(1 + 系数×柔韧) 做硬减伤，剩余伤害再进入减伤链（护体→防具→基础防御→伤害类型微调）。  
  - 行气时招架判定自动失败（见 6.1.11 行气时被攻击）。

#### 招架结算阶段（流程展开，与实现对齐）

本节把「命中 roll 成功之后、伤害写入之前」的**招架段**拆成可实现的顺序；**多 sub-hit** 时 **每一击各自**走完整段（与 Buff `18` 子击事件口径一致）。

1. **进入条件**  
   - 仅当 **本击命中判定已成功**（`attack_hit_roll_resolved` 语义）后，才进入招架段。  
   - **本段不消耗** 气力 / 底气等战斗资源（**基本招架**无消耗；其它招架技能若有消耗须在单条中声明并在本段前扣费）。

2. **解析「承担招架」的肢体 `guard_limb`**（`lhand` / `rhand` / `lfoot` / `rfoot`）
   - **战斗日志**：`CombatParry.logParryGuardLimb` 等须写明 **受击部位**（可读名 + 原始 `hit_part` id）与 **承担招架肢**（可读名 + 原始 `guard_limb` id），便于与 `09` 部位表、存档对账。  
   - **四肢部位受击**（命中部位为 **`left_arm` / `right_arm` / `left_leg` / `right_leg`**，与招式 `hit_part_weights`、身体篇一致）：**固定**取**该肢**对应映射——左手↔`lhand`、右手↔`rhand`、左脚↔`lfoot`、右脚↔`rfoot`。  
     - 若**该肢在身体状态中已损毁**（该肢无法再用于招架，与 `11`「损毁肢体无法出招/招架」一致）：**跳过整段招架结算**（不掷招架骰、不卸力），本击直接进入减伤链（无招架带来的卸力前置）。  
   - **头 / 胸 / 腹受击**（**`head` / `chest` / `abdomen`**）：在 **`lhand` → `rhand` → `lfoot` → `rfoot`** 的**固定肢体优先级**上，选取**第一条尚未损毁**的肢体作为 `guard_limb`。  
     - 若**四肢均已损毁**：**跳过整段招架结算**（无法格挡）。  
   - 实现可参考 **`CombatParry.resolveParryPhaseContext`**（`js/combat-parry.js`），其中「损毁」由调用方注入 **`isBodyPartDestroyed(部位 id)`**（`left_arm` 等与 `09` 七部位一致）。

3. **是否执行招架骰**  
   - 读取 `guard_limb` 上 **`limbs[guard_limb].parry`** 所挂的招架**技能 id**。  
   - **招架槽为空**：**跳过招架段**（不掷骰、不卸力），本击直接进入减伤链。  
   - **槽非空但技能未习得**（存档 **`skills[parry_skill_id].level < 1`**，含初始未学）：**跳过招架段**。**基本招架**默认**无额外学习门槛**；若某招架技能有门槛，须在单条设计中声明并在更早阶段拦截。  
   - 以上跳过须写**战斗日志**（文案 key 见 `data/ui_text_zhCN.json` `log.combat.parry.skipped.*`），并发射 **`parry_phase_skipped`**（`data/editor/buff_event_registry.json`，`tags` 含 `parry_skip` 与具体原因，见下）。

4. **取基础招架率 / 卸力**  
   - 用 **`skills[parry_skill_id].level`**（角色级一条等级）调用 **`CombatSkills.getParryValues(parry_skill_id, level, character)`** 得 **基础招架成功率**、**基础卸力比例**（三系共用同一组基础值）。  
   - 再乘柔韧、硬顶、失衡百分点等（见上文「招架效果与柔韧」「失衡与招架几率」），得到 **最终招架几率** 与 **最终卸力比例**。

5. **掷骰与结果**  
   - **随机判定**是否招架成功（实现用统一 RNG 口径）。  
   - **成功**：本击**伤害记 0**（不写 HP），可 **`incrementSkillMoveUsage`** 累计招架熟练度、发射 **`parry_roll_succeeded`**、日志 `log.combat.parry.roll.success`；再处理「命中仍叠 debuff」等（如失衡）按招式声明。  
   - **失败**：对原始伤害（或实现约定的「卸力前伤害」）乘以 **(1 − 最终卸力比例)** 做**硬减伤**，再进入护体→防具→基础防御→类型微调；发射 **`parry_roll_failed`** 与 **`parry_shunt_applied`**（`payload` 可含 `shunt_ratio_final`）；日志 `log.combat.parry.roll.fail_shunt`。

6. **事件与标签（登记）**  
   - **`parry_guard_limb_resolved`**：`payload` 建议含 `hit_part`、`guard_limb`、`is_torso_pick`、`parry_skill_id`。  
   - **`parry_phase_skipped`**：`payload` 建议含 `reason` ∈ `empty_parry_slot` | `unlearned` | `all_limbs_destroyed` | `struck_limb_destroyed` | `unknown_hit_part`。  
   - **`parry_roll_succeeded` / `parry_roll_failed` / `parry_shunt_applied`**：与上条衔接。  
   - 所有上述 `event_kind` 均为 **`combat`**；`tags` 至少含 **`parry`**，并加 **`torso_guard`** / **`limb_struck`** / **`parry_skip`** 等便于筛选。
