# 海藻精持续供给网络改进方案

状态：规划，尚未修改玩法。2026-09-10。

## 已确认的设计前提

作物种下后建立持续供给关系；供给不因累计营养达标而停止。玩家通过作物、设施和水渠布局改变网络，网络反过来塑造种植环境。超融合开启 A 面的需求响应，关闭后回到 B 面。保留土壤改造与供电超融合的联动。

LISP/Fabric 仅作为设计类比：登记、定位、响应和共享基础网络；不向玩家暴露协议概念，不实现真实网络协议。

## 当前实现核对

| 实现位置 | 当前行为 | 改进影响 |
|---|---|---|
| `js/agriculture-map.js` 的 `registerPlotSeaweedRequestsIfEligible`、`syncCropSeaweedExtractRequests` | 必须邻接有水渠才登记；支流作物同时登记主流和所属支流；成熟待收获仍登记 | 能复用生命周期，但要区分持续需求与当前是否可送达，避免断水就表现成没有需求 |
| `getIrrigationSourceForPlot` | 每株只从一个实际水源吸收，按距池距离、坐标等选源；水池也可能优先 | 路径终点必须与实际吸收源一致，不能只到任意邻渠，否则画出的供给与实际吸收可能不一致 |
| `seaweedBfsOnFlow` | 在选定水流范围内检查非上坡可达，只返回布尔值 | 需要返回实际路径，供结算和显示共用 |
| `pickInjectionForFlow` | `reachCrop || reachEnd` 即接受注入口 | A 面中到不了目标、仅能到水流末端也可能通过；新 A 面必须严格抵达目标接入点 |
| `pickFirstReachableRequestForFlow` | 每条水流只找第一条可用请求 | 登记顺序可能影响选择；无法明确表达多条关系共同作用 |
| `getPostEntryWetCells` | 从注入口后一直到水流末端 | 请求作物的远近没有明确控制输送终点 |
| `processSeaweedExtractMaintain` | 每条水流独立以完整设定量除以覆盖格数；来源键是施肥器坐标加水流标签 | 同一台设备跨多条水流可能多次分配预算；物理重合格可能收到同一设备的多个水流贡献 |
| 同上 | 每刻清空、重算渠内浓度，不保留沉积；不同施肥器贡献相加 | 可以继续采用，首版不增加残留、传播延时或逐株扣料 |
| `js/agriculture-panel.js` | 有设施浓度调节、作物累计吸收；主网格没有供给路线、关系或中断原因 | 必须补上玩家可观察的因果关系 |
| `tools/gen-agriculture-crop-defs.mjs` | `requests_seaweed_extract: !!b.trace` | 把“能从营养获益”和“主动建立供给关系”绑在一起，需要拆开 |

当前 50 种作物按行为分为：31 种主动请求、11 种敏感、8 种中性，0 种纯受益。上一轮数据重做的测试证明了水肥冲突，但没有覆盖本方案的三类作物搭配。

## 建议的首版规则

### 1. 持续需求与当前供给分开

从场上作物推导需求：主动请求作物存在就保留需求；收获、清理、健康枯萎移除时撤销。成熟待收获仍维持关系，成熟后不吸收，沿用现有语义。断水、缺料、关闭超融合都不删除作物本身的需求。

单独计算当前状态：等待接入、无可达设备、设备缺料、正在供给。A 面关闭时显示粗放供给模式，不把所有作物误报成断线。需求只是持续声明，不是根据缺口大小自动生成的补给单。

### 2. A 面生成真实路径

每个主动请求者的终点是 `getIrrigationSourceForPlot` 当前实际选中的有水渠格。若选中水池，明确视为没有营养渠接入；不能画到另一格邻渠但实际从池中吸水。

寻路使用与清水连通一致的有水渠图，只沿非上坡四邻移动，不能跨干渠。A 面不再用“到得了水流末端”代替“到得了作物”。主干/支流标签保留用于清水分配与显示，不再让同一请求在两个标签中重复结算。

首版推荐每株选择一台可达施肥器：比较最短合法路径，距离相同时按固定坐标顺序决定，不按播种顺序。已有设备暂时缺料时关系保留并显示缺料，不因为每刻料液状态变化反复换设备。拆除、接入点改变、拓扑改变才重新选路；断水恢复时重算可送达路径。

路径到作物接入点为止，包含终点；沿途旁接作物仍从各自实际水源吸收。注入口本身也属于路径，避免“设备就在接入点旁却永远吸收不到”的例外。此项区别于旧版“不含注入口”，需要同步修改相关测试及重新校准浓度。

### 3. 一台设备只有一份输出预算

对于施肥器 j，把它服务的全部有效路径取渠格并集 Uj。每刻设定输出为 Qj，则它在每个覆盖格的贡献为 `Qj / |Uj|`。同一设备在同一格只贡献一次；不同设备的贡献可以叠加，继续可能引发过量或水藻。

没有可供给路径就不注入；增加一条完全重合的关系不凭空增浓，也不额外扣除预算。新关系延伸或分叉、使覆盖范围增加时，原有覆盖格的浓度降低。

这里选择“覆盖范围共享”而非“每株固定分一份”。当前作物吸收不扣渠浓度，单纯按株数分配却不扣吸收，会引入另一套难以解释的计数规则。先保留路径并集模型，不增加请求权重、优先级或自动均衡。

内部计算保留足够精度，展示再取一位小数，避免大量格子分别舍入导致输出超过设备预算；配套核对作物吸收步既有舍入的误差边界。Q 是抽象输送强度预算，不声称营养物质量严格守恒。

现有 `seaweedSetConcentration` 可兼容读取，但 A 面界面文案改成“供给强度”，与实际“渠内浓度”分开。旧设定范围 1～20 只是校准起点，不能假设路线变短后原数值仍安全。

### 4. 作物角色与数值分别配置

在平衡主表增加 `seaweed_role`：`requester`、`beneficiary`、`sensitive`、`neutral`。生成器从角色决定是否登记，营养上下限仍由现有 `trace` 和排斥配置决定。

建议用三个现有作物验证首个布局：八角为主动请求者，花生为只受益者，樱桃为敏感者。花生保留可选微量增产，不新增微量生存下限。只调整这几种原型所需的数据，通过后再逐种安排其余作物角色。

主动请求者应当是可独立正常种植的作物，避免沦为纯粹的网络开关；只受益者不要求一律必须依赖主动请求者，允许基础收成与伴种增产并存。

### 5. 玩家能看见供给关系

选中主动请求作物：高亮提供方、真实路径、接入点，显示当前供给状态。选中只受益/敏感作物：显示它实际吸收的来源渠与该渠的营养供给，不伪造它与设备的直接关系。

选中施肥器：高亮其所有有效路径，显示关联作物数、覆盖渠格数、供给强度。无需求与缺料采用不同状态。

播种、收获导致路线改变时给短暂路径亮起/熄灭反馈；不增加弹窗教学、未发现作物清单或自动配方建议。路径数据由模拟层提供，面板只负责展示，不自己寻路。

### 6. 保留 B 面作为对照

首版保持 B 面的粗放注入与既有范围，A 面负责目标路径和设备预算。两者通过明确模式文案区分。暂不同时重做 B 面、水流窃流、水藻伤害、肥料包装或整个土壤表。

多分支场景中 A 面可能比旧 B 面覆盖更小、浓度更集中，但不会保证每种布局都绝对增产；必须验证混种收益，而不能只展示设备开关或浓度增加。成熟关系不会自动撤销，持续过量也不会自动停止。

## 落地顺序与涉及文件

| 步骤 | 工作 | 完成标准 |
|---|---|---|
| 1 | 给 `tools/test-agriculture-map.mjs` 或独立新测试增加现状场景；三作物原型配置 | 记录近端/远端、多请求、多分支和注入口的旧行为，避免误把旧行为当新需求 |
| 2 | `js/agriculture-map.js` 增加需求列表、供给关系及真实路径计算 | 登记、收获、断渠、成熟、恢复都产生明确且稳定的关系变化 |
| 3 | 替换 A 面浓度维护为按设备路径并集分配 | 单台预算不随支流数复制；共享路径不重复贡献；路径之外无该设备浓度 |
| 4 | `js/agriculture-panel.js`、相关样式、`data/ui_text_zhCN.json` 展示关系 | 操作三作物布局时能看见是谁驱动哪段输送以及中断原因 |
| 5 | `data/agriculture-crop-balance.json`、生成器重新校准角色和浓度需求 | 延伸范围会改变原有田的供给；受益与敏感作物出现可观察的布局取舍 |
| 6 | 同步 `tools/agriculture-irrigation-demo.html`、生成试玩/总览；更新设计与验收报告 | 本体与离线 Demo 同规则；原 50 作物水肥/超融合验收仍通过 |

关系和路径作为可重建的运行时结果，不单独写入永久存档。新增稳定配置和版本字段才进入存档；读档从作物、设备、水网重建关系。

运输规则变更会改变旧在田作物实际吸收，仅保留作物旧阈值不足以保护收成。推荐存档记录海藻精网络版本：已有档在当前在田作物清空后切换，新档直接启用新版；不在同一水网里同时混算两套浓度。旧档仍有作物时，新播种沿用旧运输版本并延后切换；迁移状态在开发验证中明确显示，避免误把旧规则当新版。具体切换体验需随迁移一并验证。

## 必须通过的场景

1. 近端需求者：只覆盖到其接入点；远处水渠保持清水。远端需求者：覆盖延长，沿途受益作物发生变化。
2. 仅能到达水流末端、到不了作物：不得建立成功供给。
3. 作物邻接多渠：路径终点与实际吸收来源一致；注入口等于接入点时仍能供给。
4. 共享路径：增加重合关系不提高该设备总预算；分叉扩张使原路浓度下降；改变播种顺序不改变相同最终布局结果。
5. 收获近端但远端关系还在：仍保留远端所需公共路径；最后一株收获后停止供给。
6. 成熟未收获继续建立供给，不因营养达标停供；生长结束后不再吸收。
7. 受益作物不登记也能沿途获益；敏感作物在路径外正常、路径内受害；中性作物不能凭空增加需求。
8. 断渠、缺水、缺料、断电、恢复：区分关系状态和 B 面回退；旧路径浓度不得残留。
9. 两台设备：提供方选择稳定；路径物理交叠的不同设备允许叠加，仍能过量；同一设备不能借主干/支流标签重复叠加。
10. 输出预算、舍入、存档重建和版本迁移；重新运行 50 作物平衡与农业存档、电力、端到端检查。

## 规划判断

优先让玩家能用近端、远端、分叉、伴种四种布置观察到结果差异。首版不加入逐株智能配额、自动避免毒害或网络设备管理界面。待这套关系在小布局中成立，再决定是否扩展输送策略。
