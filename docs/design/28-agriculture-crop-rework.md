# 农业作物重做：从维生到繁荣

2026-09-10，作物平衡版本 2。此文替代农业主文档中旧版作物需求、五档难度和“肥料仅增产”的说明。灌溉寻路、窃流、设施范围、土壤激活门保持现有规则。

## 体验目标

玩家放置种子、土壤和设施，让这些条件与共享环境相互作用，等待收成。高级作物不通过禁止播种或强制拥有超融合来锁定：默认盐碱土上仍有解，但要扩渠、增加陶瓮，并承担同渠普通作物被高供水淹死的机会成本。供电超融合激活客土后，高级作物用更少供水与陶瓮生长，普通作物保留默认土便能与其共存。

## 数据所有权

- `data/agriculture-crop-balance.json`：50 种作物逐种编排的平衡源；保留种子、产物 id 和档位。
- `water`、`fertilizer`、`trace` 数组均为每生长刻实际吸收量，顺序是：成熟下限、高产下限、高产上限、成熟上限。`null` 表示该投入不参与普通需求判定，微量排斥仍独立生效。
- `growth_ticks` 决定周期；生成器把平均需求乘以周期，输出运行时累计区间。长周期不再自动降低每刻需求。
- `reference_soil` 是策划验证用的一种可行客土，不是种植许可、不要求玩家必须选这一种。
- `tools/gen-agriculture-crop-defs.mjs` 生成正式 JSON 及两个 embed；种子表仅提供身份、档位和产物映射，不能覆盖平衡主表。
- `js/agriculture-map.js` 是运行时真相源。旧的 HTML 反向抽取已退役，`build:agriculture-map` 仅校验模块语法，避免覆盖本体修正。

## 难度阶梯

| 档位 | 意图 |
|---|---|
| 一档 | 十种都能在默认土、供水 2、无肥无海藻精下成熟；习性仍影响高产条件。 |
| 二档 | 水需求开始分化；部分作物可用海藻精增产，零投入不白送微量分。 |
| 三档 | 肥料成为结实条件；微量主要用于增产；为专门配置种植条件建立过渡。 |
| 四档 | 更高供水、肥料，以及部分作物的微量下限；开始显著挤占水网预算与设施空间。 |
| 五档 | 区分高需水、重肥、微量需求、清水敏感路线；融合客土把供水 6/8 和多瓮方案降到供水 4、较少瓮。 |

## 成熟判定

保留健康归零枯萎、水分缺失/过量、排斥微量伤害；增加配置化的肥料和普通微量成熟上下限。缺肥、过肥、缺微量或微量过量都会产生明确失败结果。通过全部门槛才计算产量。

新作物微量/肥维在零投入时得 0 分，非零但未进高产窗得 1 分，高产窗内得 2 分。清水敏感作物保持“低微量得高分”，不能因为它们没有微量需求就忽略污染。

融合不是逐株过滤器：A 面没有请求时停止海藻精注入；若同流其他作物发出请求，敏感作物仍可能吸收并受害，需要保留清水区。

土壤延长实际周期时，版本 2 作物的累计需求按实际总周期同比缩放。否则多等一些时间就能绕过每刻需求，或仅因周期延长而过量。开启和断电引起的周期重算沿用已有机制。

## 存档与展示

新播种写入 `balanceRevision: 2`。没有该标记的旧作物从 `data/agriculture-crops-legacy.json` 取得旧参数，完成当前一季；重新播种才进入新规则。已成熟的收获量不重算。

本体地块详情补充累计水分，与微量、施肥的累计值并列；新增失败原因与失败格样式。没有向玩家展示未发现作物清单、标准答案或自动操作建议。

## 验证与实际成本边界

运行 `npm run test:agriculture-balance`；用 `node tools/test-agriculture-balance.mjs --report` 更新[全作物结果](../reference/agriculture-balance-results.md)。测试覆盖全部 50 种作物的基础条件、无融合可行方案、融合可行方案，以及三至五档高产输入区间。四、五档逐种验证高供水牺牲普通邻作物、融合后两者共存。

额外验证缺肥、缺微量、肥料过量、敏感作物污染、断电、旧作物和序列化恢复，以及离线 Demo 与本体的核心结算一致。

这轮资源压力来自渠格占用水池预算和陶瓮占地/消耗；没有新增逐株扣水或逐株分肥模型。测试预置库存，不能替代生产经济验证。现有肥料一物品仅增加一单位、每瓮每有效刻消耗一单位；整季物品消耗与重复投料是后续必须实玩核对的独立问题。
