# 72 · 普通人形敌人完整肢体战斗规则

2026-10-27。状态：用户已批准按本设计实装，七部位战斗规则及出招、招架、恢复、实例存档联动已接入，并通过下述自动化验证。敌人外观范围仍为站立、死亡两种，本轮没有新增或替换图像素材。

本文的**沿用**指已有规则，**本轮补全**指本次批准并实现的联动。具体敌人的正式招式组合、平衡数值与掉落仍需另行设计；本次没有把现有地痞示例数值宣布为正式平衡结果。

2026-10-28外观补充：用户指定所有敌人死亡使用已有面包／面粉袋式尸体棋子（`assets/dungeon/corpse.png`），包括地头头目；标记状态沿用 `corpse-marked-v2.png`。不为每个敌人生产独立倒地人物图。四肢失能但存活仍显示自身站立图。

## 1. 范围与依据

- **范围已确认**：普通人形敌人完整设计头、胸、腹、左手、右手、左脚、右脚的受伤、失能、攻击、防守、移动、恢复和死亡关系。先用于第一种正式敌人的设计，再复用于后续人形敌人。
- 外观仍只有站立和死亡倒地两种；四肢失能但存活时继续使用站立素材，通过现有战斗反馈表达状态，不用死亡图代替受伤。不恢复128状态素材生产，也不恢复骨骼拆装。
- 肢体完整不要求敌人拥有玩家的生存面板、学习成长或整套装备库存。战斗参数仍可以由敌人模板直接配置；敌人攻击招式仍从共用技能池选择。
- [09 身体部位](09-body-parts.md)提供损毁规则，[10 敌人设计](10-enemies.md)提供敌人致死与资源规则，[08 命中招架](08-hit-parry-damage.md)提供承担肢与出招占用，[49 伤害设计](49-combat-damage-rework.md)和[61 即时击退](61-breath-burst-and-immediate-knockback.md)提供结算时序，[70 武器设计](70-modular-weapon-system.md)提供持械伤残规则。
- 腹部命中降低玩家食水，不适用于没有食水条的敌人。本稿不擅自将其换成扣气、窒息或额外死亡判定；需要这些效果的招式应单独声明。

## 2. 七部位与基本状态（沿用）

每个部位保存独立的损毁值和正整数上限：0为完好，0与上限之间为受伤，达到上限为损毁失能。受伤阶段不额外增加一套百分比惩罚，继续通过已有疼痛、眩晕及招式效果结算。

| 部位 | 受击及未满时 | 满值结果 | 战斗意义 |
|---|---|---|---|
| 头 | 累积损毁；符合条件的头部攻击另累积眩晕 | 按现有敌人规则死亡 | 威胁生命，也可在未致死前打晕 |
| 胸 | 累积损毁和已有伤害后果 | 按现有敌人规则死亡 | 躯干致死路线 |
| 腹 | 累积损毁；不扣不存在的食水条 | 按现有敌人规则死亡 | 躯干致死路线，承伤差异沿用部位系数 |
| 左手、右手 | 各自独立累积 | 对应臂手失能；不直接死亡 | 禁用该肢招式、承担招架资格及依赖该手的持械能力 |
| 左脚、右脚 | 各自独立累积 | 对应腿脚失能；不直接死亡 | 禁用该肢招式及招架资格；任一腿失能即禁止自主移动 |

“手”在机制上覆盖整条臂手，“脚”覆盖整条腿脚；不拆出肘、膝、手指等新受击部位。左右固定为角色自身左右，转向和屏幕位置不能交换ID。

沿用默认上限：头50、胸100、腹80、四肢各100；各敌人可以完整覆盖七个上限。现有地痞的20／28／24／36只是旧配置，本稿不将它宣布为正式平衡值。**本轮补全**：正式模板显式填写七项，实例生成时固定上限，不随玩家当前身体配置变化。

## 3. 损毁、失能与死亡（沿用并明确边界）

敌人继续使用「损毁即血」，没有独立总生命条。**头、胸、腹任一满值即死亡**；七部位全毁也是死亡状态。完整肢体设计并不自动改变这条规则。

四肢全部失能、头胸腹尚未满值时仍然存活。没有招式可用、不能走动、眩晕和疼痛都不单独等于死亡。存活敌人继续占格，不生成尸体、掉落或击杀奖励；死亡后才进入既有尸体与搜刮流程。

伤害写入沿用09号：

1. 命中与减伤结算得到最终非负整数伤害Q；混合类型先按伤害管线汇总，每段只写入一次损毁。
2. 命中部位在本段开始时未满：Q加到该部位并封顶，溢出作废；不能在打满的同一段临时改走均分。
3. 命中部位在本段开始时已满：Q均分到当时尚未损毁的部位。余数按头→胸→腹→左手→右手→左脚→右脚分配；各部位仍独立封顶，分配后的封顶溢出作废，不再次循环摊派。
4. 因此分配前额度总和为Q，实际落地损毁总量可以小于Q。疼痛按实际落地增量计算，不能把作废伤害再次计入疼痛。
5. 每段写入后处理新失能和致死；同速交换使用共同快照并统一提交，避免先提交的一方取消另一方已经成立的同时攻击。
6. 对已死亡实例停止后续攻击、伤势恢复和重复击杀结算。木桩的显式无敌配置仍是例外，不能因漏配部位上限就获得无敌。

七部位二元组合共128种；沿用上述致死规则时，16种四肢组合可以存活，另112种含致命区满值的组合属于死亡。这里是逻辑覆盖范围，不是图片生产清单；未满伤势、疼痛、眩晕另外保存。

## 4. 出招必须依赖真实可用肢体（本轮补全）

每条徒手动作必须指定发动肢，允许另行声明确实必需的配合肢。最低条件为：敌人存活、未被状态禁止攻击、发动肢与必要配合肢可用、资源可支付，且目标满足本招范围与遮挡规则。

- 右手招式不能在右手失能后自动搬到左手。敌人可以使用已经配置在左手或腿上的其他合法动作。
- 多肢动作逐项检查必要肢体；单腿支撑等条件必须由招式明确声明，不从站立图片、历史骨架或姿势图推导。尚未声明的动作继续按已有发动肢条件处理。
- **全部已配招式失效时，本次没有攻击。** 不能回退到一个无肢体要求的通用挥拳。若敌人需要零气耗或徒手兜底动作，就将其作为完整动作显式配置，同样经过肢体、状态、距离与资源校验。
- 未配置动作列表的正式可攻击敌人属于配置不完整，不能在运行时暗中获得攻击；训练木桩等明确不可攻击对象无需配动作。
- AI可以在合法动作中按自身策略选择，但不能为了保持每回合输出而临时创造招式、换手、免除消耗或解除失能。
- 因无动作而等待，不自动赋予逃跑、投降、爬行或求饶行为；这些可以作为具体敌人的额外行为另行设计。尚有移动能力的敌人继续遵守自己的移动策略。

**结算时序**：交换开始确定本次计划动作及占用肢；轮到实际出手前再次检查存活、眩晕、必要肢体、资源和目标位置。先手已废掉必要肢体时，后手本招取消，不在同一交换免费换一招。未发动不支付本招费用、不产生出手特效，但本次行动机会已经经过。同速双方按共同快照结算；速度带来的下一次出招重新检查。取消的动作不追溯改变本交换已经用过的招架资格。距离变化沿用61号挥空规则：有出手资格但目标已被击退到范围外时，招式照常消耗、按挥空结算。

## 5. 招架与卸力也受肢体约束（本轮补全）

敌人可继续直接配置基础招架率和卸力比例；承担招架的身体资格复用敌我共同规则，不读取玩家装备的步法、柔韧或招式槽。

1. 眩晕、死亡或其他明确禁止防守的状态下，不掷招架骰，也没有招架带来的卸力。
2. 四肢受击，优先由受击肢承担；该肢已经损毁则本次不招架、不卸力。该肢仅因本次出招占用时，才可从其他合法肢体选承担肢。
3. 头胸腹受击，从未损毁、未被本次出招占用且具备防守资格的四肢中选承担肢；沿用现有多候选随机规则。没有候选则跳过招架与卸力。
4. 有合法承担肢后，才按敌人自身的招架率与卸力值结算。0%招架率但配置了卸力的敌人，可以在有合法承担肢时卸力；不能把全肢失能仍减伤解释成卸力。
5. 招架成功免除本段伤害；有资格但招架失败，按既有卸力比例进入后续减伤链。失去招架资格不自动清除头盔、防具、护体或身体减伤，后者按各自规则结算。
6. 攻击肢和额外配合肢的占用来自实际动作声明；不能只限制玩家出招肢，也不能将一只手被占用扩大成全身不能防守。

## 6. 腿部、移动与持械

### 移动（沿用）

- 任一腿损毁满值即不能自主移动，覆盖追击、游荡、回位及攻击附带的主动跨格动作；不新增单腿跳、双手爬行或独立姿态速度。
- 不能自主移动不等于速度数值归零。战斗速度仍用于命中与先手，疼痛或招式减速照常处理，不能因腿毁把速度比公式改成零。
- 其余可用肢体仍可执行合法的原地攻击、防守。被外力击退按61号的位移、碰撞规则处理，不能以“不能走路”获得击退免疫。
- 保留真实视野、直接共享而不接力、丢失视野后回位等场景规则；肢体系统只限制可执行动作，不新增穿墙感知或全房仇恨。

### 持械（沿用70号规则，敌人接入为本轮补全）

| 武器方式 | 肢体变化与处理 |
|---|---|
| 单手持械 | 持械手失能时禁用依赖它的武器攻击与格挡，转用已配置的可用徒手动作；不自动换手 |
| 单手持械恢复 | 仅在此前因伤被迫退回徒手时恢复武器模式，不覆盖主动选择的徒手模式；各自循环进度保留 |
| 双手／长柄 | 一手失能时沿用独立×0.5伤害倍率；双手失能退回已配置徒手动作，不另定“一手损毁就整把武器失效” |
| 双持及其他特殊原型 | 沿用对应原型的明确规则；尚未设计的部分继续标为待定，不借肢体补全推定新规则 |

武器耐久归零与持械手损毁是两种状态。敌人没有背包换装系统，也不能跳过持械依赖；其招式与武器可以作为固定战斗配置记录。本轮不补造双持、双手恢复等原设计明确留待讨论的内容。

## 7. 疼痛、眩晕、恢复与行动时点

### 沿用的状态规则

- 损毁是部位账，疼痛与眩晕是另外的状态账。损毁下降不等于疼痛立即清零，眩晕解除不等于肢体完好。
- 头部伤害及招式显式效果产生眩晕；默认眩晕条上限100，触发后归零并失去一次行动机会。无新累积时按既有每tick衰减1点规则处理。
- 疼痛沿用现有共享计算与分档；剧痛可禁止移动，但不据此新增全攻击禁用。具体技能或状态若禁止攻击，依其声明执行。
- 村外废墟沿用丢失视野超过3 tick后回位；回位及回位后的剩余疗伤阶段，每tick最多恢复**合计8点**实际损毁，不是每个部位各8点。按现有头→胸→腹→左手→右手→左脚→右脚顺序扣减，治疗额度用尽即停。
- 腿毁导致走不动时，回位状态中的伤势恢复仍可进行，不要求先走回出生点才恢复。当前废墟眩晕跳过行动的tick也跳过这次回位疗伤；不借本稿更改其既有节奏。重新发现玩家恢复追击时，停止回位治疗。
- 任何肢体降到其损毁上限以下，即重新取得该肢的身体资格；实际动作仍检查其他限制。沿用损毁可恢复的抽象模型，不增加永久截肢、再生或手术门槛。

### 本轮补全

- 每个世界tick对每名敌人的计时、眩晕消耗和资源恢复只处理一次；一次行动中的反击、主动攻击和连击不能重复恢复或重复扣除眩晕回合。
- 眩晕的一次失能机会应贯穿该敌人的本次行动资格检查，避免先跳过主动AI，再在同一机会中通过反击出手；本次失能结束后才清除对应限制。
- 敌人气力按实例记录，恢复放在明确的世界tick结算点，不能由“查询能出什么招”触发恢复。沿用敌人简化气力模型，不照搬玩家底气与呼吸法成长。
- 已死亡实例不接受回血、部位恢复或自动恢复攻击。尸体交接只发生一次，原有标记、搜索和掉落规则继续适用。
- 脱战不瞬间复原，读档不洗掉伤势，刷新页面不重置致死状态。其他地图的敌人是否具备恢复、恢复条件与速度由其规则声明，不自动复制废墟8点疗伤或玩家自然自愈。

## 8. 实例状态与玩家反馈（本轮补全）

每一名敌人有稳定身份，模板ID只表示种类。实例状态至少包括七项损毁与上限、死亡标志、疼痛及衰减进度、眩晕及剩余失能机会、当前气力、已有盾量、动作／武器循环和相关Buff、恢复状态及最近结算tick。

- 同种敌人之间不共享伤势、疼痛Buff、气力或控制状态；地图数组删去前一名敌人后，后一名不能继承其状态。
- 存档保存本实例的全部战斗状态；旧档缺项有明确迁移默认值，不能整体重建成满状态，也不能重复生成尸体和奖励。
- 模板上限与当前伤势在实例生成后稳定；调平衡优先作用于新实例，已有实例迁移需有显式版本规则。
- 当前只用两张外观，战斗日志仍需说明“哪一肢失能／恢复”“哪次出招因伤无法发动”“是否死亡”。不播放被取消肢体的攻击特效，不把没有攻击能力记作一次未命中。
- 只反馈当前可感知的结果；不通过全图状态面板、隐藏敌人的伤势数字或恢复日志泄漏视野外情况。不因本稿新增敌人图鉴、完整招式预览或教学弹窗。

## 10. 验收范围

1. 七部位各自受击、首次满值、再次命中已满部位；覆盖固定余数顺序、封顶溢出和零伤害不加损毁。
2. 遍历128种满值组合，验证16种可存活四肢组合和112种死亡组合；存活时根据动作声明判断能否攻击、防守和移动。
3. 仅右手有攻击的敌人右手失能后停止攻击；有左手备选时只使用其已配动作。无资源、无动作及全肢失能都不能生成通用挥拳。
4. 单肢受击、自身出招占肢、头胸腹受击、全肢失能及眩晕时，逐一验证承担肢和卸力资格。
5. 任一腿失能后不能追击、游荡或回位移动，但可以执行剩余合法原地动作并承受外力击退。
6. 先手废肢／击晕／击杀取消后手非法动作；同速双方按共同快照完成；后续连击重新检查条件，不额外恢复气力。
7. 回位治疗不能复活尸体；腿失能者原地恢复后可再次移动；8点为整名敌人每tick的恢复预算，重新接敌即停疗伤。
8. 同种两名敌人状态互不影响；删除第一名、移动、存读档及重复结算不串伤势、不共享资源、不重复发奖。
9. 存活失能者仍占格，不可搜刮；真正死亡只生成一次尸体。两种外观及攻击特效反映实际结果，隐藏状态不泄漏。

自动化入口 `npm run test:enemy-body`：128种满值组合的生死／攻击／招架／移动资格、溢出与分摊、死亡终态、发动肢及配合肢、武器依赖、气力隔离、单tick眩晕、正式场景先手废肢与同速互击、真实Buff隔离、存读档与删除索引、废腿原地疗伤后重新移动、眩晕暂停回位治疗均已通过。

同时通过既有伤害与资源、疼痛、步法招架、武器连击、催气击退、元招、战斗脱离、掉落、废墟跨层／存档／死亡结算，以及主角图册和地痞显示回归。这里的场景验证为隔离运行的正式游戏脚本测试，不表示新增美术或具体敌人数值已获人工试玩验收。

## 11. 配置与旧档兼容

- 动作必填 `id`、`limb`、`power_min`、`power_max`；`required_limbs` 可列出配合肢，`requires_movement: true` 表示必须能自主移动。`qi_cost` 沿用原配置。
- 默认随机选合法动作；`action_selection: "cycle"` 可按模板顺序循环，徒手、武器分别保存游标；只有实际发动才推进。
- 固定武器用 `weapon: {kind: "single", hand: "rhand"}`，或 `kind: "two_handed" / "polearm"`；武器动作另标 `mode: "weapon"`。身体依赖按第6节处理；双持等未定原型不作为已支持配置。
- `qi_li_initial` 可指定初始气力，缺省0；`qi_li_max` 与 `qi_li_regen_per_turn` 沿用。初始恢复和后续恢复均以世界tick为准，选招不产生气力。
- `CombatEnemies.validateTemplates()` 检查攻击模板的七项正整数上限、动作肢体、配合肢、模式与威力。训练陪练补了显式动作，地痞既有威力、损毁上限与掉落数值未改。
- 新存档保存稳定身份、部位状态、气力、盾量、疼痛、眩晕、动作游标、AI状态及普通地图敌人布局；Buff仍走原有统一存档。旧地牢档保留已有部位伤势，为缺失字段补默认值。旧档没有保存的普通地图伤势无法追溯恢复，不冒称能迁移原本不存在的数据。
