# Metaskill 运行接入

2026-10-18。实现依据为 [70号第13节与第15节](70-modular-weapon-system.md#13-元技能与徒手持械连招)，不新增具体元技能、触发阈值或获取方式。

## 实装范围

`js/combat-metaskills.js` 接入正式 `SceneCtx.actions.attackEnemy`、招式结算、BuffSystem、世界时间、装备配置和 SaveSystem。`data/move-variants.json` 的正式变式表仍为空；A–H及测试中的条件仅存在于自动化测试，不能当成正式技能内容。部件自带的七种兜底招式不接受变式。

- **替换**：先选出实际主招及其模式，再计算速度、先后手和连击次数。E替换B后只执行E；连击展开为EE、EEE或EEEE，循环从F继续。未出手的B不扣资源、不推进循环、不产生效果。
- **追加**：原主招及其所有速度连击结算完，再执行一次E。按执行时资源及距离重新检查，主循环和格挡模式仍属于B。追加不推进另一循环的攻击位置，也不切换装备。
- **排队**：成功激活的条目最早在下一世界tick的攻击机会执行。默认每处装配最多一条待执行，每个攻击tick最多消费一条有效元技能；无效条目取消并继续检查。不同tick的批次保持FIFO。同tick批内按激活时的主循环与配置顺序排序；本次实际主招完成后的下一位置作为扫描起点。排序锚点保存，切组不重新排列旧条目。
- **行动资格**：移动、等待、眩晕或没有可及攻击机会时不消费队列。不同速时，先手摧毁后手所需部位，后手取消失效条目并重新选招，保留本次已确定的速度与连击次数。同速双方原主招仍按共同快照演算，完成双方提交后再处理追加。
- **中断**：目标被前面的攻击击杀时，未出手的连击和追加不扣费、不发Buff，不自动换目标。已经占用的元技能名额不因追加取消而让给下一条。
- **资源**：复用实际招式、呼吸法和出力的计费。B的资源恢复先于E的读取；资源不足仍是一次实际出招，按原规则归零，不退回队列。声明的免耗只作用于被触发的招式，恢复、积气和呼吸状态要求继续独立结算。
- **禁止连锁**：被触发的整招、速度连击、资源变化、Buff、延迟效果、到期变化和延迟提交的撞墙效果保留来源。事件和状态扫描均排除这些来源；状态扫描保存已观察值及来源，不能等到下一tick把旧变化当成新条件。追加型的正常B及后续正常F/G/H仍可触发。

## 变式数据接口

现有变式解锁、招式过滤和装配规则继续使用。元技能变式新增 `metaskill` 对象；不送入普通变式的当击效果处理器。

| 字段 | 含义 |
|---|---|
| `mode` | `replace` 或 `append` |
| `enabled_when` | 必须明确声明 `in_combat` 或 `always`；不根据虚构技能推导启用时机 |
| `condition.kind` | `event` 或 `state` |
| `condition.listen` | 需要监听的事件名数组；不把目标变更当成自动触发或重置 |
| `condition.test` | 声明式条件，支持 `all_of`、`any_of`、`not`，或 `path / op / value` 比较；不执行配置里的代码 |
| `condition.repeat_interval_ticks` | 仅在明确声明时允许持续状态周期性再次激活 |
| `cooldown_ticks` | 可选；成功入队起按世界tick计时，取消不刷新冷却 |
| `max_pending` | 可选；默认1，超过1必须由具体条目明确声明 |
| `recheck_on_execute` | 可选；为真才在执行时复核条件；追加出手前也会复核 |
| `resource_waivers` | 可选的 `qi`、`diqi` 列表；取消对应触发招式的支付，保留恢复和独立状态要求 |
| `activation_policy` | 可选；引用已注册的条目专属消耗／返还策略 |

条件读取 `self.qi`、`self.diqi`、相应上限、`self.mode`、`self.survival`、`self.buff_stacks.<buffId>`、`self.body_destroyed.<部位>` 或 `event` 字段。比较支持 `eq / neq / gt / gte / lt / lte / in`。未声明或不认识的规则不自行补齐为新技能。

监听入口包括 `action_completed`、`incoming_action_completed`、`hit`、`parry`、`damage_taken`、`resource_changed`、`buff_changed`、`world_tick`，以及已注册Buff事件的 `event_kind:event_name`。整招事件包含实际 `skill_id / move_id / limb_id`、是否命中、总伤害和格挡结果；每次速度连击是独立招式事件，多段攻击的整招完成只发一次。

状态条件默认记录由假变真的变化；装配或旧档迁移建立当前状态基线，不凭空补发一次激活。排队、执行、取消、冷却结束都不自动制造新边沿。显式周期触发仍受来源、去重和冷却约束。

### 条目专属消耗与返还

通过 `CombatMetaSkills.registerActivationPolicy(id, policy)` 注册游戏代码，`activation_policy` 只保存其ID。策略回执必须可以保存成JSON。

| 回调 | 时点 |
|---|---|
| `canActivate(context, binding)` | 去重与冷却通过后，检查该条目能否激活 |
| `onActivate(context, binding)` | 成功激活入队时；返回可保存的回执 |
| `onSelected(receipt, entry)` | 本tick主招真正开始，元技能名额被占用时 |
| `onExecute(receipt, entry)` | 被触发的E第一次实际出手前；追加型在B完整结算后调用，速度重复不重复调用 |
| `onCancel(receipt, reason, entry)` | 队列条目被取消，或已选中的追加尚未出手就中断 |

框架不统一代扣激活资源，不预设取消返还，也不把招式免耗自动套到激活费用。各回调及其资源/Buff后果均属于元技能来源，不能通过支付或返还触发另一个元技能。

## 装配、换装与存档

- 徒手仍使用 `move_sequences[limb]` 的招式与变式槽。现有战斗面板修改metaskill配置会消耗一个战斗行动，清空待执行队列，保留冷却与既有状态记录。
- 武器位置配置接受 `skill_id / move_id / variants / power_level`，由 `ModularWeaponCombat.setMoveConfig` 校验已学功夫、招式解锁、位置伤害属性、变式资格和槽数。`SceneApp.combatApi.setWeaponConfig('move', …)` 提供同一行动入口。未配置合法人物招式时继续使用部件兜底；正式可学武器招式仍待设计，当前面板不添加虚构招式供选择。
- 实际换装删除旧武器条目，保留徒手条目的相对顺序；重装旧武器也重置其配置与攻击／格挡进度。部件换装只删除该部件占用位置的条目。改变元技能配置则使用整队清空规则。
- 冷却按装配位置分别记录；移除或挪动已有元技能会携带其未完冷却，不能通过重装刷新。同名变式已有的不同合法装配位置不合并去重。
- 正式脱战清空队列并重置徒手及武器攻击进度、武器格挡进度；保留冷却。换目标或只击杀其中一名敌人不触发此清理。
- 保存 `metaskills` 的队列、批内排序锚点、冷却、状态边沿、来源记录和本tick已用名额；武器模式／游标仍由武器实例保存。恢复时暂停监听，不多走tick、不额外激活。Buff实例同时保存 `metaskill_source`，延迟效果不能通过读档洗掉来源。
- 继续沿用地牢读档判死等正式读取规则；没有新增绕过该规则的存档入口。

原有武器战斗、伤害、资源、呼吸爆发、步法格挡、战斗面板、交战状态和铸造接入测试继续作为回归检查。测试中的招式、阈值和策略只驻留在隔离环境，不进入正式物品、技能或角色存档。
