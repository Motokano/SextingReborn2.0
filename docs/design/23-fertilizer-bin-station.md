# 二十三、肥料桶 / 堆肥与沤肥设施（已定稿纪要）

> 本文汇总截至目前已敲定的设计口径，供实现与策划对齐；与旧段落冲突时以本节为准。

---

## 23.1 总览

- **设施形态**：同一设施内 **分页（Tab）**：**堆肥**、**沤肥**。
- **并行规则**：初始单批次；**升级后解锁第二批次槽**，堆肥与沤肥 **可同时各跑一批**（第二槽为升级内容）。
- **技能**：首版复用 **`life_farming`**（不单独新建 `life_fertilizing`，除非日后拆分）。
- **投料呈现**：**盲投**——不展示实时碳氮比数值；结算给档位与风味文案。
- **开新批次前置（堆肥/沤肥一致）**：开始新一批前，设施内若存在**未取出的已结算产物**，则必须先全部取走；未清空时禁止开始堆肥/沤肥。
- **熟练度计次（堆肥/沤肥一致）**：仅以下行为给熟练度：① **开始一批堆肥/沤肥**；② **每个事件窗内的一次有效互动**。每次记 **1 次农业技能（`life_farming`）熟练度**；并尝试记 **1 次主角当前已装备呼吸法** 的熟练度（未装备呼吸法则该次不加呼吸法熟练度）。**纯投料过程**与**收取成品**不计熟练度。
- **熟练度提示可见性**：与堆肥/沤肥相关的熟练度增加提示对普通玩家界面默认隐藏；运行时仅保留调试日志（供开发/排查使用）。

## 23.2 投料与碳氮（物品字段）

- **`fert_c`**、**`fert_n`**：整数，表示该物品在本批次中贡献的 **碳量 / 氮量**（游戏内相对单位即可，全表统一）。已配置的字段允许取 **0**；**未配置的字段**在 **23.3** 合计时按 **0** 计入。
- **主料格准入（堆肥、沤肥两页一致；菌剂除外）**：凡放入 **主料格**（**2～8 件** 那一组格位）的物品，物品模板 **须至少包含 `fert_c`、`fert_n` 其中之一**（实现上：键存在且类型为整数）；**两键皆无**（例如 **23.5.2** 废产物）则 **不允许** 放入堆肥/沤肥主料格。
- **菌剂**：**另计**，不占 8 格主料上限；通常 **0～1 份** / 批（首版建议最多一种菌剂）。菌剂 **不要求** `fert_c` / `fert_n`，不参与 **23.3** 的 `C`/`N` 合计。
- **菌剂物品字段（建议）**：`compost_inoculant` 对象，例如  
  `{ "modes": ["aerobic"|"anaerobic"], "consumed_per_batch": true }`  
  - `aerobic` ↔ 堆肥页；`anaerobic` ↔ 沤肥页；可同时含两者表示通用菌剂。
  - **启动器定位（首版已定）**：菌剂 **仅**用于门控「可进堆肥页 / 可进沤肥页」与 **失败仍消耗**；**不参与** `C`/`N` 合计，**不提供**容错、耗时、风险或数值上的任何额外增益；**不改变** **23.3** ratio 与随机事件池（见 **23.8.1c**）。
- **一批主料**：须满足最少 2 件、最多 8 件，且 **每件** 均通过上款准入。`C`、`N` 由各件 **已定义** 的 `fert_c`/`fert_n` 相加，**缺失键按 0**。**批次合计**若 **`C <= 0` 或 `N <= 0`**，不进入 **23.3** 的 ratio 分档，改出 **23.5.2** 第四档废产物。

## 23.3 盲投后台判定（用于分档）

- 批次合计：`C = Σ fert_c`，`N = Σ fert_n`（**仅主料格**内各件之和；单件 **仅有 `fert_c`** 则该件 `fert_n` 按 **0** 计，**仅有 `fert_n`** 则该件 `fert_c` 按 **0** 计；**菌剂不计入**，见 23.2）。
- **非法比例（优先判定，不走 ratio）**：若 **`C <= 0` 或 `N <= 0`**（例如全纯碳侧合计仍无氮、全纯氮侧仍无碳、或各件有键但数值全为 0），视为 **无法构成可发酵碳氮结构**，**不**再计算 `ratio`，直接对应 **23.5.2 第四档废产物**（堆肥 / 沤肥各给本页专用废物物品，见下）。
- **合法批次**下 **碳氮比（游戏内）**：`ratio = C / N`（合法时必有 `N > 0`，无需 `ε`）。
- **阶段理想比（堆肥/沤肥统一）**：  
  - **投料阶段理想**：`25:1 ~ 35:1`（即 `25 <= ratio <= 35`）  
  - **成品阶段理想**：`10:1 ~ 15:1`（用于结算后产物口径约束，见 **23.5.1** 与 **23.7**）  
- **投料分档（用于结算档位）**：  
  - **优档**：`25 <= ratio <= 35`  
  - **中档**：`18 <= ratio < 25` 或 `35 < ratio <= 45`  
  - **差档**：`ratio` 在合法前提下落入 **既非优、也非中** 的区间（其余）  
- **菌剂**：不写入 `fert_n`/`fert_c`；**首版无数值参与本节分档**（见 **23.2** 启动器定位）。

## 23.4 堆肥 vs 沤肥（玩法与产物分工）

| 维度 | 堆肥（好氧） | 沤肥（厌氧/水沤向） |
|------|----------------|----------------------|
| **时间** | 相对 **较短** | 相对 **更久** |
| **操作** | 需要 **较多互动**（如翻堆等，细节实现阶段展开） | 配好后 **少动**、偏放置 |
| **直接产出定位** | **腐熟基质**（**三档可用** + **一档废物**，见 23.5），属 **半成品** / 失败即 **无用途残渣** | **常见施肥用肥料**（**三档可用** + **一档废物**；废物无 **23.7** 肥力/缩时效果） |
| **与种植关系** | 基质需 **再经其他生活技能加工** 才成为可 **替换地块基底土** 的特殊土 | 走 **施肥 / 肥力与缩成熟时间** 等 additive 路线（见 23.7） |

## 23.5 堆肥产出（四档：三档可用基质 + 一档废产物，非品质档）

堆肥结算对应 **四档**，在物品表中为 **四个独立 `item_id`**（不是同一物品的 `quality_tier`）：前三档为可用基质，第四档为 **非法碳氮批次** 的专用废物。

| 档位 | `item_id`（与 **`data/items/compost_matrix_base.csv`** 一致） | 显示名（见 CSV `sn`） | 肥力意向 / 用途 |
|------|----------------|------------|-----------------|
| 差 | `compost_matrix_grade_low` | 腐熟基质·散 | 低；可用基质 |
| 中 | `compost_matrix_grade_mid` | 腐熟基质·匀 | 中；可用基质 |
| 优 | `compost_matrix_grade_high` | 腐熟基质·细 | 高；可用基质 |
| **废** | `compost_matrix_batch_void` | 发酵废坨 | **无**：不可作换土链原料、**无**种植增益；**不配** `fert_c`/`fert_n`，见 **23.5.2** |

- **语义（前三档）**：均为 **营养土向半成品**；**不可**直接当作「可替换种植田土壤」的终局土使用。
- **后续（前三档）**：进入 **其他生活技能**（如 **`life_manufacturing`**，最终以实现为准）配方链，产出带 **`grants_soil_id`**（或等价）的 **特殊土壤物品**，才允许执行「换土」。

### 23.5.1 前三档基质的 `fert_c` / `fert_n`（可作沤肥主料）

**可用**三档腐熟基质 **同时配置** `fert_c`、`fert_n`（强于 **23.2** 的「至少其一」底线），便于作为均衡主料进入 **沤肥**（或未来同源设施）参与 **23.3** 演算。取值原则：

- **单品 C/N**（`fert_c / fert_n`）与 **成品阶段理想区间（10:1~15:1）** 对齐：优/中/差三档都应落在该区间附近，并通过档位差异体现稳定度与下游配方效率，不再沿用早期“显著高碳比”口径。
- 三档 **均带正氮**（`fert_n > 0`），降低「单格即把批次拖进 `N<=0`」的边角；批次是否落入 **废产物** 仍由 **合计 `C`、`N`**（**23.3**）判定。
- **混投时** 永远用批次合计 `C = Σ fert_c`、`N = Σ fert_n` 算 `ratio`（**23.3**）；基质可与鲜料、残渣等一起沤，高/中档是「拉高或稳住 C/N」的填料，低档是「高碳负债」需配氮源矫正。

| 建议 `item_id` | `fert_c` | `fert_n` | 单品 `C/N`（约） | 成品阶段口径 |
|----------------|----------|----------|------------------|--------------------------------|
| `compost_matrix_grade_low` | 42 | 3 | 14.0 | 可用，但稳定度最低 |
| `compost_matrix_grade_mid` | 36 | 3 | 12.0 | 可用，稳定度中等 |
| `compost_matrix_grade_high` | 30 | 3 | 10.0 | 可用，稳定度最高 |

> 数值为 **同一量纲** 下的建议初值；若全表整体缩放主料 `fert_c`/`fert_n`，三档宜 **同比缩放** 以保持相对关系。

### 23.5.2 第四档：非法比例专用废产物

- **触发**：批次主料合计满足 **`C <= 0` 或 `N <= 0`**（**23.3**），典型来源：**主料全为仅碳侧且合计仍无氮**、**全为仅氮侧且合计仍无碳**、或各件有贡献键但 **数值全为 0** 等组合。
- **物品模板**：**`fert_c` 与 `fert_n` 两键皆无**（非「填 0」，而是 **字段缺失**）。因此按 **23.2** 主料准入规则，**无法**再次放入堆肥/沤肥主料格；也 **不参与**任何依赖碳氮的后续配方（除非日后单开「回收」类例外）。
- **堆肥页**：产出 **`compost_matrix_batch_void`**（上表）；**不得**进入换土制造链、**不得**配置 **23.7** 类肥料字段；玩法出口以 **丢弃 / 出售（若有收购）/ 未来专用回收** 等为宜。
- **沤肥页**：同理单独 **`item_id`**（建议 `fertilizer_batch_void` / 显示名「沤肥废液渣」等），**不配** `fert_c`/`fert_n`、**零** **23.7** 肥力与缩时效果。
- **体验**：仍占一次批次时间与消耗（若有），盲投失败有 **明确风味文案**（不展示具体 C/N 数值亦可提示「比例失调发酵失败」类叙述）。

## 23.6 种植地块与土壤（「土的装备」）

- 每块种植地维护 **`soil_id`（或 `soil_profile_id`）`**，默认 **普通土**。
- **换土**：改 **基底属性**；在地块 UI 中 **展示当前土类型**（玩家可见「像土的装备」）。
- **作物约束**：部分作物需 `allowed_soil_ids` 或 `required_soil_tags`（实现时二选一即可）；不满足则禁止播种或明确提示。
- **换土时机（建议）**：首版仅 **空茬** 时可换土，避免生长中换土规则爆炸（若日后允许再扩展）。

## 23.7 沤肥产物：肥料效果（不增产、缩成熟时间）

因 **物品不堆叠**，肥料 **不增产**，主效果为 **缩短成熟时间**（与堆肥「基质 → 换土」链路分离）。**非法碳氮批次**（**23.3**）产出 **23.5.2** 所述沤肥废渣物品，**不**走本节数值。

- **地块字段（概念）**：`soil_fertility`、`growth_time_mult`（默认 1.0）、`fertility_expire_tick`。
- **肥料物品字段**：`fertility_add`、`time_reduce_pct`、`duration_ticks`。
- **沤肥来源标记字段（新增）**：沤肥线**三档可用肥料**在物品模板增加 **`is_anaerobic_fertilizer: true`**，用于后续种植系统施肥入口识别（与通用肥料区分）；**沤肥废档不加该字段**。
- **约束**：`growth_time_mult = clamp(1 - time_reduce_pct, 0.7, 1.0)`（最多缩约 30%）。

以下为 **沤肥线肥料** 的预置示例 id（与堆肥三基质区分），数值仍可调：

| 档位（示例） | `item_id`（示例） | `time_reduce_pct` | `duration_ticks` | `fertility_add` |
|--------------|-------------------|-------------------|-------------------|-----------------|
| 优 | `fertilizer_compost_plus` | 0.25 | 72 | 30 |
| 中 | `fertilizer_basic` | 0.15 | 60 | 20 |
| 差 | `fertilizer_basic_low` | 0.05 | 36 | 10 |

施肥流程：写入地块限时 `growth_time_mult` / 肥力；到期恢复；作物用 `finalGrowTime = baseGrowTime * growth_time_mult`。

## 23.8 保底与体验

- **盲投**：主料仍盲投；**结算必有产物**（堆肥为 **23.5** 四档之一；沤肥为 **三档肥料之一** 或 **废产物一档**），不做「完全空车」。
- **沤肥**可保持「慢、少动、出常用肥」；**堆肥**「快、多动、出基质再制造」——与 23.4 一致。

### 23.8.1 时长口径（按 tick）

- 项目时间尺度：**`1 tick = 10 分钟`**。
- **堆肥（好氧）基准时长**：**2 天 = `288 tick`**（默认结算时间）。
- **沤肥（厌氧）基准时长**：**7 天 = `1008 tick`**（默认结算时间）。
- 建议保留操作浮动边界（实现可选）：
  - 最短：`240 tick`（约 40 小时，菌剂/操作较优）
  - 最长：`336 tick`（约 56 小时，操作较差或状态不佳）
- 若暂不做操作影响时长，首版可先固定：
  - `compost_duration_ticks = 288`
  - `anaerobic_duration_ticks = 1008`
  先仅影响分档，不影响耗时。

### 23.8.1b 堆肥互动与时间窗（延伸至下一事件前 1 tick；禁止单 tick 强制）

- **批次进度**：堆肥批次自身的 **`compost_duration_ticks` 倒计时（或等价推进）不因「有待处理随机事件」而暂停**；只要 **游戏进程存活且 world tick 在跑**，即使玩家不打开堆肥 UI，批次时间仍正常消耗（与 **23.8.1** 一致）。**进程退出**时 **冻结** 直至下次启动，见 **23.8.1c**。
- **禁止单 tick 强制**：不得要求玩家必须在「事件触发的某一个 tick」内完成操作；**`1 tick = 10 分钟`** 下这几乎不可达成。
- **交互窗（动态长度）**：对按 tick 排程的每条随机状态事件 \(k\)，设其触发 tick 为 **`trigger_tick[k]`**（事件进入「待响应」状态的 tick）。玩家可在 **连续闭区间** 内任一时点响应：
  - **`window_start[k] = trigger_tick[k]`**
  - **`window_end[k] = trigger_tick[k+1] - 1`**（\(k\) 的下一条随机状态事件的触发 tick 之前 **1 tick**）
  - **最后一条**随机状态事件：无 \(k+1\) 时，取 **`window_end[last] = compost_duration_ticks - 1`**（收堆/结算前一 tick，与「下一事件前 1 tick」同构）。
- **排程约束**：须满足 **`trigger_tick[k+1] > trigger_tick[k]`**（严格递增），避免窗长退化为 0 或与下一窗重叠语义冲突。
- **首版默认排程（已定）**：每批堆肥固定 **`5`** 次随机状态事件（不含结算时的 `result` 文案档）。相对批次起点 **`batch_age_tick = 0`**（开堆后每推进 1 world tick，`batch_age_tick` 同步 +1，直至收堆）：
  - **`compost_random_state_event_count = 5`**
  - **`trigger_tick[] = [48, 96, 144, 192, 240]`**（每隔 **`48 tick`** 一次，约 **8 小时**）
  - 对应交互窗（闭区间）：**`[48, 95], [96, 143], [144, 191], [192, 239], [240, 287]`**（末窗终点 **`compost_duration_ticks - 1`**）
  - **`batch_age_tick ∈ [0, 47]`** 为开堆后缓冲，**不触发**随机状态事件。
- **计次与 miss**：同一窗口内 **至多计 1 次**有效操作（防刷）。若 **`window_end[k]`** 已过仍未对该窗做出有效操作，记 **miss**，并对本批 **互动分 `compost_ops_score`（或等价字段）执行 `-1`**（可累加；与 **非法 C/N 废档** 的硬判定独立，不得用 miss 替代废档规则）。
- **不得回拨时钟**：miss 或 `-1` **不得**回拨批次已消耗时间或改写 `trigger_tick` 排程。

### 23.8.1c 堆肥互动、结算与存档冻结（首版已定稿）

- **产出与品质**：堆肥四档基质/废坨 **仅区分 `item_id` 四档**，**不设**玩法向 **`quality` / `quality_tier` 品质档**；与 **23.5** 一致。
- **`compost_ops_score`（定稿阈值）**：对合法批次先得 `baseTier`（low/mid/high），再按下述区间修正并 **clamp** 到 `[low, high]`：
  - `score >= +2`：`baseTier + 1`
  - `-1 <= score <= +1`：`baseTier + 0`
  - `score <= -2`：`baseTier - 1`
  其中 `score` 由 5 个事件窗累计（动作 `+1/0/-1`，miss `-1`），理论范围 `[-5, +5]`；**不得**引入第五套产物 id，合法批次不得打成 `compost_matrix_batch_void`。
- **单窗操作与计分**：每个交互窗内玩家 **至多选择 1 次**动作；**选定后立即结算**该窗，**至下一次 `trigger_tick` 之前不再给出新的操作选择**。动作相对本窗抽样事件的 **`best_action` / `secondary_action` / `bad_action`**：**`+1` / `0` / `-1`** 计入 `compost_ops_score`；**miss**（窗过未操作）仍为 **`compost_ops_score - 1`**（与 **23.8.1b** 一致）。
- **单次动作消耗**：每次有效操作扣 **`5` 体力**，并令 **全局时间推进 `1` tick**——与项目既有的 **world / 生存主循环 tick** 完全一致，**不设**堆肥专用时间轴或例外扣进规则；**不**要求额外工具或水道具。
- **肮脏度变化（当前实现口径）**：每次堆肥桶事件窗内的有效互动（即一次 `interact` 成功落地）额外增加 **`dirtyness +10`**。当前阶段 **仅**该入口会增加肮脏度，不在开堆、收取、纯投料或其它系统入口叠加。
- **成长计次（堆肥）**：开始堆肥时记 **1 次 `life_farming` 熟练度**，并对**当前已装备呼吸法**记 **1 次熟练度**（未装备则跳过）；每个事件窗内若发生有效互动，同口径再记 **1 次**。纯投料与收取不计熟练度（同 **23.1**）。
- **非法批次不可互动**：若本批已判定为 **非法 C/N 废档路径**（`C <= 0` 或 `N <= 0`），**不**进入随机状态事件互动与上述计分（**否**）。
- **随机状态事件抽样池**：每次开窗时，在 **`data/compost-events.json`** 中 **`stage == "state"` 且 `enabled == true`** 的 **`event_id`** 集合上 **等概率** 抽取一条作为本窗观察与动作对照来源（文案再在 `variants[]` 内等概率抽一条）。
- **时间与离线**：堆肥 **`batch_age_tick` / 批次剩余时长 / 互动扣时** 均与项目 **全局 tick（与生存主循环一致）** 同步推进，**无**独立堆肥时间轴；**单机**、**关闭游戏时世界与批次状态冻结**，**重新打开后**再依冻结点继续推进与结算（不在后台偷偷跑 tick）。
- **开堆 / 收堆 / 邻格**：**开堆瞬间锁定**主料（与菌剂槽位规则不变）；收堆须玩家 **手动点一次**「收取」；**不允许**远离设施远程收堆（须在设施交互规则内，与邻格/打开面板一致）。
- **四档物品模板**：**唯一编辑源**为 **`data/items/compost_matrix_base.csv`**（四行四 `id`）；改表后须执行 **`node tools/build-items-json.mjs`**（或 `npm run build:items`）生成 **`data/items.json`**，**勿**长期手改 JSON。每档须含 **`sn` / `placeholder_name` / `fn_before` / `fn`**，与 **`item-display-language-agent`** 口径一致；三档基质带 **`fert_c`/`fert_n`**，废坨 **不配** 二键（见 **23.5.2**）。
- **菌剂（启动器）**：仅用字段区分 **可进堆肥页 / 可进沤肥页**（如 **`compost_inoculant.modes`** 含 `aerobic` / `anaerobic`）；**无**数值增益；**不改变** ratio 分档与随机事件池；**本批结算为失败或废档时，仍消耗本批已放入的菌剂**（失败消耗）。

### 23.8.2 事件文案数据流（CSV -> JSON，防脏数据）

- 策划编辑源：`data/compost-events.csv`（仅用于编辑，不直接给运行时读取）。
- 动作字典参考：`data/compost-event-actions.csv`（用于查可选 `action_id` 与中文含义；首版固定动作集）。
- 运行时只读：`data/compost-events.json`（由构建脚本生成）。
- 构建命令：`node tools/build-compost-events-json.mjs`。
- 严格校验策略（任一失败即中断，不写 JSON）：
  - 必填表头：`event_id, text_variant_id, stage, severity, title, desc, best_action, secondary_action, bad_action, success_text, fail_text, enabled`
  - `event_id`、`text_variant_id` 仅允许小写字母/数字/下划线；行唯一键为 `(event_id, text_variant_id)`
  - 同一 `event_id` 的 `stage/severity/action 字段/enabled` 必须一致，仅文案字段（`title/desc/success_text/fail_text`）允许变体差异
  - `stage` 仅允许 `state|action|result`
  - `severity` 仅允许 `good|info|warn|bad`
  - 固定操作枚举：`none|turn_pile|add_water|ventilate|cover_keepwarm|break_clumps|remove_contaminant`（`state` 事件至少填写 `best_action`）
  - 随机事件统一等概率触发，不再使用 `weight` 字段；`enabled` 为空或 `true/false/1/0/yes/no`
- 输出文件采用临时文件 + 重命名的原子写入，避免中途失败留下半文件。
- 运行时文案抽取口径：同一 `event_id` 下从 `variants[]` **等概率随机**选取一条文案展示。
- Agent 维护硬约束见 **`.cursor/rules/compost-fertilizer-bin-agent.mdc`**（CSV→JSON、枚举、禁止双轨等）。

## 23.10 沤肥首版（新增定稿）

- **分档口径**：沤肥盲投与堆肥一致，复用 **23.3** 的同一套 `C/N` 合计与 `ratio` 分档；非法仍走 **23.5.2** 废档。
- **产物形态**：沤肥主产物为液体类，一次收取为多份数量，首版在 **2~4** 份中**等权随机**（每档同概率，按同一 `item_id` 的计数结算，不引入品质字段）。
- **产物字段约束**：沤肥页产出的**可用肥料** `item_id` 必须带 **`is_anaerobic_fertilizer: true`**；沤肥废档不加该字段。
- **CSV 复用**：沤肥放气事件与文案继续复用现有 **`data/compost-events.csv` -> `data/compost-events.json`** 构建链路，不新增并行事件 CSV；运行时按 **`event_id`** 约定筛选沤肥事件。
- **沤肥专属事件（放气）**：
  - 每个沤肥周期固定触发 **2 次**放气互动窗口；按 **`anaerobic_duration_ticks = 1008`** 等分排程：`trigger_tick = [336, 672]`，窗口为 **`[336, 671]`** 与 **`[672, 1007]`**（终点到下一窗前 **1 tick**）。
  - 每次窗口仅两种动作：**`vent_gas`（拧开放气）** 与 **`leave_as_is`（放置不理）**；其中 **`vent_gas` 为正确动作**。
  - 与堆肥不同，放气事件 **不改变最终产物档位 / `item_id`**，仅影响最终数量。
  - 「成功互动」定义为：玩家在设施旁与设施对话后进入沤肥页，并在窗口内选择正确动作 **`vent_gas`**。选择 **`leave_as_is`** 视为该次未成功。
  - 若该周期内玩家 **两次都未成功互动**，则最终产量在原定结果基础上 **减半并向下取整**，并给玩家附带 `buff_id = 沤肥满身`（效果参数后续补充）；减半后数量 **保底 1**。
  - 若该周期内玩家 **至少成功互动 1 次**，则该周期按原定数量结算（不触发减半惩罚）。
- **与堆肥的产量差异**：堆肥结算固定产出 **1 个单格物品**；沤肥按数量结算，一次可得 **2~4** 份液体产物。
- **动作成本与成长**：放气互动 **不扣体力**；每次互动推进 **1** 全局 tick，并记 **1 次 `life_farming` 熟练度**，且仅在主角**当前已装备呼吸法**时记 **1 次该呼吸法熟练度**。
- **肮脏度变化（当前实现口径）**：沤肥放气窗同属堆肥桶事件互动入口；每次有效互动同样增加 **`dirtyness +10`**（与上文 23.8.1c 保持一致）。
- **成长计次（沤肥）**：开始沤肥时记 **1 次 `life_farming` 熟练度**，并对**当前已装备呼吸法**记 **1 次熟练度**（未装备则跳过）；每个放气窗内若发生有效互动，同口径再记 **1 次**。纯投料与收取不计熟练度（同 **23.1**）。
- **收取与背包不足**：沤肥收取允许**部分收取**；背包不足时先拿得下的份数，剩余产物保留在设施内等待后续继续收取。
- **废档优先**：若本批为非法 C/N 废档（**23.3**），则直接走废档产物（**23.5.2**），覆盖液体 **2~4** 数量规则。
- **时间与交互约束**：除上面的「事件次数=2、影响数量」差异外，其余时钟、冻结、邻格收取、开堆锁定、菌剂启动器语义均与 **23.8.1c** 一致，并受 **23.1**「开新批次前必须清空已产出物」约束。
