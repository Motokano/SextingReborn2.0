# 仓库界面整合（2026-09-26）

用户要求彻底改造仓库界面，解决旧升级层与新材料面板割裂的问题。本记录优先于 29 号文档中旧的关闭禁用、打开自动施工与固定配方展示约定。

## 窗口结构

同一个仓库窗口使用“物品存取 / 整备扩建”两页。存取页保留容量、分页、详情及原有 QoL 门控；随身容器显示全部物品，可滚动，名称遵循认知展示。点击随身物品存入，选择仓格后取出。不新增免费筛选、整理或其他付费 QoL。远驿模式保持只存不取，隐藏扩建入口。

扩建页左侧显示已发现的项目和状态，右侧显示用途、准备材料 / 动手施工 / 整备完成三个阶段。首次选路线仍沿用原三选一规则。未发现节点继续隐藏，不改容量、解锁效果、材料点数和前置关系。

## 备料与施工

后续以用户最新反馈为准：移除右侧重复项目名称、顶部阶段标签和备料说明入口。仓库直接检查随身及仓内未封签、可用于本项目的材料，保留认知名称，不写入鉴定或全局材料用途知识；其他设施仍保留原用途门槛。材料交齐后立即显示施工状态与“开始施工”，交付明细可另行收起，无须先关闭收据。右侧标题只说明当前操作或施工状态。

2026-09-26 后续体验修正：仓库嵌入备料改为单页选材。材料用途尚未了解时只突出“查看备料说明”；了解后说明默认折叠，各类材料同页排列，不再显示分类步骤页、“备齐 / 清空”与额外核对页。底部固定展示本次实际物品件数和唯一主要操作“交付所选材料”，直接结算、不追加确认。独立设施修复窗口暂时保持原交互。

共用 FacilityUnlockPanel 新增 mount/unmount 嵌入模式，在项目详情内直接完成说明、按类别滑条选材、核对交付和收据，无第二层弹窗。设施独立修复窗口保持原有入口。材料名称、可用库存、封签与整件退回仍由共用结算层处理。需求点数、材料贡献、工程剩余 tick 和百分比不显示。

材料交付后，收据留在原位置，点击完成返回同一项目并手动开工。施工使用原工程规则：独立工程 tick，原时长、体力与天气修正保持不变，不额外推进世界 tick。工程进展改为阶段描述，体力显示实际数值。

开始 / 暂停 / 继续由同一个按钮承担。暂停、关闭、切换项目或存取页、页面隐藏、体力不足及读档均停止计时；回来后手动继续，恢复体力不自动复工。每次有效施工保存，保存失败停工并提示，内存中已经付出的体力与工程一起保留；关闭失败时留在面板供重试，不独立回滚体力。

## 实现与验收

- `js/hideout-warehouse-panel.js`：双页状态、阶段描述、嵌入备料、显式施工控制、随身库存展示。
- `js/cooking-repair-panel.js`：复用材料面板的嵌入模式，独立设施仍使用弹窗。
- `css/warehouse-workspace.css`、`index.html`：统一布局，较窄屏幕下项目列表改为上方横向布局。
- `js/save-system.js`：应用存档之前取消仓库施工计时及临时备料选择。
- `tools/warehouse-workspace-acceptance.html`：隔离 8018 端口，加载真实仓库、物品、生存与材料模块，模拟保存接口。验证全部随身物品、存入取出、认知名称、页内交料、收据、部分材料快照恢复、暂停、低体力、读档中断计时、重新打开不复工、完工扩容、保存失败。此页不是正式浏览器持久化存档的端到端测试。
- 既有仓库、共用材料修复、烹饪修复、农业存档检查通过。
