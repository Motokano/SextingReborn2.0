# 攻击特效试作记录（01–13）

2026-10-02。第 13 版已获用户确认并接入正式游戏，规范以 [69 攻击特效规范与正式接入](69-combat-fx-art-direction.md) 为准。默认 `limb` 的绘制器、招式编排与完整棋子视觉偏移现与游戏共用；原始外观由冻结的 V13 对照测试守护。本页的交手情境仍是独立预设，不读写存档。下文保留各轮探索和当时验收状态，不能用旧版的“尚未接入”描述当前实现。

运行 `npm run prototype:combat-fx`，打开 `/combat-fx-prototype.html?no_reload`。若 8014 项目服务已启动，直接打开页面。

本轮问题：在 144px 格宽、现有站姿棋子下，九个共用招式的方向、轮廓和交手顺序是否足够清晰？

- 读取 `data/combat-skills.json` 的招式名、功法、伤害类型与段数；结果由预设情境指定，没有执行命中、招架或伤害随机结算。
- 提供敌我互换、八向、出招侧、命中部位、正常/慢放、暂停/重播/进度拖动、144px 实际尺寸/1.7 倍放大。
- 情境：命中、招架、闪开、防具吸收、底气不足、两段分别招架和命中、顺序还击、同速互中、正蹬击退后距离挥空、撞阻眩晕停手、催气冲锋与招架后击退。
- 第一版外观：暖白/淡金手绘线条、短弧与楔形拖尾、紧凑接触爆点，招架偏灰绿，地面尘迹表示实际位移。没有全屏闪光或抖屏。
- 沿用玩家 D000 图册裁切与地痞透明站姿，底座宽约 46px，沿用 `TileRendererV2.makeGroundShadow`；不生成或修改棋子素材，不恢复骨骼拆装。
- 肢体与部位落点是视觉近似锚点，不是骨架数据；普通出手仅给完整棋子很小的视觉位移，实际格坐标只用于预设冲锋/击退。

验收后再决定轨迹、颜色和节奏。接入正式战斗时必须用实际招式、承招肢、逐段结果、状态应用与位移事件取代预设；按 49 / 61 号规则保存发生时刻的坐标和原因，处理敌方动作 ID 映射、同速提交、死亡/眩晕中止。不要直接把本页脚本作为玩法结算器。

用户结论：首版方向已认可，要求继续丰富特效细节，让玩家看到效果即可辨别招式；第二版细节待验收。

第二版为九招分别设计出手痕迹与接触细节：刺拳拳锋与四点冲击、正蹬鞋底纹与压缩环、摆拳重弧与横向碎屑、鞭腿收尖长弧与鞋尖、戳眼双指与两点针芒、踹膝低位鞋跟与下压折痕、推搡双掌与宽面压波、连环掌掴反向掌影与指缝拖痕、兵击直斩薄锋与断裂亮屑。轨迹仅在一次既有命中中展开，不增加攻击段数。接触时收掉重叠的掌/鞋残影，掌掴首段接触在第二段前淡出；摆拳实心爆点减淡，保留棋子可见性。

每招蓄势时长仅控制本页演出，不修改玩法速度或先后手。同速情境仍同时接触；敌我共享同一套绘制函数，沿攻击方向和出招侧翻转。招架与防具仍使用对应接触反馈，闪开、距离挥空和底气不足没有命中爆点。

第二轮检查：九招均在浏览器查看，检查实际格宽与 1.7 倍细节；敌方左侧出招、招架、闪开、底气不足及掌掴先挡后中正常显示。连段结果文字分层，避免招架与淤伤重叠。模块语法检查通过，浏览器无错误日志。

第三版方向：用户要求放开表现，不局限于线条。默认使用体积版：有明暗面的拳/掌/鞋/双指残像，宽幅渐变风面，局部柔光、烟团、实体碎屑和脚下尘雾。暖金短拳、琥珀重拳、青白鞭腿、肉色掌掴与冰白斩击形成区别；招架增加反向承力弧面，护甲吸收增加半透明护甲面。素材由 Canvas 绘制，不重画棋子、不改变骨架或占格。

交手设置新增「体积版 / 线描版」对照，可在同一暂停帧切换；URL 的 `variant=volume` / `variant=line` 可保存预览选择。线描版保留第二版原绘制。体积残像在接触后 115ms 内消退，掌掴仍严格两段；碎屑固定生成，拖动进度可重现。脚下尘雾仅在实际预设命中的腿法/推搡中出现，并在棋子后方绘制。闪开、挥空和乏力没有命中烟尘或碎屑。

第三版细节待用户验收，仍未接入正式战斗。

第四版反馈与修正：用户认为第三版有停顿、力量不足，要求像格斗术一样干净利落。问题在于原 `ease-out` 轨迹提前接近终点后减速，搭配长达 210ms 的整条残影和较大的拳掌图形，出现悬停感。默认改为 `variant=snap` 利落版；前三版仅保留对照。

- 各招预备到接触 110–200ms，最后 55% 时长按平方曲线加速，接触前不减速；接触后残影 65ms 内消失，局部接触闪点最多 120ms。
- 取消大拳掌图标、宽幅风墙、持续光雾，保留末端局部运动残影和小块接触实体面；招式通过路径、高低位、双指/双掌及连段方向区分。
- 整枚棋子仅做短距前送和 95ms 回收，受击方一次快速退震，不来回正弦摇晃；这是现有站姿的视觉位移，不是新肢体动作或真实位移结算，不修改素材、底座、骨架参数。
- 掌掴两段接触间隔 155ms；顺序还击、同速、击退、撞阻仍由原预设因果关系控制。演出参数不改动正式战斗规则。
- 切换风格会重播，以各自节奏对照；默认 1× 正常速度。体积版和线描版仍可在选择器中查看。

第四轮检查：浏览器切换九招，逐帧查看摆拳出手/接触/退震/回收，检查 144px 格宽和放大预览；敌方左侧掌掴先挡后中、同速、招架/闪避/护甲/乏力、击退挥空、撞阻停手与催气预设均运行，无浏览器错误。模块语法检查通过。利落版表现仍待用户验收，尚未接入正式战斗。

第五版反馈：用户认为利落版过快且难以辨认招式，允许夸张，要求更多特色。第四版未通过辨识度验收，不能据此确定最终演出。当前默认改为 `variant=signature` 识招版，正常速度 1×。

- 出手到接触放宽为 340–480ms，约前 20% 展示招式轮廓，之后连续加速；恢复 220ms、轨迹余势 240ms、接触表现 280ms。掌掴两段接触间隔 360ms，不制造新增段数。
- 拳掌鞋刃沿实际弧线移动，并随路径转向；接触后沿余势继续运动并消失。招架、防具与底气不足改为回收方向，不画穿过承招点的命中余势。
- 刺拳是紧凑直拳；摆拳是绕出的厚重拳影；正蹬由靴侧转出鞋底；鞭腿是带鞋尖的弯月；戳眼展示双指；踹膝提靴后向低位折下；推搡显示两张直立掌面；掌掴左右反向横抽；兵击展示可见的刃与柄，再留下斜斩面。全部使用 Canvas 独立效果，没有重绘或拆装棋子。
- 末端拳锋、鞋尖、指尖与刀尖按图形前缘对齐接触位置；摆拳预览默认部位与顺序还击改为头部，符合其部位权重。掌掴默认头部，其余仍可切换预设部位。

第五轮检查：查看九招放大动作轮廓，检查实际 144px 格宽下的正蹬、推搡和掌掴；检查敌方左侧两段先挡后中，切换八方向及所有交手情境，无浏览器错误。脚本语法检查通过。识招版等待用户视觉反馈，依然是独立预设演示，未接入正式战斗。

第六版：用户指定 1.3× 速度，并希望更华丽、接近《街霸6》的打击特效。默认播放速度固定为 1.3×，保留第五版可辨认的动作轮廓、运动路径与连续余势；在识招版内增加高亮接触核、带深色墨边的方向性笔刷、双色轨迹、离散油墨颗粒。视觉方向参考 [Capcom 对 SF6 彩墨与街头美学的介绍](https://news.capcomusa.com/2022/06/02/street-fighter-6-redefines-the-genre-in-2023/)，效果仍由本项目 Canvas 自绘。

配色用于识别动作，不表示元素伤害：刺拳金橙、正蹬青蓝、摆拳橙红、鞭腿青绿、戳眼淡紫、踹膝赭金、推搡蓝色、掌掴粉色、兵击冰蓝。飞溅大小和方向按招式变化，戳眼收窄、推搡使用宽面压力而无尖锐中心、刀斩沿斜切方向展开。彩墨只由真实预设命中触发；招架使用冷色反向碎片，闪避与底气不足不产生命中飞溅。不增加停帧、抖屏或额外攻击段。

第六轮检查：九招均在浏览器查看，确认速度选择与运行初值为 1.3；检查 144px 格宽下敌方左侧摆拳的命中、招架、闪开、乏力，视觉反馈区分正常。无浏览器错误，脚本语法及 diff 空白检查通过。用户已明确速度偏好，新增彩墨细节仍待视觉验收。

第七版反馈：用户指出正蹬像侧踹，要求所有招式尽量符合本身动作特色。保留 1.3× 与彩墨方向，修正默认识招版的动作语义：

- 正蹬删除横向侧鞋与横鞋底，改画脚尖朝上的竖向前视鞋底，以足跟为接触锚点；预备小幅提脚，随后直线送出，命中后回收。余印同步改为竖向鞋印，不再恢复横鞋底。
- 鞭腿改为绷直踝部、脚背领先的足部轮廓；上提分量独立于攻击朝向与左右侧，防止反向时下垂成贴地扫腿。默认落点按招式最高权重选腹部。
- 踹膝改为较小的低位足跟前送，预览腿部锚点由脚踝附近抬至膝部附近，去掉高抬后向下跺的弧线。此处仅是视觉锚点，不改变命中部位 ID 或伤害。
- 刺拳与戳眼使用直线送出并回收；摆拳收浅为横向外绕弧，掌掴继续两侧交替横抽。
- 推搡双掌改为屏幕胸前并排，取消上下叠放，轨迹同步对齐两掌。
- 兵击展示立起的刃面劈落，接触点落在刃面，不再沿刀尖方向前刺；起落高度也不随攻击方向倒转。

动作语义参考：[国际武联套路规则中的蹬腿定义](https://www.iwuf.org/xhimg/soft/240912/WUSHU-TAOLU-COMPETITION-RULES-AND-JUDGING-METHODS-2024.pdf)（屈伸与脚尖勾回）及 [England Boxing 教练手册](https://www.englandboxing.org/wp-content/uploads/2022/03/Level-2-Coaching-Handbook-compressed.pdf)（直拳与弧形拳路区别）。这些只用于视觉辨识，当前仍是静态棋子上的独立特效，没有新增完整人体动作、骨骼或素材。

第七轮检查：独立预览检查正蹬、鞭腿、踹膝、推搡、摆拳与兵击放大形态；144px 格宽检查敌方左侧正蹬，切换八方向，查看相反朝向的足底竖直表现；检查招架、闪开、乏力和击退后挥空。无浏览器错误，脚本语法检查通过。用户认可动作修正，随后提出特效需跟随可装备的招式变式。

第八版：增加敌我独立的装备变式预览选择。示范「三连」将当前选中的招式改为三段，每段招式威力系数为原值的 50%；50% 仅用于展示，不是最终伤害或平衡决定。原本两段的掌掴改为三段而非六段，卸下恢复基础段数。不同招式的还击不受当前招式的示范变式影响，速度仍为 1.3×。

- `resolvePreviewMove` 先生成变式后的招式副本，预设情境再产生逐段结果；`scheduleAttackFx` 只消费最终结果列表，不根据招式名称猜段数，也不自行结算伤害。动作 ID、段 ID、出招侧、命中部位、结果与威力参数随事件传入。实际列表可短于计划段数，以便未来接入中止结果。
- 逐段播放同一招式的轮廓和路径，并标出 1/3、2/3、3/3；减威力示范稍收小命中爆点，不缩掉辨识轮廓。新增「逐段结果」情境展示命中、招架、闪开，结果仍为预设。
- 多段复用指定的出招肢体，不自动在左右肢体间交替。掌掴的反向横抽仅改变轨迹，不改变所装备的肢体。整招结束与击退根据最后实际段计算，资源仍不由演出处理。
- 正式接入缺口：`data/move-variants.json` 当前为空；`combat-melee-resolve.js` 在管线变式执行之前读取基础 `hit_segments`，而 `combat-variants.js` 目前在逐段上下文阶段应用效果。需在生成攻击段之前解析结构性变式，再将管线实际逐段结果交给演出；不能只在晚期上下文里修改段数字段，也不能让特效重放等价于多结算伤害。本轮没有修改正式装备表、存档或战斗管线。

第八轮检查：浏览器验证三段正蹬分别命中/招架/闪开，敌我独立装配，原式/三连切换，掌掴卸下恢复两段，以及第三段结束后仅击退一次、后手刺拳距离挥空。浏览器无错误日志，新调度模块及主脚本语法检查通过。当前为独立预览，正式装备事件尚未接入。

第九版：用户确认变式只需保留驱动特效的能力；主要问题是识招版的独立拳掌/鞋底和长彩色拖尾像飞行道具。默认新增 `variant=limb`「连贯出招」，旧线描和识招版保留对照，等待本轮视觉反馈。

- 出手使用细线描与淡填充：手臂轮廓始终从肩部连接到拳掌，腿部轮廓从髋部经膝部连接到足部。根部跟随整枚棋子的临时前送位移，不再停在出招前坐标。拳掌与足部缩小，删去飞行中的宽彩色能量拖尾。
- 预备屈收、逐渐伸展、命中后回收；闪开和招架同样收回，不让拳掌继续脱体向前漂。摆拳/掌掴保留更明显的屈肘横抽，正蹬脚尖上勾、足跟前送，鞭腿足背领先，踹膝落在低位。推搡从双肩并排推掌，兵刃连着持握的手。
- 保留识招版接触瞬间的彩墨与招架反馈，1.3× 默认节奏，以及按最终逐段列表播放的变式能力。不扩展正式装备功能或变式数值。
- 本轮仍是 Canvas 动作残影和整枚棋子短距前送，非完整人体动画。未拆分/重绘棋子，未恢复骨骼实验，未改变姿势数据、底座或阴影尺寸，视觉前送不改变占格与距离结算。

第九轮检查：放大查看九招的出手轮廓；144px 格宽检查敌方左侧正蹬及反向，验证三连命中/招架/闪开列表与无控制台错误。主脚本及新模块语法检查通过。用户否定此版视觉：封闭的肢体轮廓和折角像机械杆，腿部起点看起来从腹部长出。第九版不能作为已认可的动作方向。

第十版：用户允许更大胆的日式战斗动画风格，强调帅气。`variant=limb` 原位替换为「动画挥击」，移除虚构肘膝、平行管状轮廓与长肢体结构。使用渐变、尖梢和粗细变化的开放挥击笔触；起点从肩/髋视觉坐标下移到现有手/脚附近，并跟随棋子前送。近接触时才浮现简短拳锋、足跟、指痕或刀锋，不绘制一路飞行的独立拳掌图标。

直拳短锥、正蹬上挑后前送、摆拳厚弧、鞭腿长弧、戳眼双细痕、踹膝低位短推、双掌并列、掌掴扇形、刀斩半月，用招式轨迹区分而非假肢结构。保留接触彩墨和 1.3×，残影接触后 160ms 内收短消散，棋子前送幅度收小。未修改棋子图像、骨架或正式战斗结算。变式逐段播放能力保留。

第十轮检查：九招放大查看；正蹬敌方左侧实际 144px 格宽验证脚边起势，三连的命中/招架/闪开事件正常，浏览器无错误。脚本语法检查通过。用户认可这种挥击感觉，要求保留方向并进一步夸张、丰富各招特色。

第十一版：保留第十版动作路径与 1.3× 时序，扩大重招笔触，以暗色外沿、饱和彩色主笔、亮色内锋、细白留痕组成有层次的挥击面；墨屑和分叉笔丝贴着同一动作分布，不制造飞行物或新增攻击段。

- 刺拳：金橙短锥，命中四角脆闪；紧凑、不画大扇面。
- 正蹬：青蓝厚笔、脚跟压入、两道断开的压缩环。
