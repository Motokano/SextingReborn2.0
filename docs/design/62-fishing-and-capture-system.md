## 0. 实现约束：配置驱动，不增加物理模拟（2026-09-22，全篇优先）

用户明确要求控制钓鱼代码规模。本文的“真实”“实际”“受力”“下沉”“路径”等描述表示游戏状态必须一致且具有因果依据，不要求按现实物理公式推导结果。所有后续设计与实现遵循以下边界，不得以提升真实性为由另加物理模型。

- **配置负责差异**：鱼种、体型档、环境档、装备规格、动作与阶段，通过条件、权重、阈值、固定增减值和结果表表达。代码仅执行必要的查表、条件判断、简单加减/修正、上下限和有条件的随机选择。
- **状态负责连续性**：保留作业阶段、实际饵状态、鱼行为、少量有上限的进度/计数、部件状态及随机序列；不保存水下坐标轨迹、速度、加速度、绳段、力向量或历史物理采样。
- **世界时间只有整数 tick**：一个 tick 可包含有限决策节点；无小数时间、跨操作余量、秒级子步或按帧更新。读档和节点续接不能重复结算。
- **复用现有管线**：物品身份与装配依赖 k278 的共用契约；时间、体力、腐败、知识、加工、经济与存档接已有系统。钓鱼只补必要的配置、作业状态和接口，不再造平行系统。
- **实现规模有边界**：优先一个有明确阶段的作业流程与少量专用查表函数；不为每种鱼、每种饵、每个点位写独立算法，不为本玩法引入通用脚本语言、公式解释器或物理规则框架。复用配置预设与有限条件修正，不穷举所有装备组合的巨型表。

| 玩法环节 | 配置推算方式 | 不实现的内容 |
|---|---|---|
| 钓深、下沉、漂相 | 设定距离与点位配置作简单比较；浮漂/配重/钩型档位查得下沉阶段、停留水层与露漂状态；事件映射可见表现 | 浮力方程、流体阻力、连续沉降、线形变 |
| 抛投、收回与出线 | 站位—点位可达表、装备范围门槛、固定线长及每事件配置出线量/距离档变化 | 抛物线、三维路径、精确水下距离几何 |
| 发现、试探与入口 | 鱼种偏好、饵类别/气味、呈现档和环境修正阶段权重；有限状态推进 | 嗅觉扩散、摄食生理、鱼嘴几何 |
| 遛鱼、脱钩与上岸 | 鱼种/体型档读取行为参数，行为×策略更新收鱼进度、疲劳与挂牢状态，按条件转阶段 | 游泳动力、鱼体运动学、组织撕裂模型 |
| 承载、断线与磨损 | 行为、策略、竿性、泄力和障碍查得游戏负载值/档；与部件承载配置比较，按超载档更新有上限计数或直接损坏 | 弹性、弯曲、摩擦、瞬态冲击求解或现实拉力公式 |
| 障碍 | 点位/路线/水层标签匹配，按密度档与工具修正抽取接触事件，有限受阻阶段由动作推进 | 坐标碰撞、缠绕几何、逐根水草模拟 |
| 天气、水温和水层偏好 | 读取现有世界环境输入，以水域/点位配置查温感档与鱼行为修正；必要过渡用整数 tick 档位规则 | 热传导、能量收支、水流模型、重建逐 tick 天气历史 |
| 窝点、鱼群与恢复 | 按位置/鱼种汇总资源，邻接关系与条件表决定转移；固定档位的吸引、消耗和恢复，限定容量 | 逐鱼生态、连续气味场、繁殖或迁徙物理模型 |
| 捕捞与容量 | 作业档位、工具、鱼种/体型档查捕获与占用值，容量作为配额扣减，保留事件顺序 | 鱼体体积推导、网体变形、笼内空间排布 |

随机只用于配置允许的不确定事件，不替代前置条件，也不因查看界面而重复抽取。断线等已确定条件的结果须一致；后台状态不通过反馈泄露给玩家。调试重点是相同配置/状态/随机序列的可复现性、资源守恒、tick 单次结算及认知边界，而不是现实物理精度。

后续需要改变行为差异时，先修改配置；若现有状态无法表达，先说明玩家可见的决策价值，再考虑最小状态扩展，不默认增加新公式。下文所有“参数待定”均指配置值与有限规则待调，不授权开发额外物理模拟。

## 1. 定位与范围

- 参考《俄罗斯钓鱼4》的环境判断、鱼口、配装与准备深度，简化动作执行，保留决策。
- 钓鱼系统包括垂钓与捕捞。垂钓分饵钓（浮漂钓、底钓）与路亚钓；“雷强”不作为并列类别，雷蛙属于路亚拟饵。
- 系统只放在地表，首个水域位于基地附近，不放进地牢拖慢探索节奏。
- 核心关系：位置环境影响鱼的分布；时间、天气和温度影响活跃度与水层；钓组和饵的呈现影响具体鱼的反应。等待不保证上鱼。
- 不做新手教学、引导流程或第一竿保底。保留必要操作说明、可知参数与观察反馈，不推荐最佳配装。
- 本文内部鱼种与参数目录不等于玩家已知内容；未发现的鱼种不得在玩家图鉴中以名单或剪影泄露。

## 2. 地图入口与水域窗口

大地图设置一个类似 NPC 的水域交互格。交互后打开完整水域窗口；不在大地图逐格抛竿，不做自由坐标落钩。

窗口包含岸边站位与预设水中位置，两者分开、支持多对多关系：

- 在窗口选择岸边站位，切换消耗 tick，不返回大地图走格子。
- 站位通过可见性、距离档、可达表及路线标签影响观察、抛收和障碍处理；装备配置决定范围门槛，不计算几何角度与连续路径。
- 落钩位置具有水深、底质、水流、水草和障碍等环境；玩家在位置内选择钓深。
- 同一水中位置可从不同站位到达；鱼情和窝料绑定水中位置，换站位不复制或清除状态。
- 关闭窗口不重置鱼情、窝料、资源与惊扰。

### 2.1 观察

探查、探底、温度感知和记录是系统自带机制，不做独立探查物品。内置操作不代表拥有测量仪器，环境信息精度与探底动作以 §10.14—10.15 的后续确认为准。

1. 整体观察：消耗 tick，寻找明显环境及活动线索。
2. 定点观察：继续投入 tick，获得更细的信息，受通用经验及当地认识影响。
3. 查看已有记录：不额外消耗观察成本，显示记录时间，旧记录不冒充实时鱼情。

观察提供活动迹象与可知环境，不直接显示隐藏鱼群数量、准确咬钩率或最佳点位。迹象与真实状态保持因果一致，但一种迹象可以对应多种原因。

### 2.2 首个池塘（已确认）

三个岸边站位、五个预设落钩位置；站位坐标、连通与可达关系待绘制。

| 落钩位置 | 环境方向 | 决策用途 |
|---|---|---|
| 近岸浅滩 | 浅水、遮挡少 | 观察、小钩小饵 |
| 水草边缘 | 水草与开阔水交界 | 饵钓、路亚 |
| 密草缺口 | 障碍多、空间有限 | 防挂、配线、控鱼路线 |
| 开阔水面 | 障碍少、多水层 | 调深度、比较呈现方式 |
| 深水洼 | 较深、部分淤泥底 | 底钓、离底、打窝 |

首塘资源：鲫鱼、白条、鲤鱼、黑鱼、小虾、田螺。位置不绑定单一鱼种或必出物；鱼情动态变化。其余淡水候选鱼尚未定案。

初始基地仓库放置一套已装配的基础手竿钓组、少量鱼饵与备用件。面向鲫鱼、白条，部件可查看、拆换；大鱼可能超过承载能力。型号、数量、成本及发放/旧档规则待定，不代表本次已写入仓库。

## 3. 通用组合物品：兵器系统试验田

钓组是一件由真实物品组成的完整装备，不是物品 ID 清单或虚拟配装预设。

- 部件保留独立身份、状态与唯一归属，同一渔轮不能同时安装到两套钓组。
- 支持必要的多层装配与子组件；保存、拆装、搬运、入库、丢弃和读档不能丢状态、复制数量。
- 鱼竿自身是完整物品，首版不拆竿体或握把。
- 允许保存缺件的组合；开始使用时检查必要部件与接口兼容。
- 只提示无法使用的客观原因，不警告“配重过重”“子线太细”等性能搭配问题。可用但不合适的搭配通过实际表现体现。
- 整体占用背包空间，内部部件不重复占格；重量合计，具体占格规则待定。拆件必须有接收位置，不能静默丢物。
- 水边可换件、调参数、换整套；维修在基地设施。整套切换比逐件重装更省 tick。
- 共用部件、连接、归属、状态保存机制；钓鱼行为与未来兵器行为各读取自己的玩法配置，不强行共用伤害公式，也不为钓鱼新增物理求解层。

### 3.1 已确认的钓组结构

| 类型 | 组成 |
|---|---|
| 手竿浮漂 | 完整手竿＋主线＋浮漂＋铅坠＋子线＋鱼钩＋鱼饵 |
| 底钓 | 底钓竿＋渔轮＋主线＋铅坠或饵笼＋子线＋钩饵 |
| 路亚 | 路亚竿＋渔轮＋主线＋适用的前导线＋拟饵；是否必需前导线按结构确定 |

- 主线与子线分别搭配，使用固定长度成品；整件安装/拆下。不做裁线、剩余线卷或拼线；钓深是设置，不改变线的物品规格。
- 浮漂与固定重量铅坠独立搭配，不剪铅皮，不自动配重。描述下沉、露漂、漂移等实际现象，不给诊断。
- 基础饵钓首版单钩单饵，结构预留多钩。钩重复使用，饵在吃掉、脱落等事件中扣除，不按每次抛投强制扣一份。
- 雷蛙为自带配套钩的完整拟饵，内部钩的性能可参与计算；首版不要求另配普通钩。它的双钩不等于两条独立挂饵支线。
- 子线材质首版：尼龙、碳线、金属前导线。线径、柔软度、可见性、承载、耐磨和防咬切有不同作用；耐磨不等于防咬切。具体规格待定。
- 子线通过隐蔽性、饵的呈现及负载作用于具体鱼与环境，不做“细线统一增加咬钩率”。
- 泄力控制出线阻力；实际拉力超过部件承载才产生损坏，不是拧紧后自动断线，也不把鱼重等同拉力。主线、子线、竿、轮、钩按各自负载处理。
- 泄力与遛鱼策略职责分开：策略控制动作，不暗改玩家设置。1—10档及“松/中/紧”快捷操作曾作为建议，具体档位尚未明确敲定。

## 4. 垂钓、鱼口与反馈

流程：进入水域 → 观察 → 选站位与落钩位置 → 配装/打窝/设水层 → 作业 → 判断提竿 → 遛鱼 → 收获或放流。

- 鱼饵依据食物类别、大小、呈现方式与鱼的当前摄食状态发挥作用。一饵可吸引多种鱼，一种鱼可接受多饵。不显示针对鱼种的成功率加成。
- 玩家选择水层，实际能否到达/保持取决于钓组与环境。按米还是档位设置钓深、精度与快捷选项尚待定。
- 路亚选择搜索水层、慢/中/快收饵速度，以及匀速/停顿/抽动方式；拟饵限制有效组合。浮水雷蛙不能直接指定深水搜索。
- 等待分段推进游戏 tick；关键事件提前中断。普通等待结束后给观察结果，允许继续等待或调整。无现实等时等待要求。
- 咬口时暂停推进供玩家判断：立即提竿、再观察片刻、收回检查。选择不限现实时间；再观察推进有限决策节点，当前 tick 节点用尽才进入下一 tick，鱼可能吞饵或离开。
- 自动执行遛鱼，玩家根据提示调整稳妥遛鱼、强行收鱼、让线缓冲等策略；可用策略受装备限制，手竿无渔轮放线能力。
- 挂底/挂草依据运行路径、水层、钩的暴露和障碍判断；玩家可尝试放松、换角度、强拉、切线，动作受条件限制。防挂不等于免疫。

### 4.1 信息边界

观察阶段推测鱼种/体型；咬口主要表现为漂、竿、线变化；遛鱼通过冲刺、力量、露出水面逐渐提供线索；上岸后确认鱼种、重量、体长并记录。遵循认识前不暴露未发现内容的全局原则。

反馈描述现象，例如“浮漂轻点后恢复平静”“鱼追饵后离开”“钩饵裹着淤泥”，不直接宣布某件装备错误。一种现象不唯一对应一种原因；系统也不能无视实际状态随机播报误导文案。

### 4.2 失败与磨损

- 脱钩：鱼逃走，钓具通常保留，鱼饵可能损失。
- 断线：按实际断点及连接关系丢失下游部件；断裂的固定长度线件不可用，不做截短回收。不能写死每次都是子线先断。
- 部件事故损坏单独处理，不把整套统一判废。
- 每个部件保存当前耐久及必要损坏状态；整套不设重复耐久，不保存逐次磨损历史。
- 性能阶段变化：完好、磨损、严重磨损、损坏。同阶段内性能不随耐久连续变化；阈值和各部件效果待定。事故可直接导致损坏。
- 阶段从耐久与规则计算，不重复存储。可维修耐用品消耗材料和 tick 修复；首版不因维修永久降低上限。鱼线等更换、饵料补充；完整可维修目录待定。

## 5. 打窝

- 钩饵与窝料分开；首版窝料为固定配方成品，不自由混配。
- 玩家选窝料、位置、份数及补窝时机。直接投放与饵笼随钓组投放两种方式，直接投放受距离限制。
- 逐渐生效，受种类、用量、水深和水流影响，只吸引附近已有资源，不刷新鱼。过量可能降低鱼吃钩饵的意愿。
- 不显示聚鱼进度条，通过鱼活动迹象反馈；具体吸引范围、消耗与衰减档位配置待定，不计算扩散场。

## 6. 主动捕捞

捕捞为独立现场玩法：观察 → 选位置/方式/装备/投入档位 → 支付资源和 tick → 一次结算。撤回“放置后离开、以后回来收取”的被动布设方案；过程中不插入分段操作。

| 方式 | 组合结构与决策 |
|---|---|
| 网捕 | 网体＋配重；网目/容量由网体决定，选择适用水层与范围 |
| 笼捕 | 笼体＋可替换入口＋诱饵；容量由笼体决定 |
| 采捕 | 首版工具为完整物品，针对位置与贝螺等目标作业 |

- 投入档位：短时、标准、长时；开始前明确显示 tick 与资源成本，数值待定。
- 工具磨损、耗材扣除；收益受当地资源、活跃度、匹配及容量约束，不保底、不无限线性增长。
- 展示渔获与作业迹象，例如水草混入、诱饵被啃而空笼、容量已满，不直接诊断最佳方案；记录支持后续经验整理。
- 捕捞与垂钓共用同一水域资源，按一致顺序结算扣减，不重复捕获同一份资源。

## 7. 鱼情、资源与存档

- 水域鱼种范围相对固定；具体位置、水层、活跃状态随条件改变。观察短期内有参考价值，变化有迹可循。
- 按水中位置、鱼种记录汇总资源，不逐条模拟/保存水中鱼。
- 固定环境、鱼种范围和基础丰度保存在配置；存档保留必要的丰度变化、惊扰、窝料和更新时间。具体字段是待设计契约。
- 按经过的游戏 tick 延迟更新恢复、衰减；恢复默认后可清理变化记录。恢复较快的惊扰与恢复较慢的资源分开；不用现实离线时间，也不通过退出重进刷新。
- 即时鱼情计算与随机状态的持久化需保证读档连续性；具体随机与事件快照方案待设计。
- 正在咬钩/遛鱼的个体只保存继续事件所需状态，精确存档时机待定。
- 上岸收取后，逐条生成鱼获实例，保存鱼种、实际重量、体长、鲜度；卖价、负重、加工接既有物品管线，鱼种与体型差异按配置映射，不增设物理公式。
- 加工进入共用食材体系，鱼种决定产物，不所有鱼统一掉鱼头/鱼骨等；与现有原料映射待整理。
- 允许立即放流；钓获纪录仍保留，返还资源，不清除惊扰，不持续追踪个体身份。
- 捕鱼数量较大时的鱼获生成、背包容量不足处理、虾螺计量仍待细化，不自动把逐条鱼实例规则扩展为每只虾独立占格。

## 8. 认知、熟练度与 tick

- 替代旧“熟练度直接增加成功率和稀有鱼概率”的设计。
- 通用熟练度改善观察辨认与动作执行；鱼种、水域经验补充具体认识。陌生水域仍需调查，等级不改变隐藏鱼种存在情况。
- 新观察、试钓、调整、失败、钓获及捕捞都可积累相关经验；重复读取同一信息不能刷经验，增长曲线与去重规则待定。
- 记录事实：位置、时间、已知环境、配装、水层、结果。系统再基于实际证据逐渐形成带不确定性的判断，并随新证据修正。
- 不能读取隐藏鱼情来伪装经验推理；一次没口不等于没有鱼，一次钓获不等于天气规律。
- 一切作业时间接现有 tick；观察、站位移动、换件、换套装、挂饵、打窝、控饵、等待、提竿/遛鱼、捕捞等成本分别配置。浏览既有记录不另收观察成本；面板开关沿用或调整既有通用规则须在接入时核对。

## 10. 鱼口与作业细化（后续讨论已确认，待实现）

本节补充前文；具体概率、阈值、时长及程序状态机尚待设计。

### 10.1 水下事件与可观察信息

- 基本过程：发现饵 → 靠近 → 试探 → 吞咬/带走 → 挂牢或吐饵、离开等结果。允许跳过、反复、中止，不按固定脚本完整播放。
- 发现与靠近阶段可以无可见信号；试探、吞咬经钓组、水流、线松紧等传到浮漂/竿梢/鱼线，形成实际表现。
- 提竿按当时钩饵与鱼嘴状态、钩型、受力及动作执行判断；没有固定的必胜提示。
- 水流、接触水草也可造成动静，必须来源于真实事件，不随机插入假提示。普通风浪不应频繁触发暂停。
- 无口等待结束后，描述可见钓具表现和环境变化；没有变化就说明没有明显动静，不编造线索、不推荐改装。
- 经验可改善辨认与带不确定性的解释，不直接读取隐藏失败原因给出结论。

### 10.2 饵、空竿与再次抛投

- 钩上鱼饵只有“还在/消失”两种状态，不模拟残饵大小、受损程度或对应吸引力变化；此前残饵描述示例不再适用。
- 鱼饵消失需补饵，收回检查才能确认；等待时不自动揭晓被悄悄取走的饵。
- 空竿后收回并检查钩饵。有饵可重新抛投，无饵需补充。短暂挂住后脱钩可造成局部惊扰，不按捕获扣除资源。
- 再次抛投沿用位置、钓深及呈现设置，可先调整；正常消耗 tick，鱼情不重置，不以重新开始计时保证上鱼。

### 10.3 窝点、惊扰与单竿

- 窝料吸引附近合口的鱼逐渐靠近；种类、水流、深度及位置影响作用。鱼可只吃窝料，不吃钩饵。
- 加量主要增加食物量与持续时间，不无限扩大吸引范围，也不保证增加鱼口。
- 每处窝点独立持续；换饵、换组、换站位、离开或关窗均不清除。存读档保留，按游戏 tick 扩散、取食、衰减；现实时间不单独消耗窝料。
- 鱼种警惕倾向与局部临时惊扰分开。抛投、遛鱼、强拉挂物、捕捞等实际行为可以产生不同强度与范围的惊扰。
- 不同鱼种可能减少试探、离开或换层，不统一扣咬钩率；一次空竿不能惊走整塘。
- 同时只使用一套垂钓钓组，不做多竿并行。换组、换站位、关闭窗口或开始捕捞前先收回/结束当前钓组作业；战斗、离场等强制中断细节待定，不能用关窗绕过已挂鱼的处理。

### 10.4 个体与遛鱼

- 同种鱼体型影响钩饵适口、挣扎、操作空间与时间、负重/价值/加工；小饵不绝对排除大鱼，不把大鱼一概设为更警惕。
- 鱼可冲向开阔水面、钻障碍、下潜顶住、转向摆头；行为由鱼种倾向、体型、体力和环境共同决定，不同阶段可切换。
- 挣扎和对抗消耗鱼的体力，低强度对抗可部分恢复。放松泄力缓冲负载但可能延长过程；强拉加快靠近但增加损坏风险。
- 鱼进入岸边可收取范围且挣扎已可控制时自动上岸，不要求体力归零，不另做反应小游戏。精确体力不显示，以冲刺缩短、收线顺畅等现象表达。
- 关键行为变化、出线/竿弯/收线明显变化或一段动作结束时暂停；其余按当前策略自动推进 tick，不逐回合要求点击，也不保证事故前必有预警。
- 遛鱼接现有角色体力体系，按负载与策略消耗；体力不足限制高强度动作，不另设钓鱼体力条。
- 决策暂停时可主动切线止损。只切岸边可接触线段，不能遥选水下子线断点；可列出确定会失去的实际部件。按连接损失，不计成功捕获，惊扰保留。

### 10.5 待处理鱼获

- 上岸后可查看鱼种、重量、体长及预计占用，再收下或放流。
- 背包不足时保留待处理结果，允许整理背包；整理沿用现有 tick 规则，不静默丢物。
- 当前结果未处理完，不允许下一次作业；捕捞批次使用同一待处理环节。
- 待处理状态需要存档，不成为无限额外仓库。其中鲜度随 tick 的衔接、部分收取/放流等具体接口待定。

### 10.6 完整流程讨论样例与界面原则

布局确认（2026-09-21）：采用试作 A 的三分区同屏布局，作为正式钓鱼窗口的交互基准；保留岸边站位地图标记与当前站位提示。B/C 仅作历史试作对照。此决定确认界面方向，不代表试作中的脚本事件和样例数值成为正式玩法规则。

数值操作尽量避免手动输入，降低非法数值和误操作风险：有连续范围的设置使用带上下限、固定步长的滑块；固定方案与投入档位使用选项；物品数量使用受库存与容量约束的加减按钮或预设数量。控件只提供当前可用范围，执行与结算层仍需校验数值类型、范围、步长和资源约束，不能只依赖界面限制。钓深滑块表示钓组设置，不泄露未探明的实际水深；当前试作的 0.2—4 米范围不是所有正式钓组的统一上限。

已讨论通过的样例：取初始手竿和蚯蚓 → 进入首塘选站位 → 整体/定点观察水草边 → 近底作钓并打窝 → 无口时根据漂移收回检查、调整深度 → 再抛 → 轻顿后继续观察 → 后续下沉横移时提竿 → 鱼向水草移动时决定强收 → 控制后上岸 → 收获与事实记录。

该样例是假设场景，用于检查选择与反馈，不是强制教学、固定鱼口序列、首竿保证或已运行的测试。窝料假设由玩家另行准备，不加入已确认的初始仓库清单。手竿不提供渔轮放线动作。一次鲫鱼钓获只能留下事实，不立即产生稳定习性结论。

控件允许解释必要含义，例如“钓深以水面向下计量”；不替玩家选择数值、装备或位置，不恢复首次教学流程。

### 10.7 仍待确定

首塘站位图、环境与鱼种参数、鱼口计算及事件映射、暂停阈值、tick 成本、装备/饵/窝料目录、收益与加工、磨损阶段数值、恢复速度、存档具体字段及强制中断细节尚未敲定。可达判断、玩家主动退出与读档连续性已在下节补充方向。上述玩法确认不代表参数已确认或功能已实装。

### 10.8 对比场景确认

- 同位置、同装备守底无口，鱼可能已主要活动于中层。有实际视野/水体/角色能力支持时可以观察到较浅鱼影；无法看清时允许通过改变钓深试钓。不为引导换层凭空生成鱼影。
- 只改钓深后的钓获作为比较证据；记录可以逐渐认识到活动水层会变化，不能一次就断言天气导致上浮。
- 基础手竿意外挂大鱼时根据实际负载、鱼行为与玩家策略结算，不按推荐体重直接判必断，也不保证稳妥策略必然成功。没看清的逃鱼只能留下拉力/行为记录，不能泄露具体鱼种。
- 窝点有活动却无口，可以来自鱼只吃窝料、钩饵不合适、位置/水层或警惕等不同原因；活动不保证是目标鱼。换层、换钩饵、暂停补窝用于试验，结果不直接证明唯一原因。
- “窝点中心/边缘”呈现选项仍为候选，不引入自由落钩，也不视为首版必做。

### 10.9 负载、断线与文字反馈

- 鱼种与体型档查得行为力度配置，结合疲劳阶段、当前行为、玩家策略、竿性、泄力及余线状态，查表得到本节点的游戏负载。竿弯是由该状态映射的表现，不模拟竿体弯曲或现实拉力。
- 当前线件承载读取规格与磨损阶段对应的有效承载配置；不推导材料强度，不增加隐藏的随机结节质量。
- 游戏负载未超承载时不因纯拉力断线；轻度超载按配置增加有上限的过载计数，卸载节点按配置减少，达到阈值才损坏；严重超载可按配置立即断裂。只按事件节点更新计数，不积分真实张力或计算短时冲击公式。
- 泄力档对应出线门槛和负载修正，不是绝对负载上限；猛烈冲刺、余线耗尽、受阻使用各自事件修正，不计算连续瞬态峰值。线径不直接等于强度，鱼重通过体型档取配置，不直接换算成拉力。
- 主线、子线独立判断；摩擦磨损、障碍割线与咬切另行处理，不写死子线优先断。
- 相同配置、状态和事件序列得到一致断线结果，不额外掷随机断线率。不确定性来自配置允许的鱼行为与接触事件及玩家掌握的信息。
- 只用文字描述受力，不显示负载条、精确实时拉力或距断裂的余量。装备规格和损伤只有具备认知、标记或检查依据时才展示，不直接公开后台磨损阶段。
- 可描述竿身弯曲、持续出线、线骤然绷紧等；经验改善辨认，不直接宣布“即将断线”或给操作指令，突发损坏可无预警。

### 10.10 鱼钩、提竿、竿性与抛投

- 按入口状态、钩型/尺寸档、提竿档及竿线状态修正查挂牢结果；不推导传力与刺入力公式。挂牢程度与钩本身耐久分开。
- 遛鱼中的摆头、松线、持续拉力影响脱钩；冲击过大可撕裂挂钩处、使钩变形或导致线过载，不是提得越猛越好。
- 提竿力度为轻提、正常、有力三档，可下竿前设置默认、咬口时临时改选，不使用力度条。实际效果由竿、线状态、钩与角色执行共同决定。
- 竿性简化为软/中/硬，影响缓冲、动作传递与控鱼，承载独立；软竿不等于弱竿，硬竿不自动更强。
- 手竿以竿长、主线长度判断可达范围；带轮钓组结合整套抛投性能判断。选位置显示距离和可达性；换站位可缩短距离，长竿不直接加鱼口或承载。
- 可达位置稳定抛投成功，消耗正常 tick，不做瞄准小游戏或随机偏移。熟练度具体执行收益待细化，不靠随机投错点体现成长。
- 线松紧为内部状态，受收放线及鱼移动影响；通过提竿、泄力、策略间接干预，不增加张力按钮。描述松垂、重新绷紧等可见现象。

### 10.11 补给、装饵与退出连续性

- 基础饵可购买并接入适用采集来源；符合条件的小鱼小虾可作饵；固定配方窝料可买或按已知配方制作，拟饵首版购买获取。具体商店、物品、价格待定。
- 小鱼小虾整件作饵，保留原实例身份、大小、鲜度，不能同时留在背包；未消耗可卸回，装卸不刷新鲜度。被吃掉/脱落时消耗；不做切片或活饵健康度系统。
- 无挂鱼时关闭窗口先收竿并消耗 tick；遛鱼/挂底时先完成事件或切线才能游戏内离开。
- 退出游戏可保存继续，不强制失败。保存当前钓组、鱼状态、窝点、待处理事件；读档不重新抽鱼种/体型，不重置挣扎、过载等风险。
- 精确序列化字段、随机状态、版本迁移与异常退出恢复仍需技术设计，不能把上述连续性要求当成已实现。

### 10.12 主动捕捞与窝点衔接

- 首版一次作业只选一个预设水中位置，不跨多个点布网；工具、档位决定该位置内的作业范围和效率。
- 网目筛选可捕体型，笼口/诱饵影响进入，采捕匹配当地环境；不超过当地资源与工具容量，统一扣减并产生惊扰，长时不简单等于短时乘倍数。
- 可捕到尚未认识的水产，实际获得后形成认识；不要求先解锁鱼种，不显示完整潜在掉落表，作业前只给规格、成本及已知鱼情。
- 窝料作用于位置内鱼群聚集，对后续垂钓和捕捞都可产生影响；笼内诱饵属于本次投入，主要影响靠近和进入笼具。
- 两种吸引不简单叠成固定收益加成；基于同一鱼群状态与不同作用环节计算。捕捞后剩余窝料持续存在，作业惊扰也影响后续鱼情。

### 10.13 捕捞容量、资源与损坏结算（已确认）

- 工具内部按配置的渔获容量占用值限制装载，界面以容量等级描述，不计算物理体积或要求玩家逐件换算。
- 鱼按鱼种与体型档查固定容量占用，小虾、田螺按批次查占用；不由重量、密度或体形推导物理体积。工具容量是玩法配额，与鱼获进入背包后的占格规则分开。
- 装不下的鱼不截成部分渔获，不扣对应资源。网目/笼口的进入条件与剩余容量是不同约束。
- 网目按体型与体形影响留鱼，小鱼可穿网，大鱼可能挣脱或损坏工具；笼口限制进入，结构和工具状态影响留存。诱饵不保证单一物种，允许混获，不提供精确指定鱼种/重量筛选。
- 穿网、未入笼、容量不足、逃逸不按捕获扣资源，可产生惊扰或损伤；最终进入待处理渔获时扣除，放流时归还，读档不能重复扣除。
- 作业中工具损坏按事件顺序计算已有捕获、逃逸及最终留存；可保留部分收获，严重损坏停止后续捕获，不一律清空。
- 无论中途满载或损坏，按已选投入档位支付 tick 与耗材，不自动退还未带来额外收益的时间；工具损伤保存。
- 内部按整个作业期间的时段、鱼情、窝料、诱饵、容量和惊扰变化计算，不只读取起点/终点，也不做固定时长收益倍率。对玩家仍一次提交、一次结算，不新增过程弹窗。

### 10.14 天气、感知与设置的边界（已确认）

> 2026-09-26 后续决定优先：采用 [钓点气温接入](fishing-temperature-integration.md)，统一环境输出五档气温，钓点查配置调整遇鱼机会。不再执行下文水温过渡、温感存储方案；本次不调整水层偏好，其余认知边界保留。

- 同地区共用天气与昼夜，开关钓鱼窗口不重新生成。水温随游戏时间与天气逐渐变化，水深、遮阴等使局部环境有差异；鱼按习性响应，不统一套雨天增益。
- 如需温度过渡，仅保存温感档、更新时间及必要的有界计数，用配置过渡时长更新。读取现有可用环境输入，不新增热学模型或重建天气历史；离开期间按配置的粗粒度恢复/衰减补算，不将返回时天气当作整段历史，也不据此生成未观察的历史见闻。
- 玩家没有温度计，不显示精确温度；可通过触水等实际行为获得冰凉、偏凉、温热等感受，不能触水就不能凭空获知该处水温。
- 目视水深只提供浅水、较深、看不见底等有依据的描述；探底可进一步形成水深估计。水流、底质、障碍只报告可观察/可探查信息，不直接显示后台状态。
- 经验提高辨认能力，不凭空提供仪器精度；已获得信息标注时间，未获得内容不提前公开。
- 玩家设定与实际状态分开：浮漂钓可调整钩饵距浮漂的距离，并从漂相和探底判断触底；底钓结合配重下沉与受力迹象判断，不自动揭示准确水深；路亚选择水层意图，实际水层由拟饵与操作决定。
- “近底”需要探查依据，系统不得自动精准找到未知水底。通过线长及触底试验得到的水深估计是合理测量，不等同于后台数值直读。

### 10.15 钓鱼窗口内的探底动作（已确认，本段定案）

- 以当前钓组能够实施的探底行为为依据，不是任意装备都能成功；例如浮水雷蛙不能直接测出深坑水深。具体执行与兼容规则待实现设计，不自动生成永久装备物品。
- 输出水深估计与底部迹象，例如“反复试探后，水深估计在两米左右”“触底清晰，拖动有细碎磕碰感”“收回时带着水草”；示例并非固定必出提示或数值。

### 10.17 时间粒度、暂停与窗口试作（已确认方向）

- 世界时间保持10分钟/tick，采用作业时段包含多个事件决策；试探、吞饵、提竿与短促挣扎不逐按钮额外支付一个完整 tick。动作的体力、磨损、饵料消耗独立结算。
- 长时间遛鱼继续推进世界时间；保存内部进展与已结算 tick，不能无限停表或靠退出/读档逃成本。具体时段映射待定。
- 继续观察的机会由当前事件配置的有限节点决定，每次推进状态；鱼可吐饵、离开，动静结束后回普通等待，不暂停在同一状态刷信息。节点耗尽后继续作业须进入下一整数 tick。
- 垂钓长段等待逐整数 tick 推进，可感知且需处理的事件提前中断；当前已开始的 tick 完整结算，未开始的后续 tick 不扣费，不折算小数。可提前收竿，隐藏鱼口不触发全知通知。捕捞仍支付整档成本、一次结算。
- 普通变化写现场记录，关键变化/动作段结束暂停；连续现象合并，不逐条刷屏。暂停本身不代表确认有鱼或危险。
- 窗口三部分：中央水域图；位置与已知钓组/设置/调查操作；现场记录与决策按钮。尽量不反复弹小窗口。垂钓、捕捞共用位置记录，准备项按模式切换。
- 界面试作入口：[fishing-window-prototype.html](../../tools/fishing-window-prototype.html)，三种布局 `?variant=A/B/C`，默认A三分区。沿 tools 独立预览惯例，不接正式地图或存档。使用独立内存中的现有 GameTime；成本、鱼口和捕获均为样例，未实现完整生态、装配、磨损和资源结算。试用说明与待选结论见 [NOTES](../../tools/fishing-window-prototype-NOTES.md)。试作不等于正式功能验收。

### 10.18 后续确认的认知与系统衔接

- 原始鱼获加工交给现有烹饪管线，不另建钓鱼加工系统；基地处理、固定份量、保留来源鱼种、同批按来源/食材类别合并、零头损耗、鲜度不刷新为衔接要求，具体规则由烹饪统一设计。
- 鱼获贸易接现有经济，腐败接现有腐败系统，不另建价格、保鲜或鱼护体系。地表不设计危险敌人袭扰，世界状态随作业 tick 正常推进。
- 鱼种无等级锁；钓法通过认知获得，工具按实际兼容与角色必要条件使用。共用钓鱼生活技能，水域/鱼种知识互通，具体操作经验分别积累。
- 纪录仅列已认识内容：首次、最大重量/体长及当时条件，区分垂钓/捕捞，放流计入，出售不清除；不展示未知鱼种占位/总收集数，不另加纪录奖励或排行榜。
- 上岸不自动鉴定未知鱼。未知个体先以外形描述记录，后来辨认才在证据支持下关联旧纪录。重量/体长无测量依据时只能估计，真实数据留在后台。
- 固定地形环境长期可参考，首版不做水位涨落/水草季节变化。鱼情记录保留调查时间，不因后台变化自动宣告失效。
- 观察读取可感知实际状态，不重复随机抽线索；重复读记录不花调查成本，实际观察仍花 tick，不保证新发现。
- 捕捞前检查工具、耗材、体力、位置，不满足不执行不扣费；预览投入不预告收益，背包不足允许进入待处理结果。工具按自身方式判断可达，首版不船钓、潜水、涉水移动。
- 配装方案不占真实物品，只保存角色已知特征和设置，可指向原部件身份。缺件不自动购买/拆其他套装；替代品按已知信息筛选，不利用隐藏属性自动鉴定。
- 性能面板只汇总有来源的知识，未知承载/材质/耐久不揭露，不给整套评分或最弱部件诊断。依据不足的重量/范围给估计；未知可达性可通过试投认识，不等于对确定可达的位置随机投偏。
- 连接关系与收纳分开；允许子线＋钩＋饵整体拆装。更换先检查兼容、接收位置与成本，成功后一次转移，失败保持原状不扣费，存档不保存半完成操作。
- 首塘站位细化：平缓土岸接近浅滩/开阔水面；芦苇岸边接近草边/密草缺口；较陡岸边接近深水洼/开阔水面/草边。具体可达表待定。玩家首次只见可感知岸线及方位名，内部“深水洼”等名称不提前泄露。

### 10.19 首塘水产行为与鱼口过程（讨论确认）

- 六种水产采用游戏行为设定：鲫鱼偏平静近底和草边，可用蚯蚓、谷物饵；白条偏中上层，可截食下沉中的饵；鲤鱼偏安静底层，强调近底呈现与窝点准备；黑鱼偏水草和遮蔽物，可用小鱼虾或拟饵；小虾用笼、合适的小网捕捞；田螺在可接近浅水底部采捕。偏好不是限定，同点允许多种水产，迹象不直接对应鱼种。
- 鲫鱼作为共用鱼口过程基准：附近活动 → 发现并接近饵 → 试探 → 饵入口 → 提竿或错过。允许跳过、反复或离开，不是必走流程。位置和钓深影响接触机会，饵与窝料影响接近和摄食，子线/钩/饵影响呈现与入口，浮漂/配重影响信号传递。后台碰饵不保证玩家看见，收回才确认钩饵状态。
- 自动暂停依据可感知变化而非后台入口状态：随波轻晃、孤立轻点仅合并描述；连续点动、明显下顿/回升、持续偏移等中断等待；持续没漂、明显横移或绷线也暂停并据实描述。碰线、挂草、水流同样可能触发，暂停不保证可成功提竿。玩家可主动提竿或收回；继续观察推进真实过程，光线与配装影响可辨性。阈值待调试。
- 提竿依次考虑钩的位置、动作传递、刺入与挂牢。轻提/正常/有力分别影响实际作用力，不是越强成功率越高；松线、竿线特性、钩大小与锋利度等参与。反馈仅描述可感知阻力和结果，不直接诊断提早或力度不足。
- 保留下沉过程，目标钓深不是瞬间抵达；白条可在途中截食或啄食，钩饵过大可能有动静却难挂住。下沉计入抛投后的内部过程，不独立逐次扣一刻；可感知事件能够中断。
- 窝料影响附近鱼的接近与停留，不凭空生成鲤鱼；进窝不等于吃钩饵，窝料会被消耗，连续补窝不保证增益且投放可惊扰。鲤鱼不强制打窝或固定等待时长。气泡等不证明鱼种、鱼数或已进窝。
- 路亚采用匀速收回、停顿收回、小幅挑动三种控饵方案，动作由系统执行；拟饵决定响应和适用设置。首版浮水雷蛙使用控饵选项替换不适用的钓深滑块。发现、跟随、攻击不保证入口；炸水等可感知迹象暂停但不揭晓鱼种。途中事件中断收回，无口完成后回准备状态；中鱼沿用提竿、承力、遛鱼规则。
- 用户明确要求路亚体力消耗较高，明显高于普通饵钓，以持续抛投、收线和控饵的实际作业为成本来源；接入共用体力与 tick 系统。具体成本、动作差异及不足时处理待细化，不因浏览选项或事件暂停期间现实等待扣体力。
- 小虾的投入档位影响笼具诱捕时间或网具作业次数，受资源与容量约束；田螺投入影响搜索时间与范围，容易采到的部分减少后边际收益下降。长时不保证同比增产，各档不保证收获；共用水域资源，结算仅展示渔获与作业迹象，不断言资源归零或推荐最佳工具。

### 10.21 自主摸索与知识展示（2026-09-22 确认）

- 钓鱼知识通过玩家自己的观察、试验与作业证据形成，不以他人传授解锁，不采用前述讲解或阅读直接授予方法的建议。达到现有认知系统的认识条件后可显示正式名称，不再额外要求他人、书籍或标识提供术语。认识名称仍不等于知道全部性能。
- 初始允许普通人能理解的尝试：查看现成钓组、检查连接、尝试挂食物、将钩线放入水中、观察、抬竿和收回检查。操作能力与原理理解分开，不要求先解锁专业知识才能尝试；不直接赠送调漂、探底、配装与鱼口判断知识。
- 浮漂作用通过牵线时的联动、作钓时的动静与可见结果形成证据。深度调整初期可尝试移动浮物，只有实际可见或可支持的证据才揭示其作用；滑块可先用靠近/远离钩端描述，精确长度需测量或标记依据。理解距离作用不揭示当地水深。
- 探底由观察触底、改变间距、提放与阻力对比形成方法认识；单次侧躺或拖滞不足以证明到底。掌握后合并为“试探水底”便捷动作，仍需逐点调查并允许失败或不确定结果。
- 基础提竿随时可尝试，自动暂停依可见变化，不要求先有专业知识。空竿不能自动证明提早或解锁失败原因；不同经历中有依据的结果支持鱼口经验，但不提示最佳时机。
- 挂饵手法、饵料偏好和鱼种辨认分别积累。初始可从形态上可挂的持有物品尝试，不推荐目标鱼；依据实际结果描述牢固、掉落、遮住钩尖等。饵缺损不直接证明某鱼摄食，未辨认鱼的经验不授予名称或完整食性。
- 初始可向选定水面撒固定分量食物，立即扣物并形成真实窝点；可见接近、啄食等支持诱鱼认识，隐藏聚鱼状态不授予证据。掌握后整理为便捷投食操作，不自动获得成品窝料认知或配方；窝点关窗后保留，记录不展示隐藏余量与鱼数。
- 拆装先通过检查认识连接，明显扣件可尝试，系结等操作需对应方法；拆下不等于会装回。连接方法尽量复用于其他组合物品，会换件不等于理解配装效果。遵守接收空间、条件校验与原子转移规则。
- 路亚工具操作与引逗原理分别认识；通过实际转动、收线、可见拟饵运动及可见追逐/攻击积累证据。可尝试连续收、停顿、轻挑，掌握后整理为控饵方案；不要求先练满饵钓。首次尝试即按实际动作消耗体力。
- 捕捞独立学习：网具可尝试捞取，笼具可检查开口、放食物与投放回收，采捕工具可用于可见可达浅水的拾取。收获不等于理解全部原理。初学也按固定方案一次结算，不拆成重复点击小游戏；掌握后整理为位置、档位与一次结算操作。
- 沿用印象、摸索、理解的证据阶段；简单而直接可见的关系可一次理解，复杂规律需不同经历支持，不统一规定成功次数。重复查看同一结果不积累，失败只有提供新证据才增进认识；有效练习的熟练度增长不自动授予知识。
- 使用既有见闻记录，不另建知识树：区分事实、推测、已理解原理，保留必要时间地点来源；提示具体见闻与理解，不显示知识点奖励。未知知识不预列清单或灰色按钮。过去鱼情不随后台变化自动更新，便捷动作按已知状态出现。具体证据条件与实现仍待完成。

### 10.22 障碍运算与引擎接入要求（2026-09-22）

状态：障碍玩法与运算方向已讨论确认，具体配置契约、状态表和正式接入尚未实现；当前钓鱼窗口仍为脚本试作。实现严格遵循 §0，无障碍物理模型。

#### 配置与玩家认知

- 实际障碍以预设水中点位为主配置，必要时在“岸边站位 → 水中点位”的路线增加差异。配置表达类型、密度、所在水层及阻挡特征，不制作逐根水草的精细碰撞地图。地形固定，不因每次抛投重新生成。
- 点位环境与回收路线共同决定接触机会：同一位置从不同岸边回收可能经过不同障碍；能稳定送入不保证能顺利收回。
- 后台配置与玩家记录分离。玩家仅看到可见草茎、实际拖滞、回收带草等有来源的事实；记录保留点位、必要的站位/方向和时间。一次受阻不揭晓全部障碍，不直接标注隐藏风险等级。

#### 分段计算与随机性

1. 根据点位、站位路线、钩饵实际水层及当前动作筛选可能接触的障碍。设置钓深不等于实际水层；遛鱼时鱼的移动可改变接触范围。
2. 点位与路线配置障碍标签、密度档和经过程度；匹配水层与工具后查接触权重，有限随机选择接触事件，不采样水下坐标。标签无交集则不接触，配置为必经完全阻挡时直接接触；只调整表值，不增加路径/碰撞公式。
3. 接触不等于挂死：障碍类型、钩尖暴露标签、路线与动作档查结果表，得到擦过、带草、拖滞或缠绕。负载断裂沿用 §10.9 的承载与过载计数，不引入摩擦系数、缠绕几何或无条件失败骰。
4. 形成缠绕后保存有限受阻阶段及必要计数；动作查转移表推进脱开、保持或加重，并更新负载/损伤。不是每次“再试”都重抽初始脱困概率；按整数 tick 作业与体力配置支付成本。

#### 受阻操作与信息反馈

- 持续受阻时只描述可感知方向、阻力与运动变化，看不清时不直接指出障碍种类。提供放松后再试、加力拉回、切线放弃；切线按实际断开位置处理下游部件损失。
- 解除后收回检查，才能确认附着物、饵及部件可见状态。失去阻力不直接证明脱钩或断线；失败原因只有在痕迹和角色认识支持时才能推测，证据不足保留未知。
- 阶段性磨损仍在后台计算；可见裂纹、起毛等按事实呈现，细微问题需检查。未发现明显异常不等于完好，使用异常不自动揭示故障部件或精确性能损失。

#### 已有基础与待补实现

- js/hunting.js 已有按点位保存种子的随机序列及分阶段作业状态；可参考其组织方式，不把狩猎专用接口视为已经存在的通用障碍模块。
- js/survival.js 的 advanceTick 接入世界时间；钓鱼时间与体力通过现有作业/消耗路径结算。时间强制对齐整数 tick，短动作在当前 tick 的有限决策节点内处理；不累计小数时间或跨操作余量，详见 §10.24。
- js/save-system.js 已为狩猎提供状态保存、校验及恢复。钓鱼须新增自己的快照、校验和恢复接入，保存当前点位/路线、作业阶段、接触结果、缠绕与受力进展、关联部件、已结算时间及随机状态。字段以正式契约为准，不重复保存可推导的权威数据。
- 保存恢复不能重抽已经发生的接触结果或重置过载/损伤；相同存档和后续动作应保持过程连续。关窗、读取记录、刷新显示不能推进随机序列或产生学习证据。
- 所需新模块为障碍配置、接触与状态推进计算、认知反馈、时间/体力与组合物品接入、存档契约。采用少量离散状态和数值运算，不要求物理引擎或逐帧绳索碰撞模拟。
- 后续验收覆盖：无交集不接触、必经阻挡、不同路线/水层/钓组的差异、持续缠绕与损伤、切线损失、时间体力不重复结算、存读档连续性、未知障碍不经界面和日志泄露。以上是待实现验收要求，不是已通过检查。

### 10.23 挂饵腐败与空钩（2026-09-22 确认）

- 挂饵从库存转入固定一份真实物品，保留已有腐败进度；挂上、取下、换装和关窗均不刷新鲜度，不同时保留一份可食用或可再次装配的库存副本。可回收的完整饵取下后保留原状态。
- 严格接现有腐败机制：挂饵腐败到期直接消失，钩上实际状态变为空钩。不新增腐败饵物品，不保留腐败后的气味、食性或附着性能；此前相关建议撤回。拟饵为耐用品，走适用的磨损规则。
- 腐败消失提示服从可感知范围：钩在岸上可观察时立即提示钩饵腐坏无法使用；钩在水下时不自动提示、收竿或中断等待，收回检查后只提示“钩上的饵已不见了”，不据后台原因断言腐败、被吃或脱落。背包、装配详情及日志也不得间接泄露水下挂饵状态。
- “在／不在”表示实际挂饵存在性，与该物品自身的腐败进度及玩家是否知道分开。首版不建立半份饵状态。腐败、被吃、脱落须保证同一份饵只移除一次；实际移除后不再应用该饵的作用。
- 允许主动空钩下水试探或作业；失饵后继续按空钩状态推进，不自动扣备用饵补挂，收回确认后由玩家决定后续操作。当前试作以无饵禁止抛投的判断不代表正式规则，后续实现须调整。
- 空钩不将中鱼可能直接设为零：移除的是原饵的吸引与摄食作用。裸钩是否引起试探由鱼的反应、钩外观与运动决定；意外挂获需真实接触与拉动条件，不能按每次空钩等待无条件抽取收获。拟饵本身具有呈现作用，不归入普通裸钩。
- 主动咬钩与意外挂获保留各自实际原因和挂钩状态，中鱼后进入共用承力、遛鱼与收获流程；未知原因不直接透露给玩家。具体接触条件表、参数及事件映射仍待实现，不以本段确认宣称当前试作已具备该逻辑。

### 10.24 配置驱动与整数 tick 结算（后续确认，优先于前文时间细节）

- 用户明确不做完整水体物理模拟；优先配置表、离散状态转换与少量修正。下沉、水层、漂相、受阻、鱼的行为及玩家策略均据配置处理，不模拟连续水流、线形变、逐帧碰撞或游泳轨迹。
- 1 刻就是 1 世界 tick。取消小数时间、内部时间余量及跨操作累计方案。实际作业成本为整数 tick，提竿、观察、调整泄力等短动作归入当前作业阶段，不逐按钮扣一刻；已开始的当前作业 tick 即使提前结束或关窗仍完整结算。此前“按实际内部时间折算消耗”的表述以此修正。
- 每阶段配置有限决策节点，继续观察必须推进真实状态，不停留在同节点刷结果或证据；节点用尽后继续作业进入下一 tick。修改尚未执行的设置不重抽鱼行为、不生成事件，仅浏览不耗时。
- 顺序：校验工具、体力与耗材并开始作业 → 按现有完整管线推进世界 tick 与腐败，同步水域状态 → 使用更新后的状态推进钓鱼事件，在可感知决策节点暂停 → 结算损失、收获或结束。已挂鱼不因饵后续腐败而取消；暂停续接不得重复推进该 tick 或重复扣物。
- 同阶段展示优先级为已结束的作业结果、需立即处理的可感知变化、一般环境描述。优先级不删除实际影响，不允许操作已失效的选项，也不泄露隐藏原因。
- 策略持续至重要变化、作业结束或本次推进上限（首轮 1 tick）；普通小幅挣扎合并描述。保存阶段、节点和已结算标记以保证续接，不保存另一套高精度时钟。
- 鱼按鱼种与实际体重对应的体型档查能力配置，当前对抗只保存必要动态状态。配置短促挣扎、向外冲刺、向遮蔽物移动、暂时缓和四类行为的权重、时段、力度与消耗；缺少实际遮蔽物时不得选钻草行为，不按每次按钮重抽。
- 稳妥/强收按配置影响收鱼进度、受力、体力，并结合鱼行为作少量修正；不自动改泄力，不绕过承载和障碍。挂牢程度据初次入口与提竿产生，特定挣扎、过猛拉力或松线可削弱；不设置每 tick 无条件脱钩骰。疲劳阶段改变行为权重，疲劳不直接等于上岸成功；以上动态数值不展示给玩家。
- 天气光线造成的视野、漂相可辨性与操作提示仅限钓鱼窗口，不扩展到大地图。读取既有世界时间；一般变化合并描述，明显影响可感知操作时暂停一次，相同未变化条件不反复提示，隐藏鱼情变化不触发全知通知。

### 10.25 饵料配置简化（后续确认）

- 物品配置区分“可用方式”和“诱鱼特性”。可用方式声明挂钩、投撒、入笼，菜单按当前可尝试方式及实际适配条件筛选，不让玩家逐件试衣服、石头等无关物品，也不按隐藏摄食效果筛选有效鱼饵。
- 未知物品依旧用已知外观称呼。菜单可选仅表示可以尝试这种操作，不表示鱼愿意吃；特殊处理方法按知识开放。不能借筛选结果泄露目标鱼偏好。
- 所有饵采用固定单次用量，包含小鱼和小虾：按物品类型判断可用性，一次一单位，不逐个判断尺寸，不做挂饵专用重量换算。较大食材需走既有加工管线成为小份，挂饵不自动切分；加工不刷新腐败进度。
- 首版食物诱鱼属性仅食物类别（虫、谷物、小鱼、小虾等）与气味强度；不新增每份饵的软硬、活力、营养、溶散等专用参数。发现不等于摄食，摄食不等于入口或挂牢。
- 钩饵、窝料、笼内诱饵共用食物属性，不另建重复偏好表；作用位置和持续消耗由使用方式及作业/窝点状态处理。同类窝料合并，不同类别分别影响，混投无新配方或隐藏加成，投得更多不无限线性增益。
- 拟饵使用浮沉类型与控饵动作响应配置，首版只制作浮水雷蛙；钩性能与障碍沿用共用规则，不另设固定中鱼率或免挂草属性，类型行为与实例磨损分开。

### 10.26 首个可运行版本范围（用户已确认）

第一步完成一条真实基础饵钓流程：

- 鲫鱼、白条、鲤鱼参与实际鱼口计算，验证水层、下沉截食、窝点与承力差异。
- 从开始就接入认知、整数 tick、现有腐败、主动关窗中断、存读档；不能用全知界面或固定脚本中鱼替代。
- 真实组合物品已按看板 k278 接入共用身份、连接、库存和重量契约，见[65号设计](65-item-assembly-and-combined-weight.md)。钓鱼继续直接复用该结构，不另造专属身份或背包。
- 主动关闭钓鱼窗口结束作业，不后台挂机：普通等待/抛收收回结算，挂鱼或受阻按放弃脱离/切线规则处理；待处理鱼获先收取或放流再关闭。窝点、惊扰、资源与见闻保留。退出游戏的保存续接与主动关窗不同。

紧接着的第二步接入路亚、黑鱼与捕捞；保留其全部已确认设计，不因分阶段实施而取消。第一步重点验收玩家观察和调整确实改变结果、失败只留下有依据的线索、整数 tick 不重复结算、物品链路和存读档连续且不重抽事件。当前仍为设计与试作阶段，本节是实施范围确认，不是正式实现完成说明。
