### 6.2 战斗核心

- **格上互斥与「相碰」= 一回合战斗结算**
  - **玩家与敌人不得共占同一格**：地图上双方各为一枚**占格棋子**；任意时刻玩家坐标与任一敌对占格实体的坐标**必须不同格**（与 `02-regions`「占格规则」一致：主角不站在有占格敌人的格子上）。
  - **「相碰」的语义**：不是叠到同一格，而是**邻接或对位交战**——例如玩家朝敌人所在格发出**移动意图**时，若该格为敌人且落在攻击范围内，则**不走入该格**，改为在该格邻侧触发攻击（见下条「输入触发」）；或玩家在邻格使用普攻/技能等，同样是在**保持不同格**的前提下结算。
  - **与回合的关系**：上述**一次**由玩家发起的、进入完整战斗流程的交战（移动意图转攻、或等价的一次攻击行动），即消耗玩家本回合的**那一次行动份额**，并按本节 **「节奏」** 走完整**一回合战斗结算**（含敌方依规则各行动一次等）。换言之：**两枚棋子在格规则上只邻不接、不交叠；一旦发生这次「碰上」的交战，就等于跑完该回合的战斗计算链路。**

- **节奏**：风来的西林式回合刻制——玩家每行动一次，所有敌人各行动一次。
- **方向与范围**：8 向移动与攻击；普攻为正前方 1 格单体。
- **输入触发（移动意图驱动）**：方向输入支持 8 向（含对角）。当玩家对某方向发出“尝试移动”输入时，先读取该方向目标格：若为敌人且在攻击范围内，则触发正常攻击流程（不进入敌人格）；若为可对话 NPC 且在交互范围内，则触发对话；都不满足时再按普通移动/阻挡处理。
- **耗回合**：移动一格 / 普攻 / 使用技能 / 使用道具 / 等待；不耗回合动作后续定义。
- **气力值（QiLi）**：**仅在进入战斗时启用**的即时资源（概念字段建议：`qi_li_current`/`qi_li_max`）。特性为**快耗、快消**：施展依赖气力的招式会扣 `qi_li_current`；若**本回合**未发生气力值消耗，回合结算后恢复 `qi_li_max * qi_li_regen_pct_per_turn`（默认约 `25%`），并夹紧到上限；技能/道具也可显式增减气力值。**基本呼吸法** hub 动作 **「吐纳」**（`11` 8.3.3）可在战斗中消耗 tick、经冷却后 **固定回复 50 点**气力（夹紧上限），**不**与「本回合未扣气力则回合末回气」互斥，各自按配置结算。

- **底气（与战斗消耗）**：底气为生存向资源（`diqi_current`/`diqi_max`，自然恢复、行气、呼吸法与上限关系等见 `06`「底气与行气」及呼吸法相关小节）。**部分招式在 10 成出力（或按配置）施展时，除气力外还可按招式配置扣除底气**；是否与呼吸法联动、是否同时参与 `08` 的**底气催发伤害乘区**，以单条招式/技能配置为准。

  - **消耗与并存口径（本作无「气劲」）**：角色**不存在名为「气劲」的第三条资源**。战斗招式消耗仅由 **气力值** 与/或 **底气** 组成（具体比例、固定值或「占各自上限的百分比」等在招式配置中声明）。**出力大小（1～12 成）**对**伤害**与**资源消耗**的缩放见下条及 `08`（底气催发乘区）。

  - **回合自然恢复（气力，仅当本回合未扣气力）**：定义本回合是否发生过“气力值消耗”（即扣除 `qi_li_current` 的事件）。若未发生，则回合结算后按上式回气。
- **头顶显示（仅玩家 + 条件解锁敌人）**：该条为战斗反馈 HUD，不在左侧常驻面板显示。仅当 `inCombat=true` 且 `qi_li_current < qi_li_max` 时才渲染“血条样式”的气力条；并且仅当角色拥有特殊技能 `special_battle_sense` 且其等级 `>= 1` 时解锁显示玩家自身的头顶气力条。敌人同样拥有气力值：当玩家 `special_battle_sense >= 3` 时，敌人的头顶气力条也开始显示。
- **出力大小（1～12 成）**：伤害与资源消耗均与成数挂钩（\(F_{\text{出力}} = \text{成数}/10\)，以 10 成为基准配置的资源消耗 × 成数/10，除非单条声明为「与成数无关的固定扣费」）。**实现约定**：各招式模板在技能 JSON 中提供 **`default_power_level`**（新装入槽位时的**初始成数**）及 **`power_level_min` / `power_level_max`** 夹紧范围。战斗中**生效的成数**来自 **当前招式槽位上为该格单独保存的 `power_level`**（**分槽配置**，见 `11-skills` 8.3.1）；UI 须支持**按槽**调整，并可选用「与模板默认对齐」「全槽同步」等快捷，但不改变「每槽可不同」的数据模型。
- **速度与先手、连击**
  - **速度值**：战斗速度由 **`hubs.footwork`** 当前步法技能的 **`combat_speed_base`** 提供 \(V_{\text{base}}\)（未挂载时为 **`base_speed_no_footwork`**，默认 1），身手每 +1 点使速度 +0.5%，与装备等加成相加；先算浮点再**向下取整**，用于先手、连击与命中率。速度**仅影响**战斗中的出手顺序与连击，不影响每回合可移动的格数。详见 5.7。
  - **先手的语义（一次交换内的结算顺序）**：在**同一交战交换**中（例如玩家发起普攻且对方在本回合规则下有一次对应还击），须先决定**谁先进入伤害与效果的结算链**。  
    - **先手方**：先完整跑完**本侧**本段内的结算：命中 roll → 招架 → 减伤链 → 扣血 / 损毁 / 气力与底气等资源变化，以及 Buff、招式效果、管线阶段中按既定顺序触发的**即时**效果。凡某效果在配置或管线中**未**声明延后至**本回合末**、**本 tick 末**或其它「全局收束时点」，均视为在本段内随伤害链**即时执行完毕**。  
    - **后手方**：仅在**先手方**本段**全部结束**后才开始；同样跑完本侧一整段即时结算。  
    - **设计意图**：速度高的一方有机会**先**把对方打入死亡或离场等**失能**状态，从而使对方**不再执行**本次交换中本应发生的还击（先击杀即避免再挨对方本击）。
  - **先手判定（速度不等）**：比较双方**取整后**战斗速度（与 `05` 5.7、`CharacterAttributes.getCombatSpeed` 一致）。**数值高的一方**为本交换的**先手方**（若攻击由玩家发起而玩家先手，则玩家段先结算，再结算敌人还击段；若敌人先手，则顺序相反）。  
  - **同速：同时结算（双段演算 + 一次提交）**：取整后速度**相等**时，**不**采用「一方整段落地后再跑另一方」的顺序，以免出现仅因实现遍历顺序产生的伪先手。口径如下：  
    1. **演算阶段**：以本交换**起始时刻**的战场与角色状态为**唯一快照**，**先**完整演算**玩家**一侧本击应产生的伤害与即时效果，得到**待提交变更集**（中间结果）；此阶段**不**写入 HP、不提交死亡/Buff/资源等持久状态。  
    2. **再**在**同一快照**上完整演算**敌人**一侧本交换的待提交变更集（两次演算的输入状态须一致，禁止在演算敌人侧时已经应用玩家侧结果）。  
    3. **提交阶段**：将两侧变更集**同时提交**——扣血、死亡判定、Buff、资源消耗等一并生效。同速下允许**双方互中、同归**等结果。  
    - **与命中率**：`08` 中速度比 \(r\) 仍按双方取整速度计算；同速时 \(r=1\) 与「同时提交」并行不悖。
  - **先手例外（后遗症「不假思索」等）**：若攻击方本击所出的 **`move_id`** 在**出招肢**所挂载的主动技能上，**已装配** `data/post-effects.json` 中 **`effect_type` = `initiative_always_first`** 的后遗症（且满足该后遗症的 `valid_skill_ids` / `valid_move_ids` 等配置），则**本击**在先后手比较中**固定视为攻击方严格先于防守方**（在**已与取整速度合成**的判定中使用：实现上**先**用取整速度得到「谁先 / 是否同速」，**再**叠加强制先手并互抵；**不改变**连击段数判定，连击仍仅由速度倍率规则决定）。若防守方对**同一击**亦持有经设计登记的对称规则（罕见），则**双方该条互相抵消**，回退为仅速度结构；**仍相同**则适用上条**同速（同时结算）**口径。详见 `11-skills` 基本拳脚·刺拳·「不假思索」。
  - **地图普攻与「敌先还击」时的终稿肢**：玩家自地图发起普攻且**未**显式指定 `skill_id + limb_id + move_id` 三件套时，若敌方取整速度**高于**玩家，本交换**必须先**结算敌方对玩家的还击（含玩家侧招架），再按 **`limb_strike_order` / `limb_strike_order_cursor`** 与 tick 内互斥规则**二次选定**本击实际出手肢与招式。此时 **`CombatInitiative.resolvePlayerInitiatedExchange`** 须在**终稿肢与招式**确定之后再次调用，以便读取**该肢该槽**装配的后遗症 id（与 UI 一致）。**不**因该二次解析去**回滚**已先发生的敌方还击段；若终稿上本应触发「强制玩家先手」而后遗症语义与已发生顺序冲突，仅作**提示日志**（`log.combat.initiative.enemy_speed_first_overrides_post_force`），实际执行顺序仍以本交换已选定的「敌先结构」为准。
  - **连击**：若一方速度**大于等于**另一方两倍，则速度高者产生连击，本回合内连打两次；大于等于三倍则连打三次；大于等于四倍则连打四次（更高倍数可后续细化）。连击各段均属于**先手方**在本交换内的连续段：**先手方连击各段**按顺序各做完整即时结算；**全部段结束后**，再进入对侧本次交换的还击（若对侧已在先手段死亡/离场则不再执行）。速度低的一方在对方连击全部打完后再还手一次，本回合仅此一次（与上节先后手一致）。
  - **连击判定与消耗**：连击的每一击均**单独**做命中、招架与伤害判定；每一击**单独扣除**一次该击对应配置的**气力与/或底气**（及体力，若有）。可通过某些手段减免因连击产生的额外消耗（该接口为后续扩展预留）。  
  - **招架承担肢优先级（仅头/胸/腹受击时）**：与 `08-hit-parry-damage.md`「招架结算阶段」一致，在 **`lhand` → `rhand` → `lfoot` → `rfoot`** 上取**首条未损毁肢**的招架槽；四肢受击则用**对应肢**。实现见 **`CombatParry.resolveParryPhaseContext`**。
- **tick 末位移（击退队列，全局约束）**：凡招式配置 **招架失败后于本 tick 末位移**（如 **`on_parry_failed_at_tick_end_displace_target`**，见 `11-skills` 正蹬），遵守下列统一口径（扩展新击退招式时不得违背，除非单条声明例外）：
  - **执行时机**：**该 tick 内**全部命中、招架、伤害、连击等结算**全部完成后**，再处理击退；**禁止**在伤害中途改坐标。
  - **同 tick 至多一次实际位移**：若本 tick 末队列中有多条击退候选，**仅执行一条**。先在候选中取 **`cells` 数值最大** 的子集；在此子集内再定唯一胜者（**其余丢弃**）：  
    1. 比较各候选对应 **攻击方** 的 **筋骨实际值**（先天 + 后天，见 `05`），**较低者优先**（该条被执行）；  
    2. 若筋骨相同，比较各候选 **攻击方战斗速度**（与本节先手、连击所用速度一致，**取整后的值**），**较低者优先**；  
    3. 若仍相同，取 **`event_id` 字典序最小** 的一条。  
    - **实现**：每条击退队列项须能解析到 **攻击方实体**（以读取筋骨与速度）；若缺字段则退回仅按 **`event_id`**（须在实现登记中告警）。
  - **作用对象**：**仅本击的受击目标**；**不**对溅射、替身等扩展目标自动生效（多目标须各带独立配置）。若目标已 **死亡、离场或不可位移**，**跳过**该条击退（不位移、不因此报错）。
  - **方向离散**：`direction` 为 **`away_from_actor`** 时，以攻击者格心→目标格心的向量为准，在目标当前格的 **八邻域** 中选取 **与上述向量夹角最小** 的可走格作为**第一步方向**；多格击退则沿同向逐步重复（每步重新取邻格，仍取与理想射线夹角最小的可走格，以实现登记为准）。
  - **阻挡与停格**：**不可走地形**、**地图边界**、**占格实体**（敌人 / NPC / 玩家等）均 **阻挡**，**不挤开**、不链式推移；目标停在 **最后一个可走格**。若 **第一步即不可走**（完全未动），仍视为发生「撞阻」以判定 **撞墙加伤**（见 `08`）。
  - **撞墙加伤**：若因阻挡导致 **未跑满** 配置的 **`cells`**（含一步未动），对本击应用 **撞墙加伤**：在 **`08` 减伤链全部算完后**、**写入 HP 前**，将该击 **最终伤害**（已含类型微调等）乘以系数 **`wall_slam_final_damage_multiplier`**（正蹬配置为 **1.3**；未配置时默认 **1.3**，除非全局表另改），再 **向下取整** 扣血。多 sub-hit **每击独立**判定是否撞阻。
  - **与其它系统**：击退 **不消耗** 目标本回合「移动权」、**不默认触发** 借机攻击或陷阱格（除非未来单独登记「位移触发器」）。
  - **招架口径**：**只要本击「招架成功完全免伤」未成立**（即 **`08` 上视为招架失败**、进入卸力/伤害链），即满足该招式配置的击退 **入队条件**（与 `11-skills` 正蹬一致）。
  - **存档与地图**：**允许**将 tick 末尚未执行的击退队列写入战斗存档，读档后继续执行；**允许**将击退落点 **钳制** 在 **当前战斗格图** 合法范围内（`02`），离开战斗时按战斗结束流程处理坐标。
- **资源不足仍出手（按槽成数扣费与算伤，已定）**：本击成数 **\(k\)** 取 **当前轮到的招式槽**所存的 **`power_level`**（玩家为该槽设计的成数，见 `11-skills`）。若按此 \(k\) 算出的应扣气力/底气 **大于当前剩余**，本击**仍**走完命中/招架/伤害流程。**应扣量**公式**始终按此 \(k\)** 计算（即按玩家为该槽设定的成数计费，**不**改用 `default_power_level` 降档计费）。**实际扣除** `min(应扣量, 当前资源)`，扣至 0 为止、**不记负**、不中断本击。**伤害与底气催发乘区**（见 `08`）**同样按此 \(k\)** 代入，**不**因资源不足而改用默认成数。

> 注：战斗中使用的所有属性（筋骨、柔韧、呼吸、身手、专注等）均为“先天 + 后天”的实际值。经脉与穴位系统通过增加底气上限与先天 / 后天五维，**间接**影响伤害、减伤、速度与学习等，但不改变本节的战斗流程与公式。详细规则见 `12-meridians-and-acupoints.md`。
