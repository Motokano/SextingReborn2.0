### 6.2 战斗核心

- **格上互斥与「相碰」= 一回合战斗结算**
  - **玩家与敌人不得共占同一格**：地图上双方各为一枚**占格棋子**；任意时刻玩家坐标与任一敌对占格实体的坐标**必须不同格**（与 `02-regions`「占格规则」一致：主角不站在有占格敌人的格子上）。
  - **「相碰」的语义**：不是叠到同一格，而是**邻接或对位交战**——例如玩家朝敌人所在格发出**移动意图**时，若该格为敌人且落在攻击范围内，则**不走入该格**，改为在该格邻侧触发攻击（见下条「输入触发」）；或玩家在邻格使用普攻/技能等，同样是在**保持不同格**的前提下结算。
  - **与回合的关系**：上述**一次**由玩家发起的、进入完整战斗流程的交战（移动意图转攻、或等价的一次攻击行动），即消耗玩家本回合的**那一次行动份额**，并按本节 **「节奏」** 走完整**一回合战斗结算**（含敌方依规则各行动一次等）。换言之：**两枚棋子在格规则上只邻不接、不交叠；一旦发生这次「碰上」的交战，就等于跑完该回合的战斗计算链路。**

- **节奏**：风来的西林式回合刻制——玩家每行动一次，所有敌人各行动一次。
- **方向与范围**：8 向移动与攻击；普攻为正前方 1 格单体。
- **输入触发（移动意图驱动）**：方向输入支持 8 向（含对角）。当玩家对某方向发出“尝试移动”输入时，先读取该方向目标格：若为敌人且在攻击范围内，则触发正常攻击流程（不进入敌人格）；若为可对话 NPC 且在交互范围内，则触发对话；都不满足时再按普通移动/阻挡处理。
- **耗回合**：移动一格 / 普攻 / 使用技能 / 使用道具 / 等待；不耗回合动作后续定义。
- **气力值（QiLi）＝呼吸条（与呼吸法强绑定）**：气力是**战斗内即时资源**（概念字段：`qi_li_current`/`qi_li_max`），但**不再是独立资源**——呼吸条的**形态（上限、恢复、消耗、状态）完全由当前挂载的呼吸法**（`hubs.breath`，见 `11-skills` 8.3.3）**定义**。
  - **存在前提**：未挂载呼吸法 → **无呼吸条**（`qi_li_max = 0`），依赖呼吸条的战斗动作（招式）不可释放；装备呼吸法后才拥有呼吸条。
  - **上限**：由呼吸法配置给出（基数或公式）；成长曲线由**各呼吸法自行声明**——可随呼吸法等级成长、可不成长、甚至可倒扣（如激进型呼吸法高等级反而上限更低）。
  - **常驻资源（进战斗不重置）**：呼吸条是**装备呼吸法即存在**的常驻资源条——进出战斗**不改变**当前值（无强制满条、无清零）；气力只随**消耗/回气**变化。**唯一重置点**是**切换呼吸法**（消耗 1 tick 且读取新呼吸法的初始状态，见下「切换」），以此限制玩家通过来回切换呼吸法获取战斗优势。
  - **恢复**：由呼吸法定义恢复模型（每轮回复量/比例/条件），**按完整轮次判定**（玩家行动 + 全部敌人各行动一次全部结束后的收束点，见下「回合自然恢复」）；**取消「吐纳」动作**，除呼吸法自行声明的被动回气外**无兜底回气**。
  - **消耗**：招式**不再自带气力消耗属性**；所有招式视为**「战斗动作」**，呼吸法**按动作标签（挥拳/踢击等）分档**定义「战斗动作 → 呼吸条变动值」（**可为正**＝出招回气、**可为负**＝扣气，夹紧 `[0, qi_li_max]`）；**成数 \(k\) 缩放**该变动值（见「出力大小」）。底气消耗仍由招式表配置，不受本模型影响。
  - **语义（核心条件模式，非硬阻断）**：呼吸法定义**核心条件**（默认「能支付该招的呼吸条消耗」，可与消耗 `action_delta` 分离声明，见 `11` 8.3.3），并声明**满足/不满足两个分支**的效果。出招**总是发生**（消耗动作与 tick），**不存在「无法出招」的硬阻断**；但**核心条件不满足时**由呼吸法声明的「不满足分支」接管结算——**基本呼吸法**的不满足分支为：**最终伤害降为 0** + **气力扣至 0** + **仍走完整命中/招架/减伤链**（「命中即叠」类效果如失衡/试探/驱散按命中结果照常触发，见 `08`）。
  - **状态**：呼吸法可声明**耗尽惩罚、蓄力/节奏状态、专属 buff** 等（走 Buff 系统接口，见 `18`）；本文档只留接口，各呼吸法在单条设计中展开。
  - **切换**：切换挂载的呼吸法 = **消耗 1 tick** 且 **直接读取新呼吸法的初始状态**（`breath_bar.initial_state`，至少含 `qi_li`；缺省 0）——即 `qi_li_current = 新呼吸法 initial_state.qi_li`（基本呼吸法为 0）；切换后立即按新呼吸法的上限/模型生效。

- **底气（与战斗消耗）**：底气为生存向资源（`diqi_current`/`diqi_max`，自然恢复、行气、呼吸法与上限关系等见 `06`「底气与行气」及呼吸法相关小节）。**部分招式在 10 成出力（或按配置）施展时，除呼吸条（气力）变动外还可按招式配置扣除底气**；是否与呼吸法联动、是否参与成数乘区，以单条招式/技能配置为准。

  - **消耗与并存口径（本作无「气劲」）**：角色**不存在名为「气劲」的第三条资源**。战斗消耗仅由 **呼吸条（气力）** 与/或 **底气** 组成：**底气消耗**（具体比例、固定值或「占各自上限的百分比」等）在**招式配置**中声明；**呼吸条变动**不由招式声明，由当前挂载**呼吸法**按「战斗动作」档位定义（见上「气力值＝呼吸条」）。**出力大小（1～12 成）**对**伤害**与**底气消耗**的缩放见下条及 `08`（成数乘区 \(F_{\text{出力}}=k/10\)）；对呼吸条变动值的缩放见「出力大小」。

  - **回合自然恢复（呼吸条，按 tick/轮次判定）**：恢复判定在每个 tick 收束（战斗中一轮＝一次玩家行动＋全部敌人各行动一次＝一 tick；非战斗 tick 同样判定——呼吸条为常驻资源，装备呼吸法即存在、随时回气）。是否回复、回复多少、有何条件**均由当前呼吸法定义**；呼吸法未声明恢复模型则该 tick 不恢复。旧的「本回合未扣气力则回 25%」默认规则**废除**（呼吸法可按需声明等价模型）。
- **头顶显示（仅玩家 + 条件解锁敌人）**：该条为战斗反馈 HUD，不在左侧常驻面板显示。仅当 `inCombat=true`、**已挂载呼吸法**且 `qi_li_current < qi_li_max` 时才渲染“血条样式”的呼吸条；并且仅当角色拥有特殊技能 `special_battle_sense` 且其等级 `>= 1` 时解锁显示玩家自身的头顶呼吸条。敌人同样拥有气力值：当玩家 `special_battle_sense >= 3` 时，敌人的头顶气力条也开始显示。
- **出力大小（1～12 成）**：伤害与**招式配的底气消耗**均与成数挂钩（\(F_{\text{出力}} = \text{成数}/10\)，以 10 成为基准配置的资源消耗 × 成数/10，除非单条声明为「与成数无关的固定扣费」）；**呼吸条变动值同样按成数缩放**（呼吸法定义的 10 成基准变动值 × 成数/10，除非该呼吸法单条声明固定变动）。**实现约定**：各招式模板在技能 JSON 中提供 **`default_power_level`**（新装入槽位时的**初始成数**）及 **`power_level_min` / `power_level_max`** 夹紧范围。战斗中**生效的成数**来自 **当前招式槽位上为该格单独保存的 `power_level`**（**分槽配置**，见 `11-skills` 8.3.1）；UI 须支持**按槽**调整，并可选用「与模板默认对齐」「全槽同步」等快捷，但不改变「每槽可不同」的数据模型。
- **速度与先手、连击**
  - **速度值**：战斗速度由 **`hubs.footwork`** 当前步法技能的 **`combat_speed_base`** 提供 \(V_{\text{base}}\)（未挂载时为 **`base_speed_no_footwork`**，默认 1），身手每 +1 点使速度 +0.5%，与装备等加成相加；**内部保留小数、仅展示取整**（05 5.7），用于先手、连击与命中率。速度**仅影响**战斗中的出手顺序与连击，不影响每回合可移动的格数。详见 5.7。
  - **先手的语义（一次交换内的结算顺序）**：在**同一交战交换**中（例如玩家发起普攻且对方在本回合规则下有一次对应还击），须先决定**谁先进入伤害与效果的结算链**。  
    - **先手方**：先完整跑完**本侧**本段内的结算：命中 roll → 招架 → 减伤链 → 扣血 / 损毁 / 呼吸条变动与底气等资源变化，以及 Buff、招式效果、管线阶段中按既定顺序触发的**即时**效果。凡某效果在配置或管线中**未**声明延后至**本回合末**、**本 tick 末**或其它「全局收束时点」，均视为在本段内随伤害链**即时执行完毕**。  
    - **后手方**：仅在**先手方**本段**全部结束**后才开始；同样跑完本侧一整段即时结算。  
    - **设计意图**：速度高的一方有机会**先**把对方打入死亡或离场等**失能**状态，从而使对方**不再执行**本次交换中本应发生的还击（先击杀即避免再挨对方本击）。
  - **先手判定（速度不等）**：比较双方**小数战斗速度**（与 `05` 5.7、`CharacterAttributes.getCombatSpeed` 一致）。**数值高的一方**为本交换的**先手方**（若攻击由玩家发起而玩家先手，则玩家段先结算，再结算敌人还击段；若敌人先手，则顺序相反）。  
  - **同速：同时结算（双段演算 + 一次提交）**：速度**小数精确相等**时（同身手足量 + 同步法 + 同加成，或对称场景），**不**采用「一方整段落地后再跑另一方」的顺序，以免出现仅因实现遍历顺序产生的伪先手。口径如下：  
    1. **演算阶段**：以本交换**起始时刻**的战场与角色状态为**唯一快照**，**先**完整演算**玩家**一侧本击应产生的伤害与即时效果，得到**待提交变更集**（中间结果）；此阶段**不**写入 HP、不提交死亡/Buff/资源等持久状态。  
    2. **再**在**同一快照**上完整演算**敌人**一侧本交换的待提交变更集（两次演算的输入状态须一致，禁止在演算敌人侧时已经应用玩家侧结果）。  
    3. **提交阶段**：将两侧变更集**同时提交**——扣血、死亡判定、Buff、资源消耗等一并生效。同速下允许**双方互中、同归**等结果。  
    - **与命中率**：`08` 中速度比 \(r\) 按双方小数速度计算；同速时 \(r=1\) 与「同时提交」并行不悖。
  - **先手例外（后遗症「不假思索」等）**：若攻击方本击所出的 **`move_id`** 在**出招肢**所挂载的主动技能上，**已装配** `data/post-effects.json` 中 **`effect_type` = `initiative_always_first`** 的后遗症（且满足该后遗症的 `valid_skill_ids` / `valid_move_ids` 等配置），则**本击**在先后手比较中**固定视为攻击方严格先于防守方**（在**已与小数速度合成**的判定中使用：实现上**先**用小数速度得到「谁先 / 是否同速」，**再**叠加强制先手并互抵；**不改变**连击段数判定，连击仍仅由速度倍率规则决定）。若防守方对**同一击**亦持有经设计登记的对称规则（罕见），则**双方该条互相抵消**，回退为仅速度结构；**仍相同**则适用上条**同速（同时结算）**口径。详见 `11-skills` 基本拳脚·刺拳·「不假思索」。
  - **地图普攻与「敌先还击」时的终稿肢**：玩家自地图发起普攻且**未**显式指定 `skill_id + limb_id + move_id` 三件套时，若敌方小数速度**高于**玩家，本交换**必须先**结算敌方对玩家的还击（含玩家侧招架），再按 **`limb_strike_order` / `limb_strike_order_cursor`** 与 tick 内互斥规则**二次选定**本击实际出手肢与招式。此时 **`CombatInitiative.resolvePlayerInitiatedExchange`** 须在**终稿肢与招式**确定之后再次调用，以便读取**该肢该槽**装配的后遗症 id（与 UI 一致）。**不**因该二次解析去**回滚**已先发生的敌方还击段；若终稿上本应触发「强制玩家先手」而后遗症语义与已发生顺序冲突，仅作**提示日志**（`log.combat.initiative.enemy_speed_first_overrides_post_force`），实际执行顺序仍以本交换已选定的「敌先结构」为准。
  - **连击**：若一方速度**大于等于**另一方两倍，则速度高者产生连击，本回合内连打两次；大于等于三倍则连打三次；大于等于四倍则连打四次（更高倍数可后续细化）。连击各段均属于**先手方**在本交换内的连续段：**先手方连击各段**按顺序各做完整即时结算；**全部段结束后**，再进入对侧本次交换的还击（若对侧已在先手段死亡/离场则不再执行）。速度低的一方在对方连击全部打完后再还手一次，本回合仅此一次（与上节先后手一致）。
  - **连击判定与消耗**：连击的每一击均**单独**做命中、招架与伤害判定；每一击**单独结算**一次该击对应的**呼吸条变动值**（按当前呼吸法的「战斗动作」档位与成数 \(k\)）与**底气消耗**（招式配置，若有）。可通过某些手段减免因连击产生的额外消耗（该接口为后续扩展预留）。  
  - **招架承担肢优先级（仅头/胸/腹受击时）**：与 `08-hit-parry-damage.md`「招架结算阶段」一致，在 **`lhand` → `rhand` → `lfoot` → `rfoot`** 上取**首条未损毁肢**的招架槽；四肢受击则用**对应肢**。实现见 **`CombatParry.resolveParryPhaseContext`**。
- **tick 末位移（击退队列，全局约束）**：凡招式配置 **招架失败后于本 tick 末位移**（如 **`on_parry_failed_at_tick_end_displace_target`**，见 `11-skills` 正蹬），遵守下列统一口径（扩展新击退招式时不得违背，除非单条声明例外）：
  - **执行时机**：**该 tick 内**全部命中、招架、伤害、连击等结算**全部完成后**，再处理击退；**禁止**在伤害中途改坐标。
  - **同 tick 至多一次实际位移**：若本 tick 末队列中有多条击退候选，**仅执行一条**。先在候选中取 **`cells` 数值最大** 的子集；在此子集内再定唯一胜者（**其余丢弃**）：  
    1. 比较各候选对应 **攻击方** 的 **筋骨实际值**（先天 + 后天，见 `05`），**较高者优先**（该条被执行）；  
    2. 若筋骨相同，比较各候选 **攻击方战斗速度**（与本节先手、连击所用速度一致，**小数速度**），**较低者优先**；  
    3. 若仍相同，取 **`event_id` 字典序最小** 的一条。  
    - **实现**：每条击退队列项须能解析到 **攻击方实体**（以读取筋骨与速度）；若缺字段则退回仅按 **`event_id`**（须在实现登记中告警）。
  - **作用对象**：**仅本击的受击目标**；**不**对溅射、替身等扩展目标自动生效（多目标须各带独立配置）。若目标已 **死亡、离场或不可位移**，**跳过**该条击退（不位移、不因此报错）。
  - **方向离散**：`direction` 为 **`away_from_actor`** 时，以攻击者格心→目标格心的向量为准，在目标当前格的 **八邻域** 中选取 **与上述向量夹角最小** 的可走格作为**第一步方向**；多格击退则沿同向逐步重复（每步重新取邻格，仍取与理想射线夹角最小的可走格，以实现登记为准）。
  - **阻挡与停格**：**不可走地形**、**地图边界**、**占格实体**（敌人 / NPC / 玩家等）均 **阻挡**，**不挤开**、不链式推移；目标停在 **最后一个可走格**。若 **第一步即不可走**（完全未动），仍视为发生「撞阻」以判定 **撞墙加伤**（见 `08`）。
  - **撞墙加伤**：若因阻挡导致 **未跑满** 配置的 **`cells`**（含一步未动），对本击应用 **撞墙加伤**：在 **`08` 减伤链全部算完后**、**写入 HP 前**，将该击 **最终伤害**（已含类型微调等）乘以系数 **`wall_slam_final_damage_multiplier`**（正蹬配置为 **1.3**；未配置时默认 **1.3**，除非全局表另改），再 **向下取整** 扣血。多 sub-hit **每击独立**判定是否撞阻。
  - **与其它系统**：击退 **不消耗** 目标本回合「移动权」、**不默认触发** 借机攻击或陷阱格（除非未来单独登记「位移触发器」）。
  - **招架口径**：**只要本击「招架成功完全免伤」未成立**（即 **`08` 上视为招架失败**、进入卸力/伤害链），即满足该招式配置的击退 **入队条件**（与 `11-skills` 正蹬一致）。
  - **存档与地图**：**允许**将 tick 末尚未执行的击退队列写入战斗存档，读档后继续执行；**允许**将击退落点 **钳制** 在 **当前战斗格图** 合法范围内（`02`），离开战斗时按战斗结束流程处理坐标。
- **核心条件不满足时的结算（呼吸条新语义；底气按槽成数扣费与算伤，已定）**：本击成数 **\(k\)** 取 **当前轮到的招式槽**所存的 **`power_level`**（玩家为该槽设计的成数，见 `11-skills` 8.3.1）。
  - **呼吸条（气力）——核心条件**：出招前检查当前呼吸法**核心条件**（默认「能支付该招的呼吸条消耗」，消耗 = `breath_bar.action_delta` 按动作标签档位 × 成数缩放，见 `11` 8.3.3）：
    - **满足**：正常结算（呼吸条按变动值扣/回，夹紧 `[0, qi_li_max]`，伤害照常）；
    - **不满足**：按呼吸法声明的「不满足分支」接管——**基本呼吸法**为：**最终伤害降为 0**、**气力扣至 0**（`qi_li_current = 0`）、**仍走完整命中/招架/减伤链**（命中即叠类效果照常触发）。
    - 其它呼吸法可在 `usage_conditions.on_unsatisfied` 声明不同后果（如伤害减半、改为消耗底气等），未声明则默认同基本呼吸法（伤害 0 + 扣至 0 + 走完整链）。
  - **底气**：维持旧规则——若按此 \(k\) 算出的应扣底气 **大于当前剩余**，本击**仍**走完命中/招架/伤害流程，伤害照常。**应扣量**公式**始终按此 \(k\)** 计算（**不**改用 `default_power_level` 降档计费）。**实际扣除** `min(应扣量, 当前底气)`，扣至 0 为止、**不记负**、不中断本击。**伤害与成数乘区**（见 `08`，即 \(F_{\text{出力}}=k/10\)）**同样按此 \(k\)** 代入，**不**因底气不足而改用默认成数。

> 注：战斗中使用的所有属性（筋骨、柔韧、呼吸、身手、专注等）均为“先天 + 后天”的实际值。经脉与穴位系统通过增加底气上限与先天 / 后天五维，**间接**影响伤害、减伤、速度与学习等，但不改变本节的战斗流程与公式。详细规则见 `12-meridians-and-acupoints.md`。
