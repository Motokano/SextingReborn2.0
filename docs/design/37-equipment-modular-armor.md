# 三十七、模块化躯干防具与新底气护体（设计正本）

> **状态**：已定稿（机制层）。数值（基础盾量、模块消耗%、底材槽位配置等）留待框架表/模块表设计时确定。
> **取代范围**：本文件为**躯干防具（`clothing` 槽）**与**底气护体（`diqi_huti`）**的最新机制正本；与此冲突的旧表述以本文件为准（迁移标注见 `06` / `08` / `11` / `14` / `19`）。

## 1. 动机与世界观依据

- **动机**：装备系统精简（15 → 10 槽，砍掉饰品五槽，见 `02` §2.5）；躯干防具从"整件写死减伤"改为**模块化**；底气护体从"空荡的魔法盾"改造为**激活防具的机制**。
- **世界观依据**（`30-story-outline-blackout.md` §全民技术）：
  > "浸布后普通人衣物耐久大增；习武者以呼吸法灌底气，可挡刀箭，热兵器性价比被废。枪还在，但没人用。"
- **对应关系**：**硅叶浸布** = 底材工艺（决定防具的基础盾量与可激发性）；**呼吸法灌底气** = 激活机制（把防具的潜在防御激发出来）。普通人穿硅叶防具 = 仅被动（口袋/重量）；习武者（呼吸法 ≥50）可激活 = 全力（盾 + 模块属性）。

## 2. 装备槽位现状（上下文）

- 全游戏 10 个装备槽，分三组（`02` §2.5、`js/inventory-equipment.js` 的 `EQUIP_SLOT_IDS`）：
  - **出招装备**：武器×2、手套×2、鞋×2（被肢体出招结算读取）；
  - **防具**：`head`、`clothing`；
  - **载物**：`vest`、`backpack`（容器，非护甲）。
- 本文件改造 **`clothing`（躯干防具）**，并记录 **`head`（头部防具）** 的设计（见 §9：头盔模块化 3 槽，但**不接激活体系**，常驻生效）。

## 3. 躯干防具模块化

### 3.1 底材（框架）

| 属性 | 规则 |
|------|------|
| 材料 | 底材由材料制成，**材料决定空板位兜底属性**（见下「材料 → 兜底属性」） |
| 减伤 | 主要减伤来自模块（激活后生效）；**空板位有材料兜底 2~3%**（防"完全无减伤"的空白体验） |
| 基础盾量 | 防具自身的潜在容量；**决定激活成本与盾池大小**（数值按框架设计时定） |
| 口袋 / 重量 | **常驻**，不依赖激活（底材自带口袋数量） |
| 槽位 | **6 个板位**（见 3.2）；槽位数量/具体数值由各框架（如厚皮大衣 / 战斗服 / 轻便套装）自行配置 |

- 底材 = "载具" + "材料底子"：决定能装多少板位、多重、多少口袋；主要防护数值由模块提供。

**材料 → 兜底属性（空板位时生效；基于现有物品表材料，不新增）**：

| 材料 | 空板位兜底（~2-3%） | 材料特色 |
|------|---------------------|----------|
| 兽皮（皮革） | 钝击 3% | 柔韧：被钝击命中时损毁值略减 |
| 兽骨 | 钝击 2% | 骨架加固（结构/耐久） |
| 青竹 | 劈砍 3% | 轻量硬质：重量减 |
| 蚕丝（野/家蚕茧） | 戳刺 2% | 抗割 + 极轻 |
| 铸铁 / 钢 | 劈砍 3% + 戳刺 3% | 重（重量大增） |
| 铜 | 戳刺 2% | 待定 |
| 硬木（橡木/榉木等） | 劈砍 2% | 耐潮 / 细腻 |

- 空板位兜底 = 材料的**天然属性**，玩家通过制作/鉴定逐步认识（认知论友好）；不同材料做同一框架，兜底不同。

### 3.2 六个板位（对应身体部位）

板位即模块槽，语义与身体部位一一对应（`09-body-parts.md` 七部位去掉「头」）：

| 板位 | 对应身体部位 | 命中结算 |
|------|--------------|----------|
| **胸** | 胸 | 命中胸 → 取胸板模块减伤 |
| **腹** | 腹 | 命中腹 → 取腹板模块减伤 |
| **左臂** | 左手 | 命中左手 → 取左臂板 |
| **右臂** | 右手 | 命中右手 → 取右臂板 |
| **左腿** | 左脚 | 命中左脚 → 取左腿板 |
| **右腿** | 右脚 | 命中右脚 → 取右腿板 |

- **头部不归躯干防具**（独立 `head` 槽，后续单独设计）。
- **部位命中为随机权重**（躯干高、头低、四肢中等，`09`）：护甲覆盖是**概率性防护**，玩家无法完全掌控命中部位——已定取舍（"人生无常"，见 §7）。躯干板位（胸/腹）因命中权重高而天然价值更高。

### 3.3 模块

- **结构**：模块 = **基础属性 + 1 条附魔**。模块本身有基础属性（如垫片自带防御力）；附魔是额外附加的 1 条词条。**附魔工艺材料 = 硅叶**（浸泡/处理，与底材浸布同一套"配方"，见 §6）。
- **槽位占用**：由模块配置自行声明。普通模块通常占 **1 个板位**；特殊模块可**横跨多个板位**（如"胸腹一体板"占胸+腹两板）。占板越多、额外消耗越高，效果就必须越强才划算。
- **额外底气消耗%**：每块模块有一个**独立的额外底气消耗%**，**可正可负**（加耗模块 / 减耗模块），数值由各模块独立设计。Σ模块消耗% 参与激活成本计算（见 4.2）。
- **减伤按板位生效**：模块装在哪个板位，就护对应部位（胸板护胸、左臂板护左手…）。
- **防具本身不能附魔**：词条全部来自模块（激活后生效）。一件防具的词条数 = 已插入模块的附魔数。

### 3.4 与旧模型的差异

- 旧：`clothing` 模板直接配置 `damage_reduce_slash/pierce/blunt_pct`（常驻百分比减伤）+ `enchant_slots: 6`。
- 新：底材零减伤；减伤由模块按板位提供，且**激活后才生效**（见 4）。旧字段不再作为底材防护来源。

### 3.5 复合模块（跨部位模块 / 套装件）

- **定义**：占用**跨槽位槽点集合**的模块——同时占 `head`（头部）与 `clothing`（躯干）的槽位/板位。例：「兜帽大衣」占 `head.shell` + `clothing.chest` + `clothing.abdomen`；「全包裹甲」占头衣全部槽点。本质是**套装件 / 整体防具**（如硅叶浸布的一体式防具）。
- **穿戴约束**：**两个底材必须同时在场**（穿衣服 + 戴头盔），否则复合模块不可用。
- **部位数值**：**分开声明**——头部基础数值、躯干基础数值各自独立；生效按各自槽位规则（**头部常驻、躯干激活制**）。
- **特殊效果**：整体奖励效果（规则级，如"劈砍按钝击结算"）——**仅当全部处于激活时生效**，即**跟随躯干激活**（头部分反正常驻；不开底气护体则特殊效果不生效）。
- 复合模块占用的槽点被占满后，该槽点不能再装其他模块；其激活消耗按占用槽点所属底材各自结算（头部常驻不消耗，躯干部分并入躯干激活成本）。

## 4. 新底气护体（激活防具）

### 4.1 前提

- **呼吸法（`combat_basic_breath`）等级 ≥ 50**（沿用旧解锁门槛）；
- **仅战斗内**；
- **必须装备躯干防具**（裸奔不可激活——"肉体凡身没有意义"）；无防具或防具无基础盾量 → 整次失败。

### 4.2 激活消耗

```
激活消耗 = 基础盾量 × (1 + Σ模块额外消耗%)
```

- **一次性**扣除（无持续消耗；无 duration，盾破前一直生效）。
- 例：基础盾量 20，6 块模块各 +10% → 消耗 = 20 × 1.6 = 32 底气。
- 消耗可被**减耗模块**（负消耗%）下调。
- 底气不足（`diqi_current < 消耗`）或 `diqi_max = 0` → 整次失败，不扣底气、不推 tick。
- 护体未破（`shield_value > 0`）时不可重复施展。

### 4.3 盾与减伤

- **激活后**：盾 = **板位模块减伤（比例）+ 基础盾量（容量）** 同时生效。
- **盾的减伤比例 = 模块减伤**（不再单独为盾设百分比）：命中某部位 → 取该部位板位的模块减伤作为本层减伤比例（空板 = 0 减伤）→ 按比例减免 → **被减免部分从盾池（基础盾量）扣除**。
- **模块分工**：
  - 模块 → 减伤**比例**（按板位）；
  - 基础盾量 → 减伤**容量**（盾池能扛多少减免）；
  - 底气 → 激活成本（一次性消耗，模块越多通常越贵）。

### 4.4 结算流程（激活态）

```
命中某部位 →
  ① 盾层：取该部位板位模块减伤比例 → 减免 → 被减免部分扣盾池（基础盾量）
          （盾池扣到 ≤0 → 本击之后护体消失）
  ② 柔韧基础防御（动态%，见 05 5.6.2）
  ③ 伤害类型微调系数（按命中部位与伤害类型，见 05 5.6.2）
```

### 4.5 未激活态（白板）

- 未激活时防具**无防具减伤层**：模块属性不生效、无盾。仅底材的口袋/重量常驻。
- 减伤链退化为：**柔韧基础防御 → 伤害类型微调**。
- 世界观对应："不运功，硅叶甲就是件普通衣服"。

## 5. 减伤链（新）

| 状态 | 减伤链 |
|------|--------|
| **激活态** | **盾（板位模块减伤 + 基础盾量）→ 柔韧基础防御 → 伤害类型微调** |
| **未激活** | 柔韧基础防御 → 伤害类型微调（无防具层） |

- 旧链「底气护体(固定 25%) → 防具(常驻%) → 柔韧 → 微调」中，"底气护体层"与"防具层"合并为新的**激活态盾层**；固定 25% 与"盾量 = 消耗底气量"的旧规则废弃。
- 头部命中仍取 `head` 槽防具（常驻减伤，不接激活），规则见 §9。

## 6. 世界观衔接

| 设定 | 机制 |
|------|------|
| 硅叶浸布（普通人衣物耐久大增） | 底材工艺：决定基础盾量、可激发性 |
| 硅叶处理 = 改造配方（"像腌咸菜一样普及"） | **附魔 / 改造工艺**：模块附魔（`life_enchant`）材料 = 硅叶 |
| 习武者以呼吸法灌底气，可挡刀箭 | 激活机制：呼吸法 ≥50 + 消耗底气激活防具 |
| 热兵器性价比被废 | 世界观背景（冷兵器世界的成因），不涉及本机制 |

## 7. 已定取舍 / 待定事项

**已定取舍：**
- 部位命中随机（"人生无常"）：护甲为概率性防护，**不**为敌人加部位攻击倾向。
- 新手期体验靠**初期敌人强度**控制（吃力但可过），**不**靠防具兜底。
- 模块消耗% 可正可负（加耗/减耗），激活成本由模块表自行平衡。
- 空板位兜底 = **材料属性**（2~3%），不是统一数值（见 §3.1）。
- **附魔 / 改造材料 = 硅叶**（见 §6）。
- **精英敌人穿模块化防具**（普通敌人不穿）：敌人侧复用本系统（激活/眩晕/模块），细节后议。
- **稀有度系统移除（已定）**：品质六档 / 稀有度系统已移除（见 `41-quality-removal.md`）；本模块不再引用品质档，装备差异由词条与 `numeric_rolls` 承担。

## 8. 实现约定（摘要，供落地参考）

> **具体 JSON schema（模块表 / 防具模板字段 / 实例格式 / effect_type 目录 / modifier key / 校验规则）见 [38-equipment-data-contract.md](38-equipment-data-contract.md)**。本节为机制摘要。

- 底材模板新增字段：`base_shield`（基础盾量）、`module_slots`（6 板位配置，可按框架差异化）。
- 模块作为**独立物品**：模板含基础属性、附魔位（1 条）、**占用声明**（`occupies`：跨槽位槽点集合，如 `["clothing.chest", "head.shell"]`；普通模块 = 单个板位，特殊模块 = 同防具内多板位，复合模块 = 跨 head/clothing 槽点）、`activation_cost_pct`（额外消耗%，可负）、按槽点生效的数值（复合模块分头部/躯干两段声明）。
- 防具实例结构建议：`{ item_id, modules: { chest?: itemId, abdomen?: itemId, arm_l?: itemId, arm_r?: itemId, leg_l?: itemId, leg_r?: itemId } }`（或等价有序数组）；实例不再存整件式 `enchants`（词条随模块）。**复合模块**挂在主底材（`clothing`）的模块列表，其 `occupies` 声明为唯一事实源（同时占据 `head` 槽点）；`head` 底材只需"在场"作为穿戴前置，不重复存储。
- 结算：命中部位 → 映射槽点 → 取模块对应段数值；复合模块的头部段按常驻、躯干段按激活制，特殊效果由躯干激活状态门控。
- 命中结算：按命中部位映射板位 → 取模块减伤；盾池独立于底气值，扣减走统一接口（`06` 的 `changeDiqi` 风格）。
- 存档兼容：旧档 `equipment.clothing.enchants` 废弃；加载时迁移为无模块的白板底材（或按约定处理）。

## 9. 头部防具（`head` 槽，头盔模块化）

### 9.1 定位

- **有意弱点**：头 = 全局最脆（七部位中损毁上限最低 50、钝击微调 1.3 最脆）。"爆头死"保留为**低概率高代价**事件（恐怖感来源），但通过多重闸门避免成为常态挫败。
- **与躯干分工**：躯干甲保命（激活制），头甲保清醒（常驻）。职责分离，互不冲突。

### 9.2 眩晕累积系统（全局战斗状态）

眩晕不再是"命中头即晕"的即发效果，而是**累积型异常状态**（玩家与敌人通用）：

- **眩晕值**：0 ~ 100（战斗状态字段，存档持久化）。
- **累积来源**：
  - 命中**头**：**大幅累积**（基础值由攻击/技能配置，如 +30 ~ +40/击；可被头防具比例减免）；
  - 命中**其他部位**：默认 **0**；除非攻击技能显式声明「命中某部位 +X 眩晕」。
- **衰减**：**-1 / tick**（未受击时每 tick 恢复 1 点）——战斗内基本只增不减（单击累积远大于衰减），战斗外慢慢恢复。
- **触发**：眩晕值 **≥ 100** → **眩晕 1 回合**（本回合无法行动，沿用 `09` 规则）→ 眩晕值**归 0**。
- **抗眩晕（头防具专属）**：**比例减免**——受到眩晕累积 × (1 − 豁免%)；豁免% 设上限（~60%），头永远是威胁。任何其他槽位、模块、词条**不提供**抗眩晕。
- **双向**：敌人共用本系统，玩家打敌人头同样累积其眩晕值——「打头眩晕流」是合法战术。

### 9.3 头盔模块化（3 槽）

头部防具 = **头盔底材 + 3 个模块槽**，**不接躯干激活体系**（常驻生效）：

| 槽位 | 定位 | 内容 |
|------|------|------|
| **盔体**（外壳） | 减伤赛道（互斥） | 铁制（劈砍强）/ 皮制（钝击强）/ 硅叶（戳刺强）——防利器 vs 防震荡的取舍 |
| **内衬**（缓冲） | 抗晕 / 补强（互斥） | 软衬（抗眩晕高）/ 硬衬（减伤补强） |
| **护面**（**万能功能槽**） | **不提供被动减伤**；其余效果方向不限 | 照明（夜间命中/视野）、感知、社交、装饰、**可接入伤害结算**等任意功能/效果模块 |

- **护面 = 万能槽**：只要不参与「防御减免」结算，任何奇怪方向都可以——它既是头部装备的"个性"维度，也是未来扩展的出口。
- 盔体/内衬槽内模块互斥（各装 1 个），护面槽装 1 个功能模块；模块本身可有附魔（同躯干模块体系）。

### 9.4 头脆弱性约束（红线）

- 头防具**总减伤上限压住**（远低于躯干激活后的 40~60%，建议 ≤20%）：作用是**保底不秒杀**——普通攻击打头不致死，重击 / 暴击 / 破防才可能爆头死；
- 抗眩晕豁免 **≤60%**——头永远是威胁；
- 头防具**不接激活体系**（常驻），保持「常驻基础弱点」的设定感。

### 9.5 设计含义

- 玩家想对抗"被打头眩晕"，**必须**戴头盔（抗眩晕为头部专属价值）——头盔因此不可替代，即使减伤弱；
- 护面万能槽让头盔不只是防具，还是工具 / 身份 / 个性的载体（电筒、护目镜、装饰、甚至攻击向效果）；
- 平衡锚点：低命中权重（概率闸门）→ 保底减伤（防秒杀）→ 抗眩晕（累积制，头部专属），三道闸共同保证"爆头死"是意外而非日常。

## 10. 开放接口与扩展点（面向未来强化系统）

> 本系统（6 板位模块 + 3 槽头盔 + 激活）是**基础层**；未来可能新增强化系统（如"通过其他手段额外增加词条"）。以下扩展点**必须在实现时预留**，新增强化系统只做"加配置/加 handler/加来源"，不拆核心流程。架构范式对齐畜牧 `32`（声明式 effect + modifier 修正层）。

### 10.1 声明式效果 + handler 注册（核心架构）

- 模块 / 词条 / 特效的效果一律走 **`effect_type` + `effect_params`** + **注册 handler** 分发；**禁止** `switch(effect_id)` 硬编码分发。
- 新增效果类型 = 加配置 + 注册 handler；现有目录（`enchant.json`：`stat_bonus` / `hit_bonus` / `armor_bonus` / `speed_bonus` / `skill_coef`）可随时扩展。
- 例：未来"强化淬炼"系统要加新效果（如"激活时返还底气"），只需新 effect_type + handler，不动核心。

### 10.2 统一修正层（modifier）

- 所有参与结算的数值暴露**修正接口**：`getModifier(key) → number`（乘区默认 1 / 加区默认 0）：
  - 覆盖：减伤（各伤害类型）、**基础盾量**、**激活成本**、抗眩晕、命中、速度、重量等。
- 修正来源**可叠加**（模块 / 材料 / 强化系统 / buff 各自贡献，统一聚合），互不覆盖。
- 例：激活成本 = `base_shield × (1 + Σ模块消耗%) × getModifier('activation_cost')`——未来系统只需往 modifier 里注入。

### 10.3 来源标记（source tag）

- 每条词条 / 效果 / 修正带 **`source`**（如 `module_enchant` / `material` / `enhance` / `buff`）。
- 未来系统可：按来源查询、按来源清理、同源互斥 / 跨源叠加——不互相踩踏。

### 10.4 词条 / 附魔扩展（预留"额外加词条"通道）

- 当前规则：模块 **1 附魔位**。**"1 条"是规则层约束，不是结构硬编码**：
  - 实例层词条以**多来源集合**存在（如 `enchants: [{ enchant_id, source }]` 或等价），来源可混。
  - 未来"通过其他手段额外增加词条"的系统 = 往集合里加带新 `source` 的条目，并各自声明上限；不需要改结构。
- 防具级 / 模块级 / 全局级词条共用同一集合形态，按 `source` + 挂载对象区分作用域。

### 10.5 槽位与占用扩展

- 槽位数量**不写死**：底材 `module_slots` 可配置；未来可开"额外槽"（如强化解锁新板位、头盔加槽）。
- 模块 `occupies`（跨槽位槽点集合）已是开放声明；新槽位类型只需扩展**槽点命名空间**（如 `clothing.extra1`、`head.face2`），占用 / 结算逻辑不变。

### 10.6 激活机制扩展

- 激活成本 / 盾量 / 减伤公式的所有输入暴露为**可修正变量**（见 10.2）。
- 未来特效（"残盾回收"退还底气、减耗模块、延长盾、二次激活）通过 `effect_type` + modifier 接入，**不改核心流程**。

### 10.7 存档结构预留

- 实例格式预留开放容器：`extras` / `overrides`（对齐变式的 `variant_effect_param_overrides` 思路），供未来系统写入而不破坏读档。
- 存档版本号：模块化改造引入存档世代变更时，保留迁移钩子（旧档 → 白板底材 → 未来系统逐层补全）。
