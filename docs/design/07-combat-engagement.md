# 角色战斗状态与进战反馈

日期：2026-09-10。状态：已实现。本文是 [战斗核心](07-combat-core.md) 的补充；进战、脱战的判定以本文为准。

## 1. 状态语义

玩家有「非战斗」「战斗中」两种状态。被敌人发现并开始追击即进入战斗，不必等到第一次受击。主动攻击同样建立交战关系。

战斗状态由当前地图中与玩家交战的存活敌人实例集合决定。集合非空即战斗中；一个敌人死亡或放弃追击，不影响其他交战关系。攻击范围、邻接关系、技能面板开关、渲染性能模式均不能替代战斗状态。

第一版覆盖玩家与敌人的交战关系，不扩展 NPC 互殴、阵营战争等系统。

## 2. 进入战斗

- 敌人 AI 从未追击转为追击玩家时，将该敌人加入交战集合。
- 玩家主动攻击：目标、距离等前置校验通过，确认攻击将执行后，在命中、招架和伤害结算前登记交战，同时通知目标 AI 建立仇恨。
- 敌人主动攻击或反击也使用同一登记入口，操作须幂等。
- 未命中、被招架或最终伤害为 0 均算交战。失败的攻击意图（无效目标、超出范围、前置条件拒绝）不触发进战。
- 同速演算、伤害预览等模拟过程不得提交交战状态或发出提示；在真实攻击执行入口登记一次。

### 主动攻击与距离规则

玩家可以在尚未被发现时先手攻击。该攻击建立的仇恨不能在同一行动内被普通发现距离或脱离距离检查立即清掉。

实现须让目标在这次 AI 响应中按已交战状态作出决策，再于后续世界 tick 按既有追击、放弃追击规则判断脱战。响应可以是移动、攻击或因阻挡无法行动，不要求强制命中或凭空移动。保护按世界 tick/行动批次记录，不使用现实时间计时器。已死亡或已离场目标不受此保护。

## 3. 保持与退出

- 仍有敌人在追击或交战时保持战斗；暂时拉开一格、被障碍物阻挡、敌人本回合未移动均不自动脱战。
- 敌人明确放弃追击、死亡或离场时移除对应关系。
- 进入战斗即时提交；退出战斗在当前行动的攻击、死亡处理与 tick 末位移全部收束后统一确认，避免同一回合反复切换。
- 最后一名敌人被一击击杀：攻击时进战，行动收束后脱战。两条切换日志允许存在，最终 HUD 必须为非战斗。
- 不额外引入脱战倒计时；追击和脱离距离沿用敌人 AI 配置。
- 玩家死亡时清空关系；复活后根据新场景重新判断。
- 成功切图后清空旧地图交战关系，目的地图按正常 AI 判定建立新关系；切图被拒绝不能清空。本文不增加战斗中禁止切图的规则。
- 新游戏清空状态；读档恢复交战关系及必要的 AI 仇恨状态，剔除失效实例。旧档缺字段时按当前场景和 AI 规则重建。恢复 HUD 不重播进战日志，也不额外推进 tick。

## 4. 模块与接线

实现位于 `js/combat-engagement.js`，全局名 `CombatEngagement`。对外提供统一查询 `isPlayerInCombat()`，内部维护交战实例集合、进战原因及主动攻击响应保护信息。

实例标识必须稳定且区分同种敌人，不可仅使用敌人模板 ID，也不能在数组删除后将旧下标误认成其他实例。实现前检查当前敌人运行时与存档标识方案，必要时补兼容迁移。

接线职责：

| 层 | 职责 |
| --- | --- |
| `CombatEnemies.updateEnemyAI()` | 产生开始追击、保持追击、放弃追击的事实，接受主动攻击建立仇恨 |
| `CombatWorld.tickEnemiesAfterWorldTick()` | 提交 AI 变化；敌人攻击入口确保登记交战 |
| 玩家攻击入口 | 前置校验成功后、真实命中结算前登记交战 |
| 敌人死亡落地、切图、死亡/复活、存读档入口 | 清理、恢复对应关系 |
| 行动/tick 收束入口 | 在死亡及末位移之后确认最终脱战状态 |
| 场景组合层 | 接收状态变化，刷新 HUD 和写入日志 |

状态模块提供变化通知，不直接操作 DOM。场景层沿用 `SceneHud.refresh(...)` 刷新通道与 `GameLog` 日志通道。普通重绘只查询状态，不修改仇恨、不推进 tick、不重复写日志。

现有 `Survival.advanceTick` 包装中，生存更新先于敌人 AI；实现须核实完整攻击及末位移的真实顺序，不能假定敌人 AI 函数末尾就是整轮收束点。本次不修改恢复倍率或额外加入战斗中休整限制。

## 5. 玩家反馈与已有规则迁移

- 在角色状态区显示常驻文字徽标：`⚔ 战斗中` / `非战斗`。战斗态使用与现有 UI 一致的强调色，同时保留文字，不能仅靠颜色表达。
- 真正切换状态时，使用现有 `GameLog` 显示「你已进入战斗」「你已脱离战斗」。多个敌人加入或离开但玩家总状态没变时，不重复提示。
- 文案进入 `data/ui_text_zhCN.json`，沿用项目取词方式。
- 头顶呼吸条的战斗条件读取统一状态，保留原有呼吸法、气力值和战斗感知等级等显示条件。
- 外敷、注射的战斗门禁改读统一状态，保留注射静止要求等独立条件。
- 已有仅战斗中可用的动作读取统一状态；动作若还需要相邻目标或攻击范围，则继续独立校验。
- 区分 `renderProfile` 性能策略和玩法状态，打开战斗技能面板不能触发进战、日志或用药限制。
- 本次不顺带增加装备切换限制、资源重置、恢复倍率或其他玩法限制。呼吸条仍按 07 的常驻资源规则运行。

## 6. 验收场景

1. 敌人开始追击但尚未贴身：HUD 进入战斗，日志仅一条，用药门禁同步。
2. 未被追击时主动攻击：命中前进战，目标获得仇恨；未命中、招架及 0 伤害结果一致。
3. 目标在普通发现范围外：有效先手攻击仍进战；同一行动不因距离立即清仇恨，后续可正常脱战。
4. 无效目标、超范围等被拒绝攻击：不进战。
5. 多敌人及同模板多实例：单个死亡、数组移除或放弃追击不误清其他关系；最后一个离场才脱战。
6. 击退、阻挡或临时不相邻：依 AI 追击状态保持，攻击范围仍独立验证。
7. 一击击杀最后敌人、同速双方死亡：无悬挂交战关系，最终 HUD 正确，模拟不发日志。
8. 成功/失败切图、死亡复活、新游戏、读新旧档：清理或恢复正确，无多余 tick 和重复进战提示。
9. 打开/关闭技能面板、连续 HUD 重绘：不改变交战状态。
10. 外敷/注射、战斗限定动作、头顶气力显示共用状态；原有独立条件不丢失。

## 7. 实现记录

2026-09-10 已完成：

- `CombatEngagement` 统一维护玩家交战集合；同模板多实例使用运行时实例标识，敌人数组删除后同步 AI 下标状态。

- 存档增加可选 `combat_engagement` 字段；旧档缺失时安全回到非战斗，后续世界 tick 按 AI 规则重建。
