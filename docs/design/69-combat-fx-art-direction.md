# 69 · 攻击特效规范与正式接入

2026-10-02。用户确认试作第 13 版的卡通笔触、招式辨识度与鞭腿方向，批准接入游戏。本文件为后续攻击特效的正式规范；[试作记录](combat-fx-prototype.md)保留探索过程，不将此前被否定的方案作为标准。

## 视觉基准

- 默认演出速度 **1.5×**。只压缩视觉时间，不修改玩法速度、先后手、消耗、伤害或连击判定。
- 采用夸张的日式战斗动画笔触：宽实色运动面、深色边缘、细亮芯、收尖拖痕和短促的接触泼墨。144px 格宽下也应明显、可辨认。
- 运动痕迹从出招者的手、脚附近展开，体现伸拳、送脚、扫击与回收。禁止把独立拳头、鞋子或光球当飞行道具投过去；禁止封闭机械管状肢体、关节球或从腹部凭空长出大腿。
- 锚点只是现有棋子的视觉近似位置，不是骨架数据。不重画棋子、不拆装肢体、不改变头身比例、底座或投影；不得恢复已停止的骨骼实验。
- 出手连续加速，接触干脆，余势快速淡出；不能在命中前悬停。局部爆点足够醒目，但不用持续光墙、全屏闪光或抖屏遮挡战场。
- 正式地图先绘制昼夜遮罩，再绘制攻击特效，最后绘制视野遮挡与距离压暗。昼夜亮区的 `destination-out` 擦除只作用于遮罩，不能擦掉笔触和伤害文字；不可视区域仍受原有遮挡约束。

2026-10-02 接入补正：用户发现正式游戏特效很淡。原先验收仅调用 `SceneAnimation`，遗漏了正式场景随后执行的昼夜擦除，同一画布的近身特效因此被擦掉约 95%，再叠加夜色压暗。现将完整合成统一为 `SceneRenderer.renderEffects`，正式地图和验收页共同使用；验收页增加正午、午夜与无光照对照。`tools/test-scene-fx-composition.mjs` 通过真实合成入口检查笔触不会被亮区擦除，已纳入 `test:combat-fx`。修正绘制顺序，不改变已确认的颜色、笔触或 1.5× 节奏。

## 九招的辨识特征

2026-10-02 原型对齐补正：用户明确要求与已确认的 demo 完全一致，不再调整美术。撤回未提交的加粗、增亮与延长峰值方案，保留第 13 版原始笔触、透明度和 1.5×。除共用笔触外，试玩与正式游戏现在通过 `CombatFxPresentation` 共用起势锚点、完整棋子前送/退震、横扫轨迹、接触细节和淡出曲线；补齐原先漏接的招架外弧与吸收轮廓。正式连段间隔与整招后还击间隔也按 demo 对齐。

正式主角是地图之外的 DOM 图层，原先遮住了画布内的攻击笔触。攻击现置于独立前景画布，在双方棋子之后绘制，与地图同步镜头和平移；昼夜擦除不作用于该层，不可视区仍按正式视野遮蔽。棋子只做整身屏幕偏移，原图册变换、骨架和占格不变。验收必须比较同招式、同出招侧、同命中部位、同结果和同时间点；闪避或底气不足不能拿来与 demo 的默认命中爆点比较。

2026-10-03 连续播放与细笔触补正：用户再次明确以第 13 版水墨挥洒感为准。发现此前共用绘图和指定关键帧仍遗漏两项 demo 的运行方式：正式特效画布未按设备像素密度建图，且直接按现实时间推进，长结算或后台停顿可能跳过笔触展开和接触帧。攻击前景层现在与 demo 一样按 `devicePixelRatio` 绘制；动画推进共用 `frameDelta`，每次实际动画帧最多计入 60ms，再按 1.5× 播放。同步场景重绘不消耗未呈现的攻击帧；天气和旧场景效果仍使用原时钟。原始笔触库、颜色、形状、拖尾和透明度不变。此修正针对已复现的掉帧时间差与已观测到的 1× / 1.25× 画布差异，不将其说成已经证明是用户所有观感差异的唯一原因。

| 招式 ID | 颜色与轮廓 | 动作方向与接触特征 |
|---|---|---|

## 结算驱动与变式

正式流程是：战斗管线捕获出招坐标 → 完成实际逐段结算 → 在位移执行前发出 `combat:resolved` → 地图 FX 层播放。事件独立复制坐标和结果，后续敌人移动、上下文复用不改变已经发生的一击。

一个动作事件包含 `actionId`、`mapId`、双方坐标与身份、可选同速 `groupId`，以及实际 `segmentsResults` 映射出的逐段数组。每段包含招式、出招肢、命中部位、结果、实际伤害、伤害类型和可选表现强度。单段动作按同一格式处理。

- 特效段数取自**实际结算结果**，不重新读招式基础段数来猜测，也不自行读取装备后增伤或补打。
- 变式将结算改为三段时，表现层播放三段，各自显示命中、招架或闪开及对应真实伤害。碎屑、残影、双掌、双指都不是额外攻击。
- 可选 `fxMoveId` / 招式模板 `fx_move_id` 指定共用视觉；可选 `fxPowerFactor` 调整接触强度，缺省为 1。特效不会用伤害数字反推出未经定义的强度规则。
- 当前正式 `move-variants.json` 尚无装备变式条目。这次交付的是兼容实际段数和结果的表现层，**没有新增“三次、每次 50%”等玩法数值**。以后实现改变段数的装备效果，须在战斗管线分段前解析；仅在某段内部修改变式不足以新增结算段。

零伤害按原因区分，优先次序为：距离挥空 → 资源不足 → 未命中 → 招架 → 防具完全吸收 → 命中。单纯伤害为 0 不自动当作闪避或防具吸收。

- 命中：对应招式的接触爆点与实际伤害。
- 招架、完全吸收：各自的承力反馈，不叠加命中爆点。
- 闪开、距离挥空、乏力：对应运动与文字，不生成命中爆点。
- 不凭视觉预设添加流血、淤伤、眩晕等玩法状态。

## 时序与运行范围

1. 普通交手按涉及双方的动作队列播放，整招完成后再显示还击；不以旧的 120ms 节流丢弃真实连段。
2. 同速交手只在结算提交时发事件，试算不发。双方共用组 ID，起势和接触时刻对齐；不同招式的预备时长也不能造成假先后手。
3. 正蹬等位移前的接触采用当时坐标；随后还击采用其自身结算时的坐标和原因。因此击退导致的挥空、撞阻眩晕导致的取消还击均沿用正式结果。
4. 地图切换、地图对象替换及动画清理会清空队列。动作 ID 去重；最多保留 64 个动作、512 个去重 ID、128 个同速组。
5. 新动作已发完整结果时，旧 `combat:attack` 粒子跳过，避免旧红点/飞线与新效果重叠。

当前接入负责攻击笔触、接触反馈、逐段文字，以及与 demo 相同的整枚棋子前送、受击退震和闪避偏移。**生命值、世界格位移、死亡等仍按原有玩法立即更新**，特效按发生时坐标回放；已离开发生格的角色不再套用旧格上的视觉偏移。尚未把冲锋、击退位移与死亡显示统一延迟到演出时刻，不将这些范围宣称为完整角色动画。

## 实现与验收

- `js/combat-fx-paint.js`：第 13 版的唯一正式绘制源；试玩的 `combat-fx-limbs-prototype.mjs` 仅转接此模块。
- `js/combat-fx-presentation.js`：试玩和游戏共用的招式编排、接触细节及完整棋子视觉偏移。
- `js/combat-fx-events.js`：捕获坐标、将真实结果转为表现事件。
- `js/combat-fx-runtime.js`：1.5× 调度、地图投影、动作映射、去重和清理。
- `js/combat-pipeline.js`、`js/scene-app.js`、`js/scene-animation.js`：管线、同速组与地图 FX 层接线。敌方旧动作在 `data/combat-enemies.json` 显式关联共用视觉，伤害数值不变。

回归入口：`npm run test:combat-fx`、`node tools/test-breath-burst.mjs`。覆盖实际分段、坐标快照、同速试算/提交、不同招式同时接触、普通还击、零伤害原因、九招六类结果八向绘制和地图清理；催气测试覆盖先手击退后挥空、撞阻取消还击和正式敌方动作入口。

`tools/fixtures/combat-fx-demo-v13.mjs` 保存提交 `a87d173` 中原 demo 的编排作为独立对照，不随正式实现修改。`tools/test-combat-fx-demo-parity.mjs` 比较 1,620 个关键帧的实际绘制命令、透明度、接触细节及双方棋子偏移，防止两个入口一起改错后仍自称一致。

`tools/test-combat-fx-playback.mjs` 覆盖首帧延迟、连续掉帧与后台停顿，并通过真实地图动画循环验证同步结算重绘不会跳过水墨演出、攻击时钟与环境时钟独立、高分屏密度及镜头对齐。指定关键帧相同不能替代连续播放验收。

伤害、资源消耗、交战、地图切换与等距地图回归亦通过。浏览器验收页 `/tools/combat-fx-runtime-check.html?no_reload=&view=isometric` 使用正式战斗管线、绘制器、地图投影和 FX 层，在隔离情境下检查效果，不读写玩家存档；它的脚本命中和伤害配置不属于游戏平衡。已检查鞭腿方向、双方逐段结果及同速表现，无浏览器错误。数值回归和隔离画面验收不等同于所有装备、地图和完整角色动画均已人工验收。
