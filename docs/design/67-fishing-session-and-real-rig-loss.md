# 67 钓鱼作业状态、真实受力与连接损失

状态：2026-09-22 已完成第一版底层闭环，对应 k278 第五阶段。

本阶段让[62号设计](62-fishing-and-capture-system.md)的作业过程直接读取[65号设计](65-item-assembly-and-combined-weight.md)中的真实钓组。作业状态不复制物品树，也不把临时张力写入物品永久属性。

## 1. 状态边界

`js/fishing-session.js` 保存一次进行中作业所需的最小状态：

- 所用钓组的稳定实例引用；
- `ready → waiting → signal → fight → landed / ended` 阶段；
- 已经过的整数 tick；
- 已经发生的接触事件及其行为位置；
- 当前挂牢程度、收鱼进度和连续过载计数；
- 待处理的上岸结果与最近一次部件损失。

鱼竿、主线、子线、鱼钩、鱼饵、永久磨损和损坏状态仍保存在物品实例及 `connections` 中。存档恢复时先恢复库存，再恢复作业引用；引用不存在、计数非法或版本错误的作业状态会被拒绝。旧档没有 `fishing` 字段时按无进行中作业处理。

钓组从投放到收回、断线或上岸处理期间会被锁定。背包装配界面继续可见，但 `ItemAssembly` 拒绝玩家主动连接或拆下其中任何节点。作业内部已经结算的吃饵、断裂和切线使用专门的销毁接口，不绕过玩家拆装的接收空间规则。

## 2. 生态事件与作业执行分开

`FishingSession` 不抽取鱼种、点位资源或上钩概率。未来水域/生态系统在接触已经发生后，通过 `acceptContactEvent` 提交一次确定事件。事件包含配置给出的负载、耐力、钩型适配和有限行为序列。

作业层只负责：

1. 校验当前真实钓组具有必要连接，且没有已损坏部件；
2. 支付配置中的体力和整数 tick；
3. 消耗实际连接在鱼钩上的那一份鱼饵；
4. 依次读取已保存的鱼行为，不在读档后重新抽取；
5. 把本次游戏负载与各承力部件配置比较；
6. 更新部件磨损，或在断点处分离并销毁真实下游连接树；
7. 向玩家只返回阶段和现象反馈。

因此同一事件状态、相同钓组与相同行动会得到相同的断点和损失。当前实现没有水下坐标、连续拉力、线段物理或逐帧模拟。

## 3. 首版负载与磨损

正式物品目录增加 `equipment.fishing_tackle.fishing_load_rating` 模板字段，并在实例状态中登记 `fishing_wear_stage`、`fishing_broken`。首套基础钓组的游戏承载档为：

| 部件 | 基础承载档 |
|---|---:|
| 基础手竿 | 4 |
| 细尼龙主线 | 3 |
| 尼龙子线 | 2 |
| 小号单钩 | 3 |

有效承载为基础档减磨损阶段，最低为 1。负载不超过有效承载时，连续过载计数逐步恢复；高 1 档时累计过载并形成一阶段永久磨损；达到配置的连续次数时断裂；高 2 档及以上立即断裂。多个部件同时达到断裂条件时，优先选择有效承载最低者，相同时选择连接树更下游者。

这些是首版可验证规则，不代表现实拉力单位，也不替首塘最终数值定案。以后调整差异应修改 `data/fishing-session-config.json` 或物品字段，而不是增加物理求解。

## 4. 实际损失

`ItemAssembly.discardConnectionSubtree` 是已结算消耗/损坏的通用接口。它在快照事务内收集并移除指定槽位的完整下游树，返回物品清单与总重量，然后再次检查结构和唯一归属。

- 鱼饵被吃掉：只移除鱼钩 `bait` 槽中的那一份真实鱼饵；
- 子线断裂：移除子线及当时仍连在它下面的鱼钩、鱼饵等；
- 主动切线：移除鱼竿 `main_line` 以下当前存在的整棵结构；
- 根鱼竿事故损坏：保留根实例并标记损坏，不凭空删除整套库存物品。

基础完整钓组重量为 `0.526 kg`。在挂饵仍存在时从主线切断会丢失 6 件、`0.076 kg`，背包中只留下 `0.450 kg` 的鱼竿。断点不是固定写死为子线；由当次负载与各实际部件状态决定。

## 5. 鱼饵腐坏与信息边界

`HideoutWarehouse.tickSpoilage` 现在沿物品真实归属树递归推进腐败。连接在鱼钩上的易腐鱼饵不会因为不占背包格而停止计时；到期时只删除该连接节点，不删除宿主。

作业记录投放时的鱼饵身份。鱼饵在水下腐坏后，等待阶段仍只显示水面可观察现象；玩家收回钓组检查时才得到“鱼饵不见了”的反馈。`getPublicState` 不包含钓组实例编号、接触事件身份、鱼种、隐藏负载或行为序列。

## 6. 正式接线与验收

- `index.html` 加载 `FishingSession`；
- `SceneApp` 加载 `data/fishing-session-config.json`；
- `SaveSystem` 的正式快照保存、校验和恢复 `fishing`；
- `ItemAssembly` 在进行中作业拒绝玩家装卸；
- `HideoutWarehouse` 递归处理连接后代的腐败；
- `tools/fishing-session-acceptance.html` 展示三组可重复情境。

自动验收：

```text
npm run test:fishing-session
npm run test:item-assembly
npm run test:item-assembly-display
npm run test:item-instances
npm run test:hideout-warehouse
```

`test:fishing-session` 覆盖挂饵精确消耗、作业锁定、第一次过载磨损、存档恢复行为位置、第二次受力在子线断裂、按断点丢失、主动切线、连接鱼饵腐坏、收竿延迟反馈、体力不足不变更状态、公开信息不泄露以及正式存档包往返。
