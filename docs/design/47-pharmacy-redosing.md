# 重复用药与持续时间刷新

状态：用户已确认设计，尚未据此修改运行时。

## 已确认规则

重复服用同一种药，持续窗口从本次成功使用重新计时，按本次应得时长刷新，不将剩余时间与新窗口相加。每次成功使用照常消耗药品，并完整结算该次应增加的依赖与毒性；仍应用已经定义的成分、剂量、途径和免疫修正，不因已有同名药效而豁免，不将应得增量误作无修正固定值。

例：苦根镇痛丸基础窗口90 tick，剩20 tick时再次成功使用，刷新为90 tick，不变成110 tick。按免疫0的已定设计，本次仍增加依赖0.25、体内毒性2.4；这是待部署的数值，不表示当前代码已接入。

实现必须区分“药品成功使用”和“首次新增buff”。不能因同名buff已经存在而跳过消耗、成瘾或毒性结算；同一次使用也不能因刷新或重新挂载buff被重复结算。失败或取消的使用不算一次成功服用。

## 与既定规则衔接

镇痛仍取最高已起效比例，不叠加强度。依赖与体内毒性独立于主药效持续时间：刷新药效不清空两者，也不停止已定自然代谢。戒断缓解与对应主药效同步结束，不另开独立尾段。

不同成品共用同一buff模板时的刷新身份仍需部署前明确，不能把“同一药效族”直接当作“同一种药”。已定不同强度镇痛各自计时、取最高值的规则不变。

界面应明确显示重复服用将刷新窗口，并提示本次依赖与毒性仍会增加；具体数值展示遵守既有分阶段信息规则。

## 续药的起效衔接（已确认）

- 原药已起效且尚未结束：重复服用刷新结束时间，保留已起效状态，药效不中断。
- 原药仍在起效等待中：保留原起效时刻，不重新倒计时；结束时间按最后一次成功服用及其应得总窗口刷新。
- 换用更强的药：新药按自身起效等待计时，期间旧药继续生效；新药起效后按最高效果规则判定。
- 原药已结束：重新使用须正常等待起效。是否已结束沿用统一buff到期判定，避免边界tick各模块判断不一致。

以上各情形每次成功服用均照常增加依赖与毒性，不因起效连续或仍在等待而免除。持续窗口包含起效等待的口径不变，不能通过保留起效时间额外叠加剩余时长。戒断缓解随对应主药效的起效状态与结束时间衔接。以上仍为待实装设计。
