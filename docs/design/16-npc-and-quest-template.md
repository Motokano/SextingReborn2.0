## NPC 与任务模板 — 可复用字段清单与伪数据结构

本文件定义**通用 NPC 行为模板、触发条目（Trigger Entry）模板与任务（Quest）模板**，并给出首个示例 NPC「林书瑶（林经理）」的配置摘要。

目标是：后续新增 NPC 或任务时，可以**完全不再重新解释规则**，而是直接照本文件的字段与伪数据结构填表。

---

## 一、NPC 行为模板

本节定义「一个 NPC 在场景里是怎么存在、怎么被交互（点击或方向输入触发）、交互后出现什么菜单、菜单项如何显示/隐藏」的最小字段集合。

### 1. 出现规则（Appearance）

- **基础字段**
  - `id`: NPC 唯一 ID（如 `"npc.supervisor.linShuyao"`）。
  - `name`: NPC 展示名（如 `"林书瑶"`）。
  - `displayTitle`: 展示称呼（如 `"林经理"`）。
  - `appearanceSchedule`:
    - 结构示例：`{ start: "09:00", end: "17:30" }`
    - 语义：**只在该时间段内实际出现在场景里**。
  - `location`:
    - 结构示例：`{ sceneId: "base_main", x: 10, y: 3 }`
    - 语义：NPC 在何处被看见与交互（通常是基地某个固定位置）。

- **下班行为**
  - 非 `appearanceSchedule` 时间段内：
    - **NPC 不存在**于场景中。
    - **没有任何可点击的交互点**（不出现“她下班了”之类提示）。

> 说明：若后续某 NPC 需要“留一个门铃/留言簿”，应通过**额外场景物件**实现，而不是本 NPC 模板本身。

### 2. 交互入口（Main Menu）

玩家与 NPC 交互后进入主菜单。最小菜单建议为：

- 交互触发支持两种入口：
  - 鼠标左键点击 NPC（保留原逻辑）。
  - 玩家位于 NPC 交互范围内（默认相邻 1 格，8 邻域），并朝 NPC 所在格输入方向（8 向，含对角）时触发对话。

- `闲聊`
- `工作/任务`
- `离开`

其中：

- `闲聊`：
  - 进入「触发条目扫描 → 默认台词池」逻辑（见下文「触发条目模板」）。
- `工作/任务`：
  - 进入任务列表 UI。
  - **显示条件**：存在「可接（`Available`）」或「可交付/可结算」任务之一时显示；两者都没有时**隐藏按钮**。
- `离开`：
  - 关闭对话，返回场景。

字段示例：

```text
NpcMainMenu {
  showChat: boolean;            // 是否展示「闲聊」
  showWorkWhen: "hasAvailableOrTurnIn"; // 当前策略：有可接或可交付任务时显示
  showLeave: boolean;           // 是否展示「离开」
}
```

### 3. 对话流转与重效果

- **触发条目播完后流转**：
  - 默认：**回到主菜单**，而不是自动结束对话。
- **重效果（强引导 / 自动接任务 / 改世界 / NPC 消失）**
  - 默认策略：**不弹确认，直接执行**。
  - 若后续需要某条目弹确认，可在该条目上单独扩展字段（例如 `requiresConfirm: true`）。

## 二、触发条目模板（Trigger Entry）

本节定义「当玩家通过交互入口进入主菜单并点了 `闲聊` 之后，系统如何决定播出哪段对话，以及这段对话会不会解锁任务、改变世界、让 NPC 消失」。

### 1. 条目标识与组织方式

- 每个条目都有**唯一 ID**：
  - 统一建议前缀：`supervisor.*`（若为监督者系 NPC），或按 NPC 命名空间，如 `npc.<npcId>.*`。
  - 示例：
    - `supervisor.firstTalk_01`
    - `supervisor.languageFix_01`

- 条目不按“主题模块”（技能/物品/地图）分组，而是**完全按「IF 条件 → 触发一次性事件」的粒度独立存在**。

### 2. 条件（condition）

- 条件可以引用**任何可供判断的游戏数据接口**，包括但不限于：
  - 技能：已学会/某技能等级 ≥ X。
  - 物品：背包持有某物品 / 数量 ≥ X。
  - 进度 flag：某剧情 flag 为 `true` 或数值 ≥ X。
  - 时间：游戏时间段/日期/星期等。
  - 地点/地图状态：某地图已解锁、某建筑等级、某资源点状态等。
  - 玩家状态：属性、各类生存值、受伤状态、金钱数量等。
  - 与 NPC/阵营的好感/信任值。
  - 重复门槛：冷却已过、重复次数未超上限。

- 结构示例（伪代码）：

```text
Condition {
  // 由实现方决定表达方式：表达式树 / 脚本 / 结构化条件等
  // 这里只规定：可以访问任意游戏数据接口。
}
```

### 3. 关系约束（requires / blocks）

为避免剧情乱序或互斥条目同时出现，引入**显式关系字段**：

- `requires: string[]`
  - 前置条目 ID 列表。
  - 含义：只有当这些条目都已经处于“已触发”状态时，本条才有机会被触发。
- `blocks: string[]`
  - 被屏蔽条目 ID 列表。
  - 含义：本条一旦触发，这些条目将永远不再触发。

> 说明：复杂的先后顺序与互斥可同时借助 `requires` 与 `blocks` 实现。

### 4. 对话结构（dialogue）

- 默认形态：
  - 纯文本多句，无选项。
  - 适合「她说几句，然后结束本条，回到主菜单」。
- 可选分支：
  - 字段：`hasOptions: true`。
  - 可定义选项数组，每个选项：
    - 写入对应 flag。
    - 触发不同的 `effects`（例如分支到不同任务、不同世界状态）。

伪结构示例：

```text
Dialogue {
  lines: string[];           // 逐句台词（由策划手写）
  hasOptions?: boolean;
  options?: DialogueOption[];
}

DialogueOption {
  id: string;                // 选项 ID
  text: string;              // 选项文案
  setFlags?: Effect[];       // 选中后写入的 flag（或更广义的效果）
  nextDialogueId?: string;   // 若有多段对话，可指向下一个对话块
}
```

### 5. 效果（effects）

触发条目可以附带任意效果。为保持可扩展性，本设计规定：

- **效果是“全开放”的**：
  - 只要游戏逻辑层提供接口，就可以在 `effects` 中调用。
- 常见例子包括：
  - 给物品 / 扣物品。
  - 改变 flag / 数值（属性、好感等）。
  - 解锁任务：`unlockTaskIds: string[]`。
  - 自动接任务 / 自动完成任务。
  - 改变地图状态 / 解锁新区域 / 刷新点位。
  - 改变 NPC 的出现时间、位置或行为。
  - 让 NPC **消失**（并在消失瞬间应用一组世界改变）。

伪结构示例（不限定类型）：

```text
Effect {
  // 示例字段（实际可按实现需要扩展）
  type: string;              // "giveItem" | "setFlag" | "unlockTask" | "modifySkill" | ...
  params: any;               // 参数由具体 type 决定
}
```

对于「消失并改世界」的特殊条目，建议增加布尔字段：

- `causesNpcDisappear: boolean`
  - `true` 时：本条触发后，该 NPC 当场从场景中消失，并立即执行所有世界改变效果；NPC 将在**次日上班时间**重新出现。

### 6. 一次性与作用域（repeat / scope）

- 默认行为：
  - `repeatable: false`。
  - 一条条目在**同一存档中只触发一次**。
- 作用域：
  - 字段：`scope`。
  - 可选值示例：
    - `"global"`：全局存档级，只要触发过就永不再触发（默认）。
    - `"region"`：某区域内一次性，切换到其他区域可重新触发。
    - `"daily"` / `"weekly"`：按游戏内时间周期重置。

- 可重复条目：
  - `repeatable: true` 时，建议额外配置：
    - `cooldown`: 如 `"1d"`, `"3d"`, `"7d"`。
    - `maxRepeats`: 最大重复次数（可选；不填则视为无限次）。
  - 条目逻辑可通过「上次触发时间 + 次数」配合 `scope` 实现复杂重置策略。

### 7. 闲聊扫描规则

当玩家在主菜单选择「闲聊」时，按如下顺序处理：

1. **扫描所有触发条目**：
   - 范围：包括普通对话条目、解锁任务条目、自动接任务、改世界条目、以及「消失并改世界」条目。
   - 条件成立的条目形成候选集合。
2. **同次多条命中**：
   - 从候选集合中**等概率随机抽取 1 条**执行。
3. **没有任何条目命中**：
   - 进入默认台词池（摸鱼）：
     - 从预先配置的台词池中**等概率随机一句**（例如嚼槟榔、抽烟、抱怨上班等）。
4. **条件检测时机**：
   - 在玩家点下「闲聊」并进入对话时做一次条件扫描。
   - **本次对话过程中不再重新扫描**；新的条件变化将在玩家下次点「闲聊」时再判断。

### 8. 触发条目伪数据结构

```text
TriggerEntry {
  id: string;                        // 唯一 ID（推荐命名空间 supervisor.* 或 npc.*）
  condition: Condition;              // 条件表达式：任意游戏数据接口
  requires?: string[];               // 前置条目 id
  blocks?: string[];                 // 触发后屏蔽的条目 id
  dialogue: Dialogue;                // 纯文本 或 带选项
  effects?: Effect[];                // 全开放效果（含解锁任务、改世界等）
  repeatable?: boolean;              // 是否可重复
  scope?: "global"|"region"|"daily"|"weekly"; // 已触发状态的作用域
  causesNpcDisappear?: boolean;      // 若 true，触发时 NPC 当场消失并应用世界改变
}
```

## 三、任务模板（Quest）

本节定义「任务」的最小状态机与字段结构，供 `工作/任务` 菜单使用。

### 1. 状态机（最小集合）

推荐任务状态集合：

```text
Locked     // 已存在于系统中，但尚未解锁显示
Available  // 可接任务（按钮可见，可接取）
Accepted   // 已接任务，进行中
Completed  // 已完成（并结算）
Failed     // 已失败（进入终态）
Abandoned  // 玩家主动放弃
```

### 2. 结构与形态

- **默认形态**：单段式
  - `接取 → 达成条件 → 交付/结算`。
  - 适合大多数「工作流」或小任务。
- **可升级形态**：
  - 多阶段链：
    - 任务拆成 `阶段 1 → 阶段 2 → 阶段 3 ...`。
    - 每阶段拥有自己的触发/目标/结算。
  - 节点图：
    - 允许分支、互斥、合流。
    - 适用于复杂剧情或多解法任务。

本文件只给出最小字段，复杂形态由实现方在 `objectives` 或额外图结构中表达。

### 3. 解锁与显示

- 解锁来源：
  - 通常由触发条目在 `effects` 中调用：
    - `unlockTaskIds: string[]`。
- 解锁后的可见性：
  - 一旦任务被解锁，便**永久出现在「工作/任务」列表**中，直到任务进入 `Completed` / `Failed` / `Abandoned` 等终态。
  - 当前设计中：任务入口本身不做额外时间/周期隐藏。

### 4. 失败 / 放弃策略

- 字段：
  - `allowAbandon`: 是否允许玩家主动放弃。
  - `allowFail`: 是否存在失败分支（例如时间用尽、条件被破坏）。
  - `onFail`: 失败后的去向策略：
    - `"remove"`：从列表中移除。
    - `"archive"`：移入“已失败”归档。
    - `"allowRetry"`：允许一定条件下重试（通常配合 `repeatable`、`cooldown`、`maxRepeats`）。

### 5. 可重复任务

- 字段：
  - `repeatable`: 是否可重复。
  - `cooldown`: 重复间隔（如 `"1d"`, `"7d"` 等）。
  - `maxRepeats`: 最大重复次数（可选）。
- 行为：
  - 当任务完成/失败/放弃后，若满足 `repeatable` 条件，并且未超过 `maxRepeats`，且 `cooldown` 已过，则任务可重新进入 `Available` 状态。

### 6. 列表展示

- 任务列表展示位置：`工作/任务` 菜单。
- 当前设计：
  - **不做排序规则约束**（可按配置顺序或实现默认排序）。
  - **不强制提供筛选/搜索**（可在未来版本追加）。
  - 玩家从全量列表中自行选择要查看/接取/操作的任务。

### 7. 任务伪数据结构

```text
Quest {
  id: string;
  state: "Locked"|"Available"|"Accepted"|"Completed"|"Failed"|"Abandoned";

  title: string;                    // 任务名
  description: string;              // 任务描述

  acceptConditions?: Condition;     // 可接条件
  objectives: Objective[];          // 目标列表（单段/多阶段统一用该字段表达）
  turnInConditions?: Condition;     // 交付/结算条件

  allowAbandon?: boolean;
  allowFail?: boolean;
  onFail?: "remove"|"archive"|"allowRetry";

  repeatable?: boolean;
  cooldown?: string;                // 重复冷却，例如 "1d", "7d"
  maxRepeats?: number;              // 最大可重复次数
}
```

> 说明：`Objective`、`Condition` 等结构可依照战斗/生存/收集等系统再细化，这里只定义接口层面存在该概念。

## 四、首例 NPC：林书瑶（林经理）配置摘要

本节将「林书瑶（林经理）」作为**首个按本模板实现的 NPC**，仅做摘要，具体台词文本与任务内容由策划在实现阶段补充。

### 1. 基本信息

- **正式姓名**：林书瑶
- **常用称呼**：主角称她为「林经理」（主角不直呼其名）。
- **角色定位**：
  - 表面：上班族属性，公事公办，有明显上下班时间观念，会偷懒。
  - 本质：来自更高层神秘系统/世界规则的**监督者/观测者**；是主角这场冒险的「监督员」。
- **在基地中的行为**：
  - 上班时间：站在基地固定位置，不主动搭话。
  - 下班时间：完全不存在，无替代交互点。

### 2. 出现规则与菜单

- **出现时间**：`09:00–17:30`。
- **场景**：主角基地（具体坐标待实现时配置）。
- **主菜单**：
  - `闲聊`：
    - 触发「扫描所有触发条目 → 随机命中 1 条 → 未命中则走摸鱼台词池」。
  - `工作/任务`：
    - 当「既无可接任务，又无可交付/可结算任务」时隐藏。
    - 任务列表暂不做排序/筛选。
  - `离开`：
    - 退出对话。

### 3. 默认台词池（无触发时）

- 语气：
  - 像在上班摸鱼的职场人：嚼槟榔、抽烟、抱怨、敷衍。
- 行为：
  - 在当前没有任何触发条目满足条件时：
    - 从「林经理默认台词池」中**等概率随机**选取一条台词播出。
  - 台词池内容由策划在实现时手动填入。

### 4. 已定义的触发条目示例

#### 4.1 Entry #1 — 综艺主人公告知

- **条目ID**：`supervisor.firstTalk_01`
- **入口**：`闲聊`
- **条件**：
  - 这是主角第一次与林经理对话：
    - 可实现为 `flag.lsy_has_talked == false`。
- **对话大意**：
  - 她告知主角：你已经被选为某个综艺节目的主人公。
  - 节目的核心内容是：**「找到回家的路」**。
- **效果**：
  - 无直接任务或世界改变。
  - 仅写入一次性 flag，例如：`flag.lsy_has_talked = true`。
- **一次性与作用域**：
  - 一次性。
  - `scope = "global"`。

#### 4.2 Entry #2 — 语言技能修正

- **条目ID**：`supervisor.languageFix_01`
- **入口**：`闲聊`
- **条件**：
  - 检测到主角的**语言技能等级为 0**：
    - 例如：`character.skills["survival_language"].level == 0`。
- **对话大意**：
  - 林经理恍然大悟，表示自己差点忘了提醒：
  - 大意为：「这地方语言不通，你这样出去会有大问题」。
- **效果**：
  - 直接让主角的**语言技能 +1 级**（从 0 提升到 1）。
- **一次性与作用域**：
  - 一次性。
  - `scope = "global"`。

> 注：以上两条触发条目仅为示例；后续可继续为林经理或其他 NPC 在本文件基础上添加更多条目与任务。

## 五、与实现约定的衔接说明

本节说明本模板与「14-implementation（实现约定）」等文档之间的关系，方便程序侧落地。

- **配置位置建议**：
  - NPC 行为与触发条目可放入 `/data/npc/` 或等效目录下 JSON：
    - 如：`/data/npc/supervisor_lin.json`。
  - 任务可放入 `/data/quests/` 目录下按模块拆分的 JSON。
- **技能字段对齐**：
  - 语言技能 ID 推荐与技能系统文档保持一致（例如 `survival_language`）。
  - 触发条件中对于技能等级的读取，与实现约定中 `character.skills[skill_id].level` 保持一致。
- **存档与 flag**：
  - `TriggerEntry` 的「已触发状态」「重复次数」「上次触发时间」应记录在存档的某个子树下（例如 `character.npcTriggers` 或 `world.triggerStates`）；字段名由实现方决定，只需保证能支持本文件中的 `repeatable` 与 `scope` 语义即可。
  - 任务状态应存入存档中的 `quests` 子树（例如 `save.quests[questId] = { state, ... }`）。
- **扩展空间**：
  - 若后续需要更复杂的 NPC（比如会移动、会在多个场景出现、会主动找玩家），可以在本文件结构上扩展：
    - 增加 `movementPattern`、`multiSceneAppearances` 等字段。
    - 但尽量保持「TriggerEntry 与 Quest 结构不变」，以便共享同一套工具链与策划写法。

本文件到此为止，作为后续所有 NPC 与任务设计的**模板与约定规范**。
