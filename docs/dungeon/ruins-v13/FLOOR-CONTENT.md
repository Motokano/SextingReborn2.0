## 普通房间的随机分配

2026-10-23 确认：普通楼层的房间内容随机生成，允许空房，不要求每间建筑都安排敌人、资源或兴趣点。敌人房、混合房和空房的具体抽选权重本轮不定新数值；已有资源房和领悟点比例继续作为可覆盖的默认配置，不能把演示地图中的固定房数组合作为每层模板。

房间是否有内容，与入口是否装门分开决定。允许没有门但有敌人、资源或兴趣点的房间；没有门不等于空房。无门房仍有合法出入口和墙体，不允许穿墙或斜穿墙角。通过无门入口按普通移动处理，不扣开门体力，也不产生开门奖励倍率；敌我视线由实际墙体和开口判断。有门房沿用木门／铁门费用和只能开启、不能关闭的规则。

本轮原型先以 20% 空房预留判定、35% 无门判定演示，两项为可调整的预览默认值，不视为已定稿的最终平衡数值。每间房独立抽选，按种子与楼层保存；两种判定使用独立随机序列，无门可以与敌人、资源、领悟或空房任意组合，不保证每层固定数量。

空房先预留，敌人、资源和领悟不再占用这些房间；仍需为本层既定资源额度保留候选空间。后续没有分配内容的房间也算空房，因此 20% 不是最终空房占比上限。房间列表与地图标签按最终实际内容判断空房；空房保持完整可行走空间，不填充假奖励或强行安排敌人。房间比例的分母仍包含全部可用房间，包括空房和无门房。

无门入口保留原门口的格子和朝向，移除门扇、门框交互与门实体；该格作为普通室内地板，不在小地图上画成已开门。原有墙体和角落碰撞不变；敌人可通过开口发现玩家并追击。入口内外落脚格保持畅通，室外容器、恢复点和游荡路线不会因为移除门而自动迁入房内。

普通楼层之间的难度、内容和比例差异后续调整，当前不新增逐层强度表或强制递增规则。

配置按“默认值 → 地牢覆盖值 → 门票提供的本次覆盖值”的顺序按字段合并。没有修改的字段保留前一层值；只影响本次探险，不修改全局默认值。门票词条的具体内容和多条词条如何叠加尚未设计，本版只接受门票系统算好的最终覆盖数值，不预定加法、乘法或词条强度。

调用 `RuinsContentConfig.resolve({overrides, ticketOverrides})` 可得到独立、不可变的完整配置。原型生成入口接收 `contentOverrides` 与 `ticketOverrides`，经探险记录的 `contentConfig(settings, options)` 解析后传给资源和领悟生成器。实际入场时把生效配置保存在 `run.contentConfig`：同次刷新、重置和继续深入沿用该份配置，重新进入才重新计算。已经存在的探险不会因传入另一组门票参数而被中途改写。

仅用于说明接口的例子（不代表正式门票）：

```js
const ticketOverrides = {
  resourceRooms: { minRatio: 0.15, maxRatio: 0.25 },
  insight: { chance: 0.10 }
};
```

比例与概率允许 0～1，下限不能高于上限；权重允许为零但总和必须大于零，奖励为非负整数。非法值明确报错，不悄悄改回默认值。配置控制目标数量与权重，合法空位、可达性及整层共用额度仍需满足；可用候选不足时不强占敌人房或通路。

新探险使用版本 11 配置。版本 8 的据点与车间地形保持原规则：车间由中央机组、一道挡视线的残墙及一道低工作台排形成分区，每个容器路线须比仅有机组时至少多 3 步。完整规则见[土匪据点](OUTPOSTS.md)和[废弃修理车间](WORKSHOP.md)。版本 9 新增[废弃诊疗所](CLINIC.md)，采用两个隔间及两条汇合通路，3～4 名敌人、1 个急救推车与 1 个容器，恢复点占用本层室内恢复额度。三类大型房共用目标与敌人、容器总额；车间和诊疗所各自默认候选概率 45%、每层最多 1 间，这是候选偏好而非最终房间占比。版本 1～10 的已保存探险沿用原配置。版本 10 新增[废弃食堂](CANTEEN.md)，80～100 格、3～4 名敌人、2 个食材取用点及 1～2 个生活物资容器，替换一间已有采集房的资源额度。食堂与其他大型房共用目标，不提高敌人、容器和资源房总额。

版本 1～6 配置和未保存配置的旧探险继续沿用旧布局，不在刷新时移除门、追加障碍或重算收益。旧存档没有配置字段时使用 `legacyV1`，版本 2～6 分别使用对应的 `legacyV2`～`legacyV6` 历史快照；快照不能随日后的平衡调整修改。历史配置下的地图身份保持不变，新配置与最终入口状态纳入地图身份，避免把旧奖励、使用状态或探索记录套在另一组内容上。地图分类、点位窗口和实际领取统一读取生成结果，不另写固定数值，也不新增玩家界面说明。

## 当前生成口径

比例以本层内容房总数 N 为分母。采集、采矿、伐木的纯资源房和资源混合房合并计算，一间房只计一次；默认三种资源合计占 10%～20%，不是每种各占一份，门票修正也作用于这份合计范围。

资源房数量在 `ceil(N × 生效下限)` 至 `floor(N × 生效上限)` 的整数范围中等概率抽取，并随地图种子和配置固定。例如默认配置下 14 间内容房安排 2 间资源房，占 14.3%。资源类型轮换分配，不要求每层三种都有。极小地图若不存在符合区间的整数，暂取不超过生效上限的数量，允许为 0；这是原型的整数处理方式。

新生成地图中的资源混合房从一间纯资源房整体迁入资源点，原房撤销资源身份。目标混合房必须容纳整组资源，否则跳过这次转换，避免分拆后增加资源房数量或额外增产。房间面积、点位疏密与通行检查沿用原规则。

领悟点数量按 N 次独立的生效概率判定累计；默认 5%，长期目标为每 100 间内容房约 5 处。每层可以为 0，也可能有多处，不强制取整成 1。目标点位放入未分配敌人、资源或混合内容的房间，每间最多一处，优先约 16 格的紧凑空间；当前先做室内点，类型按生效权重抽选，默认书桌与残桩各 50%。室内偏好仍属于预览调参。

棋子占一格并阻挡通行，靠墙、与门至少相隔两格，避开进门落脚位。至少保留一个可达的正交操作格，以及 60% 的房内可通行空间；检查八向不能穿墙角、全图连通及关门时撤离通路。合法位置不足时允许少放领悟点，不补到路上或额外挤入其他房间。

资源点、容器和恢复点仍共用各自已有的整层额度。混合房的功能内容不另增一份收益，沿用[混合内容房规则](MIXED-ROOMS.md)。

## 特别房间与特别楼层

特别内容由设计时手动指定。手动指定哪些内容、出现条件及所在层，与运行时具体如何摆入随机地图分开配置；本次不规定固定坐标，也不自动给每层或最深层加首领。

特别内容需要一间房时，优先在本层新增一间满足要求的房间；空间已经满了、无法合法新增时，再替换其他普通房间。不能为了新增越过本地牢的地图上限或破坏通路；替换仍需容纳该内容，并保留本次已指定的其他必需内容。新增或替换后的普通层继续按最终房间集合检查资源比例与已有整层额度，不额外复制一份普通资源奖励。

特别内容也可以是一整个特别楼层。特别楼层独立设计，布局、房间、敌人、兴趣点、奖励与专属规则逐个指定，不自动套用普通废墟楼层的随机内容配置、房型比例或层间差异；本轮仅确认它与普通探险之间的入口和往返关系，不代为设计特别楼层本身。

例如某条传闻要求入口只能出现在普通三层：三层生成独立特别入口，进入对应特别楼层后可返回原来的三层。三层原有通往四层的普通通行口保留；特别入口和特别楼层不承担进入普通四层的通道。三层只是这条传闻的限制示例，不规定所有特别楼层都从三层进入。往返保存规则见[特别楼层分支](PASSAGE.md#特别楼层分支)。
