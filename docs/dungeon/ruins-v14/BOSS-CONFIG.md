# 头目出现率与独立掉落配置

> 2026-10-31最新人数设计修订：非房间敌人改为基础12名、±20%，房间人数独立。头目属于专属房间0／1名，不再扣非房间普通敌人名额，仍按独立60%判定，详见[人数设计](../../design/street-thug-floor-distribution.md)。此项尚待运行接入；下文“替换一名普通敌人”的描述与测试记录是当前旧运行逻辑，后续实装应同步更改。

2026-10-31。用户要求头目出现率为60%，通过配置调整；两种特殊容器与头目掉落可分别配置。第四层小屋仍按此前约定固定生成，本次概率只控制头目本人，不控制房间或两种容器。

## 配置入口

统一修改 `data/dungeon-config.json` 的 `boss`：

| 字段 | 当前值／作用 |
| --- | --- |
| `floor` | 4，投放楼层 |
| `enemyId` | `enemy.street_thug_boss` |
| `spawnChance` | `0.6`，0为不出现，1为必定出现 |
| `loot.corpse` | 头目死亡后的尸体袋奖励 |
| `loot.containers.den-private` | 头目私藏箱奖励 |
| `loot.containers.den-basket` | 赃物袋筐奖励 |

三份奖励配置各自使用以下结构，当前均为 `inheritSharedPool: true`、`extraDrops: []`，因此暂不改变已有奖励内容：

```json
{
  "inheritSharedPool": true,
  "extraDrops": [
    {
      "item_id": "sewing_toe_cap",
      "chance": 0.25,
      "min": 1,
      "max": 2,
      "rarity": "uncommon"
    }
  ]
}
```

此段仅示范格式，**未写入正式掉落**。将该结构填到需要的奖励来源即可。

- `inheritSharedPool: true`：保留该来源原本的通用有限库存抽取，再追加专属奖励；普通容器类别权重仍有效。
- `inheritSharedPool: false`：只使用该来源的 `extraDrops`。若数组为空，则没有物品。
- 每条 `extraDrops` 独立判断 `chance`（0～1），成功后在 `min`～`max` 内等概率抽取整数数量，含两端；设为1可保证掉落。不同条目可以同时掉落。
- `item_id` 必须是游戏已登记的物品；`rarity` 必须是 `search.rarities` 中的稀有度，决定搜索所需时间。数量范围必须为正整数且不超过100000。
- 专属奖励不扣通用池库存，不受通用空箱率或容器类别权重过滤；门票的数量加成只影响通用池，专属条目按填写的概率与数量结算一次。
- 奖励仍进入原容器／尸体袋搜索流程，不直接发到背包；搜索、领取、标记回收和佣金继续用原规则。
- 普通敌人及普通容器不读取这三份专属表。

## 生成与存档

出现判定由远征种子、楼层和敌人ID派生，独立于布局重试次数；同一远征生成重试不会反复抽取直到出现。新远征的新种子重新抽取。概率是长期比例，不保证每十次必有六次。

未抽中时仍放置完整小屋及两个特殊容器，原有普通敌人保留；抽中时从本层已有敌人额度替换一名，不额外增加敌人。头目出现后的坐标、AI、底气500、普通招式消耗14、膝撞消耗21、自选挑战与绕行撤离均不变。

三份专属奖励配置在生成该层时复制到对应实例，随楼层保存。配置改动只影响之后新生成的楼层，不替换已生成或已打开容器的内容；读档不会重抽头目、复活头目或重抽奖励。旧存档没有专属覆盖字段时继续原通用掉落。历史调用省略 `spawnChance` 时按旧版必定出现兼容；正式配置显式使用0.6。

## 接入与检查

`js/dungeon/boss.js` 负责出现判定与固定房间部署，`boss-rewards.js` 负责奖励配置校验／实例快照／额外奖励抽取，`runtime.js` 接通真实开箱和死亡结算。预览显示本层头目在场状态及配置概率。

`node tools/test-dungeon-boss-config.mjs` 检查0%／100%边界、错误配置、无头目小屋完整性、配置快照、真实开箱／尸体奖励、叠加与独占奖励、有限池库存、重复死亡防重、存档恢复。10000个独立种子抽样为5960次出现。`tools/test-street-thug-boss.mjs` 的战斗验收显式设100%生成，避免把概率判定混入AI和数值检查；固定小屋的布局检查同样显式使用100%。
